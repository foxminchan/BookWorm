## Explanation: Why a Layered Monorepo?

BookWorm serves two separate web experiences: a customer-facing storefront and a staff administration dashboard. Both applications share authentication against [[system|identity-provider]], typed backend API clients, form validation rules, telemetry, UI components, and test configuration.

Without clear boundaries, shared code tends to accumulate circular dependencies, duplicated configuration, and direct coupling between low-level helpers and application screens. Organizing `src/Clients` as a Bun and Turborepo workspace enforces a strict, one-way dependency flow:

### Design Principles

- **One-way dependency tiers:** Every package belongs to one of four tiers (`config`, `foundation`, `domain`, or `app`). Lower tiers never import from higher tiers, which prevents circular dependencies and keeps shared utilities reusable.
- **Composable configuration:** Shared linting, TypeScript, Next.js, and test presets live once in configuration packages so both applications stay aligned without copy-pasting setup files.
- **Scoped environment validation:** Each capability (authentication, API gateway, telemetry, AI chat) defines its own environment schema, and each application composes only the variables it actually needs.
- **Direct workspace resolution:** Next.js and Vitest resolve workspace packages directly from source during builds and tests, avoiding slow cascading pre-build steps while still enforcing boundaries.
- **Single package manager:** Standardizing on Bun and a single root lockfile avoids lockfile drift between local development and CI.

### Package Boundary Tiers

Turborepo validates imports across all 17 workspace packages using boundary tags in `turbo.json`:

| Tier Tag     | Allowed Dependencies             | Denied Dependencies           | Purpose                                                               |
| :----------- | :------------------------------- | :---------------------------- | :-------------------------------------------------------------------- |
| `config`     | None within workspace            | `app`, `domain`, `foundation` | Shared ESLint, TypeScript, Next.js, Vitest, Playwright, and Allure    |
| `foundation` | `config`, `foundation`           | `app`, `domain`               | Pure types, helpers, environment schemas, and telemetry registration  |
| `domain`     | `config`, `foundation`, `domain` | `app`                         | UI design system, API clients, query hooks, auth, SEO, schemas, mocks |
| `app`        | All tiers                        | —                             | End-user Next.js applications (`storefront`, `backoffice`)            |
