## How to Run Frontend Quality Checks

BookWorm verifies frontend changes across four layers: static checks (formatting, boundaries, types, and linting), offline unit/component tests (Vitest + MSW), browser end-to-end tests (Playwright BDD + `axe-core`), and production Next.js builds.

### Before Opening a Pull Request

1. **Format modified files** from the repository root:

   ```bash
   mise run format:fe
   ```

2. **Run static checks** from `src/Clients` to verify workspace boundaries, TypeScript types, and ESLint (`--max-warnings 0`, including `jsx-a11y` rules):

   ```bash
   bun run boundaries
   bun run check-types
   bun run lint
   ```

3. **Run unit and component tests** from `src/Clients` (uses deterministic mock data and requires no running backend):

   ```bash
   bun run test
   ```

4. **Verify the production build** when changing layouts, routes, or Server/Client Component boundaries:

   ```bash
   bun run build
   ```

5. **Run browser E2E tests** when modifying user journeys, navigation, or accessibility behavior:

   ```bash
   bun run e2e
   ```

### Generating Test Reports

To aggregate Vitest and Playwright results into an Allure report from `src/Clients`:

```bash
bun run allure:report
```

## Reference

### Verification Command Matrix

| Check                      | Working Directory | Command                 | Scope                                                                                                 |
| :------------------------- | :---------------- | :---------------------- | :---------------------------------------------------------------------------------------------------- |
| Format frontend files      | Repo root         | `mise run format:fe`    | Prettier across `src/Clients` (`*.{ts,tsx,md,feature}`)                                               |
| Verify package boundaries  | `src/Clients`     | `bun run boundaries`    | Enforces `config` / `foundation` / `domain` / `app` import rules                                      |
| Type check all packages    | `src/Clients`     | `bun run check-types`   | Strict TypeScript check across workspace packages                                                     |
| Lint all packages          | `src/Clients`     | `bun run lint`          | ESLint (`--max-warnings 0`) including `eslint-plugin-jsx-a11y`                                        |
| Run unit & component tests | `src/Clients`     | `bun run test`          | Vitest + Happy DOM + MSW v2 across all three apps                                                     |
| Collect code coverage      | `src/Clients`     | `bun run test:coverage` | V8 coverage reports (`lcov`, `json-summary`, `html`) per app                                          |
| Build production apps      | `src/Clients`     | `bun run build`         | Next.js production builds with Turbopack                                                              |
| Run BDD E2E tests          | `src/Clients`     | `bun run e2e`           | Compiles Gherkin specs and runs Playwright tests                                                      |
| Generate Allure report     | `src/Clients`     | `bun run allure:report` | Combines unit and E2E results across `backoffice`, `storefront`, and `commerce` into `allure-report/` |

### Shared Test Infrastructure

- **Configuration (`@workspace/app-config`):** Centralizes Vitest, Playwright BDD, and Next.js settings so all apps share deterministic Faker seeds, isolated MSW mock lifecycles, and router stubs without per-app duplication.
- **Coverage exclusions:** Thin declarative files (`page.tsx`, `layout.tsx`, `env.mjs`, `instrumentation.ts`, `proxy.ts`, `config/`) are excluded from coverage metrics so percentages reflect executable logic in `features/`, `components/`, and `hooks/`.
