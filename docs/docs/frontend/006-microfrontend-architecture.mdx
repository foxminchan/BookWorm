## Explanation: Why Split the Customer Website?

BookWorm's customer-facing website serves two very different kinds of pages:

- **Public browsing (`@bookworm/storefront`):** The home page, book catalog, book details, reviews, info pages, sign-in pages, and the AI assistant. These pages are the same for most visitors, so they can be cached for speed and indexed by search engines.
- **Personal shopping (`@bookworm/commerce`):** The shopping basket, checkout, customer profile, and order history. These pages belong to a specific signed-in shopper, so they must stay private, always show fresh data, and stay hidden from search engines.

Splitting these into two separate apps lets each side be tuned, updated, and deployed on its own—while customers still experience one single website.

### One Entry Point, One Routing File

<MermaidFileLoader file="mermaids/mfe-gateway-routing.mmd" />

Customers never see two separate websites. Everything goes through a single gateway, and both the gateway and the frontend apps read from the same configuration file (`src/Clients/apps/storefront/microfrontends.json`):

- **No URL conflicts:** Backend API routes (like `/catalog` or `/ordering`) and sign-in routes are matched first, so frontend pages can never accidentally override them.
- **Separate asset paths:** The commerce app serves its own static files under `/commerce-assets/*` so they never clash with the storefront's files.
- **Storefront as the default:** Any customer route that does not match a backend service or a commerce path goes to the storefront app.

### Seamless Look and Navigation

Even though the storefront and commerce pages live in separate apps, shoppers should not feel like they are jumping between different sites. Both apps use a shared layout package (`@workspace/storefront-shell`) that provides:

- The same header, footer, and mobile navigation bar.
- Cross-app links that preload pages smoothly when moving between browsing and checkout.
- A shared basket counter so the header badge stays up to date everywhere.

### Single Sign-In Across Both Apps

<MermaidFileLoader file="mermaids/mfe-user-journey.mmd" />

Sign-in is handled in one place—the storefront app—so there is only one login flow to maintain. Because both apps sit behind the same website address, they share the same login session. If an unauthenticated shopper visits a protected page like `/basket`, `/checkout`, or `/account`, they are sent to the login page and returned to where they started once signed in.

## How-to Guide: Add a New Customer Page

Follow these steps when adding a new page for shoppers:

1. **Pick the right app:**
   - Put public, shareable, or search-indexed pages in `src/Clients/apps/storefront/app/`.
   - Put personal or signed-in pages in `src/Clients/apps/commerce/app/`.
2. **Register commerce routes:** If you added the page to `commerce`, add its URL pattern to `routing[].paths` in `src/Clients/apps/storefront/microfrontends.json`. (Storefront pages are matched automatically as the default fallback.)
3. **Avoid backend path names:** Make sure the first part of your new URL does not match an existing backend prefix (`/catalog`, `/basket`, `/ordering`, `/rating`, `/chat`, or `/entra`).
4. **Require sign-in if needed:** If the new `commerce` page is only for signed-in users, check that its path is listed under `protectedRoutes` in `src/Clients/apps/commerce/proxy.ts`.
5. **Run the checks:** From `src/Clients`, verify boundaries, types, linting, tests, and the build:
   ```sh
   bun run boundaries
   bun run check-types
   bun run lint
   bun run test
   bun run build
   ```

## Reference

### App Ownership

| App          | Package                | Routes                                                       | Cached & Public | Sign-In Owner                   | Health Check  |
| :----------- | :--------------------- | :----------------------------------------------------------- | :-------------- | :------------------------------ | :------------ |
| `storefront` | `@bookworm/storefront` | `/{**remainder}` (default)                                   | Yes             | `/api/auth/[...all]`            | `/`           |
| `commerce`   | `@bookworm/commerce`   | `/basket`, `/checkout/*`, `/account/*`, `/commerce-assets/*` | No              | Shared via gateway              | `/api/health` |
| `backoffice` | `@bookworm/backoffice` | `/backoffice/{**remainder}`                                  | No              | `/backoffice/api/auth/[...all]` | `/backoffice` |
