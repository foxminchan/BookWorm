This reference specifies BookWorm's frontend data pipeline across `@workspace/types`, `@workspace/validations`, `@workspace/api-client`, `@workspace/api-hooks`, and Jotai client atoms. For architectural rationale behind these layers, see [[doc|frontend/007-architecture-and-state-design]].

## Overview

| Property              | Value                                                                                                                                        |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**             | BookWorm Frontend (`src/Clients/packages/`)                                                                                                  |
| **Source**            | `packages/api-client`, `packages/api-hooks`, `packages/types`, `packages/validations`, `packages/storefront-shell`                           |
| **Protocol / format** | HTTP/JSON (including HTTP `QUERY`), conditional ETags (`If-None-Match`/`If-Match`), Server-Sent Events (SSE), Agent-User Interaction (AG-UI) |
| **Authentication**    | Bearer token injected via `ApiClient.setTokenProvider(...)` from Better Auth + Microsoft Entra ID                                            |

## HTTP client, retries, and ETag headers (`@workspace/api-client/client`)

### Standard headers (`@workspace/api-client/headers`)

`HttpHeaders` standardizes header names across clients and MSW mocks: `Accept`, `Authorization`, `Cache-Control`, `Content-Type`, `ETag`, `If-Match`, `If-None-Match`, `Link`, `Location`, `Pagination-Count`, `x-request-id`, and `Retry-After`.

### Retry and conditional request contract

| Setting / behavior                 | Verified value (`packages/api-client/src/client.ts`)                                                                       | Notes                                                                       |
| :--------------------------------- | :------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------- |
| Max retries                        | `NEXT_PUBLIC_MAX_RETRIES` (default `5`)                                                                                    | Executed via `p-retry`; respects `AbortSignal`                              |
| `Retry-After` cap                  | `60,000 ms` (`MAX_RETRY_AFTER_MS`)                                                                                         | Parses both delay-seconds and HTTP-date headers                             |
| Always retried statuses            | `408 Request Timeout`, `429 Too Many Requests`                                                                             | Never retries other `4xx` responses                                         |
| Network error retry                | Retried when `error.code` is present and not `ECONNABORTED`                                                                | Never retries canceled requests (`axios.isCancel`)                          |
| `5xx` retry rule                   | Retried for idempotent methods (`GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`, `QUERY`) or any request carrying `x-request-id` | Prevents duplicate non-idempotent writes without an idempotency key         |
| Conditional GET (`getConditional`) | Sends `Cache-Control: no-cache` and optional `If-None-Match`; accepts `2xx` or `304 Not Modified`                          | Returns `{ data, etag, notModified }`                                       |
| Optimistic concurrency conflict    | `isPreconditionFailedError(error)` checks HTTP `412 Precondition Failed`                                                   | Triggered when `If-Match` fails on Backoffice book or order-summary updates |

### `QueryClient` defaults (`@workspace/api-hooks/query-client`)

| Option                           | Server (`typeof window === "undefined"`)                           | Browser                                                                            |
| :------------------------------- | :----------------------------------------------------------------- | :--------------------------------------------------------------------------------- |
| Instance lifecycle               | New `QueryClient` per request (prevents cross-request state leaks) | Module-scoped singleton (`browserQueryClient`)                                     |
| `staleTime`                      | `60,000 ms` (60 seconds)                                           | `60,000 ms` (60 seconds)                                                           |
| `retry`                          | `false` (zero SSR retries)                                         | Up to `2` retries (`MAX_CLIENT_QUERY_RETRIES`); skips `4xx` except `408` and `429` |
| `dehydrate.shouldDehydrateQuery` | Includes `pending` queries alongside default settled queries       | —                                                                                  |

## Real-time channels and client state

### Real-time streaming channels

| Channel           | Application    | Endpoint & protocol                                                                              | Reconnect / streaming contract                                                                                                                                                                                     |
| :---------------- | :------------- | :----------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dashboard metrics | **Backoffice** | `/ordering/api/v1/dashboard/stream` (`text/event-stream` SSE via `dashboardApiClient.subscribe`) | Sends `Accept: text/event-stream`, `credentials: "include"`, `cache: "no-store"`, and Bearer token; parses `event: dashboard` frames; reconnects with exponential backoff starting at `1,000 ms` up to `30,000 ms` |
| AI assistant chat | **Storefront** | `/api/copilotkit/[[...slug]]` -> `/chatting/ag-ui` (CopilotKit AG-UI & declarative A2UI)         | Forwards authenticated customer tokens to **Chat API**, streams responses, and connects to `@generative-a11y/ag-ui` for screen-reader pacing                                                                       |

### Jotai client atoms

| Atom                   | Source file                                          | Applications         | Behavior                                                                                                              |
| :--------------------- | :--------------------------------------------------- | :------------------- | :-------------------------------------------------------------------------------------------------------------------- |
| `isAuthenticatedAtom`  | `packages/storefront-shell/src/atoms/basket-atom.ts` | Storefront, Commerce | Boolean auth flag (default `false`) gating basket fetches                                                             |
| `basketAtom`           | `packages/storefront-shell/src/atoms/basket-atom.ts` | Storefront, Commerce | `atomWithQuery` keyed by `basketKeys.detail()`; `enabled: get(isAuthenticatedAtom)` short-circuits anonymous requests |
| `basketItemCountAtom`  | `packages/storefront-shell/src/atoms/basket-atom.ts` | Storefront, Commerce | Derived sum of item quantities (`0` when empty or signed out)                                                         |
| `basketItemsAtom`      | `packages/storefront-shell/src/atoms/basket-atom.ts` | Storefront, Commerce | Derived array of `BasketItem` (stable empty array fallback)                                                           |
| `isCopilotEnabledAtom` | `apps/storefront/atoms/feature-flags-atom.ts`        | Storefront           | Initialized from `env.NEXT_PUBLIC_COPILOT_ENABLED`                                                                    |

## Error responses

| HTTP status                                     | Condition                                                         | Client recovery behavior                                                                                                 |
| :---------------------------------------------- | :---------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------- |
| `304 Not Modified`                              | `If-None-Match` matches current server ETag on `getConditional()` | Returns `{ data: null, etag, notModified: true }`; caller retains cached entity                                          |
| `401 Unauthorized`                              | Missing or expired Microsoft Entra ID token                       | Not retried; triggers re-authentication or redirects to `/login`                                                         |
| `408 Request Timeout` / `429 Too Many Requests` | Transient timeout or API rate limit                               | Retried by `ApiClient` (up to `NEXT_PUBLIC_MAX_RETRIES`, honoring `Retry-After` up to `60,000 ms`)                       |
| `412 Precondition Failed`                       | `If-Match` ETag is stale due to a concurrent Backoffice edit      | Detected by `isPreconditionFailedError(error)`; never retried; prompts user to reload latest version                     |
| `5xx`                                           | Upstream service error                                            | Retried only for idempotent methods (`GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`, `QUERY`) or requests with `x-request-id` |
