BookWorm targets the **Web Content Accessibility Guidelines (WCAG) 2.1 Level AA** across all three Next.js applications (**Storefront**, **Commerce**, and **Backoffice**). Because automated scanners catch only a subset of real-world barriers—especially around keyboard focus and streaming AI responses—BookWorm layers static linting, accessible headless primitives, browser `axe-core` tests, and live screen-reader announcements together.

## Context and motivation

BookWorm is a reference e-commerce and AI-assisted application with distinct accessibility challenges across its three zones:

- **Storefront** combines catalog discovery with a streaming conversational AI assistant (`CopilotKit` + Agent-User Interaction (AG-UI)). Unthrottled token streams can overwhelm screen readers, while dynamic generative UI cards need semantic landmarks and keyboard reachability.
- **Commerce** handles authenticated basket updates, confirmation dialogs, and multi-step checkout flows where broken focus management or missing error associations block keyboard-only shoppers from completing purchases.
- **Backoffice** presents data-dense tables, charts, and CRUD dialogs where keyboard navigation, non-color status indicators, and accessible form labels are essential for staff productivity.

Because BookWorm is a demonstration project, WCAG 2.1 Level AA is maintained as an ongoing engineering practice rather than a formal third-party conformance claim across every external dependency.

## How it works

BookWorm defends accessibility across four complementary layers from authoring time through runtime assistive-technology behavior.

- **Accessible UI primitives and static linting:** Shared components in `@workspace/ui` wrap `@base-ui/react` headless primitives and semantic HTML. Every lint run (`bun run lint`, enforced in `.github/workflows/frontend-shared.yml` with `--max-warnings 0`) executes `eslint-plugin-jsx-a11y` across all three apps and shared packages.
- **Automated browser audits:** Storefront's Playwright BDD suite (`e2e/features/accessibility.feature`) runs `@axe-core/playwright` color-contrast and landmark checks alongside 10 end-to-end keyboard and focus scenarios spanning Storefront and Commerce.
- **Keyboard and focus management:** Every interactive page provides a **Skip to main content** link on first `Tab`, visible focus indicators, and logical focus order. Modal dialogs and drawers trap focus while open, dismiss on `Escape`, and restore focus to the triggering control.
- **Paced screen-reader announcements:** Dynamic state indicators (offline banners, rate-limit notices, syncing states, basket updates) use `aria-live` regions. In **Storefront**, `@generative-a11y/react` and `@generative-a11y/ag-ui` connect the AI chat stream to assistive technologies so streaming text, tool calls, and prompts announce at a readable pace.

### Core accessibility priorities

- Full keyboard access to every interactive workflow (including end-to-end checkout)
- Clear focus indicators and predictable focus order
- Semantic HTML landmarks (`main`, `navigation`, `contentinfo`) and single `<h1>` heading hierarchies
- WCAG 2.1 Level AA color contrast paired with non-color status, required-field, and error cues
- Meaningful text alternatives (`alt` text and accessible names) for images and icon controls
- Explicit labels, instructions, and error messages on every form input
- Responsive layouts that remain readable under zoom and increased text sizes

## Design trade-offs

| Decision                                                     | Benefits                                                                                | Costs and limits                                                                                                    |
| :----------------------------------------------------------- | :-------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------ |
| Headless primitives (`@base-ui/react`) in `@workspace/ui`    | Built-in ARIA roles, keyboard navigation, and focus restoration across all 3 apps       | Custom styling must preserve visible focus rings and contrast tokens                                                |
| Static `jsx-a11y` as a blocking CI gate (`--max-warnings 0`) | Catches missing labels, alt text, and invalid ARIA before merge with fast feedback      | Cannot detect runtime contrast, focus traps, or screen-reader pacing issues                                         |
| Playwright BDD + `axe-core` scenarios in Storefront          | Verifies real keyboard journeys (including Storefront-to-Commerce checkout) in Chromium | Requires a running browser stack; Backoffice and Commerce do not yet have standalone `accessibility.feature` suites |
| Dedicated streaming announcements (`@generative-a11y/*`)     | Prevents screen-reader announcement flooding during AI token streaming                  | Adds Storefront-specific integration surface tied to AG-UI events                                                   |

## Alternatives considered

- **Automated scanners alone (`axe-core` / linting only):** Misses roughly half of real accessibility defects, including focus-return regressions, confusing tab order, and unreadable AI streaming announcements.
- **Custom hand-rolled dialogs and menus:** Eliminates `@base-ui/react` dependency, but repeatedly reintroduces subtle ARIA, focus-trap, and `Escape`-handling bugs across three applications.

## Supported environments and reporting barriers

- **Supported environments:** Modern desktop and mobile browsers, keyboard-only navigation, and common screen-reader workflows. Behavior can vary across browser, operating system, and assistive-technology combinations; third-party embeds are supported on a best-effort basis.
- **Reporting a barrier:** Open a GitHub issue with the [accessibility issue template](https://github.com/foxminchan/BookWorm/issues/new?template=accessibility.yml) (including affected page, reproduction steps, browser/assistive technology, and severity), or email [nguyenxuannhan407@gmail.com](mailto:nguyenxuannhan407@gmail.com) without disclosing personal or medical data.
- **Security boundary:** Never post passwords, private data, or security-sensitive details in public accessibility issues; follow [SECURITY.md](https://github.com/foxminchan/BookWorm/blob/main/.github/SECURITY.md) for security disclosures. See [ACCESSIBILITY.md](https://github.com/foxminchan/BookWorm/blob/main/.github/ACCESSIBILITY.md) for the repository entrypoint.
