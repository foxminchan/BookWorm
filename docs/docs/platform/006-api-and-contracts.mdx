## Configuration & Operational Defaults

### Global API & Error Conventions

- **Single public ingress:** External browser and API traffic enters through the YARP API Gateway, which strips `/{service}` prefixes before forwarding.
- **API versioning:** REST services use URL-segment and header versioning (`V1` at `/api/v1/...`).
- **Rate limiting:** Global chained limiter (100 concurrent requests + 30 requests/minute per IP/Host) plus a per-user token bucket (30-token burst, 20 tokens replenished every 10s, queue limit 5).
- **Standard error format:** HTTP services return RFC 9457 Problem Details JSON (`application/problem+json`).

| Status                  | Meaning                           | Typical cause                                                                      | Client recovery                                      |
| :---------------------- | :-------------------------------- | :--------------------------------------------------------------------------------- | :--------------------------------------------------- |
| `400 Bad Request`       | Validation or domain-rule failure | Payload validation error, missing request ID header, or invalid Order transition   | Fix payload or preconditions; do not retry unchanged |
| `401 Unauthorized`      | Authentication failed             | Missing, expired, or invalid Microsoft Entra ID JWT                                | Re-authenticate and retry                            |
| `403 Forbidden`         | Authorization denied              | Token lacks required Entra ID role or scope                                        | Request token with required role and scopes          |
| `404 Not Found`         | Missing or out-of-scope resource  | Entity does not exist or belongs to another customer                               | Verify resource ID and ownership                     |
| `409 Conflict`          | Concurrency or duplicate request  | Duplicate request ID (1-hour Redis window), lock contention, or duplicate feedback | Query current state before issuing a new request     |
| `429 Too Many Requests` | Rate limit exceeded               | Global or per-user rate limit hit (`Retry-After` header included)                  | Back off for `Retry-After` seconds and retry         |
| `500 / 502 / 503`       | Server or upstream failure        | Unhandled error or unavailable downstream dependency (e.g., fail-closed Presidio)  | Retry idempotent requests with exponential backoff   |
