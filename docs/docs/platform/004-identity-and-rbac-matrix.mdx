This reference documents how BookWorm authenticates users, AI agents, and services. Microsoft Entra ID handles user and agent identity. User-assigned Managed Identities handle service-to-resource authorization, so Azure-managed data and AI services need no static passwords or keys.

## Overview

| Property                | Value                                                                                                                       |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------------- |
| **Owner**               | BookWorm platform (AppHost)                                                                                                 |
| **Source**              | `src/Aspire/BookWorm.AppHost/Extensions/Security/EntraIdExtensions*.cs`, `Infra/entra-agent-identities.bicep`, `AppHost.cs` |
| **Identity provider**   | Microsoft Entra ID (`entra`, `Aspire.Hosting.Azure.EntraId`)                                                                |
| **Agent identities**    | `entra-agent-identities` (Microsoft Graph Bicep, publish mode only)                                                         |
| **Service credentials** | User-assigned Managed Identities with Azure RBAC role assignments                                                           |
| **Frontend sessions**   | Better Auth with Entra ID (`BETTER_AUTH_SECRET`)                                                                            |

## Entra ID application registration (`entra`)

Source: `EntraIdExtensions.cs`. Aspire registers the application with `.WithApplicationIdUri()`, `.WithAllowWebApiToBeAuthorizedByACL()`, a local developer certificate credential in run mode, and a federated Managed Identity credential in publish mode.

### App roles

| Role value      | Display name | Allowed member types  | Description                              |
| :-------------- | :----------- | :-------------------- | :--------------------------------------- |
| `admin`         | Admin        | `User`, `Application` | Manages all aspects of the application   |
| `business_user` | BusinessUser | `User`, `Application` | Manages books and catalog reference data |
| `customer`      | Customer     | `User`, `Application` | Browses and purchases books              |

### OAuth2 scopes

`WithEntraId` in `EntraIdExtensions.Dotnet.cs` adds a `{resource}_read` and `{resource}_write` scope for each .NET project that calls it. `AppHost.cs` calls it on six APIs, which gives 12 scopes.

| Service      | Read scope      | Write scope      |
| :----------- | :-------------- | :--------------- |
| Catalog API  | `catalog_read`  | `catalog_write`  |
| MCP Tools    | `mcptools_read` | `mcptools_write` |
| Basket API   | `basket_read`   | `basket_write`   |
| Ordering API | `ordering_read` | `ordering_write` |
| Chat API     | `chatting_read` | `chatting_write` |
| Rating API   | `rating_read`   | `rating_write`   |

### Redirect URIs

| Client           | Callback path                                                                                 | Source                                                      |
| :--------------- | :-------------------------------------------------------------------------------------------- | :---------------------------------------------------------- |
| Storefront       | `https://gateway.<aca-default-domain>/api/auth/oauth2/callback/microsoft-entra-id`            | `EntraIdExtensions.Frontend.cs`                             |
| Backoffice       | `https://gateway.<aca-default-domain>/backoffice/api/auth/oauth2/callback/microsoft-entra-id` | `EntraIdExtensions.Frontend.cs` (path prefix `/backoffice`) |
| Commerce         | — (no own registration; shares the Storefront session through `.WithoutEntraId()`)            | `FrontendExtensions.cs`                                     |
| Quartz Dashboard | `<quartz-dashboard-endpoint>/signin-oidc`                                                     | `EntraIdExtensions.Quartz.cs`                               |

In run mode, Aspire also registers the gateway's local HTTP endpoint as an extra redirect URI.

The generated root Bicep passes `https://quartz-dashboard.${AZURE_CONTAINER_APPS_ENVIRONMENT_DEFAULT_DOMAIN}` as the Quartz Dashboard redirect URI. The generated `quartz-dashboard` ingress is external, so the scheme is HTTPS; a live Entra registration was not inspected.

### Quartz Dashboard OpenID Connect settings

| Environment variable                           | Value                               |
| :--------------------------------------------- | :---------------------------------- |
| `Quartz__Dashboard__Authentication__Mode`      | `OpenIdConnect`                     |
| `Quartz__Dashboard__Authentication__Authority` | `<entra-instance>/<tenant-id>/v2.0` |
| `Quartz__Dashboard__Authentication__ClientId`  | `entra` client ID                   |
| `Quartz__Dashboard__Roles__Administrators__0`  | `admin`                             |

## Entra Agent Identities (`entra-agent-identities`)

Source: `Infra/entra-agent-identities.bicep`, `EntraIdExtensions.cs`. Aspire provisions these only in publish mode. Each Federated Identity Credential (FIC) trusts the parent `entra` service principal, uses issuer `<login-endpoint>/<tenant-id>/v2.0`, and uses audience `api://AzureADTokenExchange`.

| Application                       | Unique name                                | Federated Identity Credential   | Bicep output     |
| :-------------------------------- | :----------------------------------------- | :------------------------------ | :--------------- |
| BookWorm Agent Identity Blueprint | `bookworm-agent-blueprint-<unique-suffix>` | `bookworm-parent-blueprint-fic` | `blueprintAppId` |
| BookWorm Chat Agent               | `bookworm-chat-agent-<unique-suffix>`      | `bookworm-chat-agent-fic`       | `chatAgentId`    |
| BookWorm Rating Agent             | `bookworm-rating-agent-<unique-suffix>`    | `bookworm-rating-agent-fic`     | `ratingAgentId`  |

- `<unique-suffix>` is `{environment-name-lowercase}-entra-agent-identities`.
- All applications use `signInAudience: AzureADMyOrg` and get a service principal.

| Service    | Environment variable              | Value           |
| :--------- | :-------------------------------- | :-------------- |
| `chatting` | `AgentIdentities__DefaultAgentId` | `chatAgentId`   |
| `chatting` | `AgentIdentities__Agents__rating` | `ratingAgentId` |
| `rating`   | `AgentIdentities__DefaultAgentId` | `ratingAgentId` |

The generated PostgreSQL role modules add each assigned service principal as a Flexible Server administrator (not as a per-database role). Redis uses the database access policy named `default`. Cosmos uses the built-in SQL role definition ID `00000000-0000-0000-0000-000000000002`, assigned at the account scope; this is the Cosmos DB Built-in Data Contributor role.

## Non-Entra secrets

These secrets are outside Managed Identity coverage. Rotate them as described in [[doc|operational/004-security-hardening-checklist]].

| Secret                   | Aspire parameter                                                 | Environment variable          | Consumers                            | Origin                                           |
| :----------------------- | :--------------------------------------------------------------- | :---------------------------- | :----------------------------------- | :----------------------------------------------- |
| HMAC signing key         | `basket-hmac-key`, `ordering-hmac-key`, `notification-hmac-key`  | `HMAC__Key`                   | `basket`, `ordering`, `notification` | Generated (min length 32, no special characters) |
| Better Auth secret       | `storefront-better-auth-secret`, `backoffice-better-auth-secret` | `BETTER_AUTH_SECRET`          | `storefront`, `backoffice`           | Generated (min length 32, no special characters) |
| Kafka credentials        | `broker` connection string                                       | `ConnectionStrings__broker`   | Kafka consumers and producers        | External                                         |
| Qdrant Cloud credentials | `vectordb` connection string                                     | `ConnectionStrings__vectordb` | `catalog`, `catalog-ingestion`       | External                                         |
| SMTP password            | `email-smtp-password`                                            | `Email__Password`             | `notification`                       | External (SendGrid)                              |

:::note
Notification has a Managed Identity binding only for Azure Managed Redis. It reaches Kafka and the SendGrid SMTP relay with the external credentials listed above.
:::
