This reference describes the Azure topology that Aspire 17 generates from `src/Aspire/BookWorm.AppHost/AppHost.cs` when you run `aspire deploy`. It covers the shared Azure Container Apps backbone, the network ingress boundary, and the YARP API Gateway route map.

## Overview

| Property                | Value                                                                                                  |
| :---------------------- | :----------------------------------------------------------------------------------------------------- |
| **Owner**               | BookWorm platform (AppHost)                                                                            |
| **Source**              | `src/Aspire/BookWorm.AppHost/AppHost.cs`, `src/Aspire/BookWorm.AppHost/Extensions/`                    |
| **Provisioning tool**   | Aspire 17 CLI (`aspire deploy`); see [[doc\|operational/001-azure-deployment-guide]]                   |
| **Compute platform**    | Azure Container Apps environment `aca` (`Consumption` workload profile)                                |
| **Compute workloads**   | 16 application Container Apps, plus `quartz-dashboard` operational tooling                             |
| **Public entry points** | `gateway` (YARP API Gateway) and `quartz-dashboard` (Entra ID OpenID Connect, `admin` role)            |
| **Environments**        | `Development`, `Staging`, `Production` (`aspire deploy --environment`)                                 |
| **Identity**            | Microsoft Entra ID for users and agents; user-assigned Managed Identities for service-to-resource RBAC |

## Shared platform layer

Aspire configures the Container Apps environment in `src/Aspire/BookWorm.AppHost/Extensions/Infrastructure/AzureExtensions.ContainerApp.cs` with `.WithDashboard()`, `.WithAzdResourceNaming()`, and a `Consumption` workload profile.

| Resource                                          | Azure resource type                                | Configuration                                                                                   | Source                                                |
| :------------------------------------------------ | :------------------------------------------------- | :---------------------------------------------------------------------------------------------- | :---------------------------------------------------- |
| Container Apps environment (`aca`, `cae-<token>`) | `Microsoft.App/managedEnvironments`                | `Consumption` workload profile; hosts every compute resource through `AssignComputeResources()` | `AppHost.cs`, `AzureExtensions.ContainerApp.cs`       |
| Azure Container Registry (`acr<token>`)           | `Microsoft.ContainerRegistry/registries`           | Stores .NET SDK container images and Next.js (`oven/bun:1-alpine`) images                       | Generated by Aspire                                   |
| Environment Managed Identity (`mi-<token>`)       | `Microsoft.ManagedIdentity/userAssignedIdentities` | Holds `AcrPull` (`7f951dda-4ed3-4680-a7ca-43fe172d538d`) on ACR                                 | Generated by Aspire                                   |
| Log Analytics workspace (`law-<token>`)           | `Microsoft.OperationalInsights/workspaces`         | Retention 90 days in `Production`; 30 days in `Development` and `Staging`                       | `AzureExtensions.ContainerApp.cs`                     |
| Aspire Dashboard (`aspire-dashboard`)             | Managed Container Apps `dotNetComponents`          | Live OpenTelemetry logs, traces, and metrics                                                    | `AzureExtensions.ContainerApp.cs` (`WithDashboard()`) |

The generated Bicep snapshot uses ACR SKU `Basic`. With `resourceToken = uniqueString(resourceGroup().id)`, it names the registry `acr<token>` (hyphens removed), the shared registry-pull identity `mi-<token>`, the Log Analytics workspace `law-<token>`, and the Container Apps environment `cae-<token>`.

## Network and ingress boundary

| Workload                                                    | Ingress  | Reason                                                                                                                            |
| :---------------------------------------------------------- | :------- | :-------------------------------------------------------------------------------------------------------------------------------- |
| `gateway`                                                   | External | Sole public ingress for frontends and backend APIs (`.WithExternalHttpEndpoints()` in `ApiGatewayProxyBuilder.cs`)                |
| `quartz-dashboard`                                          | External | Quartz job dashboard (`.WithExternalHttpEndpoints()` in `AppHost.cs`); protected by Entra ID OpenID Connect with the `admin` role |
| `storefront`, `commerce`, `backoffice`                      | Internal | Reached only through `gateway` frontend routes                                                                                    |
| `catalog`, `basket`, `ordering`, `rating`, `chatting`       | Internal | Reached through `gateway` backend routes                                                                                          |
| `mcptools`                                                  | Internal | Not routed through YARP; accepts CORS from the gateway browser origin (`WithMcpCors`)                                             |
| `catalog-ingestion`, `finance`, `notification`, `scheduler` | Internal | Event-driven workers with no gateway route                                                                                        |
| `presidio-analyzer`, `presidio-anonymizer`                  | Internal | Privacy sidecars called by `chatting` and `rating` on HTTP port `3000`                                                            |

- **Public gateway URL:** `https://gateway.<aca-default-domain>`
- **Internal service URL pattern:** `https://<app>.internal.<aca-default-domain>`
- **CORS:** Every routed backend API receives `Cors__Origins__0` set to the gateway browser origin, with methods `GET`, `POST`, `PUT`, `PATCH`, and `DELETE` and credentials allowed (`CorsExtensions.cs`).

The generated Bicep confirms gateway ingress is external on target port `5000`. It also declares external ingress for `quartz-dashboard` on port `8080`; this is the second publicly reachable workload in the generated snapshot.

:::warning
`quartz-dashboard` is the second externally reachable workload. Restrict its ingress before Production traffic, as described in [[doc|operational/004-security-hardening-checklist]].
:::

## YARP gateway route map

The gateway is built in `src/Aspire/BookWorm.AppHost/Extensions/Proxy/ProxyExtensions.cs`. Backend routes use their registration order, and the Storefront catch-all route has the lowest priority (`int.MaxValue`).

| Route pattern                                                                                        | Destination                          | Transforms and headers                                                                      | Source                                            |
| :--------------------------------------------------------------------------------------------------- | :----------------------------------- | :------------------------------------------------------------------------------------------ | :------------------------------------------------ |
| `/chatting/{**remainder}`                                                                            | `chatting`                           | Remove `/chatting` prefix; preserve host; `X-Forwarded-*`; `X-Powered-By: BookWorm Gateway` | `AppHost.cs`, `ProxyExtensions.cs`                |
| `/rating/{**remainder}`                                                                              | `rating`                             | Same as above, prefix `/rating`                                                             | `AppHost.cs`, `ProxyExtensions.cs`                |
| `/ordering/{**remainder}`                                                                            | `ordering`                           | Same as above, prefix `/ordering`                                                           | `AppHost.cs`, `ProxyExtensions.cs`                |
| `/basket/{**remainder}`                                                                              | `basket`                             | Same as above, prefix `/basket`                                                             | `AppHost.cs`, `ProxyExtensions.cs`                |
| `/catalog/{**remainder}`                                                                             | `catalog`                            | Same as above, prefix `/catalog`                                                            | `AppHost.cs`, `ProxyExtensions.cs`                |
| `/entra/{**remainder}`                                                                               | External Microsoft Entra ID instance | Remove `/entra` prefix; do not preserve original host                                       | `ApiGatewayProxyBuilder.cs`, `ProxyExtensions.cs` |
| `/backoffice/{**remainder}`                                                                          | `backoffice`                         | `X-Mfe-Zone: backoffice`                                                                    | `AppHost.cs`                                      |
| `/basket`, `/checkout`, `/checkout/:path*`, `/account`, `/account/:path*`, `/commerce-assets/:path*` | `commerce`                           | `X-Mfe-Zone: commerce`                                                                      | `src/Clients/apps/storefront/microfrontends.json` |
| `/{**remainder}`                                                                                     | `storefront`                         | `X-Mfe-Zone: storefront`; lowest priority                                                   | `FrontendExtensions.cs`                           |

:::note
The exact Commerce path `/basket` collides with the backend `/basket/{**remainder}` service prefix. `ResolveFrontendOrder` in `ProxyExtensions.cs` gives colliding exact microfrontend routes order `-1`, so the Commerce page wins for the bare `/basket` path while `/basket/...` API calls still reach Basket API.
:::

## Deployment parameters and naming

`aspire deploy` reads Azure targeting and external dependencies from configuration. The GitHub Actions workflow `.github/workflows/apphost-cd.yml` supplies them as environment variables.

| Configuration key                  | Purpose                                              | Default / notes                     |
| :--------------------------------- | :--------------------------------------------------- | :---------------------------------- |
| `Azure__SubscriptionId`            | Target subscription                                  | Required                            |
| `Azure__TenantId`                  | Microsoft Entra ID tenant                            | Required                            |
| `Azure__Location`                  | Azure region for regional resources                  | `southeastasia` in `apphost-cd.yml` |
| `Azure__ResourceGroup`             | Target resource group                                | Required                            |
| `ConnectionStrings__broker`        | External Kafka connection string (`broker`)          | Required in publish mode            |
| `ConnectionStrings__vectordb`      | External Qdrant Cloud connection string (`vectordb`) | Required in publish mode            |
| `Parameters__email_smtp_endpoint`  | SMTP endpoint for Notification                       | `smtp://smtp.sendgrid.net:587`      |
| `Parameters__email_smtp_username`  | SMTP username                                        | `apikey`                            |
| `Parameters__email_smtp_password`  | SMTP password (secret)                               | Required                            |
| `Parameters__email_sender_address` | Sender email address                                 | Required                            |
| `Parameters__email_sender_name`    | Sender display name                                  | Optional                            |

Resource names use Azure Developer CLI-compatible naming (`WithAzdResourceNaming()`), which derives a deterministic token per resource group. Deploy each environment to its own resource group to keep names isolated.

## Run mode versus publish mode

| Concern                | Run mode (`aspire start` / `mise run run`)                                                                       | Publish mode (`aspire deploy`)             |
| :--------------------- | :--------------------------------------------------------------------------------------------------------------- | :----------------------------------------- |
| Data stores            | Local containers and emulators (PostgreSQL, Redis, Cosmos DB emulator, Azurite, Durable Task Scheduler emulator) | Azure-managed services                     |
| Kafka and Qdrant       | Local containers with Kafka UI                                                                                   | External connection strings                |
| Email                  | Mailpit container (SMTP port `587`)                                                                              | SendGrid SMTP parameters                   |
| Developer tooling      | `scalar` and `inspector`                                                                                         | Not provisioned                            |
| Entra Agent Identities | Not provisioned (`AddEntraAgentIdentities` returns `null`)                                                       | Bicep `Infra/entra-agent-identities.bicep` |
