The compute platform hosts 16 application Container Apps plus the Quartz Dashboard operational tooling container inside the shared Azure Container Apps environment on the `Consumption` workload profile. Every workload runs in single-revision mode with at least one active replica.

## Configuration & Operational Defaults

### Workload Identity Bindings

User-assigned Managed Identities are provisioned for [[service|catalog-api]], [[service|catalog-ingestion]], [[service|basket-api]], [[service|order-api]], [[service|chat-api]], [[service|rating-api]], [[service|mcp-server]], [[service|notification-api]], [[service|scheduler-service]], [[service|order-orchestration]], Storefront, and Backoffice. API Gateway, Commerce, both Presidio sidecars, and Quartz Dashboard have no workload-specific identity; the environment uses a shared managed identity for registry pulls.

## Guardrails & Constraints

<Admonition type="warning" title="Baseline Scaling Bounds Are Unspecified">
	The published deployment baseline declares single-revision mode with a minimum of 1 replica on all
	17 Container Apps, with no upper replica limit or scale rules. Establish explicit upper bounds and
	scale signals before production capacity commitments.
</Admonition>

<Admonition type="info" title="Run-Mode Tooling Exclusion">
	Developer and diagnostic containers (Scalar, MCP Inspector, pgAdmin, RedisInsight, Kafka UI, Azure
	Storage Explorer, Cosmos DB Data Explorer, and Mailpit) are active only in local run mode and are
	never deployed to Azure.
</Admonition>
