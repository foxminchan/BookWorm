[[service|scheduler-service]] persists durable job definitions, cron triggers, cluster locks, and execution history across 15 PostgreSQL tables in [[container|scheduler-database]] using Quartz.NET `4.8.1`. This reference documents the active job schedule, table keys, and retention defaults for platform operators.

## Component & Responsibility

| Component                       | Role                                                        | Protocol / Interface                                                             | Persistence / State                                                        | Notes                                                       |
| :------------------------------ | :---------------------------------------------------------- | :------------------------------------------------------------------------------- | :------------------------------------------------------------------------- | :---------------------------------------------------------- |
| [[service\|scheduler-service]]  | Executes durable cron jobs & syncs schedule definitions     | Quartz.NET `4.8.1` + Kafka                                                       | [[container\|scheduler-database]] (PostgreSQL)                             | Processor-count concurrency; drains active jobs on shutdown |
| **Quartz Dashboard**            | Operational UI for inspecting jobs & triggering manual runs | External HTTPS (`/quartz`)                                                       | Reads [[container\|scheduler-database]] via [[service\|scheduler-service]] | Protected by [[service\|oauth-api]] OIDC (`admin` role)     |
| **Core Job & Trigger Tables**   | Stores job definitions, triggers, and cron expressions      | PostgreSQL (`qrtz_job_details`, `qrtz_triggers`, `qrtz_cron_triggers`)           | Relational (FK cascade)                                                    | Synced every 1 minute from schedule config                  |
| **Cluster & Lock Tables**       | Coordinates active firings, heartbeats, and row locks       | PostgreSQL (`qrtz_fired_triggers`, `qrtz_scheduler_state`, `qrtz_locks`)         | Ephemeral / cluster state                                                  | Scoped by `sched_name`                                      |
| **Execution & Misfire History** | Tracks job outcomes, retries, logs, and misfires            | PostgreSQL (`qrtz_execution_history`, `qrtz_misfire_history`, `qrtz_job_status`) | 30-day retention, max `100,000` entries                                    | Rolling summary in `qrtz_job_status`                        |

## Configuration & Operational Defaults

### Active Scheduled Jobs

| Job name                | Trigger name                | Group       | Cron expression (UTC)        | Misfire policy | Durable / Recover | Concurrency        |
| :---------------------- | :-------------------------- | :---------- | :--------------------------- | :------------- | :---------------- | :----------------- |
| `ProcessVectorBatchJob` | `ProcessVectorBatchTrigger` | `Scheduler` | `0 0/5 * * * ?` (every 5m)   | Fire once now  | `true` / `false`  | Non-concurrent     |
| `HeartbeatJob`          | `HeartbeatTrigger`          | `Scheduler` | `0/30 * * * * ?` (every 30s) | Fire once now  | `true` / `false`  | Concurrent allowed |

`ProcessVectorBatchJob` publishes [[event|ProcessVectorBatchIntegrationEvent]] to [[channel|scheduler.process-vector-batch]] via Wolverine's PostgreSQL outbox in [[container|scheduler-database]]. Schedule configuration is scanned every 1 minute, overwriting existing definitions and failing fast on missing or invalid schedules.

### Core Tables

#### `qrtz_job_details`

Primary key: `(sched_name, job_name, job_group)`.

| Column              | Type      | Required | Description                                            |
| :------------------ | :-------- | :------- | :----------------------------------------------------- |
| `sched_name`        | `text`    | Yes      | Logical Quartz scheduler name                          |
| `job_name`          | `text`    | Yes      | Unique job name within `job_group`                     |
| `job_group`         | `text`    | Yes      | Logical job group (`Scheduler` in BookWorm)            |
| `description`       | `text`    | No       | Human-readable operator description                    |
| `job_class_name`    | `text`    | Yes      | Fully qualified job type name                          |
| `is_durable`        | `boolean` | Yes      | Keeps the job stored when no triggers reference it     |
| `is_nonconcurrent`  | `boolean` | Yes      | Prevents overlapping runs                              |
| `is_update_data`    | `boolean` | Yes      | Persists modified `JobDataMap` entries after execution |
| `requests_recovery` | `boolean` | Yes      | Re-executes the job if a node crashes mid-run          |
| `job_data`          | `bytea`   | No       | Serialized binary `JobDataMap` payload                 |

#### `qrtz_triggers`

Primary key: `(sched_name, trigger_name, trigger_group)`. Foreign key: `(sched_name, job_name, job_group)` -> `qrtz_job_details`.

| Column                                                                        | Type                       | Required | Description                                              |
| :---------------------------------------------------------------------------- | :------------------------- | :------- | :------------------------------------------------------- |
| `sched_name`, `trigger_name`, `trigger_group`                                 | `text`                     | Yes      | Composite primary key                                    |
| `job_name`, `job_group`                                                       | `text`                     | Yes      | Target job in `qrtz_job_details`                         |
| `description`                                                                 | `text`                     | No       | Human-readable trigger description                       |
| `next_fire_time`, `prev_fire_time`                                            | `bigint`                   | No       | Next and most recent fire timestamps (UTC ticks)         |
| `priority`                                                                    | `integer`                  | No       | Firing priority when triggers share a fire time          |
| `trigger_state`                                                               | `text`                     | Yes      | `WAITING`, `ACQUIRED`, `PAUSED`, `BLOCKED`, or `ERROR`   |
| `trigger_type`                                                                | `text`                     | Yes      | `CRON`, `SIMPLE`, `SIMPROP`, or `BLOB`                   |
| `start_time`, `end_time`                                                      | `bigint`                   | Yes / No | Active window timestamps (UTC ticks)                     |
| `calendar_name`                                                               | `text`                     | No       | Optional exclusion calendar in `qrtz_calendars`          |
| `misfire_instr`, `misfire_orig_fire_time`, `misfire_threshold`                | `smallint` / `bigint`      | No       | Misfire handling code, original fire time, and threshold |
| `execution_group`, `preferred_node`, `preferred_node_auto`                    | `varchar(200)` / `boolean` | No / Yes | Execution grouping and cluster node affinity             |
| `retry_policy`, `retry_attempt`                                               | `varchar(250)` / `integer` | No       | Retry policy descriptor and current attempt count        |
| `continues_trigger_name`, `continues_trigger_group`, `continuation_condition` | `text` / `integer`         | No       | Follow-on continuation trigger metadata                  |
| `overlap_policy`, `fixed_delay`                                               | `integer` / `boolean`      | No       | Overlap policy and fixed-delay scheduling flag           |
| `pause_reason`, `paused_by`, `paused_at`                                      | `varchar` / `bigint`       | No       | Pause audit metadata                                     |
| `job_data`                                                                    | `bytea`                    | No       | Serialized trigger-scoped `JobDataMap` payload           |

#### `qrtz_cron_triggers`

Primary / foreign key: `(sched_name, trigger_name, trigger_group)` -> `qrtz_triggers`.

| Column                                        | Type   | Required | Description                                    |
| :-------------------------------------------- | :----- | :------- | :--------------------------------------------- |
| `sched_name`, `trigger_name`, `trigger_group` | `text` | Yes      | Composite primary/foreign key                  |
| `cron_expression`                             | `text` | Yes      | Quartz cron expression (e.g., `0 0/5 * * * ?`) |
| `time_zone_id`                                | `text` | No       | Time zone ID (`UTC` in BookWorm)               |

### Inspect Recent Job Health

<CodeGroup>

```sql
SELECT
    job_group,
    job_name,
    run_count,
    consecutive_failures,
    last_failure_message
FROM qrtz_job_status
ORDER BY job_group, job_name;
```

</CodeGroup>

## Guardrails & Constraints

<Admonition type="warning" title="Do Not Edit qrtz_* Tables Directly">
	Never modify `qrtz_*` rows directly in PostgreSQL. Manage schedules through declarative
	configuration or the Quartz Dashboard so Quartz validates cron expressions, updates binary
	payloads safely, and preserves cluster lock invariants.
</Admonition>

<Admonition type="info" title="Timestamp Representation">
	All `BIGINT` timestamp columns store 100-nanosecond UTC ticks from year `0001`, not Unix epoch
	milliseconds.
</Admonition>
