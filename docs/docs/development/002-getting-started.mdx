Use this guide to configure the tools needed for your kind of work. For the shortest first run, follow [[doc|development/000-local-quickstart]]; this page covers the broader setup choices.

## Tool requirements

| Requirement                                    | Minimum or project version                                                    | Needed for                                                         | Verify                             |
| :--------------------------------------------- | :---------------------------------------------------------------------------- | :----------------------------------------------------------------- | :--------------------------------- |
| Git                                            | Current supported release; no project-specific minimum                        | All changes                                                        | `git --version`                    |
| mise                                           | Current release                                                               | Installing pinned tools and running workspace tasks                | `mise --version`                   |
| .NET SDK                                       | `11.0.100`                                                                    | Backend development, backend tests, and the full local application | `dotnet --version`                 |
| Node.js                                        | `26` selected by the project toolchain; package engine requires `24` or newer | JavaScript workspaces and documentation                            | `node --version`                   |
| Bun                                            | `1.4.4`                                                                       | Frontend and documentation workspaces                              | `bun --version`                    |
| Aspire CLI                                     | `17`                                                                          | Starting and inspecting the full local application                 | `aspire --version`                 |
| Docker Desktop or compatible container runtime | Current supported release; no project-specific minimum                        | Full local application and container-backed services               | `docker version` and `docker info` |

Git, mise, and the relevant language runtime are enough for most focused changes. Docker and the Aspire CLI are only needed when you run the distributed application locally.

## Editor and shell

- **VS Code** is a practical choice for mixed .NET, TypeScript, and documentation work. Install the C# tooling and the repository's recommended extensions when prompted.
- **Visual Studio** or **JetBrains Rider** are good options for .NET debugging and test navigation.
- Use a shell where mise is activated so commands resolve the selected tool versions. Restart the shell after installing or changing tool versions.

## Fork remotes

For pull-request contributions, set `origin` to your fork and add the main project as `upstream`. Replace the placeholder with the project's repository URL:

```bash
git remote add upstream <repository-url>
git remote -v
```

Keep your feature branches on `origin`; use `upstream` to synchronize with the shared `main` branch.

## Local services, credentials, and cloud access

For local application runs, Aspire starts the configured backing services as containers. This keeps local database, cache, messaging, storage, and privacy dependencies separate from hosted cloud resources. Unit and contract tests do not require Docker; see [[doc|development/008-testing-matrix]].

Microsoft Entra ID and Microsoft Foundry are optional for basic local startup. Authenticated user journeys and hosted AI features require valid access and application configuration. Keep credentials in user secrets or environment variables, never in source control.

Useful user-secret commands:

```bash
dotnet user-secrets list --project <AppHost-project>
dotnet user-secrets set "<setting-name>" "<secret-value>" --project <AppHost-project>
```

Replace the placeholders with the AppHost project and setting supplied by your local configuration. Do not clear all secrets to fix a single missing value.

## Common workspace commands

Run repository tasks from the repository root. Run Bun commands from the relevant frontend or documentation workspace.

| Command                             | Purpose                                                         |
| :---------------------------------- | :-------------------------------------------------------------- |
| `mise tasks ls`                     | List available repository tasks.                                |
| `mise run prepare`                  | Restore dependencies and configure Git hooks.                   |
| `mise run build`                    | Build the .NET solution.                                        |
| `mise run test:unit`                | Run backend unit and architecture tests.                        |
| `mise run test:contracts`           | Generate consumer contracts, then verify providers.             |
| `mise run test`                     | Run the backend test tasks.                                     |
| `mise run format`                   | Format all supported workspaces.                                |
| `mise run run`                      | Start the local application with Aspire.                        |
| `bun install`                       | Install dependencies in the current Bun workspace.              |
| `bun run dev`                       | Start the current frontend or documentation development server. |
| `bun run test`                      | Run frontend tests from the frontend workspace.                 |
| `bun run check` / `bun run fitness` | Check documentation formatting and architecture rules.          |

For the execution sequence, filters, and result interpretation, see [[doc|development/005-testing]]. For startup failures, see [[doc|development/007-troubleshoot-local-dev]].
