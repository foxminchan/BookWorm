Use this workflow for every backend, frontend, or documentation change so your branch stays cleanly scoped, passes Husky pre-commit checks, and merges with minimal review friction.

## Prerequisites

- A prepared local workspace from [[doc|development/002-getting-started]] (`mise run prepare` completed so `.husky` hooks are active)
- Familiarity with the bounded context you plan to modify (see [[doc|development/001-developer-onboarding]])

## Steps

<Steps>
<Step title="Sync `main` and create a focused branch">

Update your local `main` branch from `upstream` and create a short-lived branch using `<type>/<short-description>` (`feature/`, `fix/`, or `docs/` in lowercase kebab-case):

<CodeGroup>

```bash
git fetch upstream
git checkout main
git merge --ff-only upstream/main
git checkout -b <branch-type>/<short-description>
```

</CodeGroup>

Where:

- `<branch-type>`: One of `feature`, `fix`, or `docs`.
- `<short-description>`: Concise lowercase kebab-case summary (for example, `add-book-search`).

</Step>
<Step title="Review owning boundaries and repository instructions">

Before editing code:

- Read `AGENTS.md` for repository-wide rules and check `.github/instructions/` for file-scoped rules.
- Load any matching task skill from `.agents/skills/<skill-name>/SKILL.md` (for example, `tunit` when writing backend tests or `agent-framework-builder-dotnet` when modifying AI agents).
- Confirm which bounded context owns the rule you are changing so you do not introduce direct cross-service dependencies.

</Step>
<Step title="Implement the change and run targeted checks">

Follow [[doc|development/004-engineering-standards]]. During iteration, run the smallest relevant check for the files you modified rather than the full solution suite:

- **Backend service change:** Run the target service's `.UnitTests` project (see [[doc|development/005-testing]]).
- **Frontend change (`src/Clients`):** Run `bun run boundaries`, `bun run check-types`, `bun run lint`, and `bun run test` from `src/Clients` (see [[doc|frontend/004-testing-and-quality-gates]]).
- **Documentation change (`docs/`):** Run `bun run check` and `bun run fitness` from `docs/`.

> [!NOTE]
> Do not start the full Aspire AppHost (`mise run run`) for routine code or documentation edits unless you need end-to-end runtime validation.

</Step>
<Step title="Format all modified files">

From the repository root, run the unified formatter:

<CodeGroup>

```bash
mise run format
```

</CodeGroup>

This runs `format:cs` (`dnx csharpier format .`), `format:fe` (`bun run format` in `src/Clients`), and `format:docs` (`bun run format` in `docs`).

</Step>
<Step title="Commit with a Conventional Commit message">

Stage your changes and commit using a [Conventional Commit](https://www.conventionalcommits.org/) prefix (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, or `chore:`):

<CodeGroup>

```bash
git add <changed-files>
git commit -m "<type>: <concise imperative summary>"
```

</CodeGroup>

Where:

- `<changed-files>`: Explicit paths for the files belonging to this change.
- `<type>`: One of `feat`, `fix`, `docs`, `refactor`, `test`, or `chore`.
- `<concise imperative summary>`: Lowercase description of what the commit does.

The Husky pre-commit hook (`.husky/task-runner.json`) automatically executes four gates in sequence:

1. `dnx csharpier format .`
2. `dnx csharpier check .`
3. `dotnet format analyzers BookWorm.slnx --verify-no-changes`
4. `dotnet build BookWorm.slnx --no-restore --configuration Release`

</Step>
<Step title="Push and open a pull request">

Push your branch to `origin` and follow [[doc|development/006-pull-request-process]]:

<CodeGroup>

```bash
git push -u origin <branch-type>/<short-description>
```

</CodeGroup>

</Step>
</Steps>

## Verification

Confirm your working tree is clean, formatted, and committed on your feature branch:

<CodeGroup>

```bash
git status
git log -1 --oneline
```

</CodeGroup>

Expected output:

<CodeGroup>

```text
On branch feature/add-book-search
nothing to commit, working tree clean
a1b2c3d feat: add book search filter to Catalog API
```

</CodeGroup>

## Troubleshooting

| Symptom                                                           | Cause                                                        | Fix                                                                                           |
| :---------------------------------------------------------------- | :----------------------------------------------------------- | :-------------------------------------------------------------------------------------------- |
| Pre-commit fails on `csharpier check`                             | Unformatted C# files remain unstaged                         | Run `mise run format:cs`, re-stage modified files, and re-run `git commit`                    |
| Pre-commit fails on `dotnet format analyzers --verify-no-changes` | Roslyn code-style or analyzer violation in modified C# files | Run `dotnet format analyzers BookWorm.slnx`, inspect the diff, re-stage, and commit           |
| Pre-commit fails on `dotnet build ... --configuration Release`    | Compiler warning or error (`TreatWarningsAsErrors: true`)    | Run `mise run build` to inspect full diagnostics, fix all warnings/errors, and retry          |
| `dotnet husky` tool not found on commit                           | Local .NET tools were not restored                           | Run `mise run prepare` from the repository root                                               |
| `git merge --ff-only upstream/main` fails                         | Local `main` diverged from `upstream/main`                   | Run `git reset --hard upstream/main` on `main` (after ensuring no unpushed work is on `main`) |
