This glossary defines terms used across the BookWorm architecture and clarifies distinctions that affect ownership and system behavior. Each bounded context may use additional terms or more specific meanings in its own documentation; those local definitions remain authoritative within that context.

| Term                             | Definition                                                                                                                                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Anti-corruption layer**        | An adapter that translates another context's model into the terms used by its consumer. Conversational uses one when presenting Ordering data, rather than adopting Ordering's internal model.                                         |
| **Basket**                       | Shopping-owned, mutable customer shopping intent. A Basket is not an Order and does not reserve Catalog availability.                                                                                                                  |
| **Bounded context**              | A boundary within which a domain model and its language have defined meaning and ownership. Contexts exchange information through explicit contracts rather than sharing business state.                                               |
| **Catalog**                      | The context that owns canonical book information, pricing, and availability. Search data and the book rating summary are derived views, not independent sources of truth.                                                              |
| **Checkout**                     | The request to turn a persisted Basket into a purchase. Ordering validates it using current Catalog facts and, on acceptance, persists one Order; this does not mean payment settlement or fulfillment is complete.                    |
| **Conversational**               | The context providing AI-assisted customer interaction. It accesses business information through explicit tools and contracts but does not own the underlying Catalog or Order records.                                                |
| **Eventual consistency**         | A state in which an asynchronously updated view may temporarily lag its source and converge after processing. It does not imply a fixed update time.                                                                                   |
| **Feedback**                     | An individual customer review or rating record owned by Reviews. It is distinct from the aggregate rating summary displayed for a book.                                                                                                |
| **Finance orchestration**        | BookWorm's post-checkout coordination service. It coordinates work such as Basket cleanup and notifications; it is not payment processing and does not own Order status.                                                               |
| **Idempotency**                  | Handling repeated requests or messages so retries do not unintentionally repeat an operation's effects. The guarantee depends on the specific operation and implementation; it does not mean the whole workflow executes exactly once. |
| **Integration event**            | A published fact about something that happened in its producer's context. Consumers can react asynchronously, but the event does not transfer ownership of the underlying state.                                                       |
| **MCP (Model Context Protocol)** | The protocol used by BookWorm's conversational workflow to access scoped tools, including Catalog tools. Tool access does not make the conversational context the owner of the data.                                                   |
| **Order**                        | The accepted purchase record whose lifecycle and status are owned by Ordering. It is separate from the Basket and from payment settlement or external fulfillment.                                                                     |
| **Ordering**                     | The context that creates an Order at checkout acceptance and owns its lifecycle and status afterward.                                                                                                                                  |
| **Platform**                     | The generic context that supplies capabilities such as scheduled processing and notifications. It supports business contexts without owning their business state.                                                                      |
| **Projection**                   | A derived view built from source data for a particular read or processing need. A projection may be rebuilt from its source and is not authoritative for that source's data.                                                           |
| **Rating summary**               | The aggregate average rating and review count shown for a book. Reviews owns individual Feedback; Catalog maintains this summary as a derived projection.                                                                              |
| **Reviews**                      | The context that owns individual customer Feedback and rating records. It references Catalog book identities but does not own canonical book information.                                                                              |
| **Saga**                         | A persisted coordination workflow that advances through work across services and can retry or time out. It is not one atomic transaction and does not itself determine the Order's business status.                                    |
| **Service contract**             | An explicit API or message definition through which services communicate. It describes a boundary and its semantics, not the producer's internal persistence model.                                                                    |
| **Shopping**                     | The context that owns Basket state and pre-order shopping intent. It does not own an accepted Order.                                                                                                                                   |
| **Source of truth**              | The authoritative state for a business concept, owned by its responsible context. Copies, caches, and projections in other contexts do not replace it.                                                                                 |
