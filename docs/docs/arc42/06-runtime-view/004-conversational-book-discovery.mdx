## 6.4 Conversational book discovery

[[domain|conversational]] handles discovery requests through a composed chat workflow. The workflow validates the incoming message, routes it to a specialist, and can delegate complex research to independent agents. [[domain|catalog]] remains the source of book facts; agent responses do not mutate Catalog or create commerce transactions.

### Interaction

1. A customer submits a request to the [[service|chat-api]]'s AG-UI endpoint.
2. Input validation rejects empty or detected prompt-injection input. Accepted input is passed to `DecisionRouterExecutor` (`Microsoft-Decision-1`).
3. `DecisionRouterExecutor` checks language and scope, then routes to a specialist: book requests (and review requests without a catalog ID) go to [[agent|book-agent]]; store or account questions go to [[agent|qa-agent]]; review/rating requests with a book catalog ID go to [[agent|rating-agent]]. Unsupported or non-English requests short-circuit with a boundary response.
4. [[agent|book-agent]] handles a straightforward request directly. For a complex discovery request, it can delegate independent book-fact and recommendation research to specialist agents ([[agent|book-catalog-researcher]] and [[agent|book-recommendation-researcher]]) in parallel, then synthesize their results.
5. Catalog information is accessed through the scoped [[system|mcp-tools]] ([[service|mcp-server]]). The workflow formats and returns the final assistant response.

### Boundaries

- The response depends on the information available to the agents and Catalog tools; it is not a reservation, price guarantee, or [[entity|order]].
- The Chat workflow and its agents do not place Orders, mutate [[entity|basket]]s, or publish commerce lifecycle events.
- A request rejected during validation returns a rejection response rather than entering specialist routing.

See the [[flow|agent-orchestration]], [[service|chat-api]], and [[system|mcp-tools]] documentation for workflow and tool contracts.
