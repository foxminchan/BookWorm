**Chat API** (`BookWorm.Chat`) executes a Microsoft Agent Framework multi-agent workflow (`chat-workflow`) exposed over the AG-UI protocol (`/ag-ui`) to help shoppers discover books, summarize reviews, and answer store policy questions. Every turn passes through prompt-safety validation, **Microsoft Foundry** `MicrosoftDecision1` routing with human-in-the-loop (HITL) `RequestPort` disambiguation, **Presidio** PII anonymization, and read-only **MCP Tools** or remote **Agent-to-Agent (A2A) gRPC** calls—without ever mutating baskets or orders.

## Scope and constraints

- **Scope:** End-to-end conversational request processing from **Storefront** through **API Gateway** to **Chat API**, **MCP Tools**, **Catalog API**, **Rating API**, **Presidio**, and **Microsoft Foundry**.
- **Out of scope:** Order checkout and basket writes (owned by **Ordering API** and **Basket API**; chat responses are advisory only) and asynchronous vector indexing (see [[doc|arc42/06-runtime-view/002-catalog-search-index-maintenance]]).
- **Key constraints:**
  - **Chat API** stores AG-UI session state solely in **Azure Blob Storage** (`chatting-blob`, `BlobNamePrefix = "ag-ui/"`). It uses **no PostgreSQL, no Redis, and no Kafka**.
  - `/ag-ui` requires the `customer` policy (`customer` role + `chatting_read`/`chatting_write` scopes) and enforces the `PerUserRateLimit` token-bucket limiter (`30` tokens max, `20` per `10s`, queue `5`).
  - Only three specialist domains exist (`book`, `qa`, remote `rating`) plus two catalog sub-researchers (`book-catalog-researcher`, `book-recommendation-researcher`). **No Sentiment Agent exists in BookWorm.**

### Workflow stages

1. **Session load and input validation:** **Chat API** authenticates the caller via Microsoft Entra ID (`customer` policy), enforces `PerUserRateLimit` and claims-based agent isolation (`UseClaimsBasedAgentIsolation()`), loads session state from `chatting-blob` (`ag-ui/`), and runs `InputValidationExecutor` (`PromptValidationService` + `GovernancePromptSafetyEvaluator`). Empty messages, oversized prompts, or detected prompt-injection patterns short-circuit immediately to a rejection output.
2. **Decision routing (`MicrosoftDecision1`):** Accepted prompts enter `DecisionRouterExecutor`, which calls **Microsoft Foundry** `MicrosoftDecision1` (`IDecisionClient`) instead of a general-purpose LLM router. It verifies English language and domain scope, routing to `Book`, `QA`, or `Rating`, or short-circuiting out-of-scope/non-English requests with a boundary message.
3. **Human-in-the-loop (HITL) disambiguation:** When `DecisionRouterExecutor` flags a low-confidence in-scope prompt (`NeedsDisambiguation == true`), `RouteDisambiguationPrepExecutor` pauses the workflow at `RequestPort` so the customer can clarify intent in **Storefront**. `RouteDisambiguationResolutionExecutor` then resumes execution to the chosen specialist.
4. **Specialist execution and inter-agent handoffs:**
   - **Book workflow (`BookWorkflowExecutor`):** Runs `book` agent (`book-agent.yaml`) with `book-catalog` skills, read-only **MCP Tools**, and optional parallel delegation to `book-catalog-researcher` and `book-recommendation-researcher`. Can hand off to `rating` or `qa` when a query spans domains.
   - **QA workflow (`QAWorkflowExecutor`):** Runs `qa` agent (`qa-agent.yaml`) with `store-policies` skills (catalog MCP tools explicitly denied in `Policies/chat-agents.yaml` at priority `70`). Can hand off to `book` if catalog lookup is needed.
   - **Rating workflow (`RatingWorkflowExecutor`):** Invokes **Rating API**'s remote `rating` agent over **A2A gRPC** (`A2A.Grpc.AspNetCore`), discovered via Rating's `/agents` endpoint and authorized with Microsoft Entra Agent Identities (`chatAgentId` / `ratingAgentId`) and the `rating_read` scope.
5. **Privacy, governance, and formatting:** Model requests and outputs pass through **Presidio** PII anonymization and guardrail middleware. Tool calls are checked against `Policies/chat-agents.yaml` (deny-by-default, conversation guardian thresholds) and `Policies/mcp-tools.yaml` (tool-poisoning and dangerous-tool blocks). `ResponseFormatterExecutor` normalizes the final reply before persisting the session to `chatting-blob` and streaming over AG-UI.

## Read-only commerce boundaries

- **No backend mutations from chat agents:** Neither **Chat API** nor **MCP Tools** mutates **Catalog API**, **Basket API**, or **Ordering API** state, and Chat emits no Kafka events. Any storefront UI actions (such as displaying a book card or triggering client-side basket interactions) execute within the customer's browser session under standard API authorization.
- **Advisory responses only:** Assistant answers reflect live tool responses at query time and never reserve inventory or lock prices.

## Quality scenarios and known risks

| Quality attribute / risk | Scenario or exposure                                                            | Current mitigation or gap                                                                                                                                                            |
| :----------------------- | :------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Privacy**              | Customer pastes an email address, phone number, or credit card into chat.       | **Presidio** middleware anonymizes PII before prompts reach **Microsoft Foundry** and filters model outputs.                                                                         |
| **Abuse & cost control** | Caller floods `/ag-ui` or attempts multi-turn prompt injection / A2A loops.     | `PerUserRateLimit` token bucket, `InputValidationExecutor`, and `Policies/chat-agents.yaml` conversation guardian (`max_conversation_turns: 30`, `max_retry_cycles: 3`) bound abuse. |
| **Availability**         | **Rating API** A2A endpoint or **MCP Tools** is unreachable during a chat turn. | Failures surface as bounded workflow errors; **Chat API** remains stateless apart from `chatting-blob` transcripts and requires no database recovery.                                |
