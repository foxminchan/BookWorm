## 6.3 Feedback and Catalog rating projection

Reviews owns individual customer feedback, while Catalog owns the average rating and review count projected onto a book. The two services exchange integration events; Catalog does not read the Rating Database.

<MermaidFileLoader file="mermaids/feedback-and-rating-projection.mmd" />

### Interaction and consistency

1. The customer submits feedback for a book.
2. Rating API validates the feedback and persists it in the Rating Database.
3. After the write, Reviews publishes `FeedbackCreatedIntegrationEvent`.
4. Catalog consumes the event and updates its book-level rating projection. The original feedback remains owned by Reviews.

### Invalid book reference

If Catalog cannot apply the event because the referenced book does not exist, it publishes `BookUpdatedRatingFailedIntegrationEvent`. Rating consumes the compensation event and deletes the invalid feedback record. This explicit compensation avoids leaving orphaned feedback or silently ignoring projection failure.

The projection is derived data, not a second feedback store. Monitor event processing and projection consistency separately from the feedback write itself.

See the [[flow|feedback-publication]], [[service|rating-api]], and [[system|product-catalog-system]] for the detailed event contracts and ownership boundaries.
