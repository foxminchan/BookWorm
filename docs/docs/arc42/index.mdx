This overview is the navigation hub for BookWorm's system-wide arc42 architecture documentation. BookWorm is a .NET 11, Aspire 17, and Next.js 16 microservices bookstore decomposed into six backend bounded contexts behind a YARP `API Gateway` and three customer and staff microfrontends (MFEs).

:::tip
If you want a single-page visual summary before reading individual arc42 chapters, start with the [[doc|arc42/00-c4-overview]].
:::

## Architectural framing

BookWorm decomposes by business capability and data ownership rather than by technical layer or shared database. Every bounded context owns its domain rules, authoritative persistence, and public contracts.

This diagram shows how external web traffic enters BookWorm's edge tier and connects to the six backend bounded contexts.

<MermaidFileLoader file="mermaids/arc42-diagram-1.mmd" />

| Layer or bounded context | Authoritative responsibility                                                                                                               | Primary cross-context relationships                                                                                        |
| :----------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| **Edge and Frontends**   | Public ingress (`API Gateway`), customer discovery (`Storefront`), basket/checkout (`Commerce`), and staff management (`Backoffice`)       | Routes browser traffic over HTTPS to backend APIs and proxies Microsoft Entra ID                                           |
| **Catalog**              | Authoritative book metadata, authors, categories, publishers, pricing, hybrid search, and derived rating summary                           | Supplies product facts via REST/gRPC; updates Qdrant vectors from Scheduler triggers; projects ratings from Reviews events |
| **Shopping**             | Customer-scoped mutable pre-order baskets in Redis                                                                                         | Reads Catalog book details via gRPC; deletes baskets on Finance Kafka commands                                             |
| **Ordering**             | Accepted orders, purchase-time item snapshots, order status (`New`, `Cancelled`, `Completed`), and post-checkout orchestration (`Finance`) | Reads Basket and Catalog via gRPC at checkout; coordinates cleanup and emails via Durable Task Scheduler and Kafka         |
| **Reviews**              | Individual customer `Feedback` records in Cosmos DB and AI review summarization                                                            | Publishes feedback events to Catalog; exposes read-only Agent-to-Agent (A2A) summaries to Conversational                   |
| **Conversational**       | AI-assisted customer discovery and Q&A (`Chat API` + `MCP Tools`)                                                                          | Calls Catalog read-only via Model Context Protocol (MCP) and Rating via A2A gRPC; never mutates baskets or orders          |
| **Platform**             | Recurring job scheduling (`Scheduler`) and transactional order email delivery (`Notification`)                                             | Triggers Catalog Ingestion via Kafka; consumes Finance email commands without owning business outcomes                     |
