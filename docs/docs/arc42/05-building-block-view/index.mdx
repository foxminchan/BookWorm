This chapter documents BookWorm's static structure from the whole platform down to service internals and checkout orchestration. It aligns with C4 Container and Component views and isolates ownership boundaries from runtime message sequences and Azure deployment placement.

## Decomposition hierarchy

BookWorm uses three progressive zoom levels so you inspect only the depth required for your task.

This diagram shows how each arc42 Building Block View level zooms into the next level of static structure.

| Zoom level  | Document                                                          | C4 equivalent               | Scope                                                                                                                                  |
| :---------- | :---------------------------------------------------------------- | :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| **Level 1** | [[doc\|arc42/05-building-block-view/001-whitebox-overall-system]] | System / Container overview | Edge tier (`API Gateway`, `Storefront`, `Commerce`, `Backoffice`), six backend bounded contexts, shared foundation, and boundary rules |
| **Level 2** | [[doc\|arc42/05-building-block-view/002-level-2]]                 | Container / Service detail  | Internal services, dedicated data stores (PostgreSQL, Cosmos DB, Redis, Qdrant, Azure Blob, Durable Task Scheduler), and source paths  |
| **Level 3** | [[doc\|arc42/05-building-block-view/003-level-3]]                 | Component detail            | Selective deep dive into `Finance` (`BookWorm.Finance`) Azure Durable Functions orchestration components and contracts                 |

## Selective refinement rationale

- **Capability-first decomposition:** BookWorm groups code by business ownership (`Catalog`, `Shopping`, `Ordering`, `Reviews`, `Conversational`, `Platform`) rather than technical tiers, preventing a shared business middle layer.
- **Selective Level 3 zoom:** Only `Finance` (`src/Services/Finance/BookWorm.Finance/`) expands to Level 3 because its Azure Durable Functions `OrderOrchestrator` coordinates multi-step checkout outcomes across `Ordering`, `Shopping`, and `Platform`.
- **Separation of concerns:** External neighbors appear in [[doc|arc42/03-context-and-scope/003-technical-context]], step-by-step message sequences appear in [[doc|arc42/06-runtime-view]], and cloud hosting appears in [[doc|arc42/07-deployment-view]].
