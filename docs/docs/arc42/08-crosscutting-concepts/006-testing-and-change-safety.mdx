BookWorm protects domain behavior, service boundaries, and cross-service contracts through a layered automated verification strategy spanning backend **TUnit** (`1.87.12`) on **Microsoft.Testing.Platform (MTP)**, **Pact** messaging contract tests, **ArchUnitNET** structural fitness checks, **Buf** `.proto` compatibility checks, and frontend **Vitest**, **Playwright BDD**, **axe-core**, and **Turborepo** workspace boundary gates.

## Verification layers and verified inventory

| Layer                                 | Tooling & runner                                                                                                                                      | Verified repository scope                                                                                                                                                                                                      | Primary command                           |
| :------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------- |
| **Backend unit tests**                | **TUnit** `1.87.12` + **MTP**, `Shouldly` `4.3.0`, `Moq` `4.21.0`, `Bogus` `35.6.5`, `Allure.TestingPlatform` (xUnit, NUnit, and MSTest are not used) | **9 `.UnitTests` projects**: Basket, Catalog, Chat, Finance, McpTools, Notification, Ordering, Rating, Scheduler                                                                                                               | `mise run test` (`test:unit`)             |

:::note
**Contract test execution order:** Consumer tests (`Category=PactConsumer`) must run before provider verification (`Category=PactProvider`) because providers validate against the pact JSON files generated by consumers in `tests/pacts/`. `mise run test` enforces this sequence automatically.
:::

## Cross-cutting verification matrix

When changing a shared library (`BookWorm.Chassis`, `BookWorm.ServiceDefaults`, `@workspace/*`) or service boundary, verify behavior at the owning boundary:

| Concern                     | Evidence to verify                                                                                                                                                                        |
| :-------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Authorization**           | Unauthenticated calls return `401`; missing Entra ID role (`admin`, `business_user`, `customer`) or missing service scope returns `403`.                                                  |
| **Privacy**                 | Classified log fields redact via `AddRedaction()`; AI agent prompts and outputs pass through **Presidio** `PIIMiddleware`.                                                                |
| **Validation and errors**   | Invalid payloads produce field-grouped `400` `ValidationProblemDetails`; concurrency faults return `412`; unhandled exceptions return `500` with `traceId` and zero internal details.     |
| **Idempotency and retries** | Duplicate `x-request-id` returns `409 Conflict` in **Ordering API**; `5xx`/exceptions release the Redis key; duplicate Kafka `message.Id` skips cleanly in `FusionCacheIdempotencyGuard`. |
| **Messaging**               | Pact consumer and provider tests pass across all 8 messaging pairs; CloudEvents correlation headers (`requestid`, `UserId`, W3C trace) survive hops.                                      |
| **AI governance**           | `Policies/*.yaml` allow/deny/rate-limit rules hold; rejected prompts short-circuit before specialist agents; MCP tool-poisoning patterns are blocked.                                     |

## Explicit coverage gaps and risks

| Gap or risk                                 | Current repository state                                                                                      | Recommended mitigation                                                                                                                      |
| :------------------------------------------ | :------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------ |
| **No backend `.IntegrationTests` projects** | **0 backend `.IntegrationTests` projects** exist in `BookWorm.slnx` (despite naming guidance in `AGENTS.md`). | Rely on Pact contracts + unit tests today; add Aspire/Testcontainers integration tests for critical PostgreSQL, Cosmos DB, and Kafka flows. |
| **No unit tests for `Catalog.Ingestion`**   | `BookWorm.Catalog.Ingestion` has no `.UnitTests` project (9 of 10 backend services have unit test projects).  | Add unit tests covering `VectorBatchProcessor` advisory-lock contention, batch size `200`, and conditional revision `DELETE`.               |
| **No E2E features for `Commerce`**          | Storefront has 9 Playwright BDD features and Backoffice has 6; **Commerce** has unit/component tests only.    | Exercise `/basket`, `/checkout`, and `/account` flows via Storefront cross-zone checkout E2E and add dedicated Commerce E2E scenarios.      |
