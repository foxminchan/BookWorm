These concepts establish conceptual integrity and uniform rules across every building block. They define the minimum trust, compatibility, failure, diagnostic, and delivery expectations that domain-specific designs and runtime scenarios must satisfy.

	Shared mechanisms are defaults, not implicit guarantees. A team must explicitly register and
	verify every control on the host or boundary that uses it.
</Admonition>

## Conceptual Integrity Rules

1. **Preserve domain ownership.** A shared library may provide technical primitives, but it must not own business data or replace an authoritative capability.
2. **Separate acknowledgment from completion.** A successful network call or broker acceptance proves only that the handoff occurred, not that downstream work finished correctly.
3. **Design for explicit opt-in.** Identity, resilience, privacy, and governance behavior must be visible in service configuration and tested at the relevant boundary.
4. **Prefer reversible evolution.** Additive contract changes, staged rollouts, and retained observability reduce the cost of a correction.
