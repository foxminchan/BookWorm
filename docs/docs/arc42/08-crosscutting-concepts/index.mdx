BookWorm standardizes security, messaging, validation, resilience, observability, AI governance, and automated verification through shared libraries (`BookWorm.ServiceDefaults`, `BookWorm.Chassis`, `BookWorm.SharedKernel`, and frontend `@workspace/*` packages). Use this chapter to see which protections apply by default across all hosts and which require explicit per-service registration.

## Scope and principles

Four architectural rules govern all crosscutting mechanisms in BookWorm:

1. **Keep domain ownership local:** Shared technical primitives support a bounded context without transferring ownership of its business data or rules (see [[doc|arc42/05-building-block-view]]).
2. **Separate handoff from completion:** An HTTP acknowledgment, Kafka publish, Quartz trigger, or SMTP `250 OK` never proves downstream business completion (see [[doc|arc42/06-runtime-view]]).
3. **Verify per-service opt-in:** Availability in `BookWorm.Chassis` does not mean every host enables a feature. Confirm startup registration on each service before relying on a safeguard.
4. **Do not infer unstated SLAs:** Source-level timeouts, retry counts, and sampling probabilities are implementation defaults, not production availability or latency commitments.

## Shared building-block adoption boundaries

| Capability                                      | Universal via `BookWorm.ServiceDefaults`?               | Opt-in per service / scope                                                                                                                                  |
| :---------------------------------------------- | :------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OpenTelemetry traces, metrics & OTLP export** | Yes (all .NET hosts; `@workspace/otel` in Next.js apps) | Messaging traces added by `UseEventFramework()`; handler metrics added per service                                                                          |
| **Outbound HTTP resilience & Kestrel limits**   | Yes (`UseBudgetedRetries()`, HTTP/2 limits)             | MailKit Polly pipeline is specific to **Notification**                                                                                                      |
| **Rate limiting** (`AddRateLimiting()`)         | Available in ServiceDefaults                            | Wired on public API hosts; `PerUserRateLimit` applied selectively (such as `/ag-ui`)                                                                        |
| **Entra ID authentication & policies**          | Available in `BookWorm.Chassis`                         | Wired per API (`catalog`, `basket`, `ordering`, `rating`, `chatting`, `mcptools`, `quartz-dashboard`)                                                       |
| **Wolverine Kafka + durability**                | No (only hosts with `broker` connection)                | PostgreSQL outbox (`catalog`, `catalog-ingestion`, `ordering`, `scheduler`); Cosmos DB persistence (`rating`); Redis idempotency (`basket`, `notification`) |
| **HMAC log redaction** (`AddRedaction()`)       | Available in `BookWorm.Chassis`                         | Enabled on **Basket API**, **Ordering API**, and **Notification**                                                                                           |
| **AI governance & Presidio PII**                | No                                                      | Wired on **Chat API**, **Rating API**, and **MCP Tools** (`Policies/*.yaml`; Presidio on Chat and Rating)                                                   |
