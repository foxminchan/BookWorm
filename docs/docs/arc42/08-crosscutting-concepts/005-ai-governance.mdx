BookWorm governs its AI workflows across **Chat API**, **Rating API**, and **MCP Tools** using layered controls from `BookWorm.Chassis.AI`, `Microsoft.AgentGovernance.Extensions.*` (`5.0.0`), **Presidio**, and **Microsoft Entra Agent Identities**. Every AI request is screened before reaching a language model, anonymized for PII across model boundaries, isolated per user identity, and constrained by declarative deny-by-default YAML tool policies.

## Five governance layers

1. **Pre-agent input screening (`InputValidationExecutor`):** Before any specialist agent runs, **Chat API** trims empty messages, enforces maximum prompt length, checks suspicious injection patterns, and invokes `GovernancePromptSafetyEvaluator`. Rejected prompts terminate immediately without consuming model tokens.
2. **Scoped routing and human-in-the-loop (HITL) disambiguation:** `DecisionRouterExecutor` calls **Microsoft Foundry** `MicrosoftDecision1` (`IDecisionClient`) to verify English language and bookstore domain scope. Low-confidence in-scope prompts pause at `RequestPort` for customer disambiguation rather than guessing a specialist route.
3. **Privacy anonymization and untrusted-content isolation:** **Chat API** and **Rating API** wrap model clients with **Presidio** `PIIMiddleware` (anonymizing PII before prompts reach **Microsoft Foundry** `ModelRouter` and filtering outputs on return) and `GuardrailMiddleware` (marking user prompts and tool outputs as untrusted to separate them from system instructions).
4. **Agent identity and tenant isolation:** **Chat API** enforces `UseClaimsBasedAgentIsolation()` so session state and tool calls stay bound to the authenticated caller's claims. Cross-service agent calls (`Chat` → `Rating` over A2A gRPC) authenticate using **Microsoft Entra Agent Identities** (`blueprintAppId`, `chatAgentId`, `ratingAgentId` provisioned via `entra-agent-identities.bicep`) with federated credentials.
5. **Declarative deny-by-default policy enforcement:** `GovernanceKernel` loads `BookWorm.Chassis` `Policies/default.yaml` plus service-specific policy files using a `deny-overrides` conflict strategy, security rings, `DecisionToolSelectionMiddleware`, and a failure circuit breaker.

## Per-service governance policies

| Service                                  | Policy file                  | Default action | Key enforced rules & thresholds                                                                                                                                                                                                                                                                                                                                                                 |
| :--------------------------------------- | :--------------------------- | :------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Shared baseline** (`BookWorm.Chassis`) | `Policies/default.yaml`      | `deny`         | `deny-overrides` conflict resolution, security rings, injection detection, circuit breaker                                                                                                                                                                                                                                                                                                      |
| **Chat API** (`BookWorm.Chat`)           | `Policies/chat-agents.yaml`  | `deny`         | Per-agent DID allowlists (`did:mesh:bookworm:book`, `book-catalog-researcher`, `book-recommendation-researcher`, `qa`); explicitly denies catalog tools to `qa` (priority `70`); **Conversation Guardian** (`max_conversation_turns: 30`, `max_retry_cycles: 3`, `loop_window_seconds: 300`, escalation/offensive composite break at `0.8`); multi-turn injection detection                     |
| **Rating API** (`BookWorm.Rating`)       | `Policies/rating-agent.yaml` | `deny`         | Blocks all write/mutation tools (priority `100`); blocks destructive SQL DDL/DML (`DROP`, `TRUNCATE`, `INSERT`, `UPDATE`, `DELETE`, `EXEC`, priority `95`); allows read tools (priority `50`); rate-limits `GetCustomerReviews` to `30/minute`; regex PII detection for email, phone, and credit cards                                                                                          |
| **MCP Tools** (`BookWorm.McpTools`)      | `Policies/mcp-tools.yaml`    | `deny`         | Blocks dangerous tools (shell, file write/delete, raw HTTP, priority `100`); allows read-only catalog tools (`search_catalog`, `get_book`, `list_categories`, `list_authors`, priority `50`); rate-limits to `100/minute`; **MCP tool-poisoning detection** (invisible Unicode, hidden Markdown comments, hidden instructions, base64/hex encoded payloads, exfiltration, privilege escalation) |

:::note
**Explicit opt-in scope:** Governance policies and Presidio PII middleware are wired into **Chat API**, **Rating API**, and **MCP Tools** (Presidio on Chat and Rating; MCP governance on MCP Tools). New AI features or model integrations do not inherit these controls automatically unless registered at startup.
:::

## Developer change checklist

When adding or modifying an AI agent, model integration, or MCP tool:

1. Grant each agent only the minimum tools and data required, and declare explicit `allow` rules under `default_action: deny` in the service's YAML policy.
2. Keep untrusted user input and external tool outputs separated from system instructions via `GuardrailMiddleware`.
3. Register **Presidio** `PIIMiddleware` on every chat client whose prompts or responses cross an external model boundary.
4. Add unit tests covering allow, deny, rate-limit, prompt-injection, and circuit-breaker failure cases for every new tool.
5. Verify policy file copy-to-output paths and startup validation whenever editing `Policies/*.yaml`.

## Trade-offs and operational limits

- **Defense-in-depth reduces risk but is not absolute:** Pattern matching, `MicrosoftDecision1` scope checks, and Presidio detectors cannot catch every novel adversarial prompt or obfuscated PII string. Review policy files and agent tool lists before every production release.
- **Read-only commerce invariant:** No AI agent or MCP tool holds write permissions against **Catalog API**, **Basket API**, or **Ordering API**. Preserving this boundary prevents conversational ambiguity from triggering unintended purchases.
