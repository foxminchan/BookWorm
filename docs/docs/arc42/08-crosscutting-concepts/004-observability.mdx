BookWorm instruments every .NET service through `BookWorm.ServiceDefaults` (`OpenTelemetry` `1.21.0`) and every Next.js microfrontend (**Storefront**, **Commerce**, **Backoffice**) through `@workspace/otel` so traces, metrics, and structured logs correlate end-to-end via W3C trace context. Telemetry exports over OTLP to the local **Aspire Dashboard** during development and to **Azure Log Analytics** (with Aspire Dashboard enabled on Azure Container Apps) in cloud deployments.

## Signals, sampling, and log buffering

| Signal                 | Backend instrumentation (`BookWorm.ServiceDefaults` & `BookWorm.Chassis`)                                                                                                                                             | Sampling & filtering                                                                                                          |
| :--------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| **Distributed traces** | W3C `ActivityIdFormat`; ASP.NET Core, `HttpClient`, gRPC client (`Instrumentation.GrpcNetClient`), route fixer, `BookWorm` trace source, `Wolverine`, `Confluent.Kafka`, and `chat-workflow` (`.WithOpenTelemetry()`) | Excludes `/health` and `/alive`; `AlwaysOnSampler` in Development; exports via OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set |
| **Metrics**            | ASP.NET Core, `HttpClient`, .NET Runtime, `BookWorm` meter, `Wolverine` meter, `CommandHandlerMetrics`, `QueryHandlerMetrics`, and request latency telemetry                                                          | Exported over OTLP alongside traces                                                                                           |
| **Structured logs**    | Log enrichment, `GlobalLogBuffering`, and `PerIncomingRequestLogBuffering`; `GlobalExceptionHandler` flushes `GlobalLogBuffer` on unhandled errors to preserve preceding debug context                                | Trace-based log sampler in Development; `RandomProbabilisticSampler` in non-Development                                       |
| **Frontend traces**    | `@workspace/otel` (`@opentelemetry/sdk-node` + OTLP proto exporter) wired via `.WithOtlpExporter()` in AppHost                                                                                                        | Correlates browser-to-gateway HTTP requests with backend W3C traces                                                           |

### Privacy-conscious logging and correlation

- **Non-serializing CQRS logging:** `LoggingBehavior` records message and response type names, elapsed execution time, and property names without serializing raw payload values. Classified properties log explicitly as redacted.
- **HMAC redaction:** Hosts handling sensitive customer fields (**Basket API**, **Ordering API**, **Notification**) enable `AddRedaction()` (`HMAC__Key`) to mask sensitive values and apply deterministic HMAC redaction to PII (see [[doc|arc42/08-crosscutting-concepts/001-security-and-privacy]]).
- **Messaging correlation:** `UseEventFramework()` logs message start at `Debug` level and propagates W3C trace context, `requestid`, and `UserId` in CloudEvents envelope metadata without placing message bodies into trace attributes.
- **Error-to-trace correlation:** `GlobalExceptionHandler` returns `traceId` (`Activity.Current?.Id ?? httpContext.TraceIdentifier`) inside RFC 9457 `ProblemDetails` so support teams can jump directly to the failing distributed trace.

## Health checks and operational liveness

| Check / signal                           | Registered by                                  | Tags / schedule                                                     | Availability                               |
| :--------------------------------------- | :--------------------------------------------- | :------------------------------------------------------------------ | :----------------------------------------- |
| Default process liveness (`"self"`)      | `BookWorm.ServiceDefaults`                     | `live`                                                              | All .NET hosts                             |
| Wolverine bus & listeners                | `UseEventFramework()`                          | `live`, `ready` (`AddWolverine`); `ready` (`AddWolverineListeners`) | All Kafka-enabled hosts                    |
| MailKit SMTP health                      | `BookWorm.Notification` (`MailKitHealthCheck`) | Readiness                                                           | **Notification**                           |
| Presidio health (`/health`)              | `BookWorm.Hosting.Presidio`                    | Container health probe (port `3000`)                                | `presidio-analyzer`, `presidio-anonymizer` |
| Commerce frontend health (`/api/health`) | `@bookworm/commerce`                           | HTTP probe                                                          | **Commerce**                               |
| Scheduler heartbeat (`HeartbeatJob`)     | `BookWorm.Scheduler` (`jobs.json`)             | Every 30 seconds UTC (`0/30 * * * * ?`)                             | **Scheduler**                              |

:::warning
**Development-only default health endpoints:** `MapDefaultEndpoints()` in `BookWorm.ServiceDefaults` maps `/health` (all checks) and `/alive` (`live` tag) **only when `app.Environment.IsDevelopment()` is true**. Verify explicit Container Apps probe paths and host configuration before relying on HTTP health endpoints in Staging or Production.
:::

## Local and cloud telemetry endpoints

- **Local Aspire Dashboard (`launchSettings.json`):** HTTPS profile runs Dashboard at `https://localhost:17290` (`http://localhost:15061`) with OTLP on `https://localhost:21066`; HTTP profile runs Dashboard at `http://localhost:15061` with OTLP on `http://localhost:19005`.
- **Cloud (Azure Container Apps):** `AzureExtensions.ContainerApp.cs` enables the managed Aspire Dashboard (`WithDashboard()`) and provisions Azure Log Analytics with **90-day retention in Production** and **30-day retention in non-Production**.

## Operational limits and trade-offs

- **Telemetry proves execution, not business completion:** A span or log entry proves code executed, not that an asynchronous business outcome completed. Always verify final state in the owning service.
- **No implicit SLAs:** Sampling ratios, buffer sizes, and retention windows are implementation defaults—formal availability, latency, and alerting targets must be agreed per environment.
