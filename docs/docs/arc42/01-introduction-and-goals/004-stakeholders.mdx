This page documents the stakeholder roles that rely on BookWorm's architecture, what each group expects from the system, and where each group finds answers in the documentation. Because BookWorm is an open-source reference platform whose maintainers evolve over time, this register tracks **roles** rather than named individuals.

| **Store administrators and business users** | Manage catalog entries, process order changes, review feedback, and monitor scheduled work with appropriate access control.       | [[doc\|arc42/01-introduction-and-goals/002-requirements-overview]], [[doc\|arc42/08-crosscutting-concepts/001-security-and-privacy]]                                                                     |

## Governance boundaries

- **Role catalog vs. formal approver directory:** Documenting roles keeps this architecture baseline durable across contributor changes, but it does not assign named decision-makers or formal SLA sign-off authority.
- **Logical team ownership:** Repository ownership conventions are documented in [[team|architecture-enabling-team]].
