This chapter maps BookWorm's deployable applications, stateful Azure resources, identity boundaries, and external cloud providers from local development to Azure Container Apps. BookWorm uses **Aspire 17** (`aspire deploy`) as its sole cloud deployment mechanism—without `azure.yaml` or `azd up`—via `.github/workflows/apphost-cd.yml` targeting `Development`, `Staging`, and `Production` environments.

## Deployment footprint summary

BookWorm organizes its published Azure footprint into four layers defined in `src/Aspire/BookWorm.AppHost/AppHost.cs`:

- **Application compute (16 core Container Apps + Quartz Dashboard):** One Azure Container Apps environment (`aca`, `Consumption` workload profile) hosts the YARP `API Gateway`, three Next.js 16 microfrontends (`Storefront`, `Commerce`, `Backoffice`), ten .NET 11 backend services and Azure Functions workers, and two Presidio privacy containers, plus `quartz-dashboard` for scheduled job operations. Only `API Gateway` (and the Microsoft Entra ID-protected `quartz-dashboard`) expose external HTTP endpoints.
- **Azure-managed data, orchestration, and AI:** Azure PostgreSQL Flexible Server (`catalogdb`, `orderingdb`, `schedulerdb`), Azure Cosmos DB (`ratingdb` / `feedbacks`), Azure Managed Redis (used by `catalog`, `basket`, `ordering`, `rating`, and `notification`), Azure Durable Task Scheduler (`finance-taskhub`), Azure Storage (`catalog-blob`, `chatting-blob`, and Functions host storage), and Microsoft Foundry (`ModelRouter`, `MicrosoftDecision1`, `Cohere.EmbedV40`)—all accessed via passwordless managed-identity RBAC.
- **Identity and access:** Microsoft Entra ID app registration (`admin`, `business_user`, `customer` roles), per-service managed identities, and Entra Agent Identities (`entra-agent-identities.bicep`) for `chatAgentId` and `ratingAgentId`.
- **External cloud providers:** Confluent Cloud / Kafka (`KAFKA_BROKER`), Qdrant Cloud (`QDRANT_CLOUD_CONNECTION`), and SendGrid SMTP (`EMAIL_SMTP_*`, replaced locally by Mailpit).
