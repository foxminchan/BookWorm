BookWorm deploys to Azure through **Aspire 17** (`aspire deploy`) into a single Azure Container Apps environment (`aca`, `Consumption` workload profile) paired with passwordless Azure-managed data, AI, and identity services. All 16 core Container Apps (the YARP `API Gateway`, three Next.js 16 microfrontends, ten .NET 11 backend services/functions, and two Presidio containers) plus `quartz-dashboard` run side-by-side with local-container parity during development.

This Level-1 deployment diagram shows external ingress, internal Azure Container Apps compute, managed Azure backing stores, and external cloud providers.

## Building block to infrastructure mapping

| Software building block                          | Azure infrastructure element                                                                                                                              | Verified deployment fact (`AppHost.cs`)                                                                                                                            | Open production item                                 |
| :----------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------- |
| **Storefront**, **Commerce**, and **Backoffice** | 3 internal Container Apps (`oven/bun:1-alpine` standalone Next.js 16 on port `3000`)                                                                      | Built programmatically via `AddDockerfileBuilder`; `Storefront` and `Backoffice` use Entra ID Better Auth; `Commerce` shares customer session (`WithoutEntraId()`) | CDN, custom DNS, TLS certificates                    |
| **API Gateway** (`gateway`)                      | External Container App (`Aspire.Hosting.Yarp`)                                                                                                            | Routes `/catalog`, `/basket`, `/ordering`, `/rating`, `/chatting`, `/entra`, `/backoffice`, Commerce MFE routes, and Storefront catch-all                          | Max replica caps, WAF, custom domain                 |
| **Catalog API** and **Catalog Ingestion**        | 2 internal Container Apps + PostgreSQL `catalogdb` + Qdrant `vectordb` + Blob `catalog-blob` + Redis + Foundry                                            | `Catalog API` serves REST/gRPC; `Catalog Ingestion` runs Kafka-triggered Azure Functions using `StorageBlobDataOwner` and `CognitiveServicesUser`                  | Qdrant Cloud tier, backup, and rebuild strategy      |
| **Basket API** (`basket`)                        | Internal Container App + Azure Managed Redis (`redis`)                                                                                                    | Authoritative basket state and idempotency in Redis; shares Redis cluster with `catalog`, `ordering`, `rating`, and `notification`                                 | Eviction policy and key namespace isolation          |
| **Ordering API** and **Finance**                 | 2 internal Container Apps + PostgreSQL `orderingdb` + Durable Task Scheduler (`finance-taskhub`) + Azure Storage + Kafka                                  | `Ordering API` uses EF Core + Marten on `orderingdb`; `Finance` runs Azure Durable Functions on Durable Task Scheduler (no PostgreSQL)                             | Broker sizing and DTS IP allowlist tightening        |
| **Rating API**, **Chat API**, and **MCP Tools**  | 3 internal Container Apps + Cosmos DB (`ratingdb`/`feedbacks`) + Blob (`chatting-blob`) + Presidio (`presidio-analyzer`, `presidio-anonymizer`) + Foundry | `Rating API` uses Cosmos DB; `Chat API` stores AG-UI sessions in `chatting-blob`; `MCP Tools` is stateless (`/mcp`, custom CORS, not behind YARP)                  | Model quotas, region pinning, private endpoints      |
| **Scheduler** and **Quartz Dashboard**           | Internal `scheduler` Container App + external `quartz-dashboard` Container App + PostgreSQL `schedulerdb`                                                 | Persists Quartz jobs/history in `schedulerdb`; publishes `ProcessVectorBatchIntegrationEvent` to Kafka topic `scheduler.process-vector-batch`                      | Multi-replica Quartz clustering and failover         |
| **Notification** (`notification`)                | Internal Container App + Kafka + Azure Managed Redis + SendGrid SMTP                                                                                      | Stateless `MailKit` + `Mjml.Net` consumer with Redis 24-hour idempotency and HMAC validation; no PostgreSQL database                                               | SMTP deliverability SLAs and bounce handling         |
| **Identity and Agent Identities**                | Microsoft Entra ID + `entra-agent-identities.bicep`                                                                                                       | Provisions app roles (`admin`, `business_user`, `customer`), managed identities, and agent identities (`blueprintAppId`, `chatAgentId`, `ratingAgentId`)           | Tenant conditional access and private network policy |

`WithEntraId` registers read/write scopes for six .NET APIs (12 scopes total). The generated `temp/` Bicep snapshot sets the gateway target port to `5000`, `activeRevisionsMode: 'Single'`, and `minReplicas: 1` for all 17 Container Apps; it declares neither `maxReplicas` nor per-environment overrides. These are snapshot values, not verified settings in a deployed environment.

## Local development vs. Azure parity

Aspire 17 substitutes persistent local containers and emulators for managed Azure and external cloud services in run mode, while using real Microsoft Entra ID app registration with a local development certificate.

| Resource                   | Local development (`mise run run`)                  | Azure publish (`aspire deploy`)                                                 |
| :------------------------- | :-------------------------------------------------- | :------------------------------------------------------------------------------ |
| **PostgreSQL**             | Local Postgres container + `pgAdmin` + Postgres MCP | Azure PostgreSQL Flexible Server (`catalogdb`, `orderingdb`, `schedulerdb`)     |
| **Cosmos DB**              | Cosmos DB emulator + Data Explorer                  | Azure Cosmos DB (`ratingdb` / `feedbacks`, partition key `/bookId`)             |
| **Redis**                  | Local Redis container + `RedisInsight`              | Azure Managed Redis (`BalancedB0` / `BalancedB1` / `BalancedB5`)                |
| **Storage**                | Azurite emulator + Azure Storage Explorer           | Azure Storage Account (`catalog-blob`, `chatting-blob`, Functions host storage) |
| **Durable Task Scheduler** | Durable Task Scheduler emulator                     | Azure Durable Task Scheduler (`Consumption` SKU, `finance-taskhub`)             |
| **Kafka**                  | Local Kafka container + Kafka UI                    | External connection string `ConnectionStrings__broker` (Confluent Cloud)        |
| **Qdrant**                 | Local Qdrant container                              | External connection string `ConnectionStrings__vectordb` (Qdrant Cloud)         |
| **Email (SMTP)**           | **Mailpit** container (SMTP port `587`)             | SendGrid SMTP (`smtp://smtp.sendgrid.net:587` default)                          |
| **Microsoft Entra ID**     | Entra ID app registration + local dev certificate   | Entra ID + Federated Managed Identity + `entra-agent-identities.bicep`          |
| **Dev tooling**            | `Scalar` API Reference + `MCP Inspector`            | Not provisioned in publish mode                                                 |
