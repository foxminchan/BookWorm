## Overview and Motivation

Azure deployments place application workloads in Azure Container Apps and stateful dependencies in Azure-managed services, with Confluent Cloud, Qdrant Cloud, SendGrid, and Microsoft Entra ID as separate service boundaries. Local development substitutes persistent containers and emulators for most managed resources. The environments preserve logical topology but use different capacity and resilience settings, balancing operability and security with development cost.

## Quality and Operational Characteristics

- API Gateway is the customer-facing application entry point. Quartz Dashboard is a separate externally reachable administrative endpoint protected by Microsoft Entra ID; other application ingress is internal to the Container Apps environment.
- User authentication uses Microsoft Entra ID. Workloads use managed identities and scoped roles for Azure resources; external provider connections use encrypted transport and protected credentials.
- PostgreSQL has zone-redundant HA in Staging and Production, with 14- and 35-day backup retention; Production enables geo-redundant backups. Redis HA is enabled in those environments. Multi-region application recovery is not established.
- The published Container Apps baseline does not define workload-specific maximum replicas or scale triggers. Capacity limits, traffic targets, and recovery objectives must be established before production commitments, and deployed settings must be verified.
- Internal ingress describes application routing, not network isolation: no VNet or private endpoints are currently declared for managed dependencies.
