This chapter defines the non-negotiable technical, organizational, and engineering constraints that shape BookWorm across its .NET 11 backend services, Next.js 16 microfrontends (MFEs), and Aspire 17 orchestration. It separates verified constraints enforced by the repository and CI pipelines from open organizational and operational targets that still require stakeholder sign-off.

## Technical constraints

| ID      | Constraint                                                                                                                                                                                                                                                                                                                              | Rationale and architectural consequence                                                                                                                                                                                                |
| :------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TC1** | **Preserve bounded-context data ownership.** Each bounded context owns its domain behavior and persistence; services never query another service's database directly.                                                                                                                                                                   | Limits change blast radius and keeps business invariants inside their owning service. Cross-boundary needs require explicit REST, gRPC, or Kafka contracts.                                                                            |
| **TC2** | **Integrate through explicit, owned contracts.** Cross-service communication uses versioned HTTP (`ApiVersions.V1`), Protocol Buffers gRPC, or CloudEvents JSON over Kafka via **Wolverine**.                                                                                                                                           | Events carry ownership, routing metadata (`bookworm.{env}.{owner}.{topic}`, except unprefixed `scheduler.process-vector-batch`), and stable message identities. Contract changes require consumer-impact review and Pact verification. |
| **TC3** | **Evolve Protocol Buffer contracts deliberately.** Lint and check `.proto` definitions (`edition = "2023"`) for backward compatibility against the committed baseline before updating it.                                                                                                                                               | Prevents breaking gRPC clients (`Basket`, `Ordering`, `McpTools`). Deliberate breaking changes require consumer coordination and a migration plan.                                                                                     |
| **TC4** | **Standardize on the verified .NET 11 and Aspire 17 backend stack.** Target `net11.0`, C# 15 (`preview`), `BookWorm.slnx`, `Mediator.SourceGenerator` (do not add `MediatR`), **Wolverine** + Kafka, **Microsoft Entra ID**, **Aspire** 17 (`aspire deploy`), and **TUnit** on Microsoft.Testing.Platform (no xUnit, NUnit, or MSTest). | Keeps tooling, observability, resilience, and deployment pipelines uniform across all 10 backend projects without bespoke runtimes or legacy frameworks.                                                                               |
| **TC5** | **Standardize on the verified Bun and Next.js 16 frontend stack.** Use **Bun** (`1.4.4`), Turborepo with enforced package boundary tags (`config`, `foundation`, `domain`, `app`), Next.js 16, React 19, TypeScript, and Better Auth wired to **Microsoft Entra ID** across **Storefront**, **Commerce**, and **Backoffice**.           | Prevents lockfile drift (no `npm` or `pnpm`) and enforces strict dependency layering via `turbo boundaries`.                                                                                                                           |
| **TC6** | **Enforce independent deployability only where contracts remain compatible.** A service builds, tests, and deploys independently when its contracts preserve consumer compatibility.                                                                                                                                                    | Breaking contract changes require coordinated consumer migration before removing legacy behavior.                                                                                                                                      |
| **TC7** | **Keep shared platform infrastructure strictly supportive.** **Notification**, **Scheduler**, **API Gateway**, and **BuildingBlocks** must not own commerce domain state or business rules.                                                                                                                                             | Prevents shared infrastructure from becoming a coupling bottleneck or implicit domain owner.                                                                                                                                           |

## Organizational constraints

| ID      | Constraint                                                                                                                                                                                                                                           | Rationale and architectural consequence                                                                                                                    |
| :------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OC1** | **Align responsibility with bounded-context ownership.** Every service, contract, and cross-context flow has an explicit owning context and team role before boundaries change.                                                                      | Keeps incident triage, code review, and contract evolution accountable to a single owner.                                                                  |
| **OC2** | **Maintain architecture documentation alongside the system.** Behavioral, contract, or persistence changes update the relevant arc42 views, service references, and ADRs.                                                                            | Automated checks (`BookWorm.ArchTests`, `eventcatalog fitness check`, Pact contract tests) surface drift between documented boundaries and implementation. |
| **OC3** | **Keep secrets out of source control and protect toolchain pins.** Store credentials in user secrets, local environment variables, or GitHub Actions / Azure OIDC secrets; do not modify `global.json` or `NuGet.config` unless explicitly approved. | Prevents credential leaks and unexpected SDK or NuGet feed drift across contributors and CI runners.                                                       |

:::note
BookWorm is an open-source reference architecture. The repository does not establish organization-specific vendor procurement mandates, staffing structures, regulatory compliance certifications, or approved production SLA numbers.
:::

## Conventions

| ID     | Convention                                                                                                                                                                                                                                                                                      | Enforcement and application                                                                                                                                                                                       |
| :----- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **C1** | **Use `mise` workspace tasks and strict C# build settings.** Run `mise run restore`, `mise run build`, `mise run test`, and `mise run format` (`dnx csharpier format .`).                                                                                                                       | `Directory.Build.props` enforces `Nullable: enable`, `TreatWarningsAsErrors: true`, and `EnforceCodeStyleInBuild: true`. Pre-commit hooks (`.husky/pre-commit`) verify formatting, analyzers, and Release builds. |
| **C2** | **Follow C# coding and dependency conventions.** Keep endpoints, handlers, `DbContext` types, and tests `sealed` by default; propagate `CancellationToken` through all async flows; use file-scoped namespaces; centralize NuGet versions in `Versions.props` and `Directory.Packages.props`.   | Enforced by `.editorconfig`, analyzers, Central Package Management (`ManagePackageVersionsCentrally: true`), and `BookWorm.ArchTests`.                                                                            |
| **C3** | **Use `snake_case` for PostgreSQL and explicit API versioning.** Keep PostgreSQL identifiers and raw SQL in `snake_case` (`EFCore.NamingConventions`); apply authorization at endpoint boundaries; version HTTP endpoints explicitly (`ApiVersions.V1`).                                        | Preserves consistent database migrations across `catalogdb`, `orderingdb`, and `schedulerdb` and predictable HTTP contracts.                                                                                      |
| **C4** | **Preserve integration-event naming and routing metadata.** Declare shared contracts in `BookWorm.Contracts`, name events `[Action][Entity]IntegrationEvent`, and preserve owner/identity metadata for Wolverine + Kafka topic routing.                                                         | Keeps CloudEvents payloads, partition keys (`OrderId`, `BookId`, `FeedbackId`), and Pact contracts stable across releases.                                                                                        |
| **C5** | **Validate boundaries continuously in CI.** Pair unit tests (9 projects), Pact messaging contract tests (7 projects), `BookWorm.ArchTests` (`ArchUnitNET`), frontend quality gates (`turbo boundaries`, Vitest, Playwright BDD), and documentation checks (`bun run check`, `bun run fitness`). | Catches architectural, contract, and formatting drift before changes merge to `main`.                                                                                                                             |
