BookWorm satisfies its top five quality goals—**Correctness**, **Interoperability**, **Deployability**, **Modifiability**, and **Operability**—through six core architectural decisions: bounded-context decomposition with Vertical Slice Architecture, polyglot per-service persistence, explicit REST/gRPC/Kafka contracts, YARP multi-zone microfrontends (MFEs), governed multi-agent AI, and automated layered verification orchestrated with **Aspire** 17.

## Core architectural decisions

### Technology and platform foundation

- **Backend runtime and orchestration:** .NET 11 (`net11.0`), C# 15 (`preview`), **Aspire** 17 (`aspire start` locally, `aspire deploy` to Azure Container Apps), and `BookWorm.ServiceDefaults` for uniform telemetry, resilience, Kestrel limits, and rate limiting.
- **Frontend multi-zone microfrontends:** Bun `1.4.4`, Turborepo, Next.js 16, React 19, Tailwind CSS v4, TanStack Query, and Better Auth split across **Storefront** (public discovery + AI chat), **Commerce** (authenticated basket, checkout, account), and **Backoffice** (staff administration) behind YARP **API Gateway**.

### Polyglot persistence by workload

BookWorm matches each service's storage engine to its consistency and access pattern rather than forcing a single database technology:

- **PostgreSQL (only 3 databases):** `catalogdb` (**Catalog API** & **Catalog Ingestion**), `orderingdb` (**Ordering API** with EF Core + Marten event store), and `schedulerdb` (**Scheduler** Quartz persistent store).
- **Azure Cosmos DB:** `ratingdb` / `feedbacks` (partition key `/bookId`) for **Rating API** with EF Core Cosmos and Wolverine Cosmos DB transactional messaging.
- **Redis (Azure Managed Redis):** Primary mutable `Basket` store for **Basket API**, FusionCache L1+L2 backplane and distributed locks, and 24-hour integration-event idempotency (including stateless **Notification**).
- **Azure Durable Task Scheduler + Azure Storage:** Durable saga state (`finance-taskhub`) for **Finance**, cover images (`catalog-blob`) for **Catalog API**, and AG-UI conversation sessions (`chatting-blob`, prefix `ag-ui/`) for **Chat API**.
- **Qdrant:** Vector index (`vectordb`) for hybrid semantic book search refreshed asynchronously by **Catalog Ingestion**.

### Security, privacy, and governed AI

- **Identity and RBAC:** **Microsoft Entra ID** enforces JWT authentication and policies (`admin`, `business_user`, `customer`) at endpoint boundaries, plus Entra Agent Identities (`blueprintAppId`, `chatAgentId`, `ratingAgentId`) with User/Agent On-Behalf-Of (OBO) token exchange.
- **Governed multi-agent workflows:** **Chat API** and **Rating API** run on **Microsoft Agent Framework** backed by **Microsoft Foundry** (`ModelRouter`, `MicrosoftDecision1`, Cohere `EmbedV40`), protected by declarative governance policies (`Microsoft.AgentGovernance.Extensions.*`), read-only **MCP Tools**, and internal **Presidio** PII anonymization sidecars.

### Layered automated verification

- **Backend:** **TUnit** on Microsoft.Testing.Platform across 9 `.UnitTests` projects, 7 **PactNet** `.ContractTests` projects (8 pacts), and `BookWorm.ArchTests` (`ArchUnitNET`). _(Backend `.IntegrationTests` projects are not yet implemented in `BookWorm.slnx`.)_
- **Frontend & docs:** Vitest + Testing Library, Playwright BDD + `@axe-core/playwright`, `turbo boundaries`, and EventCatalog lint/fitness checks.

## Strategic trade-offs and open commitments

- **Contract discipline vs. development speed:** Per-context data stores and owned contracts require upfront schema design, Pact updates, and coordinated migrations for breaking changes, in exchange for independent deployment and isolated failure domains.
- **Eventual consistency for derived views:** Vector search indexes (**Qdrant**) and **Catalog** rating summaries converge asynchronously via Kafka so core catalog and feedback writes remain fast and decoupled.
- **Unapproved operational budgets:** Numerical SLOs (latency, availability, RTO/RPO, freshness lag) remain proposed in [[doc|arc42/10-quality-requirements/002-quality-scenarios]] pending formal stakeholder agreement.
