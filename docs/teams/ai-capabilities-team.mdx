## Mission & Topology Boundary

The **AI Capabilities Team** encapsulates specialized AI engineering complexity within [[domain|conversational]] so stream-aligned teams do not have to manage LLM orchestration, embedding pipelines, or agentic protocol details. It owns multi-agent routing, Model Context Protocol (MCP) adapters, Agent-to-Agent (A2A) integration, vector batch scheduling contracts, and composable AI governance. Explicitly **out of scope** are authoritative book inventory, basket mutations, order state transitions, and core PII detection engine hosting (consumed from [[system|data-privacy]]).

- **With [[team|catalog-experience-team]] (_Collaboration_):** Consumes read-only book and review summaries via MCP tools and A2A contracts without duplicating authoritative domain state.
- **With [[team|platform-engineering-team]] (_X-as-a-Service_):** Enforces fail-closed PII filtering via [[service|presidio-api]], agent identities via [[system|identity-provider]], and scheduled batch triggers via [[service|scheduler-service]].
- **With [[team|architecture-enabling-team]] (_Facilitating_):** Validates AI governance controls, tool-scoping boundaries, and episodic/semantic memory policies against platform ADRs.

</Accordion>

## Working Agreements

- Enforce fail-closed PII detection and anonymization on every inbound prompt and outbound response.
- Keep [[service|mcp-server]] strictly read-only over domain APIs; conversational agents never bypass domain boundaries to mutate catalog, basket, or order state.
- Govern tool access per agent and maintain explicit model-routing decisions.

:::warning
Agents must never fabricate order or inventory state; all factual book and review responses must ground in live read-only lookups from [[domain|catalog]] and [[domain|reviews]].
:::
