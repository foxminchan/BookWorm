## Integration Purpose & Boundary

OAuth API (backed by Microsoft Entra ID) is BookWorm's external OAuth 2.0 and OpenID Connect (OIDC) authentication boundary. Storefront and Backoffice clients authenticate users against it, while [[service|catalog-api]], [[service|basket-api]], [[service|order-api]], [[service|rating-api]], [[service|chat-api]], [[service|mcp-server]], and [[service|scheduler-service]] validate issued JWTs and use Entra Agent Identities for delegated On-Behalf-Of (OBO) calls.

:::warning
Authentication is not authorization: OAuth API verifies caller identity and issues role/scope claims (`customer`, `business_user`, `admin`), while each BookWorm service enforces its own resource-ownership and policy checks. Protected services must **fail closed** (`401 Unauthorized`) whenever token validation or provider metadata fails.
:::

## Integration Profile

| Property                         | Value                                                                                                                                                                                                          |
| :------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Provider / Sidecar**           | Microsoft Entra ID (OAuth 2.0 / OIDC & Entra Agent Identities)                                                                                                                                                 |
| **BookWorm Consumers**           | [[service\|catalog-api]], [[service\|basket-api]], [[service\|order-api]], [[service\|rating-api]], [[service\|chat-api]], [[service\|mcp-server]], [[service\|scheduler-service]], Storefront, and Backoffice |
| **Runtime Transport & Protocol** | HTTPS OAuth 2.0 / OIDC (proxied via API Gateway for browser flows; JWT & OBO token exchange for APIs)                                                                                                          |
| **Auth / Credential Boundary**   | Federated Managed Identity in publish environments; client secrets and signing tokens kept strictly out of source control and logs                                                                             |
| **Data / PII Sensitivity**       | High — carries user identity claims, access tokens, and session cookies; never log bearer tokens or refresh credentials                                                                                        |
| **Failure / Fallback Behavior**  | Fail-closed — protected APIs reject unauthenticated or unverifiable requests with `401 Unauthorized` without anonymous fallback                                                                                |
