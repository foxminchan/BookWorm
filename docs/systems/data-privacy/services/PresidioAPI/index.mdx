Presidio (`presidio-analyzer` and `presidio-anonymizer`) provides internal HTTP services for detecting and anonymizing personally identifiable information (PII) in text before and after AI model execution. BookWorm's `PIIMiddleware` (`BookWorm.Chassis`) calls Presidio fail-closed on behalf of Chat API and Rating API agents.

## Overview

| Property                | Value                                                                                                                                                      |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Aspire integration**  | `src/Integrations/BookWorm.Hosting.Presidio` (`AddPresidioAnalyzer`, `AddPresidioAnonymizer`)                                                              |
| **Aspire resource IDs** | `presidio-analyzer`, `presidio-anonymizer`                                                                                                                 |
| **Container images**    | `ghcr.io/data-privacy-stack/presidio-analyzer:latest`, `ghcr.io/data-privacy-stack/presidio-anonymizer:latest`                                             |
| **Port & transport**    | Container port `3000`; HTTPS with dev certificate in local run mode, internal HTTP in Azure Container Apps publish mode; **not routed via API Gateway**    |
| **Health probe**        | `GET /health` on each container                                                                                                                            |
| **BookWorm consumers**  | [[service\|chat-api]] (`book-agent`, `book-catalog-researcher`, `book-recommendation-researcher`, `qa-agent`) and [[service\|rating-api]] (`rating-agent`) |
| **Upstream contract**   | Microsoft Presidio OpenAPI v2 (`data-privacy-stack/presidio`)                                                                                              |

## Runtime architecture

BookWorm's `PIIMiddleware` sends non-empty agent inputs and outputs to `presidio-analyzer` first, and calls `presidio-anonymizer` whenever PII entities are detected.

## HTTP endpoints

Analyzer and Anonymizer run as two separate containers behind Aspire service discovery.

| Container             | Method & route           | Contract reference              | Purpose                                                                                 |
| :-------------------- | :----------------------- | :------------------------------ | :-------------------------------------------------------------------------------------- |
| `presidio-analyzer`   | `POST /analyze`          | [[command\|AnalyzeText]]        | Detects PII entities and returns entity types, character offsets, and confidence scores |
| `presidio-analyzer`   | `GET /recognizers`       | [[query\|GetRecognizers]]       | Lists active PII recognizers for a language                                             |
| `presidio-analyzer`   | `GET /supportedentities` | [[query\|GetSupportedEntities]] | Lists detectable PII entity types for a language                                        |
| `presidio-anonymizer` | `POST /anonymize`        | [[command\|AnonymizeText]]      | Redacts or transforms detected PII spans in text                                        |
| `presidio-anonymizer` | `GET /anonymizers`       | [[query\|GetAnonymizers]]       | Lists supported anonymization operators                                                 |
| Both containers       | `GET /health`            | —                               | Container liveness and readiness check                                                  |

## Middleware behavior and failure semantics

- **Middleware invocation (not an AI tool):** `PIIMiddleware` executes deterministically in the agent chat client pipeline; LLM models cannot bypass or opt out of PII screening.
- **Two-step screening:** For any non-empty prompt or response, middleware calls `POST /analyze`. If one or more PII entities match (such as email addresses, phone numbers, or credit card numbers), middleware sends the text and entity spans to `POST /anonymize`.
- **Fail-closed guarantee:** Any timeout, connection error, or non-success response from `presidio-analyzer` or `presidio-anonymizer` propagates out of `PIIMiddleware` and fails the request rather than sending unscreened text to Microsoft Foundry or end users.

### Error responses

The upstream [Presidio OpenAPI contract](https://raw.githubusercontent.com/data-privacy-stack/presidio/refs/heads/main/docs/api-docs/api-docs.yml) declares `400 Bad Request` and `422 Unprocessable Entity` for `POST /anonymize`. For `POST /analyze` and the discovery `GET` endpoints, it documents `200 OK` but no non-200 status codes or error-body schemas. Do not treat other statuses as a stable Presidio contract; the image tags are mutable. Regardless of status, BookWorm's PII middleware fails closed when an Analyzer or Anonymizer request does not succeed.
