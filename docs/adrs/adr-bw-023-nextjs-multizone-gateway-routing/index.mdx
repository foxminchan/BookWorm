## Context & Problem Statement

Growing catalog discovery, checkout, and back-office surfaces in a single Next.js application coupled release cycles and blurred domain boundaries on the frontend.

## Decision & Consequences

**Chosen Option:** Split the frontend into independent Next.js zones composed via multi-zone routing behind the API gateway, sharing UI primitives and auth session boundaries without cross-zone state coupling (see [[doc|frontend/006-microfrontend-architecture]]).

- **Positive:** Independent deployments per frontend surface and clear alignment with backend bounded contexts.
- **Negative:** Requires coordinated gateway route prefixes and cross-zone navigation links.
