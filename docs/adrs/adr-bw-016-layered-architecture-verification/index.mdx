## Context & Problem Statement

No single test layer catches every failure mode in a distributed microservices platform. Unit tests verify domain invariants quickly but miss contract drift; end-to-end browser tests validate user journeys but are too slow and coarse to cover all boundary rules and architecture constraints.

## Decision Drivers

- **Fast feedback:** Catch domain and architecture violations in seconds.
- **Contract safety:** Verify HTTP, gRPC, and Kafka compatibility without running all live services together.
- **Boundary enforcement:** Automatically prevent cross-domain coupling and catalog/doc drift.

## Options Considered

| Option                                                                     | Pros                                     | Cons                                                          |
| :------------------------------------------------------------------------- | :--------------------------------------- | :------------------------------------------------------------ |
| **Layered verification (unit, architecture, contract, E2E, catalog lint)** | Targeted feedback per risk area; fast CI | Multiple test suites to maintain                              |
| **Unit tests only**                                                        | Very fast execution                      | Misses contract drift, serialization, and UI integration bugs |
| **End-to-end UI tests only**                                               | Exercises full real journeys             | Slow, flaky, and poor coverage of internal edge cases         |
| **Manual QA review only**                                                  | Flexible human judgment                  | Misses subtle regressions and contract breaks                 |

## Decision & Consequences

**Chosen Option:** Enforce a layered verification strategy combining unit tests, architecture boundary tests, consumer/provider contract tests, schema/catalog linting, and high-value end-to-end journeys.

- **Positive:** Regressions in domain logic, contracts, or documentation are caught at the cheapest appropriate layer.
- **Negative:** Contributors must keep contract and catalog checks aligned with code changes.

### Compliance Criteria

- Domain logic changes must include unit tests; cross-service contract changes must pass consumer/provider contract verification.
- Architecture tests must enforce vertical-slice and bounded-context dependency rules.
- Documentation and EventCatalog changes must pass `eventcatalog-linter` and link validation.
