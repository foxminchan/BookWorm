## Context & Problem Statement

Customer checkout spans [[service|order-api]], [[service|basket-api]], and [[service|notification-api]]. Pure event choreography makes multi-step failure compensation (such as basket cleanup failure) hard to trace and reason about.

## Decision & Consequences

**Chosen Option:** Implement [[service|order-orchestration]] as an Azure Durable Functions orchestrator keyed deterministically by `OrderId`. Upon receiving [[event|UserCheckedOutIntegrationEvent]], it dispatches [[command|PlaceOrderCommand]] and awaits [[event|BasketDeletedCompleteIntegrationEvent]] or [[event|BasketDeletedFailedIntegrationEvent]], issuing LIFO compensations ([[command|DeleteBasketFailedCommand]]) when cleanup fails.

- **Positive:** Deterministic per-order instance state, built-in Durable Task Hub history, and explicit compensation paths.
- **Negative:** Uses Azure Functions Kafka triggers rather than Wolverine's Kafka transport, requiring Durable Task Hub inspection instead of a Kafka DLQ.
