## Context & Problem Statement

[[service|chat-api]], [[service|rating-api]], and [[service|mcp-server]] process customer prompts and review text using foundation models and external tools. Relying solely on system prompts is not a security boundary, while re-implementing PII detection and tool authorization per agent invites drift and privilege leaks.

## Decision Drivers

- **Defense in depth:** Enforce PII redaction, prompt-injection guardrails, and tool policies before and after model calls.
- **Least privilege:** Grant each agent identity only the exact tools and scopes it requires.
- **Explicit opt-in verification:** Require every AI path to declare and test its governance registration.

## Options Considered

| Option                                                           | Pros                                                                 | Cons                                                                |
| :--------------------------------------------------------------- | :------------------------------------------------------------------- | :------------------------------------------------------------------ |
| **Composable shared governance + per-agent policy declarations** | Consistent PII/guardrail reuse with strict per-agent least privilege | Adds middleware latency; requires per-path policy maintenance       |
| **Prompt-only safety instructions**                              | Zero middleware overhead                                             | Easily bypassed by prompt injection; not an enforceable boundary    |
| **Custom per-agent safety code**                                 | Full local control                                                   | Duplicates Presidio/guardrail logic and drifts over time            |
| **Implicit global package protection**                           | Fast initial wiring                                                  | Direct model calls or missed registrations silently bypass controls |

## Decision & Consequences

**Chosen Option:** Compose shared AI governanceâ€”[[service|presidio-api]] PII anonymization, input/output guardrails, and default-deny tool policiesâ€”explicitly on every enabled AI path across [[system|chat-system]], [[system|rating-system]], and [[system|mcp-tools]].

- **Positive:** Consistent privacy and safety enforcement without granting one agent another's tool permissions.
- **Negative:** Additional middleware hops add measurable latency to AI turns.

### Compliance Criteria

- Every agent and AI workflow must register PII middleware, guardrail evaluation, and a default-deny tool policy.
- Agent tool allowlists must follow least privilege (e.g., [[agent|qa-agent]] cannot access catalog tools; [[agent|rating-agent]] is read-only).
- AI paths must fail closed when [[service|presidio-api]] or guardrail evaluation is unavailable.
