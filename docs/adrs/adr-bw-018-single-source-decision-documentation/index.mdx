## Context & Problem Statement

BookWorm documents its architecture in arc42 chapters alongside EventCatalog ADRs. Duplicating full decision rationale across both places causes status drift and conflicting guidance whenever a decision is updated or superseded.

## Decision Drivers

- **Single source of truth:** Maintain one authoritative record per decision with clear status and history.
- **Zero duplication:** Keep arc42 Section 9 as an index linking to ADRs rather than copying prose.
- **Clear scoping:** Separate platform-wide decisions from system-specific decisions.

## Options Considered

| Option                                                    | Pros                                                             | Cons                                                 |
| :-------------------------------------------------------- | :--------------------------------------------------------------- | :--------------------------------------------------- |
| **Root platform ADRs + system-scoped ADRs + arc42 index** | Clear scope, single source of truth, native EventCatalog linking | New ADRs require updating both the ADR and the index |
| **Duplicate full ADR text inside arc42**                  | Everything on one page                                           | Quickly drifts out of sync with ADR status           |
| **Flat ungrouped ADR folder**                             | Simple folder path                                               | Mixes platform-wide and local system decisions       |
| **System folders only (no root ADRs)**                    | Local team autonomy                                              | Fragments cross-cutting platform decisions           |

## Decision & Consequences

**Chosen Option:** Store whole-system ADRs at the catalog root (`ADR-BW-*`), keep system-specific ADRs nested under their owning system, and maintain [[doc|arc42/09-architecture-decisions]] as a reference register. Superseded decisions remain immutable in history and link to their replacement via `supersededBy`.

- **Positive:** Readers always see one authoritative status, scope, and supersession chain.
- **Negative:** Authors must link new ADRs into `appliesTo` and the central register.

### Compliance Criteria

- Platform-wide decisions must live at the catalog root; system-scoped decisions must live under their owning system.
- Arc42 documentation must link to ADRs via `[[adr|...]]` rather than duplicating decision rationale.
- Superseded ADRs must set `status: superseded`, populate `supersededBy`, and display a top warning callout.
