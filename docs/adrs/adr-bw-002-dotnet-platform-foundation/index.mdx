## Context

BookWorm already has a shared .NET ecosystem, service building blocks, testing conventions, and centrally managed packages. Introducing a different service runtime would add separate hosting, dependency, integration, and maintenance practices.

## Decision

Use the repository SDK and language settings for application services and retain centralized package management and existing C# conventions. The engineering standards currently document .NET 11 and C# 15; future upgrades should follow the repository baseline rather than a version frozen by this ADR.

This does not require browser clients, external providers, or infrastructure products to use .NET.

## Decision drivers

- Reuse existing service and integration libraries.
- Limit technology fragmentation and dependency-management inconsistency.
- Preserve contributor familiarity and existing test infrastructure.

## Alternatives considered

| Alternative                                       | Assessment                                                                          |
| ------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Polyglot services by default                      | Allows local ecosystem choices but increases integration and operational variation. |
| Replace the service runtime                       | Requires broad migration without a documented business driver.                      |
| Independently chosen package versions per service | Gives local freedom but makes shared-library compatibility harder to manage.        |

## Consequences

- Services can reuse established libraries and engineering practices.
- Toolchain and shared-package upgrades require compatibility review across affected services.
- The decision constrains local technology choice but does not prescribe a production operating system or cloud.
