`BookUpdatedRatingFailedIntegrationEvent` (v1.0.0) is a compensating event published by Catalog API when it receives `FeedbackCreatedIntegrationEvent` for a book that does not exist in `catalogdb`. Rating API consumes this event to revert and delete the orphaned `Feedback` document in Azure Cosmos DB.

## Overview

| Property                 | Value                                                                                                                                                    |
| :----------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**                | Catalog bounded context (`Catalog API`)                                                                                                                  |
| **Producer**             | [[service\|catalog-api]] (`FeedbackCreatedIntegrationEventHandler`)                                                                                      |
| **Consumer**             | [[service\|rating-api]] (`BookUpdatedRatingFailedIntegrationEventHandler`)                                                                               |
| **Source**               | `src/Services/Catalog/BookWorm.Catalog/IntegrationEvents/Events/BookUpdatedRatingFailedIntegrationEvent.cs`                                              |
| **Protocol / format**    | Kafka + CloudEvents JSON (Wolverine)                                                                                                                     |
| **Kafka topic**          | `bookworm.{env}.catalog.book-update-rating-failed` (where `{env}` is the kebab-case environment name)                                                    |
| **Message identity**     | `BookWorm.Contracts.BookUpdatedRatingFailedIntegrationEvent`                                                                                             |
| **Partition key**        | `FeedbackId` (configured via `opts.MessagePartitioning.ByPropertyNamed("BookId", "FeedbackId")`)                                                         |
| **Outbox / idempotency** | Published via Catalog PostgreSQL Wolverine outbox (`catalogdb`, `wolverine` schema); consumed in Rating API with 24-hour Redis idempotency keyed by `id` |

## Parameters and fields

The table below reflects the runtime C# contract (`BookUpdatedRatingFailedIntegrationEvent : IntegrationEvent`) serialized as camelCase JSON inside the CloudEvents envelope.

| Name           | Type                 | Required | Default                 | Constraints                                              | Description                                                                        |
| :------------- | :------------------- | :------- | :---------------------- | :------------------------------------------------------- | :--------------------------------------------------------------------------------- |
| `id`           | `string` (UUID)      | Yes      | `Guid.CreateVersion7()` | UUID v7 inherited from `IntegrationEvent`                | Unique event identifier; used by Rating API as the Redis idempotency key.          |
| `creationDate` | `string` (date-time) | Yes      | `DateTime.UtcNow`       | ISO 8601 UTC timestamp inherited from `IntegrationEvent` | UTC timestamp when Catalog API created the event.                                  |
| `feedbackId`   | `string` (UUID)      | Yes      | —                       | Valid UUID; also used as Kafka partition key             | Identifier of the orphaned `Feedback` document in Rating API to revert and delete. |

:::warning
**Schema drift notice:** The legacy EventCatalog file `schema.json` sets `"additionalProperties": false` and lists only `feedbackId`, omitting `id` and `creationDate` inherited from `IntegrationEvent`. Consumers must accept `id` and `creationDate` when validating live Kafka payloads.
:::

## Error handling and delivery guarantees

| Condition                                                                   | Behavior                                                                                                                        | Recovery behavior                                                       |
| :-------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------- |
| `Feedback` document already deleted in Cosmos DB (`ratingdb` / `feedbacks`) | `BookUpdatedRatingFailedIntegrationEventHandler` returns without error.                                                         | No action required; compensation is idempotent.                         |
| Duplicate delivery within 24 hours                                          | `IIntegrationEventIdempotencyGuard` skips reprocessing using `idempotency:BookUpdatedRatingFailedIntegrationEventHandler:{id}`. | Safe at-least-once delivery.                                            |
| Transient Cosmos DB or network failure                                      | Wolverine retries with cooldown (`50ms`, `250ms`, `1s`) and full jitter.                                                        | Exhausted messages route to `bookworm.{env}.rating.dead-letter-queue`.  |
| Deserialization failure (`JsonException` / `FormatException`)               | Routed directly to `bookworm.{env}.rating.dead-letter-queue`.                                                                   | Check contract compatibility against `tests/pacts/Rating-Catalog.json`. |
