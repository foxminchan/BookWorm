`DeleteBook` soft-deletes an existing book listing in **Catalog API** (`DELETE /api/v1/books/{id}`) by setting `is_deleted = true` and returns `204 No Content`. It does not permanently erase the database row or delete the book's cover image from Azure Blob Storage.

## Overview

| Property              | Value                                                                                                                                                                             |
| :-------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**             | Catalog bounded context (**Catalog API**, Aspire resource `catalog`)                                                                                                              |
| **Source**            | `src/Services/Catalog/BookWorm.Catalog/Features/Books/Delete/`                                                                                                                    |
| **Protocol / format** | HTTP `DELETE`, path parameter only, empty response body (`204 No Content`)                                                                                                        |
| **Endpoint**          | Direct: `DELETE /api/v1/books/{id}` (local HTTP `5100`, HTTPS `7187`); API Gateway: `DELETE /catalog/api/v1/books/{id}`                                                           |
| **Authentication**    | Microsoft Entra ID JWT — `business_user` policy (role `business_user` or `admin` and scopes `catalog_read`, `catalog_write`)                                                      |
| **Rate limiting**     | Global concurrency (`100`) and fixed-window (`30 req/min`) limiters plus `PerUserRateLimit` token bucket                                                                          |
| **Idempotency**       | Not idempotent across retries; repeating a completed delete returns `404 Not Found` because the soft-delete query filter hides deleted rows; no `x-request-id` header is enforced |
| **Contract version**  | `1.0.0` (`ApiVersions.V1`)                                                                                                                                                        |

| Name | Type   | Required | Default | Constraints           | Description                                  |

## Behavior and side effects

- **Soft delete (`ISoftDelete`):** `DeleteBookCommand` is decorated with `[Transactional]`. `DeleteBookHandler` loads the book, invokes `book.Delete()` to set `IsDeleted = true` (`Book.cs`), and commits the update. `BookConfiguration.cs` applies a global EF Core query filter (`HasQueryFilter(x => !x.IsDeleted)`), hiding soft-deleted books from standard catalog reads and subsequent `DELETE` calls.
- **Cover image retention:** `DeleteBookHandler` does not call `IBlobService`. Any cover image stored in Azure Blob Storage (`catalog-blob`) remains in blob storage after a book is soft-deleted.
- **Cache invalidation:** `book.Delete()` registers `BookChangedEvent(Id)`; `BookChangedEventHandler` removes FusionCache keys `book:{id}` and `book:summary:{id}` and invalidates tags `books:list` and `books:search`.
- **Vector index queueing:** Updating `is_deleted` on `books` fires the PostgreSQL trigger `books_vector_update` (`AFTER UPDATE ON books`), enqueuing `book_id` into `pending_vector_updates` so **Catalog Ingestion** reconciles the Qdrant vector index asynchronously.

## Error responses

| Code / status               | Condition                                                                                                | Recovery behavior                                                         |
| :-------------------------- | :------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------ |
| `400 Bad Request`           | `{id}` is not a valid UUID                                                                               | Fix the path parameter; do not retry unchanged                            |
| `401 Unauthorized`          | Missing, expired, or invalid Entra ID JWT                                                                | Acquire a valid Entra ID access token and retry                           |
| `403 Forbidden`             | Token lacks role `business_user` or `admin`, or lacks scopes `catalog_read` and `catalog_write`          | Request the required Entra ID app role and scopes                         |
| `404 Not Found`             | No active book exists with the supplied `{id}` (`{ "detail": "The requested resource was not found." }`) | Verify the UUID; treat as already deleted only if your workflow allows it |
| `429 Too Many Requests`     | Global or `PerUserRateLimit` quota exceeded (`ProblemDetails` with `Retry-After` header)                 | Wait for the `Retry-After` interval before retrying                       |
| `500 Internal Server Error` | Unhandled server or PostgreSQL failure (`ProblemDetails` with `traceId`)                                 | Inspect Catalog API logs using `traceId`                                  |
