## 1. Context & Problem

Every book in the catalog must be linked to one or more recognized authors rather than using free-text author names that vary in spelling or formatting. Integrators and catalog tools need a clear, predictable way to register a new author first—and handle missing or invalid author details cleanly—before assigning that author to book listings.

## 2. Business Value

- **Consistent catalog records:** Registering authors once and reusing their unique identifiers prevents duplicate or misspelled author entries across books.
- **Faster onboarding for integrators:** Clear success and failure examples reduce integration guesswork and shorten delivery time for admin tools and import scripts.
- **Cleaner error handling:** Distinguishing invalid input from temporary service outages stops automated callers from blindly retrying requests that will never succeed.

## 3. How It Works

Creating an author follows two main paths:

1. **Successful registration:** The caller submits a non-empty display name for the author. Once validated and saved, the catalog returns a unique identifier for that author. The caller keeps this identifier so it can be attached when creating or updating books later.
2. **Rejected invalid input:** If the author name is missing or blank, the catalog rejects the submission and returns a structured field-level error message. The calling application should display the error so a user or operator can correct the name rather than automatically repeating the same request.

## 4. Trade-offs & Lessons Learned

- **Two-step book authoring workflow:** Requiring authors to exist before they can be linked to books enforces clean catalog relationships, at the cost of requiring callers to create or look up authors first.
- **No blind retries on validation failures:** Treating missing or empty fields as permanent input errors prevents retry loops and noisy logs, placing responsibility on the caller to fix the input before trying again.

## 5. Technical Reference

- **Endpoint:** `POST https://api.example.com/api/v1/authors`
- **Request headers:** `Content-Type: application/json`
- **Request body:** JSON object requiring non-empty `name` (at least one character).
- **Success response:** `200` returning the generated author UUID as a JSON string.
- **Validation failure:** Omitting `name` returns `400` with an RFC 7807 validation response.

const response = await fetch("https://api.example.com/api/v1/authors", {
	method: "POST",
	headers: { "Content-Type": "application/json" },

});

if (!response.ok) {
	throw new Error(`CreateAuthor failed with ${response.status}`);
