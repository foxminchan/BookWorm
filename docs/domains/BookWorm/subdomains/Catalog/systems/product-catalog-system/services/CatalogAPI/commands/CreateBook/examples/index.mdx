## 1. Context & Problem

Adding a new book to the storefront involves more than saving a title and price: each listing must also carry a description, pricing rules, links to its category, publisher, and authors, and optionally a cover image. Integrators need a concrete example showing how to submit both structured book details and an optional image together, as well as how to handle rejected submissions when required details or relationships are invalid.

## 2. Business Value

- **Complete, storefront-ready listings in one step:** Combining book metadata, catalog relationships, and cover art in a single submission prevents half-finished listings from appearing without categories, authors, or cover images.
- **Pricing accuracy:** Enforcing that any promotional sale price does not exceed the regular price protects customer trust and prevents pricing mistakes at entry time.
- **Predictable integration behavior:** Explicit validation examples help delivery teams catch missing fields or bad relationship references early before retrying requests.

## 3. How It Works

Creating a book listing covers two primary scenarios:

1. **Submitting a complete book listing:** The caller gathers the book's title, description, regular price, an optional sale price (which must not be higher than the regular price), and the unique identifiers for its existing category, publisher, and at least one author. An optional cover image file can be included in the same submission. When accepted, the catalog saves the book, stores the cover image in file storage if provided, and returns the new book's unique identifier so callers can retrieve, update, or reference the listing later.
2. **Handling invalid submissions:** If any required details are missing, pricing rules are broken, or any linked category, publisher, or author identifiers are malformed, the catalog rejects the submission and returns validation details. The caller should fix the form inputs before submitting again.

## 4. Trade-offs & Lessons Learned

- **Single submission for text and cover art:** Bundling the cover image with the book metadata simplifies client workflows into one step, though it requires callers to submit form-encoded uploads rather than plain text payloads.
- **Upfront relationship dependencies:** Requiring valid identifiers for category, publisher, and authors guarantees clean catalog links from day one, meaning callers must ensure those reference records already exist before creating a book.

## 5. Technical Reference

- **Endpoint:** `POST https://api.example.com/api/v1/books`
- **Content type:** `multipart/form-data` (required because the optional cover `image` is uploaded alongside book metadata).
- **Fields:**
  - `name`, `description`, and `price` (required)
  - `priceSale` (optional; must not exceed `price`)
  - `categoryId`, `publisherId`, and `authorIds` (required relationship UUIDs)
  - `image` (optional binary cover file; stored in blob storage)
- **Success response:** `201 Created` returning the generated book UUID as a JSON string.
- **Validation failure:** Missing required fields or malformed relationship UUIDs return `400` with validation problem details.

const form = new FormData();
form.set("name", "The Left Hand of Darkness");
form.set("description", "A science-fiction novel by Ursula K. Le Guin.");
form.set("price", "18.99");
form.set("priceSale", "14.99");

form.set("publisherId", "22222222-2222-2222-2222-222222222222");
form.append("authorIds", "33333333-3333-3333-3333-333333333333");

const cover = new Blob(["binary cover contents"], { type: "image/jpeg" });
form.set("image", cover, "cover.jpg");

const response = await fetch("https://api.example.com/api/v1/books", {
	method: "POST",
	body: form,
});

if (!response.ok) {
	throw new Error(`CreateBook failed with ${response.status}`);
}

const bookId = (await response.json()) as string;
console.log(`Created book ${bookId}`);
