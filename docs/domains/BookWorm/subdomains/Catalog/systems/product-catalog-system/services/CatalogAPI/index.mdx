## Overview

Catalog API is the internal application surface for maintaining and
discovering Catalog [[entity|book]]s and their descriptive metadata. It reads
and writes the authoritative records in [[container|catalog-database]], uses
[[container|catalog-cache]] for selected read paths, stores book image files
in [[container|catalog-blob]], and registers the [[container|catalog-vector]]
integration for vector and hybrid-search capabilities.

The API also maintains the rating summary stored with each book. Individual
[[entity|feedback]] remains owned by [[domain|reviews]]; Catalog stores only
the derived average rating and review count used by product discovery.

## Core capabilities

| Capability                | Behavior                                                                                                                                                                                                          |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Book management           | Create, update, retrieve, list, and delete [[entity\|book]]s. Book lists support pagination, sorting, text search, price bounds, and [[entity\|category]], [[entity\|publisher]], and [[entity\|author]] filters. |
| Catalog metadata          | Create, update, list, and delete [[entity\|author]]s, [[entity\|category]]s, and [[entity\|publisher]]s.                                                                                                          |
| Book images               | Upload image files to Blob Storage and retain their URNs with book data; image removal deletes the referenced blob.                                                                                               |
| Rating summary            | Process feedback-created and feedback-deleted integration messages and update the book's denormalized `average_rating` and `total_reviews`.                                                                       |
| Service-to-service lookup | Expose gRPC methods to retrieve compact or full book details, search books, list categories and authors, and return an admin-protected catalog dashboard summary.                                                 |

## HTTP API

The version 1 REST contract is documented in the accompanying OpenAPI specification, `openapi-v1.yml`.

- `/api/v1/books` supports create, update, and filtered list operations; `/api/v1/books/{id}` supports retrieval and deletion.
- Book list queries accept page index and size, sort property and direction, a search term, minimum and maximum prices, and category, publisher, and author IDs.
- `/api/v1/authors`, `/api/v1/categories`, and `/api/v1/publishers` support create, update, and list operations. Their `{id}` routes support deletion.
- Book create and update requests accept multipart form data to support image uploads.

## gRPC and integration behavior

The version 1 `Catalog gRPC` service provides [[query|GetBookGrpc]] and
[[query|GetBooksGrpc]] for book identity, price, and availability, as well as
[[query|ListBooksGrpc]], [[query|GetBookDetailsGrpc]],
[[query|ListCategoriesGrpc]], and [[query|ListAuthorsGrpc]] for full catalog
metadata lookups consumed by [[service|mcp-server]]. Those lookup methods allow
anonymous access. [[query|GetDashboardGrpc]] requires the admin authorization
policy and returns the total book count with category counts.

Wolverine integration handlers process feedback-created and feedback-deleted messages from Reviews and update the corresponding book's rating summary. If a created feedback message refers to a missing book, Catalog publishes a rating-update-failed integration event. Database triggers enqueue changed books for asynchronous vector refresh by [[service|catalog-ingestion]].

## Runtime and access

The service configures Entra ID token introspection, rate limiting, CORS, centralized exception and status-code handling, and HSTS outside development. The application is versioned around the v1 HTTP and gRPC contracts; see `openapi-v1.yml` for the REST request and response schemas.
