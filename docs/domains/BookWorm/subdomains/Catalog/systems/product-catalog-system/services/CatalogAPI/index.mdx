## Service Responsibility & Boundary

Catalog API is the system of record within the [[domain|catalog]] domain for [[entity|book]], [[entity|author]], [[entity|category]], and [[entity|publisher]] records, pricing, cover image references, and derived rating summaries. It serves versioned HTTP endpoints for storefront and backoffice workflows, exposes internal gRPC read contracts to peer services, and executes hybrid keyword-and-semantic search. Asynchronous vector index synchronization is delegated to [[service|catalog-ingestion]], while individual customer reviews remain owned by [[service|rating-api]].

| **Key Resilience / Idempotency Pattern**  | Transactional outbox/inbox, soft-delete filtering, rate limiting, and dead-letter routing on [[channel\|bookworm.&#123;env&#125;.catalog.dead-letter-queue]]                                  |

## Contracts & Data Ownership

Catalog API owns [[entity|book]], [[entity|author]], [[entity|category]], and [[entity|publisher]] in [[container|catalog-database]], stores cover image bytes in [[container|catalog-blob]], caches selected reads in [[container|catalog-cache]], and queries candidate book IDs from [[container|catalog-vector]] during semantic search.

:::note
Catalog writes trigger database-queued vector updates for [[service|catalog-ingestion]] rather than writing embeddings synchronously. Semantic search always resolves final book details and filters from [[container|catalog-database]] so stale index entries never expose outdated prices or deleted books.
:::

:::warning
When [[service|catalog-api]] consumes [[event|FeedbackCreatedIntegrationEvent]] for a missing book, it publishes [[event|BookUpdatedRatingFailedIntegrationEvent]] so [[service|rating-api]] can execute a compensating delete on the orphaned review.
:::
