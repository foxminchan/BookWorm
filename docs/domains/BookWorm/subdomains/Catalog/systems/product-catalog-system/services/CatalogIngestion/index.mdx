Catalog Ingestion (`catalog-ingestion`) is an internal Azure Functions isolated worker in the Catalog bounded context that reads queued book mutations from PostgreSQL, generates semantic embeddings with Microsoft Foundry, and updates the Qdrant vector index in bounded batches. It exposes no HTTP or gRPC endpoints and is not routed through the API Gateway.

## Overview

| Property                 | Value                                                                                                                                                                               |
| :----------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**                | Catalog bounded context (`BookWorm.Catalog.Ingestion`)                                                                                                                              |
| **Aspire resource ID**   | `catalog-ingestion`                                                                                                                                                                 |
| **Source**               | `src/Services/Catalog/BookWorm.Catalog.Ingestion`                                                                                                                                   |
| **Runtime & local port** | `Azure.Functions.Sdk` `1.1.0` (`Microsoft.Azure.Functions.Worker` `2.52.0`) — local `--port 7071`; not routed via API Gateway                                                       |
| **Trigger & protocol**   | `[KafkaTrigger]` (`ProcessVectorBatch`) on unprefixed topic `scheduler.process-vector-batch`, consumer group `catalog-ingestion`                                                    |
| **Dependencies**         | PostgreSQL (`catalogdb`), Qdrant (`vectordb`), Microsoft Foundry (`embedding` = `Cohere.EmbedV40`), Azure Storage (`storage` host state), Wolverine PostgreSQL outbox (`catalogdb`) |
| **Authentication**       | Internal worker (no public auth); Azure Managed Identity RBAC (`CognitiveServicesUser` for Microsoft Foundry) in Azure                                                              |

## Runtime architecture

Scheduler triggers Catalog Ingestion every five minutes over Kafka; the worker acquires a PostgreSQL advisory lock, reads coalesced book revisions, generates embeddings, and upserts or deletes vectors in Qdrant.

## Trigger and batch execution contract

| Property                     | Value                                                                                                           |
| :--------------------------- | :-------------------------------------------------------------------------------------------------------------- |
| **Function name**            | `ProcessVectorBatch`                                                                                            |
| **Inbound event**            | [[event\|ProcessVectorBatchIntegrationEvent]]                                                                   |
| **Kafka topic**              | `scheduler.process-vector-batch` (`AppendPrefix = false`)                                                       |
| **Consumer group**           | `catalog-ingestion`                                                                                             |
| **Cadence**                  | Every 5 minutes UTC (`0 0/5 * * * ?`), dispatched by [[service\|scheduler-dashboard]] (`ProcessVectorBatchJob`) |
| **Batch limit**              | Up to `200` pending updates per invocation (controlled by the worker, not the trigger payload)                  |
| **Target Qdrant collection** | `data-bookworm-snippets`                                                                                        |

### Processing steps per invocation

1. **Acquire exclusivity:** Requests a PostgreSQL advisory lock on `catalogdb`. If another worker holds the lock, the invocation exits immediately without duplicate work.
2. **Fetch bounded batch:** Reads up to `200` rows from `pending_vector_updates`, ordered oldest-first by update timestamp and book ID.
3. **Assemble searchable text:** For each active [[entity|book]], builds combined text from title, description, [[entity|author]] names, [[entity|category]], and [[entity|publisher]].
4. **Upsert or delete in Qdrant:** Generates embeddings through Microsoft Foundry (`Cohere.EmbedV40`) and upserts active book snippets into `data-bookworm-snippets`. Deletes the Qdrant record when a queued book is missing or soft-deleted.
5. **Revision-safe acknowledgment:** Deletes each `pending_vector_updates` row only if its stored revision still matches the revision read at step 2; concurrent edits remain queued for the next cycle.
6. **Release lock:** Releases the PostgreSQL advisory lock in all exit paths, including exceptions.

## Failure semantics and operational checks

| Condition                              | Behavior                                                                                        | Recovery behavior                                                                                                 |
| :------------------------------------- | :---------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------- |
| Advisory lock held by another instance | Invocation returns immediately with no side effects                                             | Wait for active batch to complete                                                                                 |
| Embedding or Qdrant failure            | Exception propagates; affected rows are not acknowledged and remain in `pending_vector_updates` | Next 5-minute trigger retries automatically; verify Foundry RBAC and Qdrant connectivity                          |
| Growing `pending_vector_updates` queue | Catalog writes continue normally while semantic search lags behind                              | Inspect [[service\|scheduler-dashboard]] execution history, `pending_vector_updates` count/age, and Function logs |
| Concurrent edit during active batch    | Revision mismatch prevents premature acknowledgment                                             | Newer revision is processed on the next scheduled cycle                                                           |

`VectorBatchProcessor` uses PostgreSQL advisory lock key `740031001` via `pg_try_advisory_lock($1)` and releases it in a `finally` block. Its per-invocation read limit is 200 pending updates.
