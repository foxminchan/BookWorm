## System Purpose & Boundary

The Product Catalog System delivers product catalog management, hybrid keyword-and-semantic discovery, and asynchronous search index maintenance within the [[domain|catalog]] domain. It serves **Customers** browsing and searching for books and **Business Users** maintaining titles, pricing, cover art, and reference metadata ([[entity|book]], [[entity|author]], [[entity|category]], [[entity|publisher]]). Shopping baskets ([[domain|shopping]]), accepted order lifecycles ([[domain|ordering]]), and individual customer reviews ([[domain|reviews]]) are explicitly out of scope; the system stores only a derived rating summary on each book.

:::note
[[container|catalog-database]] is the sole system of record for catalog entities and pending search-index work. [[container|catalog-cache]] and [[container|catalog-vector]] are disposable, rebuildable projectionsâ€”search results always resolve final details from the authoritative database so stale projections never leak outdated prices or deleted listings.
:::

## External Interactions & Trust Boundaries

- **Human actors via API Gateway:** Customers access public catalog read and search operations; Business Users and Administrators authenticate through [[system|identity-provider]] to create, update, or delete catalog records and upload cover images.
- **Internal service consumers:** [[service|basket-api]], [[service|order-api]], and [[service|mcp-server]] query book metadata, pricing, and dashboard counts over internal gRPC contracts.
- **Reviews integration:** [[system|rating-system]] publishes feedback lifecycle events over Kafka so [[service|catalog-api]] can maintain derived average ratings and review counts; if a review targets a missing book, Catalog emits a compensating failure event.
- **Scheduled indexing:** [[system|scheduler-system]] dispatches periodic batch-processing triggers over Kafka to [[service|catalog-ingestion]].

<Accordion title="Operational & Consistency Notes">
	- **Eventual search consistency:** Catalog writes commit immediately to
	[[container|catalog-database]] and enqueue work for [[service|catalog-ingestion]], keeping
	authoring responsive while search index updates catch up asynchronously. - **Monitoring:** Track
	the pending vector-update queue depth and ingestion execution health to detect indexing lag early.
</Accordion>
