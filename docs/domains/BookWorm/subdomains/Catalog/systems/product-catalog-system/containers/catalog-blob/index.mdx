Catalog blob storage (`catalog-blob`) is the authoritative Azure Blob Storage container owned by [[service|catalog-api]] for binary book cover images. [[container|catalog-database]] stores only the permanent blob URN in `books.image`, while Catalog API generates short-lived, read-only Shared Access Signature (SAS) URLs on demand.

## Overview

| Property               | Value                                                                                                                |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------- |
| **Owner**              | Catalog bounded context — [[service\|catalog-api]] (`catalog`)                                                       |
| **Aspire resource ID** | `catalog-blob` (container on shared `storage` resource)                                                              |
| **Source**             | `src/Services/Catalog/BookWorm.Catalog/Infrastructure/Blob/BlobService.cs`, `src/Aspire/BookWorm.AppHost/AppHost.cs` |
| **Engine**             | Azure Blob Storage (Azurite emulator locally; Azure Storage Account in cloud)                                        |
| **Authentication**     | Managed Identity RBAC (`StorageBlobDataContributor`); public blob access disabled (`AllowBlobPublicAccess = false`)  |
| **Authoritative**      | Yes (`readWrite`) for Catalog binary media                                                                           |
| **Classification**     | `internal`                                                                                                           |

## Architecture and media delivery flow

Catalog API mediates every upload, SAS URL resolution, and deletion for `catalog-blob`. Browsers fetch cover images directly from Azure Blob Storage using short-lived read-only SAS URLs rather than proxying binary bytes through Catalog API or storing expiring URLs in PostgreSQL.

## URN and object naming contract

`BlobService` enforces a strict URN format and filename sanitization policy to prevent path traversal and object collisions.

| Rule                      | Specification                                                                                                                                      |
| :------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Persisted URN format**  | `urn:{account}:{container}:{blobName}` stored in `books.image`                                                                                     |
| **Blob name format**      | `{uuidv7}-{safeName}{safeExt}` (or `{uuidv7}{safeExt}` if `safeName` is empty)                                                                     |
| **Filename sanitization** | Strips all characters outside `[a-zA-Z0-9._-]`; truncates `safeName` to `100` characters                                                           |
| **Overwrite protection**  | Uploads set `Conditions.IfNoneMatch = ETag.All` to reject accidental overwrites                                                                    |
| **URN validation**        | Rejects null/empty values, wrong prefix, mismatched storage account or container name, or blob names containing `/`, `\`, or `..` (`UrnException`) |

## Upload validation and SAS URL rules

| Operation                             | Behavior and constraints                                                                                                                                                                                                                                                         |
| :------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Upload (`UploadFileAsync`)**        | Requires a non-empty file (`Length > 0`) with an allowed content type: `image/jpeg`, `image/png`, or `image/webp`. Sets the blob's HTTP `Content-Type` header on upload.                                                                                                         |
| **Read resolution (`GetFileSasUrl`)** | Validates the URN and builds a read-only (`BlobSasPermissions.Read`) blob SAS URL with `StartsOn = UtcNow - 5 minutes` (clock-skew buffer) and `ExpiresOn = UtcNow + SasExpiryHours`. Uses HTTPS-only SAS when the container URI uses HTTPS. Never persist the returned SAS URL. |
| **SAS signing mechanism**             | Uses account-key SAS when `BlobClient.CanGenerateSasUri` is true (such as Azurite). Under Microsoft Entra ID Managed Identity, requests a 1-day User Delegation Key (`StartsOn = -5m`) and caches it per storage account until 1 hour before expiry.                             |
| **Delete (`DeleteFileAsync`)**        | Validates the URN and calls `DeleteIfExistsAsync` with `DeleteSnapshotsOption.IncludeSnapshots`. Triggered by explicit image removal or book deletion.                                                                                                                           |

`CatalogAppSettings.SasExpiryHours` defaults to `1` hour. No Azure Storage lifecycle management policy for catalog blobs is declared in the AppHost configuration.

## Hosting and environment provisioning

AppHost provisions `catalog-blob` on the shared `storage` resource alongside `chatting-blob` and Azure Functions host storage (`src/Aspire/BookWorm.AppHost/Extensions/Infrastructure/AzureExtensions.Storage.cs`).

| Environment           | Hosting & redundancy                                                  | Security & tooling                                                             |
| :-------------------- | :-------------------------------------------------------------------- | :----------------------------------------------------------------------------- |
| **Local development** | Azurite emulator (`--disableProductStyleUrl`, persistent data volume) | Azure Storage Explorer attached in AppHost                                     |
| **Azure Development** | Azure Storage Account (`StandardLrs`, Hot tier)                       | `AllowBlobPublicAccess = false`, TLS 1.2 minimum, `StorageBlobDataContributor` |
| **Azure Staging**     | Azure Storage Account (`StandardZrs`, Hot tier)                       | `AllowBlobPublicAccess = false`, TLS 1.2 minimum, `StorageBlobDataContributor` |
| **Azure Production**  | Azure Storage Account (`StandardGzrs`, Hot tier)                      | `AllowBlobPublicAccess = false`, TLS 1.2 minimum, `StorageBlobDataContributor` |

## Failure modes and operational rules

| Symptom                             | Cause                                                                                                          | Recovery                                                                                                       |
| :---------------------------------- | :------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| Image fetch returns `403 Forbidden` | SAS URL expired or storage account clock skew                                                                  | Re-fetch the book from Catalog API to obtain a fresh SAS URL                                                   |
| Image fetch returns `404 Not Found` | Blob deleted or missing after a partial restore                                                                | Restore the blob under the exact `{blobName}` in the book's URN, or re-upload through Catalog API              |
| `UrnException` on read or delete    | `books.image` URN targets a different storage account or container (for example, after cross-environment copy) | Update or replace the image through Catalog API; do not manually edit `books.image` without migrating the blob |
| Orphaned blobs in `catalog-blob`    | Upload succeeded before a PostgreSQL transaction failed (no cross-store distributed transaction)               | Reconcile unreferenced blobs periodically against `books.image`                                                |
