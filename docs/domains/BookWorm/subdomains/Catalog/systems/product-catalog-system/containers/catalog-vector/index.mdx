## Purpose & Ownership Boundary

Catalog Vector (`vectordb`) is the non-authoritative Qdrant search index owned by the Catalog bounded context for hybrid semantic and keyword book discovery. [[service|catalog-ingestion]] writes 1,536-dimensional embeddings asynchronously in batches, while [[service|catalog-api]] queries the index for candidate book IDs before hydrating authoritative prices, stock status, and ratings from [[container|catalog-database]].

## Consistency, Isolation & Security Guardrails

- **Eventual search consistency:** Catalog mutations appear in semantic search after the next 5-minute [[service|scheduler-service]] tick and [[service|catalog-ingestion]] batch run (up to `200` books per batch).
- **Revision-safe single-writer batching:** [[service|catalog-ingestion]] acquires PostgreSQL advisory lock `740031001` and deletes queued items only when both `book_id` and `revision` match, preventing lost updates from concurrent edits. If embedding generation returns fewer vectors than active items, the batch fails without acknowledging the queue.
- **No direct external access:** Only [[service|catalog-ingestion]] writes to `data-bookworm-snippets` and only [[service|catalog-api]] queries it.

:::warning
**Derived Index Only â€” Never Authoritative:** `vectordb` is strictly a derived search projection. Never treat vector payloads as canonical product data, and never return prices or availability from Qdrant without hydrating from [[container|catalog-database]]. Because the index is fully rebuildable from `catalogdb`, collection resets carry zero data-loss risk.
:::
