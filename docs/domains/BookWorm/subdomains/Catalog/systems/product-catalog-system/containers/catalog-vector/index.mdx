Catalog vector (`vectordb`) is the non-authoritative Qdrant search index used by the Catalog bounded context for hybrid semantic and keyword book discovery. [[service|catalog-api]] queries it to obtain candidate book IDs before resolving canonical product fields from [[container|catalog-database]], while [[service|catalog-ingestion]] refreshes index entries asynchronously in batches.

## Collection and payload specification

Each active (non-deleted) book is stored as one `TextSnippet` record keyed by its `book_id` (`Guid`).

| Property                | Specification                                                                                                                                    |
| :---------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Collection name**     | `data-bookworm-snippets`                                                                                                                         |
| **Record key**          | Book UUID (`Guid`, matching `books.id` in `catalogdb`)                                                                                           |
| **Indexed text fields** | Assembled string containing `Title`, `Description`, comma-separated `Authors` (ordered by `author.name, author.id`), `Category`, and `Publisher` |
| **Excluded fields**     | Cover image URN, prices, stock status, and rating summaries (always filtered and returned from `catalogdb`)                                      |
| **Vector similarity**   | `1,536`-dimension float embedding using cosine similarity (generated by Microsoft Foundry `Cohere.EmbedV40`)                                     |

The Qdrant collection is `data-bookworm-snippets`. `TextSnippet` uses Cohere Embed v4's 1,536-dimensional cosine-similarity vectors.

### Assembled text format

`VectorBatchProcessor.ReadBatchAsync` builds each searchable document from `catalogdb`:

<CodeGroup>

```text
Title: <book.name>
Description: <book.description>
Authors: <author_1, author_2>
Category: <category.name>
Publisher: <publisher.name>
```

</CodeGroup>

Where `<book.name>`, `<book.description>`, `<author_1, author_2>`, `<category.name>`, and `<publisher.name>` come from the current relational rows in `catalogdb`. Missing or soft-deleted (`is_deleted = true`) books produce a `null` content payload, which instructs `VectorBatchProcessor.IngestDataAsync` to delete the corresponding Qdrant point.

## Ingestion batching and concurrency

[[service|scheduler-dashboard]] triggers `ProcessVectorBatchFunction` every 5 minutes UTC via the unprefixed Kafka topic `scheduler.process-vector-batch` (consumer group `catalog-ingestion`).

- **Batch size:** Reads at most `200` rows per run (`BatchSize = 200`), ordered by `pending_vector_updates.updated_at, book_id`.
- **Single-writer coordination:** Acquires PostgreSQL session advisory lock `740031001` (`pg_try_advisory_lock`) before reading the queue and releases it in `finally`; concurrent invocations exit early (`return 0`).
- **Revision-safe acknowledgment:** Deletes acknowledged rows only when both `book_id` and `revision` still match the snapshot processed in the batch, preserving any concurrent mid-batch catalog edits for the next pass.
- **Incomplete-batch guard:** Throws `InvalidOperationException` without acknowledging the queue if Microsoft Foundry returns fewer embeddings than active items in the batch.

## Operational notes

- **Eventual search consistency:** Newly created or updated books appear in semantic search after the next 5-minute Scheduler tick and `catalog-ingestion` batch run.
- **Triaging stale search results:** Inspect three signals together: pending row count and age in `catalogdb.pending_vector_updates`, `ProcessVectorBatchJob` history in [[container|scheduler-database]], and Qdrant / Microsoft Foundry connectivity in OpenTelemetry traces.
- **Safe rebuildability:** Because `vectordb` is non-authoritative, you can rebuild the entire collection from `catalogdb` without risk to canonical product records.
