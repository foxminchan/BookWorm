Catalog is BookWorm's Core domain for authoritative book information, classification metadata (`Author`, `Category`, `Publisher`), pricing, and availability. It serves low-latency reads over HTTP and gRPC, stores canonical data in PostgreSQL, maintains derived Qdrant search vectors through `Catalog Ingestion`, and projects aggregate rating summaries asynchronously from Reviews events.

## Scope and constraints

- **In scope:** Book CRUD lifecycle (with soft deletion and optimistic concurrency), author/category/publisher taxonomies, cover image storage, hybrid vector search indexing, and derived book rating summaries.
- **Out of scope:** Customer shopping baskets (`Shopping`), accepted order snapshots (`Ordering`), and individual customer feedback submissions (`Reviews`).
- **Key constraints:** Catalog listing availability is not an inventory reservation held by a basket or a fulfillment guarantee owned by Ordering; price updates never rewrite already accepted orders.

### Data stores and ownership

- **PostgreSQL (`catalogdb`):** System of record for books, taxonomies, and the Wolverine transactional outbox/inbox (`wolverine` schema).
- **Azure Blob Storage (`catalog-blob`):** Authoritative object storage for uploaded book cover images.
- **Redis (`redis`):** Non-authoritative L2 FusionCache layer with Redis backplane and idempotency support.
- **Qdrant (`vectordb`):** Derived, rebuildable vector index for hybrid text and semantic search.

## Runtime view

Catalog integrates with neighboring contexts through explicit synchronous and asynchronous contracts:

- **Synchronous reads (`book.v1.BookGrpcService`):** Basket API enriches basket items, Ordering API resolves checkout prices, and MCP Tools serves conversational discovery queries (`GetBook`, `GetBooks`, `GetDashboard`, `ListBooks`, `GetBookDetails`, `ListCategories`, `ListAuthors`).
- **Asynchronous rating projection:** Catalog consumes `FeedbackCreatedIntegrationEvent` (`bookworm.{env}.rating.feedback-create`) and `FeedbackDeletedIntegrationEvent` (`bookworm.{env}.rating.feedback-delete`) to update derived `averageRating` and `totalReviews`. When a book does not exist, Catalog publishes `BookUpdatedRatingFailedIntegrationEvent` (`bookworm.{env}.catalog.book-update-rating-failed`) so Reviews compensates.
- **Scheduled vector sync:** Every 5 minutes, Scheduler publishes `ProcessVectorBatchIntegrationEvent` to unprefixed topic `scheduler.process-vector-batch`; `Catalog Ingestion` refreshes pending book embeddings in Qdrant.

### Business invariants

- Every active `Book` has a stable UUID, one `Category`, and one `Publisher`.
- A discount price cannot be negative or greater than the original price.
- Out-of-stock or soft-deleted books cannot be offered as available for new purchases.
- Catalog updates never rewrite purchase-time prices already stored on an accepted `Order`.

## Deployment and cross-cutting concerns

- **Hosting and ingress:** Catalog API runs behind the YARP API Gateway (`/catalog/{**remainder}`) with internal Container App ingress; `Catalog Ingestion` runs as an internal Azure Functions Container App with no public HTTP endpoint.
- **Security and privacy:** Microsoft Entra ID JWT authorization enforces `catalog_read` by default, `business_user` or `admin` roles with `read`/`write` scopes for catalog management, and `admin` policy for administrative endpoints. Managed identities authenticate passwordlessly to PostgreSQL, Redis, Blob Storage, and Microsoft Foundry.
- **Observability and resilience:** OpenTelemetry traces HTTP, gRPC, EF Core, and Kafka spans; Wolverine routes exhausted messages to `bookworm.{env}.catalog.dead-letter-queue`.

## Quality scenarios and known risks

| Quality attribute / risk | Scenario or exposure                                                                                                                                                                                                                                                 | Current mitigation or gap                                                                                        |
| :----------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------- |
| **Availability**         | Storefront discovery continues when Reviews or Ordering is degraded                                                                                                                                                                                                  | Catalog reads only local `catalogdb`, Redis, and Qdrant; never queries Reviews synchronously                     |
| **Eventual consistency** | New or edited books lag in semantic search up to the 5-minute batch window                                                                                                                                                                                           | `Catalog Ingestion` processes queued revisions on `scheduler.process-vector-batch`; see Vector index lag runbook |
| **Audit retention**      | Catalog persists current book price state and standard audit timestamps, but no historical price versions. Orders separately persist the purchase-time item price. Any retention requirement for backups or external audit records is not defined in the repository. | Source model and schema                                                                                          |
