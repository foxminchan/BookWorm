This reference lists the mandatory pre-merge checks, domain invariants, and verification commands for changes to **Catalog API** (`BookWorm.Catalog`) and **Catalog Ingestion** (`BookWorm.Catalog.Ingestion`). Review every affected area before merging schema, API, gRPC, caching, or messaging changes.

## Overview

| Property              | Value                                                                                                                     |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| **Owner**             | Catalog bounded context (`BookWorm.Catalog`, `BookWorm.Catalog.Ingestion`)                                                |
| **Source**            | `src/Services/Catalog/BookWorm.Catalog`, `src/Services/Catalog/BookWorm.Catalog.Ingestion`                                |
| **Protocol / format** | REST (`/api/v1/{books,authors,categories,publishers}`), gRPC (`book.v1.BookGrpcService`), Kafka (CloudEvents JSON)        |
| **Authentication**    | Microsoft Entra ID JWT (`catalog_read`, `business_user`, `admin` policies); Managed Identity RBAC for `catalog-ingestion` |

## Pre-merge review checklist

| Area                            | Required check                                                                                                                                                                                                                                                                          | Source / target to verify                                                                              |
| :------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| **HTTP & gRPC contracts**       | Prefer additive, backward-compatible changes; version breaking changes explicitly under `ApiVersions` and `book/v1/book.proto`.                                                                                                                                                         | `src/Services/Catalog/BookWorm.Catalog/Grpc/Protos/book/v1/book.proto`, Development `/openapi/v1.json` |
| **Pact & event contracts**      | Keep `FeedbackCreatedIntegrationEvent`, `FeedbackDeletedIntegrationEvent`, `BookUpdatedRatingFailedIntegrationEvent`, and `ProcessVectorBatchIntegrationEvent` backward-compatible and update Pact tests.                                                                               | `src/Services/Catalog/BookWorm.Catalog.ContractTests`, `tests/pacts/`                                  |
| **PostgreSQL schema**           | Add an EF Core migration for `catalogdb` keeping all identifiers in `snake_case` (`EFCore.NamingConventions`).                                                                                                                                                                          | `src/Services/Catalog/BookWorm.Catalog/Infrastructure/Migrations/`                                     |
| **Vector search & triggers**    | If indexed fields change, update `VectorBatchProcessor.ReadBatchAsync` searchable text and PostgreSQL triggers feeding `pending_vector_updates`, and plan a rebuild.                                                                                                                    | `src/Services/Catalog/BookWorm.Catalog.Ingestion/VectorBatchProcessor.cs`                              |
| **Redis / FusionCache keys**    | Ensure book mutations invalidate `book:{id}` and affected list/search tags; bump versioned keys (`catalog:dashboard:v1`, `catalog:categories:v1`, `catalog:authors:v1`, `catalog:publishers:v1`, `catalog:books:list:v1:*`, `catalog:books:search:v1:*`) when cached DTO shapes change. | `src/Services/Catalog/BookWorm.Catalog/CatalogCacheKeys.cs`                                            |
| **Authorization & rate limits** | Preserve Microsoft Entra ID policies (`catalog_read` default, `business_user` for catalog writes, `admin` for dashboard/privileged operations) and rate-limiting middleware on endpoints such as `GetDashboard`.                                                                        | `src/Services/Catalog/BookWorm.Catalog/`                                                               |
| **Downstream consumers**        | Verify compatibility with **Basket API** (gRPC), **Ordering API** (gRPC), **MCP Tools** (gRPC `ListBooks`, `GetBookDetails`, `ListCategories`, `ListAuthors`), and **Rating API** (Kafka feedback events).                                                                              | `src/Services/Basket/`, `src/Services/Ordering/`, `src/Services/McpTools/`, `src/Services/Rating/`     |
| **Observability**               | Keep price, availability, and book-identity mutations traceable by `BookId` in OpenTelemetry traces and structured logs.                                                                                                                                                                | `src/Aspire/BookWorm.ServiceDefaults/Extensions.cs`                                                    |

The EventCatalog docs contain checked-in Catalog `schema.sql` and `openapi-v1.yml` assets. No repository workflow that regenerates these files was found, so treat them as documentation artifacts that must be kept synchronized with schema/API changes.

## Domain invariants to verify

Every Catalog change must preserve these verified invariants (covered by `BookWorm.Catalog.UnitTests`, `BookWorm.Catalog.ContractTests`, and `BookWorm.ArchTests`):

| Invariant                              | Enforced behavior                                                                                                                                                  | Verified source                                                                                                   |
| :------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------- |
| **Discount price bounds**              | `Price.DiscountPrice` must be `>= 0` and `<= OriginalPrice`.                                                                                                       | `src/Services/Catalog/BookWorm.Catalog/Domain/AggregatesModel/BookAggregate/Price.cs`                             |
| **Soft-deleted books leave search**    | Deleting a book sets `is_deleted = true`, triggers `pending_vector_updates`, and causes `Catalog Ingestion` to delete its UUID from Qdrant (`vectordb`).           | `src/Services/Catalog/BookWorm.Catalog.Ingestion/VectorBatchProcessor.cs`                                         |
| **Taxonomy deletion rules**            | Deleting a category or publisher preserves associated books (clearing the reference); deleting an author with active books is blocked (`DeleteBehavior.Restrict`). | `src/Services/Catalog/BookWorm.Catalog/Infrastructure/EntityConfigurations/BookAuthorConfiguration.cs`            |
| **Missing-book rating compensation**   | Receiving `FeedbackCreatedIntegrationEvent` for a missing book emits `BookUpdatedRatingFailedIntegrationEvent` via Wolverine cascading return.                     | `src/Services/Catalog/BookWorm.Catalog/IntegrationEvents/EventHandlers/FeedbackCreatedIntegrationEventHandler.cs` |
| **Missing-book rating deletion no-op** | Receiving `FeedbackDeletedIntegrationEvent` for a missing book completes with no write and no compensation event.                                                  | `src/Services/Catalog/BookWorm.Catalog/IntegrationEvents/EventHandlers/FeedbackDeletedIntegrationEventHandler.cs` |

## Verification commands

Run the standard repository checks from the repository root before opening a pull request:

<CodeGroup>

```bash
mise run format
mise run build
mise run test
```

</CodeGroup>

For a targeted Catalog test run during local iteration:

<CodeGroup>

```bash
dotnet test src/Services/Catalog/BookWorm.Catalog.UnitTests
dotnet test src/Services/Catalog/BookWorm.Catalog.ContractTests
```

</CodeGroup>
