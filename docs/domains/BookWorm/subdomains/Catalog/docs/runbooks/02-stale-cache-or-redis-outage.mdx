## Symptoms

- A [[entity|book]] shows old data after an update.
- Dashboard numbers look outdated.
- Catalog read latency rises, or errors mention Redis connectivity.

## Background

[[container|catalog-cache]] is disposable. Keys: `book:{id}` (default
`Caching:Expiration`) and `catalog:dashboard:v1` (15 seconds). Book changes
remove the matching `book:{id}` entry.

## Diagnose

1. Confirm the database holds the expected value (it is the source of truth).
2. Compare with what [[query|GetBook]] returns.
3. If they differ, the entry was not invalidated: look for failed change
   handling in [[service|catalog-api]] logs.
4. If reads are slow or failing, check Redis connectivity and latency and the
   FusionCache metrics and traces.

## Recover

- **Single stale book:** delete the `book:{id}` key, or wait for expiry. The
  next read repopulates from [[container|catalog-database]].
- **Wide staleness:** flush the Catalog cache keys. This is safe; only
  temporary extra database load results.
- **Redis down:** reads fall back to the database through the cached query
  path, so expect higher latency and database load. Restore Redis, and
  scale or rate-limit the API if the database is under pressure.

## Verify

- [[query|GetBook]] returns the database value.
- Latency and database load return to baseline.

## Prevention

Never read Redis as an authority and never write catalog data there. See
[[adr|adr-004-fusioncache-redis-for-catalog-reads]].
