Use this guide when a book cover image returns HTTP `403` or `404`, or when a book has an `image` URN stored in PostgreSQL (`catalogdb`) but the cover fails to render in **Storefront** or **Backoffice**. **Catalog API** stores only an internal URN (`urn:{account}:{container}:{blobName}`) and signs short-lived, read-only SAS URLs on read (`SasExpiryHours = 1` default in `CatalogAppSettings.cs`).

## Prerequisites

- Read access to **Catalog API** logs (OpenTelemetry / Aspire Dashboard / Azure Log Analytics).
- Read access to PostgreSQL (`catalogdb`) and Azure Blob Storage (`catalog-blob`, or Azurite + Azure Storage Explorer locally).
- An authenticated Microsoft Entra ID bearer token with `business_user` or `admin` role if you need to re-upload or clear a book's cover image through **Catalog API**.

## Steps

<Steps>
<Step title="Fetch a fresh book payload to rule out an expired SAS URL">

Expired SAS URLs are the most common cause of `403` errors because `BlobService.GetFileSasUrl` issues read-only URLs valid for `SasExpiryHours` (default `1` hour, with a 5-minute clock-skew start buffer). Re-fetch the book from **Catalog API**:

<CodeGroup>

```bash
curl -sS "<gateway-url>/catalog/api/v1/books/<book-id>"
```

</CodeGroup>

Where:

- `<gateway-url>`: Base URL of **API Gateway** (for example, `https://localhost:<port>` locally or the Azure Container Apps gateway URL).
- `<book-id>`: Target book UUID.

Test the freshly returned `imageUrl` with `curl -I "<image-url>"`. If HTTP `200 OK` returns, the client cached an expired SAS URL—fix the client so it never stores SAS URLs beyond their expiry window.

</Step>
<Step title="Inspect the stored image URN in `catalogdb`">

If **Catalog API** throws `UrnException` or the fresh SAS URL still fails, inspect the stored `image` column in PostgreSQL (`catalogdb`):

<CodeGroup>

```sql
SELECT id, name, image, is_deleted
FROM books
WHERE id = '<book-id>';
```

</CodeGroup>

Where:

- `<book-id>`: Target book UUID.

Verify that `image` matches `urn:<storage-account>:catalog-blob:<blob-name>` for the current environment. `BlobService.GetBlobNameFromUrn` rejects any URN whose storage account or container name does not match the configured `BlobContainerClient`, or whose blob name contains `/`, `\`, or `..`.

</Step>
<Step title="Verify that the blob exists in Azure Blob Storage (`catalog-blob`)">

Check whether `<blob-name>` exists in the target storage account:

<CodeGroup>

```bash
az storage blob exists \
  --account-name <storage-account> \
  --container-name catalog-blob \
  --name <blob-name> \
  --auth-mode login
```

</CodeGroup>

Where:

- `<storage-account>`: Azure Storage account name configured for this environment.
- `<blob-name>`: Fourth colon-delimited segment of `books.image`.

</Step>
<Step title="Recover the missing blob or update the book through Catalog API">

Choose the recovery path matching your diagnosis:

- **Blob deleted or missing, backup available:** Restore the blob to the exact same `<storage-account>`, container `catalog-blob`, and `<blob-name>` so the existing URN works without modifying PostgreSQL.
- **Blob unrecoverable:** Upload a replacement cover (`image/jpeg`, `image/png`, or `image/webp`) or remove the image through **Backoffice** or **Catalog API** (`PUT /catalog/api/v1/books`) so `BlobService.UploadFileAsync` writes a valid new blob and updates `books.image` atomically.

> [!CAUTION]
> Do not hand-edit `books.image` in PostgreSQL unless you are executing an approved database-migration remediation (for example, after restoring a backup from another storage account). Manual edits bypass `BlobService` validation and can orphan blobs.

</Step>
</Steps>

## Verification

Re-fetch the book through **API Gateway** and confirm the returned SAS URL serves HTTP `200 OK`:

<CodeGroup>

```bash
IMAGE_URL=$(curl -sS "<gateway-url>/catalog/api/v1/books/<book-id>" | jq -r '.imageUrl')
curl -I "$IMAGE_URL"
```

</CodeGroup>

Expected output:

<CodeGroup>

```text
HTTP/2 200
content-type: image/webp
```

</CodeGroup>

## Troubleshooting

| Symptom                                                                 | Cause                                                                                                            | Fix                                                                                                                                    |
| :---------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------- |
| Image URL returns `403` (`AuthenticationFailed` / expired signature)    | Client cached a SAS URL past `SasExpiryHours` (default `1` hour)                                                 | Re-fetch the book from **Catalog API**; update the client not to persist SAS URLs                                                      |
| Image URL returns `403` immediately after generation in Azure           | Managed Identity lacks permission to request a User Delegation Key (`BlobService.GetOrRefreshUserDelegationKey`) | Verify the **Catalog API** managed identity has `Storage Blob Data Contributor` / `Storage Blob Delegator` RBAC on the storage account |
| **Catalog API** logs `UrnException` (`URN account name must match ...`) | Database was restored or migrated from another environment with a different storage account or container name    | Align the migrated blobs to the environment's storage account/container and update URNs via an approved remediation                    |
| Fresh SAS URL returns `404` (`BlobNotFound`)                            | Blob was deleted or never uploaded to `catalog-blob`                                                             | Restore the blob under the same `<blob-name>`, or upload a new image through **Catalog API**                                           |
| Upload fails with `Content type '...' is not allowed`                   | File MIME type is outside `BlobService._allowedContentTypes`                                                     | Convert the image to `image/jpeg`, `image/png`, or `image/webp` and retry                                                              |
