This reference defines the HTTP v1 API, gRPC server and client contracts, **Redis** (`redis`) storage model, validation rules, and post-checkout Kafka cleanup contracts for **Basket API** (`basket`) in the **Shopping** subdomain.

## Overview

| Property                  | Value                                                                                                                                                                                                                 |
| :------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**                 | Shopping subdomain (**Basket API**, `basket`)                                                                                                                                                                         |
| **Source**                | `src/Services/Basket/BookWorm.Basket/`                                                                                                                                                                                |
| **Persistence & caching** | **Redis** (`redis`): `IBasketRepository` (`basket:{userId}`, camelCase JSON), FusionCache, and 24-hour `IIntegrationEventIdempotencyGuard` (**no SQL database**)                                                      |
| **Protocols**             | HTTP v1 (`/api/v1/baskets`, routed via API Gateway `/basket/api/v1/baskets`), gRPC server (`basket.v1.BasketGrpcService`), gRPC client (`book.v1.BookGrpcService`), Kafka CloudEvents JSON (Wolverine)                |
| **Authentication**        | Microsoft Entra ID JWT (`customer` role + `basket_read` and `basket_write` scopes); customer identity derived strictly from the authenticated token; `PerUserRateLimit` on all HTTP endpoints; `HMAC__Key` configured |

## Integration boundary overview

Basket API serves authenticated customers through API Gateway, enriches reads via Catalog API gRPC, serves basket snapshots to Ordering API over gRPC during checkout, and processes asynchronous post-checkout cleanup from Finance over Kafka.

## HTTP API contract

All routes are versioned under `ApiVersions.V1` (`/api/v1/baskets`), require default customer authorization (`customer` role + `basket_read`/`basket_write` scopes), and apply `PerUserRateLimit`:

| Method   | Path              | Success response                          | Behavior                                                                                                 |
| :------- | :---------------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `POST`   | `/api/v1/baskets` | `201 Created` (`CustomerId` + `Location`) | Creates a customer-scoped basket (`basket:{userId}`) from one or more items                              |
| `GET`    | `/api/v1/baskets` | `200 OK` (`CustomerBasketDto`)            | Loads `basket:{userId}` (`404 Not Found` if absent) and enriches distinct book IDs via Catalog API gRPC  |
| `PUT`    | `/api/v1/baskets` | `204 No Content`                          | Loads `basket:{userId}` (`404 Not Found` if absent) and replaces the complete item collection atomically |
| `DELETE` | `/api/v1/baskets` | `204 No Content`                          | Loads `basket:{userId}` (`404 Not Found` if absent) and deletes the Redis key                            |

## Parameters and domain invariants

### Request item fields (`CreateBasketCommand`, `UpdateBasketCommand`)

| Field              | Type                  | Required | Constraints            | Description                                                                            |
| :----------------- | :-------------------- | :------- | :--------------------- | :------------------------------------------------------------------------------------- |
| `items`            | `BasketItemRequest[]` | Yes      | Non-empty collection   | Complete set of basket items; `PUT` replaces the entire collection rather than merging |
| `items[].id`       | `string` / `Guid`     | Yes      | Valid Catalog `BookId` | Book reference stored in Redis (no title or price persisted)                           |
| `items[].quantity` | `int`                 | Yes      | Greater than `0`       | Requested item count                                                                   |

### Persistence and Catalog enrichment rules

- **Key format:** `basket:{userId}` in Redis (`BasketRepository.cs`), serialized as camelCase JSON. Basket state is transient pre-order intent—out of scope for orders, payments, and fulfillment.
- **Read-time enrichment:** On `GET /api/v1/baskets`, Basket API resolves distinct book IDs through `book.v1.BookGrpcService/GetBooks` and attaches each book's current name, regular price, and sale price when available.
- **Graceful degradation on missing books:** If Catalog API has no record for a stored book ID, Basket API preserves the stored `BasketItem` and omits unavailable display fields rather than inventing values or mutating the basket during a read.

## gRPC and Kafka contracts

### gRPC contracts (`edition = "2023"`)

| Role       | Service & RPC                           | Counterpart                   | Purpose                                                                 |
| :--------- | :-------------------------------------- | :---------------------------- | :---------------------------------------------------------------------- |
| **Server** | `basket.v1.BasketGrpcService/GetBasket` | **Ordering API** (`ordering`) | Returns the customer's stored basket items during `POST /api/v1/orders` |
| **Client** | `book.v1.BookGrpcService/GetBooks`      | **Catalog API** (`catalog`)   | Enriches `GET /api/v1/baskets` with live book titles and pricing        |

### Post-checkout Kafka cleanup contracts

`PlaceOrderCommandHandler` consumes `PlaceOrderCommand` partitioned by `OrderId` and uses a 24-hour Redis `IIntegrationEventIdempotencyGuard` keyed by `command.OrderId`:

| Message                                 | Kafka topic                               | Direction            | Semantics                                                                                                                                    |
| :-------------------------------------- | :---------------------------------------- | :------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| `PlaceOrderCommand`                     | `bookworm.{env}.finance.place-order`      | Finance → Basket API | Triggers deletion of `basket:{BasketId}`; duplicate `OrderId` within 24 hours immediately returns `BasketDeletedCompleteIntegrationEvent`    |
| `BasketDeletedCompleteIntegrationEvent` | `bookworm.{env}.basket.delete-complete`   | Basket API → Finance | Emitted only when `DeleteBasketAsync` returns `true` (or on deduplicated repeat for the same `OrderId`)                                      |
| `BasketDeletedFailedIntegrationEvent`   | `bookworm.{env}.basket.delete-failed`     | Basket API → Finance | Emitted when `DeleteBasketAsync` returns `false` (key absent/not deleted); signals cleanup failure only, never payment or order failure      |
| Dead-letter queue                       | `bookworm.{env}.basket.dead-letter-queue` | Basket API → DLQ     | Captures commands that throw exceptions (releasing the `OrderId` guard) and exhaust Wolverine retries (`50ms / 250ms / 1s` with full jitter) |

## Error responses

| Status                  | Condition                                                                       | Recovery behavior                                                                              |
| :---------------------- | :------------------------------------------------------------------------------ | :--------------------------------------------------------------------------------------------- |
| `400 Bad Request`       | Empty `items` list, missing book ID, or non-positive `quantity`                 | Fix request payload; do not retry unchanged                                                    |
| `401 Unauthorized`      | Missing or invalid Microsoft Entra ID JWT                                       | Re-authenticate and retry                                                                      |
| `403 Forbidden`         | Token lacks `customer` role or `basket_read`/`basket_write` scopes              | Sign in with a customer account                                                                |
| `404 Not Found`         | `GET`, `PUT`, or `DELETE` called when `basket:{userId}` does not exist in Redis | Create a basket via `POST /api/v1/baskets`; missing baskets are never masked as empty `200 OK` |
| `429 Too Many Requests` | Caller exceeded `PerUserRateLimit`                                              | Back off for the `Retry-After` interval                                                        |

## Pre-merge change checklist

1. Update FluentValidation rules, OpenAPI v1 metadata, `basket.proto`, or Kafka contract types as applicable.
2. Preserve customer scoping from `ClaimsPrincipal`, `basket:{userId}` key format, and read purity when Catalog omits a book.
3. Verify both `BasketDeletedCompleteIntegrationEvent` and `BasketDeletedFailedIntegrationEvent` paths and `OrderId` idempotency guard release on exception.
4. Run `mise run format`, `mise run build`, and `mise run test` (verifying Pact suites `Basket-Finance` and `Finance-Basket`).
