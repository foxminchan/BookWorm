## 1. Context & Problem

When integrating a storefront or client application with the Cart System, delivery teams need concrete examples showing how a new customer basket is initialized with selected products and how the service responds when required information is missing. Without clear, tested request and response examples, client teams can misinterpret field requirements or build fragile error-handling logic.

## 2. Business Value

- **Faster client onboarding**: Gives frontend and integration teams verified patterns for creating baskets and reading back the assigned customer identifier.
- **Better user experience on errors**: Shows exactly how validation issues are reported so applications can guide customers to fix missing selections rather than displaying generic failures.

## 3. How It Works

1. **Creating a basket for selected products**: The client application gathers the customer's chosen product identifiers and quantities and submits them to start a new basket. Both a product identifier and a quantity are required for each item. When the submission is valid, the service creates the basket and returns the customer identifier associated with it.
2. **Correcting an invalid basket request**: If the submitted request omits the required item list or violates input rules, the service rejects the submission and returns a structured validation summary identifying which field failed so the caller can correct the payload before trying again.

## 4. Trade-offs & Lessons Learned

- **Upfront validation over silent defaults**: Rejecting requests that omit required item fields prevents malformed baskets from being saved, placing a small responsibility on clients to inspect validation errors and prompt corrections.
- **Defensive handling of the returned customer identifier**: Client implementations should allow for the possibility of an empty customer identifier in the creation response and validate failure outcomes explicitly before proceeding.

## 5. Technical Reference

### 1. Create a basket for selected products

Create a basket by supplying the selected product IDs and quantities. The `items` array is required; each item requires both fields.

<CodeGroup dropdown>

```sh
curl --request POST "$BASE_URL/api/v1/baskets" \
  --header "Content-Type: application/json" \
  --data '{
    "items": [
      { "id": "book-9780141182803", "quantity": 2 },
      { "id": "book-9780061120084", "quantity": 1 }
    ]
  }'
```

</CodeGroup>

The same request from TypeScript can preserve the returned customer ID:

<CodeGroup dropdown>

```ts create-basket.ts
type CreateBasketResponse = string | null;

const baseUrl = process.env.BASE_URL ?? "https://api.example.com";
const response = await fetch(`${baseUrl}/api/v1/baskets`, {
	method: "POST",
	headers: { "Content-Type": "application/json" },
	body: JSON.stringify({
		items: [
			{ id: "book-9780141182803", quantity: 2 },
			{ id: "book-9780061120084", quantity: 1 },
		],
	}),
});

if (response.status === 400) {
	throw new Error("CreateBasket validation failed");
}
if (!response.ok) {
	throw new Error(`CreateBasket failed with ${response.status}`);
}

const customerId = (await response.json()) as CreateBasketResponse;
console.log(customerId);
```

</CodeGroup>

A successful request returns `201 Created` with an `application/json` customer ID:


</CodeGroup>

### 2. Correct an invalid basket request

If the body does not satisfy the request contract, the service returns `400 Bad Request` with `application/problem+json`. Correct the failing fields before submitting the basket again.

<CodeGroup dropdown>

```json
{
	"title": "One or more validation errors occurred.",
	"status": 400,
	"errors": {
		"items": ["The items field is required."]
	}
}
```

</CodeGroup>
