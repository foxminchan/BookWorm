`BasketDeletedCompleteIntegrationEvent` (v1.0.0) signals that Basket API removed a submitted customer basket during post-checkout cleanup. Finance consumes this event to advance the order orchestration saga; it confirms basket deletion only and does not imply order completion.

## Overview

| Property                      | Value                                                                                                   |
| :---------------------------- | :------------------------------------------------------------------------------------------------------ |
| **Owner**                     | Shopping bounded context (`Basket API`)                                                                 |
| **Producer**                  | [[service\|basket-api]] (`PlaceOrderCommandHandler`)                                                    |
| **Consumer**                  | [[service\|order-orchestration]] (`OrderOrchestrator`)                                                  |
| **Source**                    | `src/Services/Basket/BookWorm.Basket/IntegrationEvents/Events/BasketDeletedCompleteIntegrationEvent.cs` |
| **Protocol / format**         | Kafka + CloudEvents JSON (Wolverine)                                                                    |
| **Kafka topic**               | `bookworm.{env}.basket.delete-complete` (where `{env}` is the kebab-case environment name)              |
| **Message identity**          | `BookWorm.Contracts.BasketDeletedCompleteIntegrationEvent`                                              |
| **Partition key**             | `OrderId` (preserves per-order saga ordering on Kafka)                                                  |
| **Persistence / idempotency** | Redis-backed 24-hour idempotency guard (`idempotency:PlaceOrderCommandHandler:{orderId}`)               |

## Error handling and delivery guarantees

| Condition                                                     | Behavior                                                                                                                                             | Recovery behavior                                                                                      |
| :------------------------------------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| Duplicate `PlaceOrderCommand` within 24 hours                 | `PlaceOrderCommandHandler` detects the Redis idempotency key for `OrderId` and re-emits `BasketDeletedCompleteIntegrationEvent` without re-deleting. | Finance handles duplicate external events idempotently within the Durable Task orchestration instance. |
| Transient broker or consumer error                            | Wolverine retries with cooldown (`50ms`, `250ms`, `1s`) and full jitter.                                                                             | After retries are exhausted, Wolverine routes the message to the consumer dead-letter queue (DLQ).     |
| Deserialization failure (`JsonException` / `FormatException`) | Routed immediately to the native Kafka DLQ without retries.                                                                                          | Inspect the payload against Pact contract `tests/pacts/Finance-Basket.json` before replaying.          |
