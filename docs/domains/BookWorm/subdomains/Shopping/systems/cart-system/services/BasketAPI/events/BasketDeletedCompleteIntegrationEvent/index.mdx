`BasketDeletedCompleteIntegrationEvent` (v1.0.0) signals that [[service|basket-api]] removed a submitted customer basket during post-checkout cleanup. [[service|order-orchestration]] consumes this event to advance the order orchestration saga; it confirms basket deletion only and does not imply order completion.

## Overview

| Property                             | Value                                                                                                                                         |
| :----------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- |
| **Bounded Context**                  | Shopping                                                                                                                                      |
| **Producer**                         | [[service\|basket-api]]                                                                                                                       |
| **Consumer(s)**                      | [[service\|order-orchestration]]                                                                                                              |
| **Protocol / Format**                | Kafka + CloudEvents JSON (camelCase payload)                                                                                                  |
| **Channel / Topic**                  | [[channel\|bookworm.&#123;env&#125;.basket.delete-complete]]                                                                                  |
| **Dead-Letter Channel**              | [[channel\|bookworm.&#123;env&#125;.basket.dead-letter-queue]]                                                                                |
| **Partition Key**                    | `OrderId`                                                                                                                                     |
| **Delivery / Idempotency Guarantee** | At-least-once delivery; producer deduplicates incoming [[command\|PlaceOrderCommand]] via Redis-backed 24-hour idempotency keyed by `OrderId` |

## Delivery Guarantees & Error Handling

| Condition                                                | System Behavior                                                                                      | Recovery / Compensation                                      |
| :------------------------------------------------------- | :--------------------------------------------------------------------------------------------------- | :----------------------------------------------------------- |
| Duplicate [[command\|PlaceOrderCommand]] within 24 hours | Producer detects the Redis idempotency key for `OrderId` and re-emits this event without re-deleting | Orchestration handles duplicate external events idempotently |
| Transient broker or consumer error                       | Retried with cooldown (`50ms`, `250ms`, `1s`) and full jitter                                        | Exhausted messages route to the consumer dead-letter queue   |
| Deserialization failure                                  | Routed immediately to the dead-letter queue without retries                                          | Inspect dead-letter payload against contract schema          |
