## 1. Context & Problem

BookWorm customers need an interactive assistant to help them discover books, interpret reviews, and understand store policies. However, giving an AI chat experience direct ownership over product listings, customer orders, shopping baskets, or persisted reviews would duplicate business rules and risk data integrity.

Conversational exists as a **Core Domain** because it delivers BookWorm's customer-facing conversational experience—not because it owns the underlying catalog items, orders, or policies discussed. It defines a clear domain language:

- A **Customer Request** is the live interaction being routed or answered; it is not an Order, Basket, or Feedback record.
- A **Handoff** transfers a conversation between specialist assistants; it is distinct from business workflows such as checkout or order fulfillment.
- Catalog remains the single source of truth for factual book details, while store-policy assistance relies strictly on supplied policy context without reading or modifying customer accounts, baskets, or orders.

## 2. Business Value

- **Focused, predictable routing**: In-scope BookWorm questions reach the right specialist, while off-topic inquiries and unsupported languages receive a brief boundary response.
- **Factually grounded book discovery**: Searches and recommendations are backed by live catalog data rather than invented product claims.
- **Safe store-policy guidance**: Customers get concise help on store services and policies, while account-specific inquiries are cleanly directed to support.
- **Built-in personal data protection**: Sensitive personal information in both customer prompts and assistant replies is screened and anonymized automatically.

## 3. How It Works

1. **Validate and route the request**: Incoming customer messages pass through initial input validation—rejected messages stop immediately without reaching specialist assistants. Accepted requests are evaluated for English language, BookWorm scope, and intent:
   - Non-English or out-of-scope messages receive a short boundary response.
   - Store policy, service, account, order, or billing questions route to [[agent|qa-agent]].
   - Review summaries or rating analyses for an already identified book route to [[agent|rating-agent]].
   - Book searches, recommendations, details, feedback, or unlinked review questions route to [[agent|book-agent]].
2. **Collaborate across specialists and parallel researchers**: [[agent|qa-agent]] can hand a support inquiry to [[agent|book-agent]] when book details are also needed, and [[agent|book-agent]] can hand review analysis to [[agent|rating-agent]] once a book is identified. For complex book inquiries, [[agent|book-agent]] can delegate concurrently to [[agent|book-catalog-researcher]] and [[agent|book-recommendation-researcher]], whereas simple lookups query catalog data directly.
3. **Protect personal information in both directions**: Every participating specialist and delegated researcher screens both incoming prompts and outgoing replies for personally identifiable information, anonymizing sensitive values before anything reaches an AI model or returns to the customer. If privacy screening fails, the request stops rather than passing unfiltered text through.
4. **Format and persist the session**: The selected assistant's reply is cleaned and formatted before delivery, and conversation state is saved across turns in session storage.

## 4. Trade-offs & Lessons Learned

- **Read-only and guidance-only boundaries**: Keeping chat tools read-only for catalog queries and excluding live Order, Basket, or account lookups protects domain ownership and authorization boundaries, even though customers needing live order changes must be directed to support.
- **Fail-closed privacy vs. service availability**: Halting a request whenever privacy screening fails guarantees sensitive data is never sent or returned unprotected, making the privacy service a hard runtime dependency.
- **Buffered streaming for output safety**: Holding generated responses until output privacy screening completes trades immediate token-by-token streaming for guaranteed filtering prior to delivery.
- **Conversation is not a system of record**: Feedback or order topics discussed in chat do not create or modify persisted Reviews, Basket, or Order records.

## 5. Technical Reference

### Context Boundaries

| Relationship                                                   | Direction          | Integration intent                                                                          |
| -------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------- |
| Customer → Conversational                                      | Inbound            | Submit a request for BookWorm assistance                                                    |
| Conversational → Catalog                                       | Read / query       | Retrieve book information through the MCP tools                                             |
| Conversational → [[system\|data-privacy]]                      | Privacy processing | Analyze and, when needed, anonymize agent input and output through [[service\|PresidioAPI]] |
| Conversational → [[domain\|ordering]] and [[domain\|shopping]] | Guidance only      | Answer general policy questions; no live Order or Basket read/write integration             |

### Chat Service Interaction & Routing

- **Endpoint & workflow**: Chat exposes an interactive AG-UI endpoint at `/ag-ui`. Accepted requests flow through input validation, `DecisionRouterExecutor`, specialist handoffs, and response formatting; rejected inputs bypass the agent handoff. Conversation session state is persisted in [[container|chat-session-blob]].
- **Decision routing**: `DecisionRouterExecutor` (backed by `ChatRoutingDecisionService` and `Microsoft-Decision-1`) evaluates `is_english`, `is_in_scope`, and `route` without invoking an LLM agent, routing to [[agent|qa-agent]], [[agent|rating-agent]], or [[agent|book-agent]].

### Catalog MCP Tools

[[agent|book-agent]], [[agent|book-catalog-researcher]], and [[agent|book-recommendation-researcher]] are granted the following read-only MCP tools querying the Catalog API (Catalog continues to own underlying book data; [[agent|qa-agent]] has no MCP tools):

| Tool              | Responsibility                            |
| ----------------- | ----------------------------------------- |
| `search_catalog`  | Find books by description or keyword      |
| `get_book`        | Retrieve full details for a known book ID |
| `list_categories` | List available book categories            |
| `list_authors`    | List available book authors               |

This list reflects the tool set assigned to Chat agents, not every capability exposed by the shared MCP server.

### Privacy Middleware

- **Registration**: All four Chat agents use [[service|PresidioAPI]] in the external [[system|data-privacy]] system. [[agent|qa-agent]] and [[agent|book-agent]] register `UsePIIMiddleware(sp)` directly; [[agent|book-catalog-researcher]] and [[agent|book-recommendation-researcher]] inherit Book Agent's middleware-wrapped chat client through `InitSubAgent`.
- **Execution**: For non-empty text, the middleware sends [[command|AnalyzeText]] over HTTP and sends [[command|AnonymizeText]] when PII is detected. It filters both input and output; streaming responses are buffered until output filtering completes. Middleware failures propagate rather than bypassing privacy processing. These are direct HTTP privacy calls, not model-selected MCP tools or brokered messages.
