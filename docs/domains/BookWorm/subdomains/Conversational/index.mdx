## Business purpose

Conversational provides BookWorm customers with an interactive assistance
service. It routes bookstore questions to a customer-support agent and book
discovery requests to catalog-backed agents, while keeping the Catalog,
Shopping, and Ordering contexts as owners of their business data.

Conversational is a **Core Domain** because it provides the customer-facing
assistance experience, not because it owns the products, orders, or policies
that agents discuss.

### Business outcomes

- BookWorm-related requests are routed to the appropriate specialist; unrelated
  requests and unsupported languages receive a brief boundary response.
- Book searches and recommendations are grounded in current Catalog results
  rather than invented product facts.
- Customers receive concise guidance about store services and policies, with
  unavailable account-specific or policy details directed to the support
  channel.
- Personal information in agent input and output is processed by the shared
  privacy middleware.

## Domain scope and language

- A **Customer Request** is the interaction being routed or answered. It is
  not an Order, Basket, or Feedback record.
- A **Handoff** transfers a request between specialist agents. It is distinct
  from a business workflow such as checkout or order fulfillment.
- The **Decision Router** (`DecisionRouterExecutor` backed by
  `ChatRoutingDecisionService` and `Microsoft-Decision-1`) evaluates language,
  scope, and target specialist without invoking an LLM agent.
- The **Book Agent** and its researchers use Catalog results for factual book
  details. Catalog remains the source of truth for book data.
- The **QA Agent** answers general store questions using the supplied policy
  context. It does not retrieve or change customer accounts, baskets, or orders.

Important boundaries:

- The current Chat MCP tool set is read-only and provides Catalog queries; it
  does not create or update Catalog or Reviews records.
- Questions that require live account, basket, or Order data are not handled by
  a live integration from this service. The QA Agent directs customers to
  support when the supplied information is insufficient.
- Customer feedback discussed in a conversation is not itself a persisted
  Reviews feedback record.

## Chat service interaction

The Chat service exposes an interactive AG-UI endpoint at `/ag-ui`. Accepted
requests pass through input validation, agent handoff, and response formatting;
rejected input bypasses the agent handoff.

1. `DecisionRouterExecutor` evaluates the accepted message via
   `Microsoft-Decision-1` (`is_english`, `is_in_scope`, and `route`).
   Non-English and out-of-scope requests short-circuit with a boundary
   response; in-scope requests route to [[agent|qa-agent]] (store policies,
   services, accounts, orders, billing), [[agent|rating-agent]] (review
   summaries or rating analysis when a book catalog ID is already present), or
   [[agent|book-agent]] (book search, recommendations, information, feedback, or
   review/rating requests without a catalog ID).
2. The QA Agent can hand a customer-service request to the Book Agent when it
   also needs book information. The Book Agent can hand off review/rating
   analysis to the Rating Agent once a book catalog ID is resolved.
3. For complex requests with independent research tasks, the Book Agent can
   delegate to the [[agent|book-catalog-researcher]] and
   [[agent|book-recommendation-researcher]] concurrently. Simple lookups use
   Catalog tools directly.
4. The selected agent's response is formatted before it is returned. The
   workflow persists conversation session state in [[container|chat-session-blob]].

## Catalog MCP tools

Book Agent and both research subagents are granted the following MCP tools.
They query the Catalog API; Catalog continues to own the underlying book data.

| Tool              | Responsibility                            |
| ----------------- | ----------------------------------------- |
| `search_catalog`  | Find books by description or keyword      |
| `get_book`        | Retrieve full details for a known book ID |
| `list_categories` | List available book categories            |
| `list_authors`    | List available book authors               |

The QA Agent has no MCP tools. The list above describes the
tool set assigned to Chat agents, not every capability exposed by the shared
MCP server.

## Context boundaries

| Relationship                                                   | Direction          | Integration intent                                                                          |
| -------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------- |
| Customer → Conversational                                      | Inbound            | Submit a request for BookWorm assistance                                                    |
| Conversational → Catalog                                       | Read / query       | Retrieve book information through the MCP tools                                             |
| Conversational → [[system\|data-privacy]]                      | Privacy processing | Analyze and, when needed, anonymize agent input and output through [[service\|PresidioAPI]] |
| Conversational → [[domain\|ordering]] and [[domain\|shopping]] | Guidance only      | Answer general policy questions; no live Order or Basket read/write integration             |

Conversational does not take ownership of another context's model. In
particular, customer-facing guidance about Orders or Baskets does not change
their state, and book information remains sourced from Catalog.

## Privacy middleware

All four Chat agents use [[service|PresidioAPI]] in the external
[[system|data-privacy]] system. QA and Book Agent register
`UsePIIMiddleware(sp)` directly; the two Book researchers inherit Book Agent's
middleware-wrapped chat client through `InitSubAgent`.

For non-empty text, the middleware sends [[command|AnalyzeText]] over HTTP and
sends [[command|AnonymizeText]] when PII is detected. It filters both input and
output; streaming responses are buffered until output filtering completes.
Middleware failures propagate rather than bypassing privacy processing. These
are HTTP privacy calls, not model-selected MCP tools or brokered messages.
