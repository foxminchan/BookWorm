## Context diagram

The Chat System accepts customer requests, uses the shared
[[system|mcp-tools]] server for Catalog-backed book data, and applies PII
processing through the external [[system|data-privacy]] system. It discovers
Rating agents through the Rating system's agent-discovery endpoint and can
call a Rating-hosted agent through A2A. Protected agent-to-agent endpoints
validate tokens using the external [[system|identity-provider]].

## Purpose and boundary

The Chat System hosts the interactive conversational workflow,
`DecisionRouterExecutor` (backed by `Microsoft-Decision-1`), and four
specialist agents: [[agent|book-agent]], [[agent|qa-agent]],
[[agent|book-catalog-researcher]], and
[[agent|book-recommendation-researcher]]. The Decision Router selects
Book Agent, QA Agent, or the Rating-hosted [[agent|rating-agent]]; the Book
Agent can delegate complex Catalog work to its two researchers.

The system provides assistance, not ownership of the business records it
discusses:

- Catalog remains authoritative for book details, categories, and authors.
- The QA Agent uses supplied store-policy information; it has no live account,
  Basket, or Order lookup or mutation tool.
- Book feedback in a conversation is not a Reviews feedback record.
- The workflow does not place Orders, modify Baskets, or publish business
  events.

## Request workflow

1. A request enters the interactive AG-UI workflow at `/ag-ui`.
2. `InputValidationExecutor` rejects empty input and detected prompt-injection
   patterns, consults the configured governance injection detector, and
   truncates messages over 2,000 characters to a 1,900-character prefix plus a
   truncation notice.
3. `DecisionRouterExecutor` evaluates `is_english`, `is_in_scope`, and `route`
   via `Microsoft-Decision-1`. Non-English and out-of-scope requests
   short-circuit with a boundary response; in-scope questions route to Book
   Agent, QA Agent, or Rating Agent (when a book catalog ID is already present).
4. The QA Agent can hand book-specific follow-up work to the Book Agent. The
   Book Agent can hand review/rating analysis to the Rating Agent once a book
   catalog ID is resolved. For complex book requests, the two research
   agents can run concurrently.
5. `ResponseFormatterExecutor` selects the last assistant response, removes
   detected system-prompt fragments, normalizes whitespace, and returns the
   formatted response. Rejected input bypasses the agent handoff.

The workflow persists conversation session state and Microsoft Foundry memory
in [[container|chat-session-blob]] (Azure Blob Storage).

## Endpoints and protocols

| Surface            | Purpose                                                                       | Access notes                                      |
| ------------------ | ----------------------------------------------------------------------------- | ------------------------------------------------- |
| `/ag-ui`           | Interactive access to the composed Chat workflow.                             | Mapped as the AG-UI server endpoint.              |
| `/agents`          | Agent discovery.                                                              | Exposes the registered agent discovery surface.   |
| `/a2a/{agentName}` | Per-agent A2A JSON-RPC and HTTP JSON endpoints for agents with an A2A server. | Both mapped HTTP endpoints require authorization. |
| gRPC A2A           | gRPC agent-to-agent access.                                                   | Mapped by the Chat host.                          |

The Chat host registers Microsoft Foundry chat (`model-router`) and decision
(`Microsoft-Decision-1`) deployments, and shares the `mcptools` MCP client
across its book agents. The client uses service discovery, Streamable HTTP
transport at `/mcp`, and token exchange. Chat's MCP client only loads the four
Catalog tools declared by Book Agent and its researchers; it does not grant
these agents every capability on the shared MCP server.

Chat connects to the Rating-hosted agent through the A2A client integration
and wires it into the Chat workflow alongside Book and QA sub-workflows
(receiving direct routes from `DecisionRouterExecutor` when a book catalog ID
is present, or handoffs from Book Agent). The A2A client supports gRPC,
JSON-RPC, and HTTP JSON bindings, preferring them in that order.

## Agent responsibilities

| Agent                                     | Responsibility                                                               | MCP access                                  |
| ----------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------- |
| [[agent\|qa-agent]]                       | Answers store policy and service questions from the supplied policy context. | None                                        |
| [[agent\|book-agent]]                     | Handles book search, detail, recommendation, and feedback conversations.     | Catalog tools and delegated research agents |
| [[agent\|book-catalog-researcher]]        | Finds Catalog-backed book, author, category, and detail facts.               | Catalog tools                               |
| [[agent\|book-recommendation-researcher]] | Finds a Catalog-backed shortlist matched to stated preferences.              | Catalog tools                               |

## Privacy and governance

QA and Book Agent register PII middleware directly. The two researchers inherit
Book Agent's wrapped chat client. For non-empty text, the middleware calls
[[service|PresidioAPI]] using [[command|AnalyzeText]] and, when PII is detected,
[[command|AnonymizeText]]. It filters input and output; streaming output is
buffered until filtering completes. Middleware failures propagate rather than
bypassing privacy processing.

The Chat host also applies per-agent governance policies. QA has no permitted
catalog tools; Book Agent and its researchers are allow-listed for their
documented Catalog tools and delegation paths.
