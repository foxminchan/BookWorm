## Purpose & Ownership Boundary

Chat Cache is the non-authoritative, multi-level caching tier owned by [[service|chat-api]] in the [[domain|conversational]] domain, scoped specifically to [[agent|qa-agent]]. It pairs FusionCache + `IDistributedCache` (`RedisCache`) for exact-match result and embedding caching with `CommunityToolkit.VectorData.Redis` (`RedisHashSetCollection`) for cosine-similarity semantic caching of standalone store-policy queries.

## Logical Data Layout & Key Patterns

| Key / Collection Pattern       | Stored Data                                                                                                          | TTL / Eviction                              | Notes                                                                               |
| :----------------------------- | :------------------------------------------------------------------------------------------------------------------- | :------------------------------------------ | :---------------------------------------------------------------------------------- |
| `BookWorm.Chat:*`              | Exact-match `DistributedCachingChatClient` and `DistributedCachingEmbeddingGenerator`                                | `30 minutes` (`Caching:Expiration` default) | Keyed by hashed prompt/options or embedding input.                                  |
| `data-bookworm-semantic-cache` | `SemanticCacheEntry` (prompt, response text, model ID, `expires_at_unix_seconds`, `1536`-dim Cohere Embed v4 vector) | `30 minutes` (`Caching:Expiration` default) | Searched via cosine similarity (`Caching:SemanticCacheSimilarityThreshold = 0.92`). |

## Consistency, Isolation & Security Guardrails

- **PII & Guardrail ordering:** `UseSemanticCache()` is registered _after_ `UsePIIMiddleware` and `UseGuardrailMiddleware` on [[agent|qa-agent]], ensuring prompt-injection checks and Presidio PII redaction run before any cache lookup or write.
- **Standalone turns only:** Semantic caching skips multi-turn histories (`User` messages > 1), `ChatRole.Tool` turns, and intermediate `FunctionCallContent` responses.
- **Agent isolation:** [[agent|book-agent]] and [[agent|rating-agent]] do not use semantic or chat result caching so personalized memory and live catalog/rating data stay fresh.

:::warning
**Shared Redis Instance:** Chat Cache shares the `redis` instance with [[container|catalog-cache]], [[container|basket-database]], [[container|order-cache]], and [[container|rating-cache]]. Never run `FLUSHALL`/`FLUSHDB` on the shared instance.
:::
