Chat session blob storage (`chatting-blob`) is the authoritative Azure Blob Storage container owned exclusively by [[service|chat-api]] in the Conversational bounded context. It persists durable AG-UI workflow conversation sessions under the `ag-ui/` blob prefix so multi-turn chat state survives container restarts without introducing a relational database or cache into Chat API.

## Overview

| Property                          | Value                                                                                                                      |
| :-------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| **Owner**                         | Conversational bounded context — [[service\|chat-api]] (`chatting`)                                                        |
| **Aspire / Azure container name** | `chatting-blob` (provisioned via `Components.Azure.Storage.BlobContainer(Services.Chatting)` on shared `storage` resource) |
| **Source**                        | `src/Services/Chat/BookWorm.Chat/Orchestration/WorkflowRegistration.cs`, `src/Aspire/BookWorm.AppHost/AppHost.cs`          |
| **Engine**                        | Azure Blob Storage (Azurite emulator locally; Azure Storage Account in cloud)                                              |
| **Blob prefix**                   | `ag-ui/` (`WithAzureBlobSessionStore`)                                                                                     |
| **Authentication**                | Managed Identity RBAC (`StorageBlobDataContributor`); public blob access disabled (`AllowBlobPublicAccess = false`)        |
| **Authoritative**                 | Yes (`readWrite`) for AG-UI conversation sessions                                                                          |
| **Classification**                | `confidential`                                                                                                             |

## Architecture and storage boundaries

Chat API is the sole service granted access to `chatting-blob`. Chat API uses **no PostgreSQL database, no Redis cache, and no Kafka broker**; durable conversational session storage is handled entirely by `WithAzureBlobSessionStore` (`Microsoft.Agents.AI.Hosting.AzureStorage`).

### Separation of conversational state stores

| State type                         | Storage location                                                                 | Owner & registration                                                           |
| :--------------------------------- | :------------------------------------------------------------------------------- | :----------------------------------------------------------------------------- |
| **AG-UI workflow sessions**        | `chatting-blob` container, prefix `ag-ui/`                                       | `WorkflowRegistration.AddChatWorkflow()` via `.WithAzureBlobSessionStore(...)` |
| **User reading preference memory** | Microsoft Foundry memory service                                                 | `BookAgentRegistration.AddBookAgent()` via `FoundryMemoryProvider`             |
| **Agent scratchpad / plan files**  | Local filesystem (`Chat:Harness:FileMemory:Root`, default `agent-files`)         | `BookAgentRegistration.AddBookAgent()` via `FileMemoryProvider`                |
| **Business domain records**        | Dedicated service stores (`catalogdb`, `basket` Redis, `orderingdb`, `ratingdb`) | Respective owning services — never stored in `chatting-blob`                   |

## Hosting and environment provisioning

AppHost provisions `chatting-blob` on the shared `storage` resource alongside `catalog-blob` and Azure Functions host storage (`src/Aspire/BookWorm.AppHost/Extensions/Infrastructure/AzureExtensions.Storage.cs`).

| Environment           | Hosting & redundancy                                                  | Security & tooling                                                             |
| :-------------------- | :-------------------------------------------------------------------- | :----------------------------------------------------------------------------- |
| **Local development** | Azurite emulator (`--disableProductStyleUrl`, persistent data volume) | Azure Storage Explorer attached in AppHost                                     |
| **Azure Development** | Azure Storage Account (`StandardLrs`, Hot tier)                       | `AllowBlobPublicAccess = false`, TLS 1.2 minimum, `StorageBlobDataContributor` |
| **Azure Staging**     | Azure Storage Account (`StandardZrs`, Hot tier)                       | `AllowBlobPublicAccess = false`, TLS 1.2 minimum, `StorageBlobDataContributor` |
| **Azure Production**  | Azure Storage Account (`StandardGzrs`, Hot tier)                      | `AllowBlobPublicAccess = false`, TLS 1.2 minimum, `StorageBlobDataContributor` |

The generated Storage template and AppHost source do not declare a lifecycle management policy for `ag-ui/` blobs. No TTL/auto-deletion is established by the repository artifacts; check for any separately managed Azure policy before relying on retention.

## Security and operational rules

- **Confidential classification:** Conversation transcripts can contain customer preferences and session context (even though Presidio PII middleware masks detected PII before model calls and outputs). Preserve `AllowBlobPublicAccess = false` and least-privilege `StorageBlobDataContributor` RBAC on `chatting` only.
- **No cross-service blob reads:** No other BookWorm service may read `chatting-blob` directly. Any cross-service interaction must flow through Chat API or agent protocols.
- **Wait-for startup order:** AppHost configures `chatApi.WithReference(chatSessionContainer).WaitFor(chatSessionContainer)`, ensuring the blob container is ready before Chat API accepts `/ag-ui` traffic.
