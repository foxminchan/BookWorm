## Purpose & Ownership Boundary

Chat Session Blob Storage (`chatting-blob`) is the authoritative Azure Blob Storage container owned exclusively by [[service|chat-api]] in the Conversational bounded context. Object storage persists durable AG-UI multi-turn conversation sessions under the `ag-ui/` prefix so chat continuity survives container restarts without introducing a relational database or Redis dependency into [[service|chat-api]].

## Logical Data Layout & Key Patterns

| Container / Prefix          | Stored Data                                          | TTL / Eviction                                                    | Invalidation / Update Trigger                           |
| :-------------------------- | :--------------------------------------------------- | :---------------------------------------------------------------- | :------------------------------------------------------ |
| `chatting-blob` / `ag-ui/*` | Serialized AG-UI workflow conversation session state | Indefinite (verify any externally managed Azure lifecycle policy) | Updated per conversation turn by [[service\|chat-api]]. |

Conversational state is intentionally split by concern: AG-UI workflow sessions live in `chatting-blob`, long-term user reading preferences live in Microsoft Foundry memory, agent scratchpads live on local ephemeral filesystem storage, and business domain records remain in their owning service stores.

## Consistency, Isolation & Security Guardrails

- **Confidential data & PII masking:** Conversation transcripts can contain customer preferences and session context even though Presidio PII middleware masks detected PII before model calls and outputs. Public blob access is disabled (`AllowBlobPublicAccess = false`), and access is restricted to [[service|chat-api]] via Managed Identity RBAC (`StorageBlobDataContributor`).
- **Startup readiness:** [[service|chat-api]] waits for `chatting-blob` health before accepting `/ag-ui` traffic.
- **No domain state leakage:** Business entities (books, baskets, orders, reviews) are never persisted in `chatting-blob`.

:::warning
**Strict Single-Service & Shared Account Isolation:** `chatting-blob` shares the Azure Storage Account with [[container|catalog-blob]] and Azure Functions host storage. No other BookWorm service or agent may read or write `chatting-blob` directly; all conversational interactions must flow through [[service|chat-api]].
:::
