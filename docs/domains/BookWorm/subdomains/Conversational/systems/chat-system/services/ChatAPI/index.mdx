Chat API (`chatting`) is the internal HTTP host in the Conversational bounded context that runs BookWorm's multi-agent `chat-workflow` over the AG-UI protocol and exposes agent discovery. It persists conversation sessions in Azure Blob Storage, uses Microsoft Foundry models and Presidio PII redaction, invokes MCP Tools for read-only catalog queries, and calls Rating API as an Agent-to-Agent (A2A) client.

## Overview

| Property                       | Value                                                                                                                                                                                 |
| :----------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Owner**                      | Conversational bounded context (`BookWorm.Chat`)                                                                                                                                      |
| **Aspire resource ID**         | `chatting`                                                                                                                                                                            |
| **Source**                     | `src/Services/Chat/BookWorm.Chat`                                                                                                                                                     |
| **Gateway path & local ports** | Gateway `/chatting/*`; local HTTP `5026`, HTTPS `7132`                                                                                                                                |
| **Protocols**                  | AG-UI (`/ag-ui`), Agent Discovery (`/agents`), MCP Streamable HTTP client (`/mcp`), A2A gRPC/JSON client → Rating API                                                                 |
| **Persistence & messaging**    | Azure Blob Storage (`chatting-blob`, `BlobNamePrefix = "ag-ui/"`) — **no PostgreSQL, no Redis, no Kafka**                                                                             |
| **AI & governance**            | Microsoft Agent Framework `1.28.0`, Microsoft Foundry (`ModelRouter`, `MicrosoftDecision1`, `Cohere.EmbedV40`), Agent Governance (`Policies/chat-agents.yaml`), Presidio PII sidecars |
| **Authentication**             | Microsoft Entra ID JWT + Entra Agent Identities (`chatAgentId`, `ratingAgentId` override) with On-Behalf-Of (OBO) token exchange and claims-based agent isolation                     |

## Runtime architecture

Chat API receives customer chat sessions from Storefront via the API Gateway, routes prompts through `Microsoft-Decision-1` and specialist agents, enforces Presidio PII screening, and stores session transcripts in Azure Blob Storage.

## Mapped HTTP endpoints

`BookWorm.Chat/Program.cs` and `Orchestration/EndpointMapping.cs` map the following surfaces:

| Route (direct)      | Gateway route              | Policy & rate limit                    | Purpose                                                                                                 |
| :------------------ | :------------------------- | :------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| `/ag-ui`            | `/chatting/ag-ui`          | `customer` policy + `PerUserRateLimit` | Interactive AG-UI streaming endpoint executing `chat-workflow` via `AGUIWorkflowAgent`                  |
| `/agents`           | `/chatting/agents`         | Service auth defaults                  | Agent discovery endpoint (`MapAgentDiscovery`)                                                          |
| `/api/v1/chats/*`   | `/chatting/api/v1/chats/*` | `ApiVersions.V1` group                 | Versioned route group (`MapEndpoints(v1, "chats")`); no REST feature endpoints are currently registered |
| `/health`, `/alive` | —                          | Development only                       | Readiness and liveness endpoints                                                                        |

:::note
Chat API does **not** host A2A server endpoints (`/a2a/{agentName}` or gRPC A2A server). It operates exclusively as an A2A _client_ communicating with [[service|rating-api]], which hosts the A2A gRPC server.
:::

## Workflow pipeline (`chat-workflow`)

1. **Input validation (`InputValidationExecutor`):** Rejects empty or suspicious prompts, runs governance prompt-safety checks (`GovernancePromptSafetyEvaluator`), and truncates oversized inputs using domain services (`PromptValidationService`, `Conversation`, `ChatTurn`).
2. **Routing and HITL disambiguation (`DecisionRouterExecutor`):** Calls `Microsoft-Decision-1` (`ChatRoutingDecisionService`) to evaluate English language and bookstore scope. Out-of-scope prompts short-circuit with a boundary response; ambiguous routes enter a human-in-the-loop (HITL) `RequestPort` disambiguation stage (`RouteDisambiguationPrepExecutor` and `RouteDisambiguationResolutionExecutor`).
3. **Specialist execution:** Routes in-scope prompts to:
   - [[agent|book-agent]] (`book`), which can enlist [[agent|book-catalog-researcher]] (`catalog-researcher`) and [[agent|book-recommendation-researcher]] (`recommendation-researcher`) using the `book-catalog` skill.
   - [[agent|qa-agent]] (`qa`), answering store-policy questions from the `store-policies` skill without MCP tools.
   - Remote [[agent|rating-agent]] (`rating`) over A2A gRPC (preferring gRPC, falling back to JSON-RPC or HTTP JSON) when review insights for a book ID are requested or handed off from Book Agent.
4. **Response formatting (`ResponseFormatterExecutor`):** Selects the final assistant reply, strips leaked system-prompt fragments, and normalizes whitespace via `ResponseFormattingService`.

## Downstream integrations and boundaries

- **MCP Tools ([[service|mcp-server]]):** `book`, `catalog-researcher`, and `recommendation-researcher` connect over Streamable HTTP (`/mcp`) with OBO token exchange and load only `search_catalog`, `get_book`, `list_categories`, and `list_authors`. `qa` loads no MCP tools.
- **Presidio PII middleware ([[service|PresidioAPI]]):** Every specialist agent runs fail-closed PII detection (`POST /analyze`) and anonymization (`POST /anonymize`) on inputs and outputs. Presidio failures propagate and abort the turn rather than bypassing privacy checks.
- **Read-only business boundary:** Chat API never places orders, modifies baskets, writes reviews, or publishes Kafka integration events.

### Error responses

| Status                  | Condition                                                                  | Recovery behavior                                       |
| :---------------------- | :------------------------------------------------------------------------- | :------------------------------------------------------ |
| `400 Bad Request`       | Empty, malformed, or policy-rejected input                                 | Revise prompt; do not retry unchanged                   |
| `401 Unauthorized`      | Missing or invalid Entra ID JWT                                            | Re-authenticate via Storefront Better Auth              |
| `403 Forbidden`         | Token lacks `customer` role or `chatting_read`/`chatting_write` scopes     | Request token with required role and scopes             |
| `429 Too Many Requests` | `PerUserRateLimit` exceeded (`Retry-After` header returned)                | Wait for `Retry-After` interval and retry               |
| `502 / 503`             | Upstream Presidio, Microsoft Foundry, MCP Tools, or Rating A2A unavailable | Retry with backoff; check fail-closed dependency health |
