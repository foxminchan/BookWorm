## Context

BookWorm needs a conversational entry point that can handle book discovery and
store-support questions without making the AI workflow the owner of Catalog,
Reviews, Basket, or Order data. Routing every customer question through one
general-purpose agent would also blur specialist responsibilities and make
tool access harder to constrain. The request path needs explicit boundaries
between deterministic validation and formatting, specialist selection, and
the business systems that own the facts being discussed.

## Decision

The Chat System composes input validation, local handoffs between the Router,
Book, and QA agents, and response formatting in the interactive AG-UI
workflow. Validation rejects empty or suspicious input and bounds long
messages before an agent handoff. Router selects Book Agent for book requests
and QA Agent for store-policy and service questions. For complex book
requests, Book Agent may delegate independent research to its specialist
researchers.

The workflow provides assistance, not business transactions. Catalog remains
the source of book facts, Reviews owns individual feedback, and Shopping and
Ordering own their respective business state. Chat agents use the approved
read capabilities available to them and do not mutate those records or make
the conversation a system of record.

## Consequences

- Routing and response handling can evolve independently from Catalog,
  Reviews, Shopping, and Ordering ownership.
- Agents must rely on owning systems and their approved interfaces for
  business facts; answers should distinguish unavailable information from
  verified facts.
- A conversational answer is not confirmation that a basket, order, review,
  or catalog record was created or changed.
- Validation, handoff, delegation, and formatting are distinct workflow
  responsibilities that must remain aligned when routing behavior changes.
- New capabilities that read or change business state require an explicit
  ownership and authorization decision; they must not be added implicitly
  through a general-purpose agent.

## Alternatives considered

### Route every request to one general-purpose agent

This would reduce orchestration structure, but combine unrelated support and
catalog responsibilities and make it harder to limit the capabilities
available to each kind of request.

### Let Chat own or mutate the business records it discusses

This could make the conversation appear self-contained, but would duplicate
domain rules and create competing sources of truth. Mutations belong behind
the owning systems' contracts and authorization boundaries.

### Allow each specialist to handle all user-facing workflow stages

This would couple input acceptance, routing, and response formatting to each
agent's instructions. Keeping those stages in the composed workflow makes
their responsibilities explicit and independent of the selected specialist.
