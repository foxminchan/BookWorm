## Purpose and scope

Chat agent orchestration routes a customer's BookWorm request to a specialist
and returns a formatted response. [[service|chat-api]] accepts the interaction
through AG-UI, validates the input, and invokes the composed workflow.
`DecisionRouterExecutor` (`Microsoft-Decision-1`) selects book discovery,
customer-support handling, or direct rating analysis; [[agent|book-agent]] can
delegate independent research before composing its answer.

This flow covers the interactive `/ag-ui` request path, agent handoffs
(including A2A handoffs to [[agent|rating-agent]]), delegated research, and
response formatting. Durable conversation domain state and business operations
such as checkout, Order cancellation, and persisted Reviews feedback are
outside its scope.

### System boundary

[[system|chat-system]] owns the composed workflow, its executors, agent
registrations, and Azure Blob Storage session store. The `/ag-ui` endpoint
invokes the complete `Workflows.Chat` workflow.

## Processing walkthrough

### 1. Invoke the workflow through AG-UI

The customer submits a request to `/ag-ui`. The host maps that endpoint with
`MapAGUIServer("/ag-ui", ...)`. The registered workflow is exposed as an AI
agent and uses an Azure Blob Storage session store (`ag-ui/` prefix).

This entry point is distinct from agent discovery at `/agents` and the
per-agent `/a2a/{agentName}` endpoints. Calling an individual agent through
A2A does not execute this composed workflow.

### 2. Validate input

`InputValidationExecutor` trims the message, then checks for empty input,
suspicious prompt-injection patterns, and an injection finding from the
configured governance detector. These checks occur before length truncation.

| Condition                                                        | Result                                                            |
| ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| Input is empty after trimming                                    | Reject with a request for more details.                           |
| A suspicious pattern or governance injection finding is detected | Reject with a rephrasing or security-policy response.             |
| Accepted input exceeds 2,000 characters                          | Retain a 1,900-character prefix and append the truncation notice. |
| Accepted input is within the length limit                        | Forward the trimmed text as a user message.                       |

`AcceptedInputExtractor` forwards the accepted message to the handoff workflow.
`RejectedOutputExtractor` returns rejection text directly, without invoking
the agents or response formatter.

### 3. Route the request

`DecisionRouterExecutor` delegates to `ChatRoutingDecisionService`
(`Microsoft-Decision-1`) to evaluate `is_english`, `is_in_scope`, and `route`
with a `0.5` probability threshold before entering a specialist sub-workflow.

| Decision outcome                                                                       | Route or response                                      |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `is_english` < 0.5 (`NonEnglish`)                                                      | Short-circuit with an English-only message.            |
| `is_in_scope` < 0.5 (`OutOfScope`)                                                     | Short-circuit with a brief boundary response.          |
| Store policies, services, accounts, orders, or billing (`QA`)                          | Route to [[agent\|qa-agent]] sub-workflow.             |
| Book search, recommendations, info, feedback, or reviews without a catalog ID (`Book`) | Route to [[agent\|book-agent]] sub-workflow.           |
| Review summaries or rating analysis with a book catalog ID already present (`Rating`)  | Route to [[agent\|rating-agent]] sub-workflow via A2A. |

QA uses the supplied `store-policies` context. It states when information is
unavailable and directs the customer to support instead of inventing policy
or account details. If the request also needs book information, QA can hand
it to Book Agent.

### 4. Handle the book request

Book Agent handles straightforward requests directly and may ask for missing
preferences. For complex requests with independent book research and
recommendation work, it delegates to both researchers concurrently. Their
findings return to Book Agent for synthesis and deduplication.

In Plan Mode, Book Agent presents a plan and waits for customer approval
before multi-step research. After approval, it switches to Execute Mode.
Simple requests do not require that approval cycle.

### 5. Format and return the response

The handoff workflow returns its messages to `ResponseFormatterExecutor`.
The formatter selects the last assistant message, trims whitespace, removes
detected system-prompt fragments, ensures sentence-ending punctuation, and
reduces runs of three or more newlines to two.

If no usable assistant text remains, the formatter returns a rephrasing prompt.

## Behavior notes

- **Validation and routing are different gates.** Passing input checks does
  not establish BookWorm relevance or English-language support.
- **Handoffs and delegated research are different.** Book, QA, and Rating
  participate in specialist sub-workflows (QA can hand off to Book; Book can
  hand off to Rating); the researchers are invoked by Book Agent for parallel
  work.
- **Do not invent book details.** Responses should distinguish known facts
  from information that is unavailable.
- **Session state is persisted in Azure Blob Storage.** AG-UI workflow sessions
  use the configured Blob Storage session store under the `ag-ui/` prefix.
- **Parallel research is not a delivery guarantee.** Both branches are shown
  as concurrent work, not as a fixed retry budget or response-time SLA.

## Outcomes and recovery

| Outcome                                   | Behavior                                                                      | Operational interpretation                                                 |
| ----------------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Input rejected                            | Rejection text returns without agent invocation or response formatting.       | Check validation findings before investigating routing.                    |
| Unsupported language or unrelated request | `DecisionRouterExecutor` short-circuits to `DecisionRejectedOutputExtractor`. | Distinguish an intentional decision-routing boundary from input rejection. |
| Direct book response or clarification     | Book Agent responds without delegated research.                               | A direct response is a valid outcome.                                      |
| Parallel research completes               | Both researcher results return to Book Agent for synthesis.                   | Check both branches before diagnosing an incomplete answer.                |
| Policy or account details are unavailable | QA states the limitation and directs the customer to support.                 | This flow has no live account, Basket, or Order lookup.                    |
| No usable assistant text remains          | The formatter returns its rephrasing prompt.                                  | Inspect the handoff message list and formatting outcome.                   |

## Operational checks

When a conversation appears incomplete or routes unexpectedly:

1. Confirm that the client invoked `/ag-ui` and the composed Chat workflow,
   not an individual agent's A2A endpoint.
2. Check whether input was rejected, truncated, or passed to `DecisionRouterExecutor`.
3. Inspect the selected route and the specialist context available to it.
4. For delegated work, check the current agent mode, any required approval,
   both researcher results, and Book Agent's synthesis.
5. Check the last assistant message and final formatting separately. Verify
   Azure Blob Storage session persistence under `ag-ui/` if session continuity
   across turns fails.
