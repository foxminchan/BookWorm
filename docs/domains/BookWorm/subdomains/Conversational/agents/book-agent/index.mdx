## Role & Autonomy Boundary

Book Agent is the primary conversational book discovery and recommendation specialist hosted in [[service|chat-api]]. It is triggered when the intent router inside [[flow|agent-orchestration]] classifies an authenticated customer chat turn as a book discovery, catalog lookup, or recommendation request, or when [[agent|qa-agent]] hands off a book-specific follow-up.

Book Agent operates strictly within a **read-only discovery boundary**: it must never place orders, mutate baskets, publish or edit reviews, bypass caller authorization, or invent unverified catalog facts such as prices, availability, or ratings.

## Data, Messaging & Handoff Boundaries

- **Data Stores:** Book Agent does not read or write relational or document domain databases directly. Durable conversation transcripts are managed by [[service|chat-api]] in [[container|chat-session-blob]], while user reading preferences and scratchpad planning files remain isolated from business domain stores.
- **Messages:** Every input prompt and buffered streaming output is screened via [[service|presidio-api]] using [[command|AnalyzeText]] and [[command|AnonymizeText]].
- **Delegation & Handoffs:** Complex multi-constraint queries fan out in parallel to [[agent|book-catalog-researcher]] and [[agent|book-recommendation-researcher]]. Review quality questions hand off over A2A gRPC to [[agent|rating-agent]], and operational support questions hand off in-process to [[agent|qa-agent]].

<Steps>
<Step title="Receive routed turn and client context">

The orchestrator validates the prompt, injects live storefront context, and filters candidate tools using the decision model before invoking Book Agent.

</Step>
<Step title="Delegate parallel research when needed">

For multi-part queries, Book Agent delegates factual verification to [[agent|book-catalog-researcher]] and preference matching to [[agent|book-recommendation-researcher]] concurrently.

</Step>
<Step title="Synthesize grounded response or hand off">

Book Agent merges verified catalog identifiers into structured storefront UI cards or Markdown, or hands off to [[agent|rating-agent]] or [[agent|qa-agent]] when the intent crosses specialist boundaries.

</Step>
</Steps>

## Safety, Privacy & AI Governance

- **Fail-Closed PII Redaction:** Input and buffered streaming output pass through [[service|presidio-api]] (`AnalyzeText` followed by `AnonymizeText`, replacing detected entities with `<PII>`). Any screening failure aborts the turn.
- **Default-Deny Tool Governance:** Only explicitly allow-listed tools for Book Agent's workload identity can execute; unapproved tools and cross-domain mutations are blocked by policy.
- **Conversation Guardian & Loop Protection:** Enforces a maximum of `30` conversation turns, caps retry cycles at `3`, and screens for multi-turn prompt injection and escalating or offensive rhetoric.
- **Context Compaction & Observability:** Applies full conversation compaction before model context limits are reached and emits OpenTelemetry traces correlated to the caller's session.

<Admonition type="warning">
	Book Agent must never claim a book is in stock, quote unverified prices, or fabricate ratings. All
	product claims must originate from live [[service|mcp-server]] responses, and review quality
	analysis must be handed off to [[agent|rating-agent]] only after resolving a single exact book ID.
</Admonition>

<Accordion title="Fallback Behavior & Evaluation Criteria">

- **Absent UI Tools:** When storefront interactive card tools are not advertised in the client context, Book Agent falls back to structured Markdown links and summaries.
- **Ambiguous Intent:** Low-confidence routing pauses for human-in-the-loop disambiguation before Book Agent is invoked.
- **Evaluation:** Verified against deterministic tool allow/deny tests, adversarial multi-turn prompt-injection suites, and Presidio fail-closed fault injection.

</Accordion>
