## 1. Context & Problem

Shoppers frequently have questions about bookstore operations—such as shipping timelines, return eligibility, billing rules, account access, or general store services. Sending those operational questions through a book discovery assistant mixes policy guidance with product search, while allowing an AI assistant to guess missing policy rules or modify order records introduces serious customer-service and compliance risks.

The QA Agent addresses this by serving as BookWorm's dedicated, read-only support specialist grounded strictly in supplied store-policy guidance.

## 2. Business Value

- **Consistent customer-support answers:** Customers receive clear, uniform guidance on shipping, delivery, returns, refunds, accounts, orders, billing, and bookstore services.
- **Safe, read-only boundary:** Because the agent cannot change business records, it eliminates the risk of unintended account, basket, or order modifications during chat.
- **Honest handling of missing information:** When policy details are unavailable, the agent states that gap clearly rather than fabricating promises.
- **Automatic privacy protection:** Customer questions and support replies are screened and redacted for personal information before reaching the AI model or the user.

## 3. How It Works

The QA Agent handles store-policy and customer-support questions in a controlled, read-only flow:

1. **Privacy screening:** Every non-empty customer message and assistant reply passes through automated privacy filtering that detects and masks sensitive personal information. If privacy filtering fails, processing stops safely rather than bypassing protection.
2. **Policy-grounded answers:** Using the store-policy information provided to it, the agent answers questions about delivery, returns, accounts, orders, billing, and store services without altering any business records.
3. **Clear boundary disclosure:** When requested details are not covered by the supplied policy information, the agent explicitly informs the customer that those details are unavailable.
4. **Specialist handoff for books:** If a support conversation shifts to book discovery, recommendations, or book-specific questions, the QA Agent hands the request to [[agent|book-agent]].

## 4. Trade-offs & Lessons Learned

- **Static policy context vs. live order integration:** Keeping the QA Agent read-only with no direct tools to look up or edit customer accounts and orders dramatically lowers security and operational risk, while meaning order-specific inquiries cannot be resolved directly in chat.
- **Focused response budget:** Limiting output length and using moderate reasoning keeps answers concise and faithful to official policy wording.
- **Fail-closed, buffered privacy checks:** Holding streaming output until personal data screening finishes prevents accidental disclosure of sensitive information typed during support chats, trading minor response latency for strong privacy compliance.

## 5. Technical Reference

### Agent Configuration & Context

- **Skill context:** Receives the `store-policies` skill as context.
- **Handoffs:** Book-specific requests are handed to [[agent|book-agent]].
- **Inherited model provider:** The runtime uses the shared chat client; the agent definition does not specify a provider or model (catalog metadata lists `Microsoft` `model-router`, version `2025-11-18`).

### Privacy Middleware

- The chat client registers `UsePIIMiddleware(sp)`.
- Calls [[service|PresidioAPI]] through [[command|AnalyzeText]] for non-empty text and [[command|AnonymizeText]] when PII is detected, replacing detected values with `<PII>`.
- Filters input and output text, buffering streaming responses before filtering and emitting them; failures propagate rather than bypassing privacy processing.
- These are middleware HTTP calls, not model-selected tools or brokered messages.

### Runtime Settings

- **Temperature:** `0.5`
- **Maximum output:** `1,000` tokens
- **Reasoning effort:** `medium`
