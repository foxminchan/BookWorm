## Trigger / Symptom & Blast Radius

A [[agent|book-agent]] answer in [[service|chat-api]] drops stated preferences, returns only facts or only a shortlist, repeats titles, or makes unsupported claims. Blast radius is limited to conversational book discovery quality; [[service|catalog-api]] and checkout remain unaffected.

<Admonition type="danger">
	Never paste raw customer prompts, names, email addresses, or order details into incident tickets.
	Keep escalation data sanitized to the same PII-redacted level enforced by
	[[service|presidio-api]].
</Admonition>

## Pre-Flight Check

Stream recent logs for [[service|chat-api]] and [[service|mcp-server]] in `<ENV>`:

```bash
az containerapp logs show --name <SERVICE_NAME> --resource-group <RESOURCE_GROUP> --tail 200
```

## Quick Recovery Procedure

<Steps>
<Step title="Confirm whether handling was direct, planned, or delegated">

Inspect the trace for [[agent|book-agent]]:

**No delegate calls:** Simple lookups intentionally bypass sub-agent delegation.

**Plan Mode active:** If the agent presented a plan without switching to Execute Mode, it is waiting for customer approval (not stalled).

**Delegated calls present:** Verify both [[agent|book-catalog-researcher]] and [[agent|book-recommendation-researcher]] completed with findings.

</Step>
<Step title="Check for governance denials">

Governance uses default-deny rules and returns `Blocked by governance policy: <reason>` as a tool result when an agent calls an unpermitted tool or delegate. Verify the agent's allowlist covers the required catalog tools or researcher delegations.

</Step>
<Step title="Verify MCP Tools and Catalog API health">

Follow `search_catalog` and `get_book` spans from [[service|chat-api]] to [[service|mcp-server]] and [[service|catalog-api]] over gRPC. Check for `401`/`403` scope errors (`mcptools_read`), gRPC errors, or stale [[container|catalog-vector]] search results.

</Step>
</Steps>

## Verification

Replay an equivalent sanitized multi-criteria request and confirm both researcher spans complete and return grounded findings:

```text
1. Decision router -> Book
2. Book Agent -> delegate_book_catalog_researcher + delegate_book_recommendation_researcher
3. Both researcher spans complete with catalog IDs
4. Response formatter returns non-fallback grounded text
```

## Rollback / Escalation

- **Rollback:** If a recent agent prompt or governance policy change caused denials or ungrounded claims, revert the [[service|chat-api]] revision in `<RESOURCE_GROUP>`.
- **Escalation:** Escalate prompt grounding defects or missing researcher merges to [[team|ai-capabilities-team]]; escalate Entra ID scope or Foundry issues to [[team|platform-engineering-team]].

<AccordionGroup>
<Accordion title="Troubleshooting edge cases">

| Symptom                              | Cause                                       | Fix                                                                     |
| :----------------------------------- | :------------------------------------------ | :---------------------------------------------------------------------- |
| Plan presented, nothing happens      | Waiting for customer approval in Plan Mode  | Ask customer to approve the plan to enter Execute Mode                  |
| `search_catalog` returns `401`/`403` | Token lacks `mcptools_read` scope           | Verify Entra ID app registration and scopes for [[service\|mcp-server]] |
| Known title missing from search      | [[container\|catalog-vector]] lag           | Follow the Catalog vector index lag runbook                             |
| Earlier research findings lost       | Container-local file memory lost on restart | Expected after restart; ask customer to re-confirm criteria             |

</Accordion>
</AccordionGroup>
