BookWorm Chat API (`chatting`) routes every interactive `/ag-ui` message through a deterministic three-layer Microsoft Agent Framework workflow (`chat-workflow`) instead of an open-ended LLM router. The pipeline validates and truncates input first, evaluates safety, language, scope, and specialist intent with `Microsoft-Decision-1`, pauses for human-in-the-loop (HITL) disambiguation when confidence is low, and coordinates bounded handoffs across Book Agent, QA Agent, and Rating Agent.

## Context and motivation

Customer chat messages span distinct domains—book discovery, store policies, and review analysis—alongside empty, non-English, off-topic, or prompt-injection inputs. Sending unscreened messages straight to a general LLM router wastes inference budget, increases latency, and makes routing behavior nondeterministic.

By separating deterministic input hygiene (`InputValidationExecutor`), calibrated classification (`Microsoft-Decision-1` via `DecisionRouterExecutor`), explicit low-confidence confirmation (`RouteDisambiguationPort`), and scoped specialist sub-workflows, BookWorm rejects invalid traffic early and keeps routing observable and testable.

### Layer 1: Input validation and resume normalization

1. **Disambiguation resume normalization:** `AGUIWorkflowAgent.NormalizeDisambiguationResume` inspects trailing user messages. If an unanswered `disambiguateRoute` tool call exists and the user replies in plain text (`1`/`book`, `2`/`qa`/`support`/`policy`/`policies`, `3`/`rating`/`review`), `AGUIWorkflowAgent` converts the reply into a `FunctionResultContent` so the paused workflow resumes cleanly across both structured UI clients and plain-text clients.
2. **Validation and truncation:** `InputValidationExecutor` bypasses pure tool-result resume turns (`IsPureToolResultResumeTurn`) and empty turns (`ignoreEmptyTurns = true`). For user text turns, `PromptValidationService` trims whitespace, enforces `UserPrompt.MinLength = 1`, checks `SuspiciousPatternRegex()` (prompt-injection and XSS markers), and invokes `GovernancePromptSafetyEvaluator` (`Policies/chat-agents.yaml`). Accepted prompts longer than `UserPrompt.MaxLength` (`2000` characters) are truncated to `1900` characters with suffix `"... [Message truncated due to length]"`. Rejected messages short-circuit directly to `RejectedOutputExtractor`.

### Layer 2: `Microsoft-Decision-1` classification and HITL disambiguation

`DecisionRouterExecutor` calls `ChatRoutingDecisionService` (`IDecisionClient` backed by Microsoft Foundry deployment `decision` = `Microsoft-Decision-1`) with four structured questions evaluated in order:

| Decision check                       | Threshold / rule                                | Outcome when triggered                                                                                  |
| :----------------------------------- | :---------------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| **`is_safe`**                        | `P(is_safe) < 0.5`                              | Short-circuits via `DecisionRejectedOutputExtractor` (`RouteTarget.UnsafeInput`)                        |
| **`is_english`**                     | `P(is_english) < 0.5`                           | Short-circuits via `DecisionRejectedOutputExtractor` (`RouteTarget.NonEnglish`)                         |
| **`is_in_scope`**                    | `P(is_in_scope) < 0.5`                          | Short-circuits via `DecisionRejectedOutputExtractor` (`RouteTarget.OutOfScope`)                         |
| **`route` (`Book`, `QA`, `Rating`)** | Confidence `< 0.6` (`RouteConfidenceThreshold`) | Pauses at `RouteDisambiguationPort` (`disambiguateRoute`) presenting `book`, `qa`, and `rating` options |
| **`route` (`Book`, `QA`, `Rating`)** | Confidence `>= 0.6`                             | Forwards directly to `BookWorkflowExecutor`, `QAWorkflowExecutor`, or `RatingWorkflowExecutor`          |

If `Microsoft-Decision-1` throws `DecisionUnansweredException` with a partial response, `ChatRoutingGuardrailEvaluator.HandlePartialResponse` defaults omitted binary probabilities to `1.0` and defaults an unanswered route choice to `RouteTarget.Book` so transient partial responses degrade predictably rather than crashing the turn.

### Specialist selection and handoffs

| Customer intent                                                                                               | Initial specialist          | Follow-up handoff behavior                                                                                                                                                                    |
| :------------------------------------------------------------------------------------------------------------ | :-------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Book search, recommendations, catalog details, emotional book feedback, or review questions without a book ID | **Book Agent (`book`)**     | Hands off to `Rating Agent` (`handoff_to_rating`) once a single book UUID/GUID is resolved, or to `QA Agent` (`handoff_to_qa`) for store-policy follow-ups                                    |
| Store policies, shipping, returns, refunds, accounts, orders, or billing                                      | **QA Agent (`qa`)**         | Hands off book-specific portions of mixed requests to `Book Agent` (`handoff_to_book`), which can continue to `Rating Agent` or back to `QA Agent`; never claims live account or order lookup |
| Review summaries or rating/quality analysis when a book catalog ID (UUID/GUID) is already present             | **Rating Agent (`rating`)** | Calls Rating API over A2A gRPC; terminal specialist (cannot search the catalog or hand back)                                                                                                  |

### Layer 3: Response formatting

`ResponseFormatterExecutor` selects the last `ChatRole.Assistant` message. If the message carries empty text plus a `FunctionCallContent` (such as a pending Storefront AG-UI UI tool call), it returns `string.Empty` without overwriting the tool call. Otherwise `ResponseFormattingService` strips leaked system prompt markers (`SystemPromptLeakRegex`), collapses excessive blank lines, ensures terminal punctuation, and returns `AssistantResponse.DefaultFallbackMessage` if no usable text remains.

## Design trade-offs

| Decision                                                                    | Benefits                                                                                                                        | Costs and limits                                                                                                                       |
| :-------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------- |
| **Use `Microsoft-Decision-1` instead of an LLM router agent**               | Produces calibrated probabilities (`0.5` guardrails, `0.6` disambiguation) at lower latency and cost than full chat completions | Requires maintaining explicit binary/choice questions and probability thresholds as scope evolves                                      |
| **Separate Layer 1 deterministic validation from Layer 2 semantic routing** | Blocks empty messages, regex/governance injections, and oversized payloads before any model call occurs                         | Truncating prompts over `2000` characters to `1900` characters can clip a trailing book UUID or intent in unusually long user messages |
| **Pause at `RouteDisambiguationPort` when route confidence `< 0.6`**        | Prevents misrouting ambiguous requests to the wrong specialist                                                                  | Adds one interactive turn before answering ambiguous prompts                                                                           |
| **Keep `Rating Agent` terminal and ID-gated**                               | Avoids duplicating MCP catalog search inside Rating API                                                                         | Title-only review requests always route through `Book Agent` first before handing off to `Rating Agent`                                |

## Alternatives considered

- **Single LLM supervisor/router agent:** Rejected because free-form LLM routing lacks calibrated probability distributions for a deterministic `< 0.6` HITL threshold and increases per-turn latency and token usage.
- **Letting each specialist self-reject out-of-scope or non-English turns:** Rejected because duplicating safety, language, and scope prompts across three specialists increases drift and wastes specialist/tool invocations on rejected inputs.
