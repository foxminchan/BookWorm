## 1. Context & Problem

Customers use BookWorm's conversational experience for very different purposes—discovering books, asking about store policies or orders, checking ratings, or even sending off-topic or non-English messages. Routing every message directly to a single generalist or an unscreened specialist wastes effort, degrades answer quality, and fails when a request spans multiple domains or lacks a specific book identifier.

## 2. Business Value

- **Higher response relevance**: Directs each customer inquiry to the specialist best equipped to answer it.
- **Early protection and clarity**: Screens out empty, suspicious, non-English, or out-of-scope inputs before deeper processing occurs.
- **Seamless handling of complex questions**: Enables specialists to collaborate on multi-part questions while clearly communicating account-lookup limitations.

## 3. How It Works

Every incoming customer message passes through a structured screening and routing pipeline before a specialist responds:

1. **Initial Input Screening**: Empty or suspicious messages can be rejected right away, and accepted messages that exceed the maximum allowed length are shortened before moving forward.
2. **Language and Scope Check**: A dedicated routing check verifies whether the message is written in English and falls within BookWorm's domain. Non-English messages receive a prompt asking the customer to resend in English; unrelated requests receive a brief boundary response.
3. **Specialist Selection**: Valid, in-scope English requests are directed to the appropriate specialist:
   - **Book discovery and general book feedback**: Handles book searches, recommendations, general book information, conversational feedback, or review questions that do not include a specific book identifier.
   - **Store and customer support**: Handles store policies, services, accounts, orders, and billing guidance.
   - **Ratings and reviews analysis**: Handles review summaries and rating analysis when a specific book identifier is already available.
4. **Handoffs and Mixed Requests**: Specialists collaborate when a question spans domains. The store support specialist can hand book-specific follow-up work to the book discovery specialist, and the book discovery specialist can hand off review or rating analysis to the rating specialist once it resolves the book's identifier. For mixed requests, the workflow handles the supported portions clearly—without implying it has checked a live customer account, basket, or order—and directs the customer to support when required details are unavailable.

## 4. Trade-offs & Lessons Learned

- **Separating input hygiene from semantic routing**: Keeping basic message screening separate from language and scope classification allows safety limits to be adjusted independently of routing models, at the cost of an additional decision step.
- **Identifier-gated rating analysis**: Requiring a resolved book identifier before invoking the rating specialist prevents failed lookups, though title-only rating requests must pass through book discovery first.
- **Explicit limits on live account data**: Refusing to imply live account, basket, or order lookups in mixed requests prevents false reassurance, even when customers expect end-to-end self-service.

## 5. Technical Reference

### Ingress and validation

- Requests enter the composed workflow through `/ag-ui`.
- Input validation runs before agent routing: empty or detected suspicious input can be rejected, and accepted messages over the configured length limit are shortened before processing.
- After validation, `DecisionRouterExecutor` (`ChatRoutingDecisionService` backed by `Microsoft-Decision-1`) checks whether the request is in English (`is_english`) and within BookWorm's scope (`is_in_scope`). These are decision-model routing checks, separate from input validation.

### Specialist routing matrix

| Customer intent                                                                    | Route                                    |
| ---------------------------------------------------------------------------------- | ---------------------------------------- |
| Book search, recommendations, book information, feedback, or reviews without an ID | [[agent\|book-agent]]                    |
| Store policies, services, accounts, orders, or billing                             | [[agent\|qa-agent]]                      |
| Review summaries or rating analysis when a book catalog ID (UUID/GUID) is present  | [[agent\|rating-agent]]                  |
| Request unrelated to BookWorm                                                      | Return a brief boundary response         |
| Request is not in English                                                          | Ask the customer to resend it in English |

### Handoffs and full request path

- `QA Agent` can hand book-specific follow-up work to `Book Agent`.
- `Book Agent` can hand off review or rating requests to `Rating Agent` once it resolves the book's catalog ID.
- Mixed or unsupported requests route based on work that can be handled without implying a live account, Basket, or Order lookup; direct the customer to support when supplied information is insufficient.
