This reference specifies the runtime architecture, workflow stages, session persistence tiers, security controls, and bounded-context boundaries of BookWorm Chat API (`chatting`). Use it to verify where Conversational responsibilities start and end relative to Catalog, Shopping, Ordering, and Reviews.

## Overview

| Property                      | Value                                                                                                                                                                                                                                                    |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**                     | Conversational subdomain (`BookWorm.Chat` + `BookWorm.McpTools`)                                                                                                                                                                                         |
| **Source**                    | `src/Services/Chat/BookWorm.Chat/`, `src/Services/McpTools/BookWorm.McpTools/`                                                                                                                                                                           |
| **Ingress and ports**         | API Gateway `/chatting/{**remainder}` → `chatting` (local HTTP `5026`, HTTPS `7132`); interactive endpoint `/ag-ui`, discovery `/agents`                                                                                                                 |
| **Orchestration framework**   | Microsoft Agent Framework (`chat-workflow`) with `Microsoft-Decision-1` routing                                                                                                                                                                          |
| **Authentication and limits** | Microsoft Entra ID JWT (`customer` role + `chatting_read`, `chatting_write` scopes); Entra Agent Identities (`chatAgentId`, `ratingAgentId`); `PerUserRateLimit`                                                                                         |
| **Backing infrastructure**    | Azure Blob Storage (`chatting-blob`, prefix `ag-ui/`), Microsoft Foundry (`chat`, `decision`, memory), Presidio (`presidio-analyzer`, `presidio-anonymizer`), MCP Tools (`mcptools`), Rating API (`rating` A2A gRPC). No PostgreSQL, no Redis, no Kafka. |

## Workflow stages and executors

Chat API composes `chat-workflow` (`WorkflowRegistration.cs`) into three layers with an interactive human-in-the-loop (HITL) pause port and terminal short-circuit extractors.

| Layer        | Stage / executor            | Implementation                                                                                                              | Responsibility                                                                                                                                                                                                                                                   |
| :----------- | :-------------------------- | :-------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Wrapper**  | AG-UI workflow adapter      | `AGUIWorkflowAgent`                                                                                                         | Pushes `AGUIRunContext` and runs `NormalizeDisambiguationResume` to convert plain-text specialist picks into `FunctionResultContent` for unanswered `disambiguateRoute` interrupts                                                                               |
| **Layer 1**  | Input validation            | `InputValidationExecutor`, `PromptValidationService`, `GovernancePromptSafetyEvaluator`                                     | Skips pure tool-result resume turns and empty turns; enforces `UserPrompt.MinLength = 1`, truncates prompts `> 2000` chars to `1900` chars + `"... [Message truncated due to length]"`, and rejects regex/governance prompt-injection patterns                   |
| **Layer 2a** | Decision router             | `DecisionRouterExecutor`, `ChatRoutingDecisionService`, `ChatRoutingGuardrailEvaluator`                                     | Calls `Microsoft-Decision-1` (`IDecisionClient`) for `is_safe`, `is_english`, `is_in_scope` (each rejected if `< 0.5`), and `route` (`Book`, `QA`, `Rating`); routes low-confidence in-scope turns (`< 0.6`) to disambiguation                                   |
| **Layer 2b** | Route disambiguation (HITL) | `RouteDisambiguationPrepExecutor`, `RouteDisambiguationPort` (`disambiguateRoute`), `RouteDisambiguationResolutionExecutor` | Pauses execution with three options (`book`, `qa`, `rating`) when in-scope route confidence is `< 0.6`, then resumes directly to the selected specialist with confidence `1.0`                                                                                   |
| **Layer 2c** | Book sub-workflow           | `BookWorkflowExecutor` (`book` + `book-catalog-researcher`, `book-recommendation-researcher`)                               | Handles catalog search, recommendations, inline emotional book feedback (no separate Sentiment Agent), Plan/Execute research, and Storefront AG-UI UI tools; can hand off to `rating` or `qa`                                                                    |
| **Layer 2c** | QA sub-workflow             | `QAWorkflowExecutor` (`qa`)                                                                                                 | Answers store-policy and support inquiries strictly from `Skills/store-policies/`; can hand off book-specific portions to `book` (which may then hand off to `rating` or back to `qa`)                                                                           |
| **Layer 2c** | Rating sub-workflow         | `RatingWorkflowExecutor` (remote A2A `rating`)                                                                              | Invokes Rating API over A2A gRPC (`2m` client timeout + Entra Agent Identity token exchange) to summarize reviews and analyze quality signals when a book ID is known; terminal (cannot hand back)                                                               |
| **Layer 3**  | Response formatting         | `ResponseFormatterExecutor`, `ResponseFormattingService`                                                                    | Selects the last `ChatRole.Assistant` message; returns `string.Empty` for `FunctionCallContent`-only tool turns; strips leaked system prompt markers, normalizes newlines/punctuation, and returns `AssistantResponse.DefaultFallbackMessage` if no text remains |

## Specialist handoff matrix

| Starting specialist         | Allowed handoff target  | Handoff tool        | Precondition                                                                                                              |
| :-------------------------- | :---------------------- | :------------------ | :------------------------------------------------------------------------------------------------------------------------ |
| **Book Agent (`book`)**     | Rating Agent (`rating`) | `handoff_to_rating` | Exactly one book catalog ID (UUID/GUID) is resolved and stated explicitly in the handoff                                  |
| **Book Agent (`book`)**     | QA Agent (`qa`)         | `handoff_to_qa`     | Current book task is resolved and the customer asks about store policies, shipping, returns, accounts, orders, or billing |
| **QA Agent (`qa`)**         | Book Agent (`book`)     | `handoff_to_book`   | Customer-support request also requires catalog lookup or book information                                                 |
| **Rating Agent (`rating`)** | None (terminal)         | —                   | Cannot search the catalog or hand control back to `Book Agent` or `QA Agent`                                              |

## Session and memory persistence boundaries

Chat API separates conversation transcript storage, short-term research scratchpads, and cross-session reading preferences into three distinct storage tiers.

| State tier                         | Backing store                                                   | Configuration / identifier                                                                                   | Scope and durability                                                                                                                       |
| :--------------------------------- | :-------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **AG-UI conversation sessions**    | Azure Blob Storage (`Microsoft.Agents.AI.Hosting.AzureStorage`) | Container `chatting-blob`, `BlobNamePrefix = "ag-ui/"` (Azurite locally; Azure Storage Account in cloud)     | Durable across Chat API container restarts; isolated per user via `UseClaimsBasedAgentIsolation()`                                         |
| **Book Agent working file memory** | Local container filesystem (`FileSystemAgentFileStore`)         | `Chat:Harness:FileMemory:Root` (default: `AppContext.BaseDirectory/agent-files`), per-session working folder | Ephemeral scratchpad surviving context compaction (`file_memory_*` tools); lost on container restart unless backed by persistent volume    |
| **Book Agent reading preferences** | Microsoft Foundry memory (`FoundryMemoryProvider`)              | `Chat:Harness:FoundryMemory:StoreName` (default: `bookworm-book-agent-session-memories`)                     | Cross-session user preferences scoped to Microsoft Entra ID subject (`NameIdentifier` / `Oid` / `ObjectId` / `Sub`, or anonymous fallback) |

:::note
Chat API does **not** use PostgreSQL, Redis, or Kafka. All state is stored in Azure Blob Storage (`chatting-blob`), Microsoft Foundry memory, or ephemeral local scratch files.
:::

## Domain ownership boundaries

| Adjacent bounded context | Authoritative owner                                                                 | Conversational interaction rule                                                                                                                                                                                                                                                  |
| :----------------------- | :---------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Catalog**              | Catalog API (`catalog`, PostgreSQL `catalogdb`, Qdrant `vectordb`)                  | Read-only access exclusively through `mcptools` (`/mcp`) -> gRPC `BookGrpcService`; never mutates catalog data or invents missing attributes                                                                                                                                     |
| **Shopping**             | Basket API (`basket`, Redis)                                                        | Chat API backend holds no Basket API client and never mutates baskets; when running inside Storefront (`@bookworm/storefront`), `Book Agent` may invoke client-side AG-UI tools (`viewBasket`, `showBasketSummary`, `addToBasket`) that require user confirmation in the browser |
| **Ordering**             | Ordering API (`ordering`, PostgreSQL `orderingdb` + Marten) and Finance (`finance`) | Zero live account or order lookup/mutation access from Chat API; `QA Agent` provides static policy guidance from `Skills/store-policies/` and directs order-specific inquiries to customer account pages or support                                                              |
| **Reviews**              | Rating API (`rating`, Azure Cosmos DB `ratingdb`/`feedbacks`)                       | Read-only review summarization via A2A gRPC (`Rating Agent`) once a book ID is known; conversational feedback never persists `Feedback` records or mutates Catalog rating summaries                                                                                              |

## Security, privacy, and rate-limiting controls

| Control                     | Enforcement point                                     | Specification                                                                                                                                                                                                                                                              |
| :-------------------------- | :---------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Endpoint authorization**  | `EndpointMapping.cs`, `Extensions/Extensions.cs`      | `/ag-ui` requires authenticated Entra ID user with role `customer` and scopes `chatting_read` and `chatting_write`                                                                                                                                                         |
| **Rate limiting**           | `BookWorm.ServiceDefaults` (`AddRateLimiting`)        | Global chained limiter (`100` concurrent requests, `30 req/min` per IP/Host) plus named `PerUserRateLimit` token bucket (`TokenLimit = 30`, `TokensPerPeriod = 20`, `ReplenishmentPeriod = 10s`, `QueueLimit = 5`); exceeds return `429 Too Many Requests` + `Retry-After` |
| **Agent governance**        | `Policies/chat-agents.yaml` (`AddAgentGovernance`)    | Default-deny per-agent tool allowlists; explicit priority-70 `qa-agent-deny-catalog-tools`; `conversation_guardian` escalation/offensive thresholds (`max_conversation_turns: 30`, `max_retry_cycles: 3`); `multi_turn_injection_patterns`                                 |
| **PII protection**          | `UsePIIMiddleware(sp)` on `Book Agent` and `QA Agent` | Detects and anonymizes PII through internal Presidio sidecars (`presidio-analyzer`, `presidio-anonymizer`, port `3000`)                                                                                                                                                    |
| **Agent-to-agent identity** | `RatingAgentRegistration.cs`, Entra Agent Identities  | Uses `AddAgentTokenExchange(Services.Rating)` (`chatAgentId`, `ratingAgentId`) to authenticate A2A gRPC calls to Rating API (`read` policy / `rating_read` scope)                                                                                                          |

## Boundary and error responses

| Condition                                                         | Originating stage                                             | Outcome                                                                                                   |
| :---------------------------------------------------------------- | :------------------------------------------------------------ | :-------------------------------------------------------------------------------------------------------- |
| Empty or whitespace prompt                                        | `PromptValidationService`                                     | Short-circuits via `RejectedOutputExtractor` with `EmptyPromptRejectionMessage`                           |
| Prompt matches injection/XSS regex or governance safety violation | `PromptValidationService` / `GovernancePromptSafetyEvaluator` | Short-circuits via `RejectedOutputExtractor` with `SuspiciousPatternRejectionMessage` or violation reason |
| `P(is_safe) < 0.5`                                                | `ChatRoutingGuardrailEvaluator`                               | Short-circuits via `DecisionRejectedOutputExtractor` (`RouteTarget.UnsafeInput`)                          |
| `P(is_english) < 0.5`                                             | `ChatRoutingGuardrailEvaluator`                               | Short-circuits via `DecisionRejectedOutputExtractor` (`RouteTarget.NonEnglish`)                           |
| `P(is_in_scope) < 0.5`                                            | `ChatRoutingGuardrailEvaluator`                               | Short-circuits via `DecisionRejectedOutputExtractor` (`RouteTarget.OutOfScope`)                           |
| In-scope `route` confidence `< 0.6`                               | `DecisionRouterExecutor`                                      | Pauses at `RouteDisambiguationPort` (`disambiguateRoute`) for customer selection                          |
| Missing or stripped assistant text                                | `ResponseFormatterExecutor`                                   | Returns `AssistantResponse.DefaultFallbackMessage` asking customer to rephrase                            |
| Unauthorized or rate-limited HTTP call                            | ASP.NET Core middleware                                       | Returns `401 Unauthorized`, `403 Forbidden`, or `429 Too Many Requests` (`ProblemDetails`)                |
