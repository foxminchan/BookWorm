This reference defines the pre-release review checklist for changes to BookWorm Chat API (`chatting`) agents, routing policies, governance rules, skills, and workflow executors. Use this checklist during pull request reviews whenever you modify agent prompts, `Microsoft-Decision-1` routing logic, MCP Tools (`mcptools`), or Rating API Agent-to-Agent (A2A) gRPC handoffs.

## Overview

| Property              | Value                                                                                                                                        |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**             | Conversational subdomain (`BookWorm.Chat`)                                                                                                   |
| **Source**            | `src/Services/Chat/BookWorm.Chat/`                                                                                                           |
| **Protocol / format** | AG-UI (`/ag-ui`), Agent Discovery (`/agents`), MCP Streamable HTTP (`/mcp`), A2A gRPC (`rating`)                                             |
| **Authentication**    | Microsoft Entra ID JWT (`customer` role + `chatting_read`, `chatting_write` scopes); Entra Agent Identities (`chatAgentId`, `ratingAgentId`) |

## Pre-change scope and boundary checklist

Verify every boundary invariant before editing prompts, executors, or tool registrations.

- [ ] **Identify affected workflow layers:** Confirm whether the change modifies Layer 1 (`InputValidationExecutor`), Layer 2 (`DecisionRouterExecutor`, `RouteDisambiguationPort`, specialist sub-workflows, delegated researchers), or Layer 3 (`ResponseFormatterExecutor`).
- [ ] **Preserve backend domain ownership:** Keep Catalog API, Basket API, Ordering API, and Rating API as the sole authoritative owners of catalog records, baskets, orders, and persisted `Feedback` records. Do not add PostgreSQL, Redis, Kafka, or direct transactional write clients to Chat API.
- [ ] **Separate backend boundaries from Storefront AG-UI tools:** Keep any user-confirmed basket UI actions (`addToBasket`, `viewBasket`, `showBasketSummary`) strictly inside Storefront (`@bookworm/storefront`) client-side AG-UI tool handlers, not server-side mutations in Chat API.
- [ ] **Preserve grounding and uncertainty rules:** Require `Book Agent`, `book-catalog-researcher`, and `book-recommendation-researcher` to cite only MCP catalog results and state missing prices, availability, or ratings as unavailable rather than guessing.
- [ ] **Preserve QA Agent policy-only scope:** Ensure `QA Agent` answers strictly from `Skills/store-policies/` and never claims live access to customer accounts, baskets, or orders.
- [ ] **Keep sentiment inline without adding a Sentiment Agent:** Keep emotional book feedback handled inline by `Book Agent` (`book-agent.yaml`) without introducing a separate sentiment service or agent, and never imply that chat feedback created a persisted Reviews `Feedback` record.
- [ ] **Account for all three persistence and memory tiers:**
  - AG-UI conversation sessions persist in Azure Blob Storage container `chatting-blob` under prefix `ag-ui/` (Azurite locally; Azure Storage in cloud).
  - `Book Agent` file memory (`FileMemoryProvider` rooted at `Chat:Harness:FileMemory:Root`) is container-local and ephemeral across container restarts.
  - `Book Agent` reading preference memory (`FoundryMemoryProvider`, store `Chat:Harness:FoundryMemory:StoreName`) is user-scoped via Microsoft Entra ID claims.

## Governance, security, and contract checklist

:::note
`Policies/chat-agents.yaml` enforces `default_action: deny`. Any new MCP tool, skill tool, harness tool, Storefront UI tool, or handoff tool fails silently or returns a governance denial unless explicitly permitted for the calling agent DID.
:::

- [ ] **Update `Policies/chat-agents.yaml` allowlists and denylists:** Add explicit `allow` rules for any new tools under the exact agent DID (`did:mesh:bookworm:book`, `did:mesh:bookworm:book-catalog-researcher`, `did:mesh:bookworm:book-recommendation-researcher`, or `did:mesh:bookworm:qa`), and preserve `qa-agent-deny-catalog-tools` (priority 70).
- [ ] **Review `conversation_guardian` and injection rules:** Confirm `escalation_score_threshold` (`0.6`), `max_conversation_turns` (`30`), and `multi_turn_injection_patterns` still permit legitimate handoffs without false blocks.
- [ ] **Verify Presidio PII and guardrail middleware:** Keep `UsePIIMiddleware(sp)` and `UseGuardrailMiddleware()` registered in both `BookAgentRegistration.cs` and `QAAgentRegistration.cs`.
- [ ] **Verify Entra ID auth and rate limits:** Keep `/ag-ui` protected by `Authorization.Policies.Customer` (`customer` role + `chatting_read` and `chatting_write` scopes), `RequirePerUserRateLimit()`, and `UseClaimsBasedAgentIsolation()`.
- [ ] **Verify Rating Agent A2A gRPC and MCP Tools contracts:** Confirm any change to `mcptools` tool signatures (`search_catalog`, `get_book`, `list_categories`, `list_authors`) matches `book-agent.yaml`, `catalog-researcher.yaml`, and `recommendation-researcher.yaml`, and confirm `RatingAgentRegistration.cs` preserves Entra Agent Identity token exchange (`AddAgentTokenExchange(Services.Rating)`).

## Documentation synchronization checklist

Update affected documentation in the same pull request as code or prompt changes.

- [ ] Update Conversational architecture and domain boundaries reference when workflow stages, persistence tiers, security controls, or handoff edges change.
- [ ] Update How BookWorm routes customer chat requests when `PromptValidationService` bounds, `Microsoft-Decision-1` questions or thresholds (`0.5` / `0.6`), or `RouteDisambiguationPort` options change.
- [ ] Update How BookWorm handles book discovery and recommendations, How BookWorm answers store and customer-support questions, or How BookWorm handles book feedback in conversation when specialist behavior changes.
- [ ] Update operational runbooks (no usable response, unexpected routing or rejection, and incomplete book research) when diagnostic log messages, error responses, or recovery steps change.

## Verification matrix and commands

Validate every conversational path before merging.

| Verification path                            | Required test cases                                                                                                                                                                                                                                                                                      |
| :------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Input validation**                         | Empty/whitespace input (`MinLength = 1`), prompts over `2000` characters truncated to `1900` + suffix, `SuspiciousPatternRegex` blocks, `GovernancePromptSafetyEvaluator` blocks, and pure tool-result resume turns bypassed (`IsPureToolResultResumeTurn`)                                              |
| **Decision Router (`Microsoft-Decision-1`)** | `is_safe < 0.5` (`RouteTarget.UnsafeInput`), `is_english < 0.5` (`RouteTarget.NonEnglish`), `is_in_scope < 0.5` (`RouteTarget.OutOfScope`), direct routes (`Book`, `QA`, `Rating`), partial response fallback (`DecisionUnansweredException`), and `< 0.6` confidence pause at `RouteDisambiguationPort` |
| **HITL disambiguation resume**               | Both tool-result responses (`disambiguateRoute`) and plain-text replies (`1`/`book`, `2`/`qa`/`support`/`policy`, `3`/`rating`/`review`) normalized by `AGUIWorkflowAgent.NormalizeDisambiguationResume`                                                                                                 |
| **Specialist handoffs**                      | `QA -> Book` (mixed support and book), `Book -> QA` (book then policy), `Book -> Rating` (only after resolving a single book ID; ambiguous or missing titles do not hand off), and `Rating` terminal behavior                                                                                            |
| **Delegated book research**                  | Direct single-step lookup vs. concurrent `book-catalog-researcher` and `book-recommendation-researcher` synthesis with deduplication and partial-evidence transparency; Plan Mode approval pause before multi-step research                                                                              |
| **Response formatting and sessions**         | Normal reply formatting, `SystemPromptLeakRegex` stripping, `AssistantResponse.DefaultFallbackMessage` on empty text, empty-string passthrough on `FunctionCallContent`-only assistant messages, and Azure Blob Storage (`chatting-blob`, `ag-ui/`) session round-trip                                   |
