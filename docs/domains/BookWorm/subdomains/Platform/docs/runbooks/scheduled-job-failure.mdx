Use this runbook when a Quartz.NET job in **Scheduler** (`scheduler`) misses its UTC schedule, appears paused or failed in **Quartz Dashboard** (`quartz-dashboard`), or reports success while **Catalog Ingestion** (`catalog-ingestion`) makes no vector indexing progress. **Scheduler** runs only two jobs (`ProcessVectorBatchJob` and `HeartbeatJob`); email notification delivery is event-driven and not scheduled here.

## Prerequisites

- Microsoft Entra ID account with the `admin` role to sign in to **Quartz Dashboard** (`/quartz`).
- Read access to **Aspire Dashboard** (locally) or **Azure Log Analytics** (Azure Container Apps) for `scheduler` and `catalog-ingestion` logs.
- Read access to **Kafka UI** (locally) or **Confluent Cloud** for the unprefixed `scheduler.process-vector-batch` topic.
- Read-only SQL access to `catalogdb` (PostgreSQL) to inspect `pending_vector_updates` and `schedulerdb` health metrics.

## Steps

<Steps>
<Step title="Verify the Scheduler service is running">

Check `scheduler` state in Aspire Dashboard or Azure Container Apps.

> [!NOTE]
> In local Aspire runs, `scheduler` is configured with `.WithExplicitStart()` in `AppHost.cs`. Start the `scheduler` resource manually from Aspire Dashboard before expecting jobs to fire locally.

In local Development, check the liveness and readiness endpoints (Development only):

<CodeGroup>

```bash
curl -sS "https://localhost:7062/health"
```

</CodeGroup>

Expected output:

<CodeGroup>

```text
Healthy
```

</CodeGroup>

</Step>
<Step title="Inspect job state, triggers, and execution history in Quartz Dashboard">

Open **Quartz Dashboard** at `https://<quartz-dashboard-host>/quartz` (authenticate with Entra ID `admin` role) and inspect both jobs defined in `src/Services/Scheduler/BookWorm.Scheduler/jobs.json`:

- **`ProcessVectorBatchJob`** (`ProcessVectorBatchTrigger`): cron `0 0/5 * * * ?` UTC (every 5 minutes), `[DisallowConcurrentExecution]`, misfire instruction `FireOnceNow`.
- **`HeartbeatJob`** (`HeartbeatTrigger`): cron `0/30 * * * * ?` UTC (every 30 seconds), misfire instruction `FireOnceNow`.

Verify:

- Scheduler instance check-ins are current in `schedulerdb`.
- Triggers are in `NORMAL` (not `PAUSED`, `ERROR`, or `BLOCKED`) state and display a valid next fire time in UTC.
- Execution history (retained for `30` days / up to `100,000` entries in `schedulerdb`) shows recent run durations and any sanitized `JobExecutionException` details.

</Step>
<Step title="Check `schedulerdb` and Wolverine outbox publication">

If `ProcessVectorBatchJob` failed with `JobExecutionException`, inspect `scheduler` logs for PostgreSQL (`schedulerdb`) or Kafka broker connectivity errors. `ProcessVectorBatchJob` publishes `ProcessVectorBatchIntegrationEvent` through Wolverine's PostgreSQL outbox (`wolverine` schema in `schedulerdb`) to the unprefixed Kafka topic `scheduler.process-vector-batch`.

Never edit `catalogdb` rows through `schedulerdb`, and never copy connection strings or credentials into incident notes.

</Step>
<Step title="Verify downstream Catalog Ingestion progress when Scheduler succeeds">

A successful `ProcessVectorBatchJob` run confirms only that `ProcessVectorBatchIntegrationEvent` was published to Kafka—not that vectors updated in Qdrant (`vectordb`). Inspect the downstream pipeline:

- **Kafka topic:** Confirm messages arrive on `scheduler.process-vector-batch` and check lag for consumer group `catalog-ingestion`.
- **Pending queue in `catalogdb`:** Run a read-only count of pending vector updates:

  ```sql
  SELECT COUNT(*) AS pending_count, MIN(updated_at) AS oldest_updated_at
  FROM pending_vector_updates;
  ```

- **Catalog Ingestion logs (`catalog-ingestion`):** Check `ProcessVectorBatchFunction` and `VectorBatchProcessor` logs for:
  - PostgreSQL advisory lock `740031001` contention (`pg_try_advisory_lock` returns `false` when another batch is still running, causing a clean `0`-item skip).
  - Microsoft Foundry `embedding` deployment errors (`Cohere.EmbedV40` quota, auth, or incomplete batch errors).
  - Qdrant (`vectordb`) upsert/delete errors.
  - Note that each batch processes at most `200` rows (`BatchSize = 200`), so a large backlog drains across multiple 5-minute cycles.

</Step>
<Step title="Recover safely">

- Restore the failing dependency (`schedulerdb`, Kafka broker, `catalog-ingestion`, Microsoft Foundry access, or Qdrant `vectordb`) through standard operational or deployment workflows.
- Resume a paused trigger in **Quartz Dashboard** only under your team's approved change procedure.
- After restoring downstream dependencies, prefer waiting for the next 5-minute scheduled firing (or `FireOnceNow` catch-up) rather than triggering multiple manual runs concurrently.
- Escalate Scheduler, `schedulerdb`, Quartz Dashboard Entra ID OIDC, or Kafka broker issues to platform infrastructure owners, and `BookWorm.Catalog.Ingestion` / embedding / Qdrant issues to Catalog maintainers.

</Step>
</Steps>

## Verification

Confirm both Scheduler and downstream Catalog Ingestion are healthy:

1. In **Quartz Dashboard**, confirm `HeartbeatTrigger` fires every 30 seconds UTC and `ProcessVectorBatchTrigger` shows a valid next 5-minute UTC fire time with `Succeeded` execution history.
2. In `catalogdb`, re-run the read-only pending count query across two 5-minute cycles and confirm `pending_count` trends downward toward `0`:

   ```sql
   SELECT COUNT(*) AS pending_count, MIN(updated_at) AS oldest_updated_at
   FROM pending_vector_updates;
   ```

3. Confirm `catalog-ingestion` logs record `"Processed <count> pending vector updates"` with no new errors.

## Troubleshooting

| Symptom                                                                                        | Cause                                                                                                                                                    | Fix                                                                                                                           |
| :--------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| No jobs fire locally in Aspire                                                                 | `scheduler` is registered with `.WithExplicitStart()` in `AppHost.cs`                                                                                    | Start the `scheduler` resource explicitly in Aspire Dashboard                                                                 |
| `ProcessVectorBatchJob` fails with `JobExecutionException`                                     | `schedulerdb` PostgreSQL unavailable or Kafka broker unreachable during Wolverine publish                                                                | Restore `schedulerdb` or Kafka connectivity; allow next scheduled firing or `FireOnceNow` catch-up                            |
| Trigger stays in `PAUSED` or `ERROR` state in Quartz Dashboard                                 | Operator paused the trigger or persistent store error occurred                                                                                           | Resolve underlying `schedulerdb` fault and resume the trigger in Quartz Dashboard with `admin` role                           |
| `ProcessVectorBatchJob` succeeds every 5 minutes, but `pending_vector_updates` does not shrink | `catalog-ingestion` consumer stopped, advisory lock `740031001` held by a stuck session, Microsoft Foundry embedding error, or Qdrant (`vectordb`) error | Inspect `catalog-ingestion` logs and Kafka lag on `scheduler.process-vector-batch`; restore the failing downstream dependency |
| `401` / `403` signing in to `/quartz`                                                          | User lacks Microsoft Entra ID `admin` app role for `quartz-dashboard`                                                                                    | Assign the `admin` role in Entra ID and sign in again                                                                         |
