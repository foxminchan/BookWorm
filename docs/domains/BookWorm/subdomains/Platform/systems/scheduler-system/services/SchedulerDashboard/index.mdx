Scheduler (`scheduler`) is the internal Quartz.NET job host in the Platform bounded context that triggers recurring catalog vector ingestion and emits liveness heartbeats. Quartz Dashboard (`quartz-dashboard`) is a separate Aspire-provisioned container that exposes the administrative UI at `/quartz` over Microsoft Entra ID OIDC authentication.

:::note
The legacy EventCatalog source catalog used the misspelled slug `sheduler-dashboard` (missing `c`). This page standardizes all names and links on **Scheduler** and **Scheduler database**.
:::

## Overview

| Property                | Value                                                                                                                                               |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**               | Platform bounded context (`BookWorm.Scheduler`)                                                                                                     |
| **Aspire resource IDs** | `scheduler` (job host, `.WithExplicitStart()` locally) and `quartz-dashboard` (operator UI container)                                               |
| **Source**              | `src/Services/Scheduler/BookWorm.Scheduler`                                                                                                         |
| **Host & ports**        | `scheduler`: HTTP `5062`, HTTPS `7062` (local); `quartz-dashboard`: external HTTP endpoint at `/quartz`; neither is routed through YARP API Gateway |
| **Protocol / format**   | Kafka + Wolverine (CloudEvents JSON), Quartz Dashboard Agent (`Quartz:DashboardAgent:Endpoint`)                                                     |
| **Persistence**         | PostgreSQL (`schedulerdb`) storing Quartz tables (`qrtz_*`), 30-day execution history, and Wolverine outbox/inbox (`wolverine` schema)              |
| **Authentication**      | `quartz-dashboard`: Microsoft Entra ID OIDC requiring the `admin` app role; `scheduler`: internal worker (no public business API)                   |

## Runtime architecture

Quartz Dashboard connects to the `scheduler` host via the Quartz Dashboard Agent, while `scheduler` persists schedules in PostgreSQL and publishes vector-batch triggers to Kafka through the Wolverine outbox.

## Scheduled jobs (`jobs.json`)

`BookWorm.Scheduler` loads job definitions from `~/jobs.json`, rescans the file every 1 minute (`OverwriteExistingData: true`, `FailOnFileNotFound: true`, `FailOnSchedulingError: true`), and registers all jobs in the `Scheduler` group as `Durable: true`, `Recover: false` with the `FireOnceNow` misfire policy in UTC.

| Job name                | Cron expression (UTC) | Cadence          | Behavior                                                                                                                     | Downstream owner                                                                 |
| :---------------------- | :-------------------- | :--------------- | :--------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------- |
| `ProcessVectorBatchJob` | `0 0/5 * * * ?`       | Every 5 minutes  | Publishes [[event\|ProcessVectorBatchIntegrationEvent]] to `scheduler.process-vector-batch`; disallows concurrent executions | [[service\|catalog-ingestion]] owns `pending_vector_updates` and Qdrant indexing |
| `HeartbeatJob`          | `0/30 * * * * ?`      | Every 30 seconds | Emits a scheduler liveness signal to logs and OpenTelemetry; publishes no Kafka message                                      | Operators and platform observability                                             |

## Published Kafka events

| Event                                         | Kafka topic                      | Prefixed                    | Consumer                                                            |
| :-------------------------------------------- | :------------------------------- | :-------------------------- | :------------------------------------------------------------------ |
| [[event\|ProcessVectorBatchIntegrationEvent]] | `scheduler.process-vector-batch` | No (`AppendPrefix = false`) | [[service\|catalog-ingestion]] (consumer group `catalog-ingestion`) |

`ProcessVectorBatchIntegrationEvent` carries only `Id` and `CreationDate` inherited from `IntegrationEvent`. Publishing uses the Wolverine PostgreSQL outbox in [[container|scheduler-database]] (`wolverine` schema).

## Operator capabilities in Quartz Dashboard

Authorized administrators using `/quartz` can perform these actions without querying `schedulerdb` directly:

- **Inspect jobs and triggers:** Review job types, groups, durability, UTC cron expressions, next fire times, and `FireOnceNow` misfire state.
- **Monitor runtime execution:** Inspect active firings, scheduler instance check-ins, execution durations, and failure details.
- **Control schedules:** Pause or resume triggers according to Entra ID `admin` role permissions.
- **Correlate failures:** Match fire instances with OpenTelemetry traces and structured logs.

:::danger
Never store credentials, authorization headers, notification bodies, or personal data in Quartz job metadata or trigger data maps.
:::

## Failure semantics

| Condition                                      | Behavior                                                                                                | Recovery behavior                                                                                               |
| :--------------------------------------------- | :------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------------------------------------- |
| Missed fire window during downtime             | `FireOnceNow` triggers a single immediate catch-up execution instead of replaying every missed interval | Downstream batch worker catches up using durable `pending_vector_updates`                                       |
| Publication failure in `ProcessVectorBatchJob` | Exception propagates back to Quartz and is recorded in execution history                                | Inspect Quartz execution history and scheduled job failure runbook                                              |
| Green job run but stale catalog search         | Scheduler only proves trigger dispatch, not downstream indexing completion                              | Check `pending_vector_updates` depth in [[container\|catalog-database]] and [[service\|catalog-ingestion]] logs |
