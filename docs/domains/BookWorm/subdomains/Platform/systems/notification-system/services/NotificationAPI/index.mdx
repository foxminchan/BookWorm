## Service Responsibility & Boundary

Notification API is an internal background worker within the [[domain|platform]] domain that consumes order lifecycle commands from [[service|order-orchestration]] over Kafka, renders MJML email templates, and submits MIME messages over SMTP to [[service|sendgrid-api]] (or a local test inbox in development). It owns no relational database, maintains no email outbox, and publishes no reply eventsâ€”calling domains retain full ownership of business outcomes.

## Contracts & Data Ownership

Notification API consumes [[command|PlaceOrderCommand]], [[command|CompleteOrderCommand]], and [[command|CancelOrderCommand]] partitioned by Order ID. Blank recipient email addresses are skipped safely without error or retry.

:::warning
SMTP acceptance from the mail provider confirms only submissionâ€”not inbox arrivalâ€”and Notification does not ingest bounce or delivery webhooks. Additionally, because [[service|order-orchestration]] retries [[command|PlaceOrderCommand]] with a new message ID on basket-cleanup timeouts, retries can send an additional placement email.
:::

	Transient SMTP failures trigger client retries followed by Kafka listener backoff; exhausted
