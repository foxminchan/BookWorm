`CancelOrderCommand` (`BookWorm.Contracts.CancelOrderCommand`) is an asynchronous Kafka integration command published by **Finance** and consumed by **Notification** to render and submit a canceled-order customer email. It never mutates order state in **Ordering API**.

## Overview

| Property              | Value                                                                                                                                                                                                                                                                                                                     |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Owner**             | **Finance** (`finance`) produces; **Notification** (`notification`) consumes                                                                                                                                                                                                                                              |
| **Source**            | `src/Services/Finance/BookWorm.Finance/Features/Orders/OrderCancellation/PublishCancelOrderActivity.cs`, `src/Services/Notification/BookWorm.Notification/IntegrationEvents/Events/CancelOrderCommand.cs`, `src/Services/Notification/BookWorm.Notification/IntegrationEvents/EventHandlers/CancelOrderCommandHandler.cs` |
| **Protocol / format** | Kafka + **Wolverine**, CloudEvents JSON (`CloudEventsOnlyKafkaMapper`), camelCase payload                                                                                                                                                                                                                                 |
| **Kafka topic**       | `bookworm.{env}.finance.cancel-order` (`[IntegrationMessageOwner(ServiceName = Services.Finance, TopicName = "cancel-order")]`)                                                                                                                                                                                           |
| **Partition key**     | `OrderId` (`opts.MessagePartitioning.ByPropertyNamed(nameof(OrderId))`)                                                                                                                                                                                                                                                   |
| **Dead-letter queue** | `bookworm.{env}.notification.dead-letter-queue`                                                                                                                                                                                                                                                                           |
| **Authentication**    | Internal Kafka broker transport (Confluent Cloud in publish mode; local Kafka container in development)                                                                                                                                                                                                                   |

:::note
`CancelOrderCommand` requests a customer email only. To change an order's authoritative status to `Cancelled`, call the Ordering API HTTP command in [[command|CancelOrder]].
:::

## Behavior and side effects

- **Finance publishing triggers:** **Finance** (`BookWorm.Finance`, Azure Durable Functions `OrderOrchestrator`) publishes `CancelOrderCommand` via `PublishCancelOrderActivity` in two cases, both gated by `order.CanSendNotification` (requires nonblank customer name and email):
  1. `OrderCancelledStep` receives `OrderStatusChangedToCancelIntegrationEvent` from **Ordering API** and completes the orchestration.
  2. `OrderOrchestrator` executes its registered `PublishCancelOrderActivity` compensation when retries exceed `MaxAttempts` (`CancelDueToMaxRetriesAsync`) or when a `TaskFailedException` or `FinanceDomainException` fails the orchestration.
- **Idempotency (Redis + FusionCache):** `CancelOrderCommandHandler` wraps execution in `IIntegrationEventIdempotencyGuard.ExecuteAsync(message.Id, nameof(CancelOrderCommandHandler), ...)` with a 24-hour TTL keyed by `idempotency:CancelOrderCommandHandler:<id>`. Kafka redeliveries with the same `id` are deduplicated within 24 hours; newly published commands with a different `id` execute again.
- **Stateless email rendering and delivery:** **Notification** has no SQL database and writes no email outbox table. `ContractToModelMapper.ToOrder()` maps the command to Notification's internal `Status.Canceled` model (`BookWorm.Notification/Domain/Models/Status.cs`), `OrderNotificationHelper.SendAsync` skips null/whitespace `email`, renders `Orders/OrderEmail` with `MjmlTemplateRenderer`, builds a `MimeMessage` via `OrderMimeMessageBuilder`, and submits through `MailKitSender` (SMTP to **Mailpit** locally or **SendGrid** SMTP in publish mode).
- **No return event:** **Notification** publishes no delivery-status event back to **Finance**. SMTP server acceptance confirms provider handoff, not final inbox delivery.

## Error responses

| Code / status                                                                                                                                       | Condition                                                               | Recovery behavior                                                                                                                                                             |
| :-------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transient SMTP failure (`CommandException` where `IsTransient`, `ProtocolException`, `IOException`, `TimeoutException`, `TimeoutRejectedException`) | Temporary SMTP server or network error during `MailKitSender.SendAsync` | Retried inside **Notification**'s Polly resilience pipeline (circuit breaker + exponential backoff with jitter + 30-second default timeout).                                  |
| `NotificationException`                                                                                                                             | Permanent SMTP failure or exhausted Polly resilience pipeline           | Propagates to **Wolverine**, which retries with cooldown `50ms` / `250ms` / `1s` (full jitter) before routing the message to `bookworm.{env}.notification.dead-letter-queue`. |
| Blank or null `email`                                                                                                                               | Command arrives without a recipient email address                       | Handler returns without error and skips template rendering and SMTP submission.                                                                                               |
