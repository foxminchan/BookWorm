## Overview

Finance's order saga publishes this command through
[[channel|bookworm.&#123;env&#125;.finance.place-order]] and may reissue it on
placement timeout. [[service|notification-api]] maps it to the new-order email
status, not to an order write. Other consumers can handle the same shared
business command independently.

The payload contains inherited `id` (UUID v7) and `creationDate` (UTC timestamp),
plus `basketId`, `orderId`, `totalMoney` (C# decimal), and nullable `fullName`
and `email`. Notification does not use `basketId`; a null name becomes `Customer`.
This command carries the payload schema; Notification's AsyncAPI specification
provides examples. Wolverine uses identity `BookWorm.Contracts.PlaceOrderCommand`.

Null, empty, or whitespace-only email addresses skip email work. Otherwise
Notification renders `Orders/OrderEmail`, saves an email outbox record, submits
through SMTP, and marks the record sent on success. Failures propagate; there
is no notification result event. Reissued commands can produce another email,
and SMTP acceptance is not proof of final recipient delivery.
