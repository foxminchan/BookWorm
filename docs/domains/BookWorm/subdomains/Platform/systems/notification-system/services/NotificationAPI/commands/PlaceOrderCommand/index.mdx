`PlaceOrderCommand` (`BookWorm.Contracts.PlaceOrderCommand`) is an asynchronous Kafka integration command published by **Finance** after checkout and consumed independently by **Basket API** (to delete the customer's Redis basket) and **Notification** (to send a new-order confirmation email). Neither consumer creates or modifies orders in **Ordering API**.

## Overview

| Property               | Value                                                                                                                                                                                                                                                                                                             |
| :--------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**              | **Finance** (`finance`) produces; **Basket API** (`basket`) and **Notification** (`notification`) consume                                                                                                                                                                                                         |
| **Source**             | `src/Services/Finance/BookWorm.Finance/Features/Orders/PlaceOrder/PublishPlaceOrderActivity.cs`, `src/Services/Basket/BookWorm.Basket/IntegrationEvents/EventHandlers/PlaceOrderCommandHandler.cs`, `src/Services/Notification/BookWorm.Notification/IntegrationEvents/EventHandlers/PlaceOrderCommandHandler.cs` |
| **Protocol / format**  | Kafka + **Wolverine**, CloudEvents JSON (`CloudEventsOnlyKafkaMapper`), camelCase payload                                                                                                                                                                                                                         |
| **Kafka topic**        | `bookworm.{env}.finance.place-order` (`[IntegrationMessageOwner(ServiceName = Services.Finance, TopicName = "place-order")]`)                                                                                                                                                                                     |
| **Partition key**      | `OrderId` (`opts.MessagePartitioning.ByPropertyNamed(nameof(OrderId))`)                                                                                                                                                                                                                                           |
| **Dead-letter queues** | `bookworm.{env}.basket.dead-letter-queue` (**Basket API**), `bookworm.{env}.notification.dead-letter-queue` (**Notification**)                                                                                                                                                                                    |
| **Authentication**     | Internal Kafka broker transport (Confluent Cloud in publish mode; local Kafka container in development)                                                                                                                                                                                                           |

:::note
`PlaceOrderCommand` initiates post-checkout cleanup and confirmation email delivery only. To submit a new order over HTTP, see [[command|CreateOrder]].
:::

## Behavior and side effects

- **Finance publishing and timeout retries:** After **Ordering API** emits `UserCheckedOutIntegrationEvent`, **Finance**'s Azure Durable Functions `OrderOrchestrator` publishes `PlaceOrderCommand` via `PublishPlaceOrderActivity`. If post-checkout basket cleanup times out before `MaxAttempts` is reached, `PlaceOrderTimeoutStep` invokes `PublishPlaceOrderActivity` again with a newly constructed `PlaceOrderCommand` (carrying a new `id`).
- **Basket API consumer (`BookWorm.Basket`):**
  - Deduplicates by `command.OrderId` via `IIntegrationEventIdempotencyGuard.TryAcquireAsync(command.OrderId, nameof(PlaceOrderCommandHandler), ...)` (24-hour Redis/FusionCache TTL). Because the key is `OrderId`, even a reissued timeout-retry command with a new `id` does not delete the basket twice and immediately returns `BasketDeletedCompleteIntegrationEvent`.
  - Deletes `command.BasketId.ToString()` from Redis via `IBasketRepository.DeleteBasketAsync`.
  - Emits `BasketDeletedCompleteIntegrationEvent` when deletion succeeds or `BasketDeletedFailedIntegrationEvent` when deletion returns `false`. If an exception occurs, the handler releases the idempotency lock and rethrows for retry.
- **Notification consumer (`BookWorm.Notification`):**
  - Deduplicates by `message.Id` via `IIntegrationEventIdempotencyGuard.ExecuteAsync(message.Id, nameof(PlaceOrderCommandHandler), ...)` (24-hour Redis/FusionCache TTL). Redeliveries of the same Kafka message `id` are skipped, whereas a Finance timeout retry minting a new `id` triggers another email send.
  - Has no SQL database and writes no email outbox table. Maps the command to Notification's internal `Status.New` model, skips null/whitespace `email`, renders `Orders/OrderEmail` via `MjmlTemplateRenderer`, builds a `MimeMessage` with `OrderMimeMessageBuilder`, and sends via `MailKitSender` (**Mailpit** locally, **SendGrid** SMTP in publish mode).
  - Emits no return event; SMTP acceptance confirms provider handoff, not inbox arrival.

## Error responses

| Code / status                                  | Condition                                                                                                                                                    | Recovery behavior                                                                                                                                                                      |
| :--------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Basket deletion returns `false`                | Redis basket key is missing or could not be deleted cleanly                                                                                                  | **Basket API** publishes `BasketDeletedFailedIntegrationEvent` so **Finance** can instruct **Ordering API** to compensate (`DeleteBasketFailedCommand`).                               |
| Redis or transport exception in **Basket API** | Transient Redis failure during `DeleteBasketAsync`                                                                                                           | Handler releases its `OrderId` idempotency lock and rethrows; **Wolverine** retries (`50ms` / `250ms` / `1s` with jitter) before routing to `bookworm.{env}.basket.dead-letter-queue`. |
| Transient SMTP failure in **Notification**     | Temporary SMTP or network error (`CommandException` where `IsTransient`, `ProtocolException`, `IOException`, `TimeoutException`, `TimeoutRejectedException`) | Retried by **Notification**'s Polly pipeline (circuit breaker + exponential backoff with jitter + 30-second default timeout).                                                          |
| `NotificationException`                        | Permanent SMTP failure or exhausted Polly pipeline                                                                                                           | **Wolverine** retries (`50ms` / `250ms` / `1s` with jitter) before routing to `bookworm.{env}.notification.dead-letter-queue`.                                                         |
| Blank or null `email` in **Notification**      | Command arrives without a recipient email address                                                                                                            | **Notification** returns without error and skips template rendering and SMTP submission.                                                                                               |
