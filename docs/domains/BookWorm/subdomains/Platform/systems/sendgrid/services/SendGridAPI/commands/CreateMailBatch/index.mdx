`CreateMailBatch` (`POST https://api.sendgrid.com/v3/mail/batch`) is an external SendGrid Web API v3 operation that generates a `batch_id` for grouping scheduled email submissions. **BookWorm does not call this endpoint at runtime**: the **Notification** service (`BookWorm.Notification`) sends individual order emails via `MailKit` over SMTP (**Mailpit** locally, SendGrid SMTP relay in Azure) and has no SendGrid REST client or batch-tracking database.

:::note
This page documents an external provider capability cataloged for future REST integration. In the current BookWorm codebase (`src/Services/Notification/BookWorm.Notification/` and `src/Aspire/BookWorm.AppHost/Extensions/Network/EmailExtensions.cs`), there is no `SendGrid` NuGet package, no `SENDGRID_API_KEY` environment variable, and no HTTP calls to `/v3/mail/batch`.
:::

## Parameters and fields

### Request headers

The [SendGrid OpenAPI contract](https://raw.githubusercontent.com/twilio/sendgrid-oai/refs/heads/main/spec/yaml/tsg_mail_v3.yaml) confirms that `on-behalf-of` is an optional header for this endpoint, but does not map `POST /v3/mail/batch` to an exact API-key permission. SendGrid's [API key guidance](https://www.twilio.com/docs/sendgrid/ui/account-and-settings/api-keys) recommends API keys, custom/restricted permissions, and keeping keys out of source control. The permission UI lists **Mail Send** and **Scheduled Sends** separately; the batch endpoint creates an ID for scheduled sends, but the public contract does not establish which exact combination authorizes this endpoint. Grant only the permissions verified as necessary for the account and do not use account-wide **Full Access**.

| Name            | Type     | Required | Default | Constraints                     | Description                                                                                                                                                 |
| :-------------- | :------- | :------- | :------ | :------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Authorization` | `string` | Yes      | —       | `Bearer <sendgrid-api-key>`     | SendGrid API key. Use a restricted key scoped to the required Mail Send/Scheduled Sends actions; the endpoint contract does not identify the minimum scope. |
| `on-behalf-of`  | `string` | No       | —       | Valid SendGrid subuser username | Optional subuser context header supported by SendGrid Web API v3                                                                                            |

### Request body

`POST /v3/mail/batch` accepts no request body.

### Success response (`201 Created`)

| Name       | Type     | Required | Default | Constraints                       | Description                                                                               |
| :--------- | :------- | :------- | :------ | :-------------------------------- | :---------------------------------------------------------------------------------------- |
| `batch_id` | `string` | Yes      | —       | Non-empty string (`minLength: 1`) | Provider-generated batch identifier to attach to subsequent `POST /v3/mail/send` requests |

## Behavior and side effects

- **Provider-side reservation only:** Calling `POST /v3/mail/batch` allocates a `batch_id` inside SendGrid; it does not send any email or confirm message delivery.
- **BookWorm runtime behavior:** `BookWorm.Notification` does not reserve mail batches or persist batch IDs. Instead, it consumes Kafka commands (`PlaceOrderCommand`, `CompleteOrderCommand`, `CancelOrderCommand`) through **Wolverine**, enforces 24-hour duplicate protection in Redis (`IIntegrationEventIdempotencyGuard`), renders MJML templates (`Mjml.Net`), and transmits individual messages over SMTP via `MailKitSender`.
- **BookWorm SMTP credentials:** In Azure publish mode, AppHost configures SMTP through `Email__Endpoint` (default `smtp://smtp.sendgrid.net:587`), `Email__Username` (default `apikey`), `Email__Password` (Aspire parameter `email-smtp-password`), `Email__From`, and optional `Email__Name`.
- **Credential handling:** Keep REST API keys in a secret manager or environment-backed secret configuration, never commit or log them, and rotate/revoke compromised keys. The current SMTP runtime uses a separate SMTP credential; do not substitute a REST API key unless deliberately migrating the integration.

## Error responses

The OpenAPI contract lists `400`, `401`, `403`, `404`, `405`, and `500` error responses for `POST /v3/mail/batch`; each uses an `ErrorResponse` object with an `errors` array (and optional `id`). It does not list `429`, which means this specification does not document that response—not that the service can never return it.

| Code / status               | Condition                                        | Recovery behavior                                                           |
| :-------------------------- | :----------------------------------------------- | :-------------------------------------------------------------------------- |
| `400 Bad Request`           | Malformed request or invalid headers             | Fix the request before retrying                                             |
| `401 Unauthorized`          | Missing or invalid SendGrid API key              | Verify the bearer API key in secret configuration and retry                 |
| `403 Forbidden`             | API key lacks permission for mail batch creation | Grant the required SendGrid API key permission                              |
| `404 Not Found`             | Referenced provider resource is unavailable      | Verify the endpoint URL and account configuration                           |
| `405 Method Not Allowed`    | Request uses an HTTP method other than `POST`    | Send an HTTP `POST` request to `/v3/mail/batch`                             |
| `500 Internal Server Error` | SendGrid service-side error                      | Reconcile before issuing a replacement batch ID; retry with bounded backoff |
