`SendMail` (`POST https://api.sendgrid.com/v3/mail/send`) represents the logical outbound email handoff to SendGrid in BookWorm's documentation, using SendGrid's Web API v3 contract. **At runtime, BookWorm does not call `POST /v3/mail/send`**: the **Notification** service (`BookWorm.Notification`) sends rendered MJML/HTML emails via `MailKit` over **SMTP**—connecting to **Mailpit** locally and to SendGrid's SMTP relay (`smtp://smtp.sendgrid.net:587`) in Azure—with **no PostgreSQL database and no email outbox**.

:::note
The HTTP `POST /v3/mail/send` schema below documents SendGrid's external REST v3 API. BookWorm's `MailKitSender` (`src/Services/Notification/BookWorm.Notification/Infrastructure/Senders/MailKit/MailKitSender.cs`) does not transmit this JSON payload or read a `SENDGRID_API_KEY` variable; it connects over SMTP using Aspire-injected `Email__*` settings.
:::

| **BookWorm runtime transport** | `MailKit` `5.0.0` over SMTP: **Mailpit** (port `587`) in local Aspire run mode; `smtp://smtp.sendgrid.net:587` (username `apikey`) in Azure publish mode                                                                                                                                                                         |

## Behavior and side effects

- **Asynchronous acceptance (REST and SMTP):** Both SendGrid REST (`202 Accepted`) and SendGrid SMTP (`SendAsync` completion) confirm only that SendGrid accepted the message for delivery processing, not that it reached the recipient's inbox.
- **BookWorm Notification runtime flow (no database outbox):**
  1. **Wolverine** consumes `PlaceOrderCommand`, `CompleteOrderCommand`, or `CancelOrderCommand` from Kafka.
  2. `IIntegrationEventIdempotencyGuard` acquires a 24-hour Redis/FusionCache lock keyed by `idempotency:{consumerName}:{eventId:N}` to prevent duplicate emails.
  3. `MjmlTemplateRenderer` renders `Templates/Orders/OrderEmail.mjml` into HTML, and `OrderMimeMessageBuilder` constructs a `MimeMessage`.
  4. `MailKitSender.SendAsync` executes inside the Polly resilience pipeline (`ResilienceExtensions.cs` + `appsettings.json`):
     - **SMTP client timeout:** `10,000` ms per `SmtpClient` instance (`MailKitClientFactory.cs`).
     - **Circuit breaker:** `FailureRatio: 0.3`, `MinimumThroughput: 5`, `SamplingDuration: 30s`, `DurationOfBreak: 60s`.
     - **Retry:** `MaxRetryAttempts: 3`, `Delay: 1s`, exponential backoff with jitter on transient SMTP `CommandException`, `ProtocolException`, `IOException`, `TimeoutException`, and `TimeoutRejectedException`.
     - **Overall timeout:** `45s` (`appsettings.json`, overriding the `30s` code default).
  5. Unrecovered failures wrap the error in `NotificationException`, allowing Wolverine error handling and native Kafka dead-letter routing (`bookworm.{env}.notification.dead-letter-queue`) to handle the failed message.

## Error responses

### External SendGrid REST v3 status codes

The [SendGrid OpenAPI contract](https://raw.githubusercontent.com/twilio/sendgrid-oai/refs/heads/main/spec/yaml/tsg_mail_v3.yaml) lists `400`, `401`, `403`, `404`, `405`, `413`, and `500` error responses, each with an `ErrorResponse` body containing `errors[]` (and optional `id`). It does not list `429` or document an `X-Message-Id` response header; these are omissions from the specification, not proof the live service never emits them.

| Code / status               | Condition                                                             | Recovery behavior                                    |
| :-------------------------- | :-------------------------------------------------------------------- | :--------------------------------------------------- |
| `400 Bad Request`           | Invalid JSON structure, unverified sender, or missing required fields | Fix the request payload; do not retry unchanged      |
| `401 Unauthorized`          | Missing or invalid SendGrid API key                                   | Verify the API key in secret configuration and retry |
| `403 Forbidden`             | API key lacks Mail Send permission or account is restricted           | Update SendGrid key scopes or account status         |
| `404 Not Found`             | Referenced provider resource is unavailable                           | Verify the endpoint URL and referenced IDs           |
| `405 Method Not Allowed`    | Request uses an HTTP method other than `POST`                         | Send an HTTP `POST` request to `/v3/mail/send`       |
| `413 Content Too Large`     | Payload exceeds SendGrid size limits                                  | Reduce message or attachment size before retrying    |
| `500 Internal Server Error` | SendGrid service-side error                                           | Retry with bounded exponential backoff               |
