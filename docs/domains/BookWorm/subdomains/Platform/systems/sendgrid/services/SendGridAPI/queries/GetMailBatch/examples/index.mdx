summary: Validate a SendGrid mail batch identifier before using it in a notification workflow.
---

## 1. Context & Problem

When notification workflows group scheduled or related emails under a shared mail batch identifier, teams need a safe way to verify that a stored batch identifier is still valid before attaching new emails to it. If a workflow assumes an unrecognized or expired batch identifier is harmless—or treats validation success as proof that emails were sent—subsequent mail submissions can fail unexpectedly or be misreported.

## 2. Business Value

- **Prevents broken batch submissions:** Confirms a batch identifier is recognized by the email provider before a workflow attempts to attach messages to it.
- **Eliminates silent workflow state errors:** Guides teams to treat unknown batches as explicit state failures rather than assuming the batch is usable later.
- **Clarifies status boundaries:** Prevents operations and business stakeholders from mistaking batch existence for message submission or delivery confirmation.

## 3. How It Works

1. **Supply the stored batch identifier:** Before reusing a previously created mail batch, the workflow checks the batch identifier with the external email provider using authenticated access.
2. **Confirm identifier recognition:** If the provider confirms the identifier exists, the workflow knows the batch is recognized—though this check does not indicate whether any messages have been submitted or delivered under that batch.
3. **Fail fast on unknown batches:** If the provider reports that the identifier is invalid or unknown, the workflow treats it as a workflow state error and stops rather than attempting to reference it in later email submissions.

## 4. Trade-offs & Lessons Learned

- **Existence check vs. delivery tracking:** Validating a batch identifier only proves the provider recognizes the identifier; teams must still rely on BookWorm's own notification state to track whether messages were queued or submitted.
- **Upfront validation cost vs. reliability:** Performing a pre-flight check adds an extra external call when resuming paused workflows, but prevents late submission failures caused by stale or missing batch state.

### 1. Retrieve a mail batch

Provide the identifier returned by [[command|CreateMailBatch]]. A `200 OK` response
confirms SendGrid recognizes the batch identifier; it does not show whether any
message has been submitted or delivered.

#### Example response

<CodeGroup dropdown>

```json
{
	"batch_id": "YWJjZDEyMzQtZWY1Ni03ODkwLWFiY2QtZWYxMjM0NTY3ODkw"
}
```

</CodeGroup>

<CodeGroup dropdown>

```csharp get-mail-batch.cs
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Text.Json.Serialization;

var apiKey = Environment.GetEnvironmentVariable("SENDGRID_API_KEY")
    ?? throw new InvalidOperationException("SENDGRID_API_KEY is required.");
var batchId = "YWJjZDEyMzQtZWY1Ni03ODkwLWFiY2QtZWYxMjM0NTY3ODkw";

using var client = new HttpClient
{
	BaseAddress = new Uri("https://api.sendgrid.com")
};
client.DefaultRequestHeaders.Authorization =
	new AuthenticationHeaderValue("Bearer", apiKey);

using var response = await client.GetAsync($"/v3/mail/batch/{batchId}");
if (response.StatusCode == System.Net.HttpStatusCode.BadRequest)
{
	throw new InvalidOperationException("The mail batch identifier is invalid.");
}
response.EnsureSuccessStatusCode();

var result = await response.Content.ReadFromJsonAsync<GetMailBatchResponse>()
    ?? throw new InvalidOperationException("SendGrid returned an empty response.");

Console.WriteLine(result.BatchId);

internal sealed record GetMailBatchResponse(
	[property: JsonPropertyName("batch_id")] string BatchId);
```

### 2. Handle an unknown mail batch

Treat a missing batch as a workflow state error rather than an empty success.
Do not assume it can be used by a later [[command|SendMail]] submission.
