## System Purpose & Boundary

SendGrid provides BookWorm's external SMTP email relay boundary within the [[domain|platform]] domain, offloading internet mail routing, sender reputation, and downstream ISP delivery. Only [[system|notification-system]] integrates with SendGrid at runtime to submit rendered order lifecycle emails. Owning BookWorm's notification state, managing retry queues, and dictating order or payment status are explicitly out of scope.

:::note
SendGrid acceptance confirms only that the provider accepted the SMTP submission—it does not guarantee recipient inbox delivery or confirm that the underlying business order succeeded.
:::

## External Interactions & Trust Boundaries

- **Sole BookWorm consumer:** [[service|notification-api]] submits rendered MIME emails over TLS-encrypted SMTP in publish environments (and uses a local test inbox during development).
- **Resilience & dead-lettering:** [[system|notification-system]] retains full ownership of 24-hour message-ID deduplication, bounded client retries, and dead-letter routing when SendGrid is unavailable or throttles requests.
- **Credential & PII boundary:** API keys and sender secrets are injected strictly via runtime secret configuration; recipient addresses and message bodies are never logged in routine telemetry.
