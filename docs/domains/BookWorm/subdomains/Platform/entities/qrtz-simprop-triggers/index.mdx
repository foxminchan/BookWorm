## 1. Context & Problem

Beyond calendar expressions and simple fixed-interval repeats, scheduling systems support specialized trigger types—such as daily time-window schedules or calendar-interval schedules—that require different sets of parameters. Creating a separate table for every trigger variant would complicate database maintenance, while storing settings in opaque binary payloads would block inspection. A typed property-slot model provides structured, reusable storage for these specialized triggers.

## 2. Business Value

- **Schema Stability:** Lets the platform support specialized schedule types without requiring new database migrations for every trigger variant.
- **Inspectable Parameters:** Keeps trigger configuration in readable text, numeric, and boolean fields rather than opaque binary payloads, helping teams troubleshoot schedule rules.
- **Time Zone Consistency:** Stores an optional time zone identifier so specialized schedules respect explicit regional or UTC boundaries across deployments.

## 3. How It Works

Each property-based trigger record extends a parent trigger in the core trigger registry. Depending on the trigger type recorded on the parent trigger, the scheduler maps that trigger's configuration into generic typed slots—supporting text values, standard and large integers, decimals, boolean flags, and an optional time zone identifier.

When the scheduler loads or evaluates the trigger, it reads the parent trigger's type to interpret which typed slots hold each schedule parameter and calculates the next execution time accordingly.

## 4. Trade-offs & Lessons Learned

- **Context-Dependent Slot Meaning:** Because slot names are generic rather than domain-specific, the stored values are only meaningful when interpreted alongside the parent trigger's type.
- **Fixed Slot Capacity:** Each record provides a fixed number of slots per data type; any specialized trigger needing more parameters cannot rely solely on this structure.
- **Avoid Direct Manual Edits:** Because parameter mapping is governed by the scheduler implementation, modifying slot values directly in storage risks breaking schedule evaluation.
