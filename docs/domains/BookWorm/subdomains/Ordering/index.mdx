Ordering is BookWorm's Core domain for committed customer purchases (`Buyer`, `Order`, `Order Item`) and their business lifecycle (`New` → `Completed` or `Cancelled`). It consists of two services: `Ordering API`, which owns authoritative order state in PostgreSQL (`orderingdb` with EF Core and Marten event sourcing), and `Finance`, an Azure Functions and Durable Task Scheduler saga coordinating post-checkout basket cleanup and customer email commands.

## Scope and constraints

- **In scope:** Buyer profiles and delivery addresses, order creation from an authenticated basket with locked purchase-time pricing, order lifecycle state transitions, Marten `OrderSummary` dashboard projections, and post-checkout Finance orchestration.
- **Out of scope:** Pre-order mutable baskets (`Shopping`), live book catalog descriptions (`Catalog`), external payment-provider settlement, physical shipping execution, and email rendering/transport (`Platform`).
- **Key constraints:** Only explicit Ordering commands change an order's business status; Finance saga retries, timeouts, and Notification outcomes never mark an order `Completed` or `Cancelled`.

### Lifecycle invariants

- Every order contains one or more `Order Item` lines with positive quantities and non-negative purchase-time prices (sale price when active, otherwise regular price).
- `Order Total` equals the sum of all item line totals (`price * quantity`).
- Every order begins in `New` and transitions once to terminal `Completed` or `Cancelled`.
- Moving an order to `Completed` or `Cancelled` publishes `OrderStatusChangedToCompleteIntegrationEvent` or `OrderStatusChangedToCancelIntegrationEvent`, prompting Finance to complete its saga and send `CompleteOrderCommand` or `CancelOrderCommand` to Notification when contact details exist.
- If Finance exhausts basket-cleanup retries, Finance closes its own saga and can emit a cancellation email without setting the `Order`'s business status to `Cancelled`.

## Deployment and cross-cutting concerns

- **Hosting and ingress:** `ordering` runs behind YARP (`/ordering/{**remainder}`); `finance` runs as an internal Azure Functions Container App with no public HTTP endpoint, using Azure Storage Blob Data Owner for Functions host state and Durable Task Scheduler (`finance-taskhub`) for saga state.
- **Security and privacy:** Microsoft Entra ID JWT policies enforce `customer` and `admin` access boundaries; HMAC key (`HMAC__Key`) protects internal signatures; Redis distributed locks (`order-cache`) and `IRequestManager` guard against duplicate order creation.
- **Observability and resilience:** OpenTelemetry correlates HTTP, gRPC, Marten, Durable Task, and Kafka spans by `OrderId`; Wolverine routes exhausted Ordering listeners to `bookworm.{env}.ordering.dead-letter-queue`.

## Quality scenarios and known risks

| Quality attribute / risk | Scenario or exposure                              | Current mitigation or gap                                                                                                                                                                                           |
| :----------------------- | :------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Consistency**          | Concurrent checkout clicks or retried requests    | Redis Buyer-scoped distributed locks + HTTP idempotency keys + Wolverine PostgreSQL outbox/inbox                                                                                                                    |
| **Resilience**           | Basket deletion fails or times out after checkout | Bounded Finance saga retries + explicit `DeleteBasketFailedCommand` soft-delete compensation                                                                                                                        |
| **Delivery SLAs**        | External shipping/carrier delivery targets        | The repository tracks `docs/domains/BookWorm/subdomains/Ordering/systems/order-system/services/OrderAPI/sla.yaml`; its status is `draft`, and the carrier terms are marked `proposed`. It is not formally approved. |
