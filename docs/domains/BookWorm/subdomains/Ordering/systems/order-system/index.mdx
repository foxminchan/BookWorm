## System Purpose & Boundary

The Order System owns accepted customer purchases, [[entity|buyer]] profiles, and the authoritative [[entity|order]] lifecycle (`New`, `Completed`, `Cancelled`) within the [[domain|ordering]] domain. It serves **Customers** placing and tracking orders and **Administrators** managing fulfillment status and viewing backoffice dashboards. Mutable shopping baskets ([[domain|shopping]]), live product catalog pricing ([[domain|catalog]]), payment settlement, and post-checkout orchestration ([[system|finance-system]]) are explicitly out of scope.

:::note
At checkout, the Order System snapshots book quantities and active prices onto [[entity|order-item]] records so future catalog edits never alter accepted orders. Soft deletion is separated from business status: failed basket cleanup soft-deletes the order record for auditability without changing its business status.
:::

## External Interactions & Trust Boundaries

- **Customer & admin entry points:** Authenticated requests enter via the API Gateway with [[system|identity-provider]] JWT validation, per-user rate limiting, and required idempotency keys on state-changing order operations.
- **Checkout enrichment:** During order creation, [[service|order-api]] synchronously queries [[system|cart-system]] for the customer's basket and [[system|product-catalog-system]] for authoritative prices over internal gRPC.
- **Post-checkout coordination:** Publishes [[event|UserCheckedOutIntegrationEvent]], [[event|OrderStatusChangedToCompleteIntegrationEvent]], and [[event|OrderStatusChangedToCancelIntegrationEvent]] to [[system|finance-system]] over Kafka, and consumes basket-cleanup outcomes back from Finance.

<Accordion title="Concurrency & Idempotency Notes">
	- **Buyer write locks & idempotency:** Distributed locks and short-lived idempotency markers in
	[[container|order-cache]] prevent duplicate checkouts and concurrent buyer mutations. -
	**Event-sourced audit trail:** Order domain events append to an event stream in
	[[container|order-database]] to support order history and summary views.
</Accordion>
