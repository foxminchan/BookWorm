`UserCheckedOutIntegrationEvent` (v1.0.0) reports that [[service|order-api]] accepted and persisted a new [[entity|order]] during customer checkout. [[service|order-orchestration]] consumes this event to start a Durable Task saga instance, which dispatches [[command|PlaceOrderCommand]] to [[service|basket-api]] (for basket cleanup) and [[service|notification-api]] (for order confirmation email). Receiving this event confirms order placement only, not basket cleanup or order completion.

## Payload Fields & Envelope

### Event Payload

| Name           | Type                   | Required | Constraints                     | Description                                                                         |
| :------------- | :--------------------- | :------- | :------------------------------ | :---------------------------------------------------------------------------------- |
| `id`           | `string` (`uuid`)      | Yes      | UUIDv7                          | Unique identifier for this integration event instance                               |
| `creationDate` | `string` (`date-time`) | Yes      | ISO 8601 UTC timestamp          | UTC timestamp when the event was created                                            |
| `orderId`      | `string` (`uuid`)      | Yes      | Valid UUID; Kafka partition key | Identifier of the accepted order                                                    |
| `basketId`     | `string` (`uuid`)      | Yes      | Valid UUID                      | Buyer-linked basket reference supplied by the producer                              |
| `fullName`     | `string \| null`       | Yes      | Nullable string                 | Customer full name when available on the buyer record                               |
| `email`        | `string \| null`       | Yes      | Nullable email format           | Customer email address when available; used to decide whether to send notifications |
| `totalMoney`   | `number`               | Yes      | Non-negative monetary amount    | Total purchase amount associated with the accepted order                            |

:::note
The current producer populates `basketId` with the order's `BuyerId`. Downstream consumers must not treat `basketId` as an independently resolved [[service|basket-api]] record.
:::

### CloudEvents Envelope Headers

| Header        | Value / Source                                      | Purpose                                                                |
| :------------ | :-------------------------------------------------- | :--------------------------------------------------------------------- |
| `messagetype` | `BookWorm.Contracts.UserCheckedOutIntegrationEvent` | Explicit message identity for cross-service deserialization            |
| `source`      | `urn:bookworm:bookworm-ordering`                    | Identifies the producing service                                       |
| `requestid`   | Propagated from `POST /ordering/api/v1/orders`      | Correlates checkout across Ordering, Finance, Basket, and Notification |

## Delivery Guarantees & Error Handling

| Condition                               | System Behavior                                                                                                                 | Recovery / Compensation                                                                             |
| :-------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------------------------- |
| `email` or `fullName` is `null`         | Payload remains valid; [[service\|order-orchestration]] still coordinates basket cleanup and evaluates notification eligibility | Consumers must tolerate `null` contact fields without failing deserialization                       |
| Transient broker or orchestration error | Transactional outbox guarantees at-least-once publication; orchestration starts idempotently per `OrderId`                      | Inspect orchestration task hub and [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]] |
