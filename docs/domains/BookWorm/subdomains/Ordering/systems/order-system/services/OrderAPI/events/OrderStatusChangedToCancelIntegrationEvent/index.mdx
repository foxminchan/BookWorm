`OrderStatusChangedToCancelIntegrationEvent` (v1.0.0) reports that [[service|order-api]] transitioned an [[entity|order]] from `New` to `Cancelled`. [[service|order-orchestration]] consumes this authoritative status change to terminate its orchestration instance and dispatch [[command|CancelOrderCommand]] for customer notification; this event is a confirmed transition, not a cancellation request or soft deletion.

## Overview

| Property                             | Value                                                                                               |
| :----------------------------------- | :-------------------------------------------------------------------------------------------------- |
| **Bounded Context**                  | Ordering                                                                                            |
| **Producer**                         | [[service\|order-api]]                                                                              |
| **Consumer(s)**                      | [[service\|order-orchestration]]                                                                    |
| **Protocol / Format**                | Kafka + CloudEvents JSON (camelCase payload)                                                        |
| **Channel / Topic**                  | [[channel\|bookworm.&#123;env&#125;.ordering.order-status-change-to-cancel]]                        |
| **Dead-Letter Channel**              | [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]]                                    |
| **Partition Key**                    | `OrderId`                                                                                           |
| **Delivery / Idempotency Guarantee** | Published via transactional outbox (at-least-once); orchestration routes idempotently per `OrderId` |

## Payload Fields & Envelope

### Event Payload

| Name           | Type                   | Required | Constraints                     | Description                                                                |
| :------------- | :--------------------- | :------- | :------------------------------ | :------------------------------------------------------------------------- |
| `id`           | `string` (`uuid`)      | Yes      | UUIDv7                          | Unique identifier for this integration event instance                      |
| `creationDate` | `string` (`date-time`) | Yes      | ISO 8601 UTC timestamp          | UTC timestamp when the event was created                                   |
| `orderId`      | `string` (`uuid`)      | Yes      | Valid UUID; Kafka partition key | Identifier of the cancelled order                                          |
| `basketId`     | `string` (`uuid`)      | Yes      | Valid UUID                      | Buyer-linked basket reference supplied by the producer                     |
| `fullName`     | `string \| null`       | Yes      | Nullable string                 | Customer full name when available on the buyer record                      |
| `email`        | `string \| null`       | Yes      | Nullable email format           | Customer email address when available; email dispatch is skipped if absent |
| `totalMoney`   | `number`               | Yes      | Non-negative monetary amount    | Total purchase amount associated with the cancelled order                  |

:::note
The current producer populates `basketId` with the order's `BuyerId`. Downstream consumers must not assume `basketId` was independently resolved from [[service|basket-api]].
:::

### CloudEvents Envelope Headers

| Header        | Value / Source                                                  | Purpose                                                                  |
| :------------ | :-------------------------------------------------------------- | :----------------------------------------------------------------------- |
| `messagetype` | `BookWorm.Contracts.OrderStatusChangedToCancelIntegrationEvent` | Explicit message identity for cross-service deserialization              |
| `source`      | `urn:bookworm:bookworm-ordering`                                | Identifies the producing service                                         |
| `requestid`   | Propagated from the triggering HTTP request                     | Correlates order cancellation across Ordering, Finance, and Notification |

## Delivery Guarantees & Error Handling

| Condition                               | System Behavior                                                                                                                            | Recovery / Compensation                                                                                   |
| :-------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------- |
| `email` or `fullName` is `null`         | Payload remains valid; [[service\|order-orchestration]] checks notification eligibility before dispatching [[command\|CancelOrderCommand]] | Consumers must tolerate `null` contact fields without failing deserialization                             |
| Transient broker or orchestration error | Transactional outbox guarantees at-least-once publication; Kafka trigger retries delivery                                                  | Inspect orchestration instance state and [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]] |
