## 1. Context & Problem

Customers need to view their saved [[entity|buyer]] details—such as their name and shipping address—during account management and checkout, while support administrators need to inspect a specific buyer's profile when assisting with orders. Providing this information safely requires enforcing ownership rules so customers cannot read another person's profile.

## 2. Business Value

- **Seamless customer experience:** Enables storefronts to display or prefill saved customer contact and address information.
- **Privacy by design:** Ensures regular customers can only access their own buyer profile while authorized administrators can inspect any requested buyer.
- **Single governed capability:** Consolidates self-service and administrative profile lookups behind one consistent query.

## 3. How It Works

1. An authenticated caller requests a [[entity|buyer]] profile and supplies a buyer identifier.
2. The service checks the caller's authorization: standard customers are always resolved to the buyer profile tied to their own signed-in identity, while administrators can retrieve the specific buyer requested.
3. If the resolved buyer profile exists, the service returns the buyer's identifier, name, and address.
4. If no profile exists for the resolved buyer, the service reports that the profile was not found.

## 4. Trade-offs & Lessons Learned

- **Shared lookup vs. separate endpoints:** Routing both self-service and administrative lookups through one operation avoids duplicating retrieval logic, at the trade-off of requiring a buyer identifier even when a customer is only retrieving their own profile.
- **Explicit missing-profile outcome:** Returning a not-found outcome when a profile does not exist means storefront journeys must handle new customers whose buyer profile has not been created yet.

## 5. Technical Reference

Retrieves a [[entity|buyer]] profile from the `/buyers/me` endpoint (`GET /api/v1/buyers/me`). Administrators may retrieve another user's profile; other callers are resolved to the Buyer associated with their authenticated identity.

### Query parameters and response

- **Query parameter:** The OpenAPI contract requires an `Id` UUID query parameter.
- **`200 OK`:** Returns a `BuyerDto` with the Buyer ID, name, and address.
- **`404 Not Found`:** Returns `ProblemDetails` when the resolved Buyer profile does not exist.
