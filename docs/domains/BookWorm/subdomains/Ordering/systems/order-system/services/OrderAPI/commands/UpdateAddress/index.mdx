The `UpdateAddress` command (`PATCH /api/v1/buyers/address`) replaces the shipping address on the authenticated customer's `Buyer` profile in **Ordering API** (v1.0.0) and returns the updated `BuyerDto`. Access is restricted strictly to the Microsoft Entra ID `customer` role (administrators cannot invoke this endpoint on another user's behalf), and external callers reach it through the YARP **API Gateway** at `/ordering/api/v1/buyers/address`.

## Parameters and fields

### Request body (`application/json`, `UpdateAddressCommand`)

All three address fields are required together to replace the `Address` value object.

| Name       | Type     | Required | Default | Constraints                                                                  | Description                |
| :--------- | :------- | :------- | :------ | :--------------------------------------------------------------------------- | :------------------------- |
| `street`   | `string` | Yes      | —       | Non-empty, max 50 chars (`DataSchemaLength.Medium`); redacted as `[PIIData]` | Updated street address.    |
| `city`     | `string` | Yes      | —       | Non-empty, max 50 chars (`DataSchemaLength.Medium`); redacted as `[PIIData]` | Updated city or district.  |
| `province` | `string` | Yes      | —       | Non-empty, max 50 chars (`DataSchemaLength.Medium`); redacted as `[PIIData]` | Updated province or state. |

### Response body (`200 OK`, `BuyerDto`)

| Name      | Type             | Required | Default | Constraints                                                            | Description                                              |
| :-------- | :--------------- | :------- | :------ | :--------------------------------------------------------------------- | :------------------------------------------------------- |
| `id`      | `string` (UUID)  | Yes      | —       | `BuyerId` UUID                                                         | Identifier of the authenticated buyer.                   |
| `name`    | `string \| null` | No       | —       | Redacted as `[PIIData]`                                                | Buyer display name stored on the profile.                |
| `address` | `string \| null` | No       | —       | Formatted as `"{Street}, {City}, {Province}"`; redacted as `[PIIData]` | Formatted full address returned by `Address.ToString()`. |

## Behavior and side effects

- **Session-bound lookup:** `UpdateAddressHandler` parses `BuyerId` as a GUID from `ClaimTypes.NameIdentifier` (no buyer ID is accepted in the route or body) and loads the buyer via `repository.GetByIdAsync((Guid)userId, cancellationToken)`. If no profile exists yet, it throws `NotFoundException` (`404 Not Found`); callers must first create a profile with [[command|CreateBuyer]].
- **Atomic address replacement:** `Buyer.UpdateAddress(street, city, province)` constructs a new immutable `Address` value object and persists the change to PostgreSQL (`orderingdb`) inside a `[Transactional]` unit of work.
- **No events emitted and PII redaction:** Updating an address emits no domain events or Kafka integration events. Both `UpdateAddressCommand` (`Street`, `City`, `Province`) and `BuyerDto` (`Name`, `Address`) carry `[property: PIIData]` for structured log redaction.

## Error responses

| Code / status               | Condition                                                                                                                                            | Recovery behavior                                              |
| :-------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------- |
| `400 Bad Request`           | Empty/whitespace address field, field exceeding 50 characters (`ValidationProblemDetails`), or non-GUID `NameIdentifier` claim (`ArgumentException`) | Fix the request body or token claims; do not retry unchanged.  |
| `401 Unauthorized`          | Missing, expired, or invalid Entra ID bearer token                                                                                                   | Acquire a fresh Entra ID access token and retry.               |
| `403 Forbidden`             | Authenticated caller lacks the `customer` role (including `admin`-only tokens) or lacks `ordering_read`/`ordering_write` scopes                      | Authenticate as a `customer` with the required scopes.         |
| `404 Not Found`             | Authenticated caller does not have an existing buyer profile in `orderingdb`                                                                         | Create the profile first using `POST /ordering/api/v1/buyers`. |
| `429 Too Many Requests`     | Caller exceeded `PerUserRateLimit` or global rate limits                                                                                             | Wait for the `Retry-After` header interval before retrying.    |
| `500 Internal Server Error` | Unhandled database or server failure                                                                                                                 | Retry with backoff and inspect Ordering API logs.              |
