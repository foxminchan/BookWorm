`DeleteBasketCompleteCommand` (v1.0.0) is an asynchronous Kafka integration command published by [[service|order-orchestration]] to inform [[service|order-api]] that post-checkout basket cleanup succeeded. [[service|order-api]] logs the outcome for operational visibility without modifying the order's business status.

## Overview

| Property                             | Value                                                                          |
| :----------------------------------- | :----------------------------------------------------------------------------- |
| **Bounded Context**                  | Ordering                                                                       |
| **Producer**                         | [[service\|order-orchestration]]                                               |
| **Consumer(s)**                      | [[service\|order-api]]                                                         |
| **Protocol / Format**                | Kafka + CloudEvents JSON (camelCase payload)                                   |
| **Channel / Topic**                  | [[channel\|bookworm.&#123;env&#125;.finance.delete-basket-complete]]           |
| **Dead-Letter Channel**              | [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]]               |
| **Partition Key**                    | `OrderId`                                                                      |
| **Delivery / Idempotency Guarantee** | At-least-once delivery; consumer is side-effect-free (structured logging only) |

:::note
`DeleteBasketCompleteCommand` is distinct from [[event|BasketDeletedCompleteIntegrationEvent]]. [[service|basket-api]] publishes `BasketDeletedCompleteIntegrationEvent` to [[service|order-orchestration]], which then publishes `DeleteBasketCompleteCommand` to [[service|order-api]].
:::

## Payload Fields & Envelope

### Command Payload

| Name           | Type                   | Required | Constraints                                           | Description                                            |
| :------------- | :--------------------- | :------- | :---------------------------------------------------- | :----------------------------------------------------- |
| `id`           | `string` (`uuid`)      | Yes      | UUIDv7                                                | Unique identifier assigned to the integration message  |
| `creationDate` | `string` (`date-time`) | Yes      | ISO 8601 UTC timestamp                                | UTC timestamp when the command was created             |
| `orderId`      | `string` (`uuid`)      | Yes      | Valid UUID; Kafka partition key; PII-redacted in logs | Identifier of the order whose basket cleanup succeeded |
| `totalMoney`   | `number`               | Yes      | Non-negative monetary amount                          | Total purchase amount associated with the order        |

## Delivery Guarantees & Error Handling

| Condition                             | System Behavior                                                                 | Recovery / Compensation                                                                      |
| :------------------------------------ | :------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------- |
| Duplicate delivery                    | Consumer logs the message again with no database or status side effects         | Naturally idempotent (no state mutation)                                                     |
| Activity publish failure in producer  | Durable orchestration retries up to 3 times (`5s` initial delay, `2.0` backoff) | Runs LIFO saga compensations if all retries fail                                             |
| Deserialization or processing failure | Retried with cooldown (`50ms`, `250ms`, `1s` with full jitter)                  | Exhausted messages route to [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]] |
