The `DeleteOrder` command (`DELETE /api/v1/orders/{id}`) soft-deletes an `Order` in **Ordering API** (v1.0.0) by setting `IsDeleted = true` while leaving its business status unchanged. Access is restricted to callers holding the Microsoft Entra ID `admin` role, and external callers reach this endpoint through the YARP **API Gateway** at `/ordering/api/v1/orders/{id}`.

## Parameters and fields

### Request parameters

`DeleteOrder` accepts no request body and requires no `x-request-id` header.

| Name | Type            | Required | Default | Constraints                          | Description                                    |
| :--- | :-------------- | :------- | :------ | :----------------------------------- | :--------------------------------------------- |
| `id` | `string` (UUID) | Yes      | —       | Path parameter; valid `OrderId` UUID | Unique identifier of the order to soft-delete. |

### Response

`204 No Content` with an empty response body confirms the order was soft-deleted.

## Behavior and side effects

- **Soft-delete without status transition:** `DeleteOrderHandler` retrieves the order via `repository.GetByIdAsync((Guid)request.Id, cancellationToken)`, throws `NotFoundException` (`404 Not Found`) if absent, calls `order.Delete()` to set `IsDeleted = true`, and saves inside a `[Transactional]` unit of work on PostgreSQL (`orderingdb`). The order's `Status` (`New`, `Completed`, or `Cancelled`) remains unchanged.
- **Global query filter:** `OrderConfiguration` registers `HasQueryFilter(x => !x.IsDeleted)`, which hides soft-deleted orders from standard read queries and causes subsequent `DELETE /api/v1/orders/{id}` calls for the same `{id}` to return `404 Not Found`.
- **No events emitted:** `Order.Delete()` raises no domain events, makes no Marten `OrderSummary` event-stream update, and publishes no Kafka integration events. To cancel an active order and notify downstream **Finance** and **Notification** workflows, use [[command|CancelOrder]] instead.

## Error responses

| Code / status               | Condition                                                                              | Recovery behavior                                                                    |
| :-------------------------- | :------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------- |
| `400 Bad Request`           | Path parameter `{id}` is not a valid UUID                                              | Supply a valid `OrderId` UUID; do not retry unchanged.                               |
| `401 Unauthorized`          | Missing, expired, or invalid Entra ID bearer token                                     | Acquire a fresh Entra ID access token and retry.                                     |
| `403 Forbidden`             | Authenticated caller lacks the `admin` role or `ordering_read`/`ordering_write` scopes | Authenticate with an `admin` token that includes the required scopes.                |
| `404 Not Found`             | Order does not exist or was already soft-deleted (`HasQueryFilter(x => !x.IsDeleted)`) | Verify the order identifier; treat as already soft-deleted if retrying a prior call. |
| `429 Too Many Requests`     | Caller exceeded `PerUserRateLimit` or global rate limits                               | Wait for the `Retry-After` header interval before retrying.                          |
| `500 Internal Server Error` | Unhandled database failure                                                             | Retry with backoff and inspect Ordering API logs.                                    |
