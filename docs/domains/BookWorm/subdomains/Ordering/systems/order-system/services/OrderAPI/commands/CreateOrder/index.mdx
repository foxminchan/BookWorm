The `CreateOrder` command (`POST /api/v1/orders`) creates a `New` order in **Ordering API** (v1.0.0) for the authenticated buyer by reading the caller's active basket from **Basket API** over gRPC and resolving current prices from **Catalog API** over gRPC. External callers reach this endpoint through the YARP **API Gateway** at `/ordering/api/v1/orders`.

## Behavior and side effects

- **Server-side basket and price resolution:** `CreateOrderHandler` reads `BuyerId` from `ClaimTypes.NameIdentifier`, calls **Basket API** (`basket.v1.BasketGrpcService.GetBasket`, 10-second gRPC deadline), and calls **Catalog API** (`book.v1.BookGrpcService.GetBooks`, 10-second gRPC deadline) with the distinct book IDs. For each item, it selects `book.PriceSale ?? book.Price`. If any book in the basket is missing from **Catalog API**, it throws `NotFoundException` (`404 Not Found`).
- **Distributed per-buyer lock:** Before saving the order, the handler acquires a FusionCache Redis distributed lock named `order-create:{userId}` (`TimeSpan.FromMinutes(1)`). If another checkout is already in progress for the same buyer, it throws `InvalidOperationException` (`409 Conflict`). The lock is released in a `finally` block.
- **Persistence and event pipeline:** Inside the `[Transactional]` unit of work on PostgreSQL (`orderingdb`), Ordering API saves the `Order` (`Status.New`, `Note = null`) and raises `OrderPlacedEvent`. `OrderEventHandler` creates the Marten `OrderSummary` stream, and Marten's Async Daemon (`MartenEventPublisher`) maps `OrderPlacedEvent` via `EventMapper` to `UserCheckedOutIntegrationEvent`, publishing it through the Wolverine PostgreSQL outbox (`wolverine` schema) to Kafka topic `bookworm.{env}.ordering.user-checked-out` (partitioned by `OrderId`) to start **Finance** orchestration.
- **Idempotency key lifecycle:** `IdempotencyEndpointFilter` claims `POST:{path}:{x-request-id}` in Redis for 3600 seconds (`409 Conflict` on replay) and deletes the key if the handler returns HTTP `5xx` or throws an exception.

Basket gRPC `GetBasket` returns an empty response when no basket exists; it does not return `NotFound`. `CreateOrderHandler` has no empty-items guard, and `Order` accepts an empty item list, so the handler proceeds to persistence and the endpoint returns `201 Created` if that save succeeds. No unit test covers this empty-basket case.

## Error responses

| Code / status               | Condition                                                                                                                                                                                    | Recovery behavior                                                                                    |
| :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------- |
| `400 Bad Request`           | Missing or whitespace `x-request-id` header (`ValidationException`), or non-GUID `NameIdentifier` claim (`ArgumentException`)                                                                | Provide a non-empty `x-request-id` header and valid token claims; do not retry unchanged.            |
| `401 Unauthorized`          | Missing, expired, or invalid Entra ID bearer token                                                                                                                                           | Acquire a fresh Entra ID access token and retry.                                                     |
| `403 Forbidden`             | Authenticated caller lacks `customer`/`admin` role or `ordering_read`/`ordering_write` scopes                                                                                                | Request the required Entra ID role and scopes before retrying.                                       |
| `404 Not Found`             | One or more basket book IDs do not exist in **Catalog API** (`NotFoundException`)                                                                                                            | Refresh the customer's basket to remove unavailable items before retrying with a new `x-request-id`. |
| `409 Conflict`              | Duplicate `x-request-id` within the 3600-second Redis TTL, or concurrent checkout lock held for the same buyer (`InvalidOperationException`: `"Other process is already creating an order"`) | Wait for the in-flight checkout to finish and query order history before retrying.                   |
| `429 Too Many Requests`     | Caller exceeded `PerUserRateLimit` or global rate limits                                                                                                                                     | Wait for the `Retry-After` header interval before retrying.                                          |
| `500 Internal Server Error` | Unhandled gRPC failure (`Basket API` or `Catalog API` timeout/error) or persistence failure                                                                                                  | Retry with backoff; `IdempotencyEndpointFilter` clears the Redis key on `5xx`/exception.             |
