## Publish a checkout event

[[service|order-api]] publishes this event after placing an Order, through
[[channel|bookworm.&#123;env&#125;.ordering.user-checked-out]].

- `id` identifies this integration event; `creationDate` is its UTC timestamp.
- `orderId` identifies the accepted Order.
- `basketId` currently contains the Order's Buyer ID, supplied by EventMapper.
- `fullName` and `email` are required fields but may contain null.
- `totalMoney` is the accepted purchase amount.

</Column>

<Column>

<CodeGroup dropdown>

```csharp UserCheckedOutIntegrationEvent.cs
[IntegrationMessageOwner(ServiceName = Services.Ordering, TopicName = "user-checked-out")]
[MessageIdentity("BookWorm.Contracts.UserCheckedOutIntegrationEvent")]
public sealed record UserCheckedOutIntegrationEvent(
    Guid OrderId,
    Guid BasketId,
    string? FullName,
    string? Email,
    decimal TotalMoney
) : IntegrationEvent;
```

```csharp EventMapper.cs
OrderPlacedEvent orderPlacedEvent => new UserCheckedOutIntegrationEvent(
    (Guid)orderPlacedEvent.Order.Id,
    (Guid)orderPlacedEvent.Order.BuyerId,
    fullName,
    email,
    orderPlacedEvent.Order.TotalPrice
)
```

## Coordinate checkout

The example shows the camelCase JSON data inside the BookWorm
CloudEvents-compatible envelope, not the full transport message. Finance uses
these checkout details for subsequent coordination. Publication does not
confirm basket cleanup, payment settlement, or Order completion.

Finance's `OrderSaga.Start` stores the checkout details in a new saga and
returns the placement command and initial timeout. This excerpt shows the
outgoing messages after that state has been initialized:

<CodeGroup dropdown>

```csharp OrderSaga.cs
var messages = new OutgoingMessages
{
    new PlaceOrderCommand(
        saga.BasketId,
        saga.FullName,
        saga.Email,
        saga.OrderId,
        saga.EffectiveTotalMoney
    ),
    new PlaceOrderTimeout(@event.OrderId, settings.MaxRetryTimeout),
};

return (saga, messages);
```
