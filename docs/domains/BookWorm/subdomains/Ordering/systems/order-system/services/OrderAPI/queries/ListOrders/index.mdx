`ListOrders` queries **Ordering API** (`GET /api/v1/orders`) to return a paginated list of order summaries (`OrderDto[]`) with optional status and buyer filters. Non-administrator callers are automatically scoped to their own authenticated Microsoft Entra ID buyer ID, while administrators (`admin` role) can filter across buyers.

## Overview

| Property              | Value                                                                                                                                |
| :-------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**             | Ordering bounded context (**Ordering API**, Aspire resource `ordering`)                                                              |
| **Source**            | `src/Services/Ordering/BookWorm.Ordering/Features/Orders/List/ListOrdersEndpoint.cs`, `ListOrdersQuery.cs`, `ListOrdersValidator.cs` |
| **Protocol / format** | HTTP `GET /api/v1/orders` (via API Gateway: `GET /ordering/api/v1/orders`), `ApiVersions.V1`, JSON (`application/json`)              |
| **Authentication**    | Microsoft Entra ID JWT required (`customer` or `admin` role; scopes `ordering_read`, `ordering_write`)                               |
| **Rate limiting**     | `PerUserRateLimit` token bucket (30 token limit, 20 tokens per 10 seconds, queue limit 5) plus global IP/concurrency limiters        |
| **Backing store**     | PostgreSQL (`orderingdb`, EF Core)                                                                                                   |
| **Contract version**  | `1.0.0`                                                                                                                              |

## Parameters and fields

### Query parameters

| Name        | Type            | Required | Default | Constraints                           | Description                                                                                                     |
| :---------- | :-------------- | :------- | :------ | :------------------------------------ | :-------------------------------------------------------------------------------------------------------------- |
| `PageIndex` | `integer`       | No       | `1`     | `> 0` (`ListOrdersValidator`)         | 1-based page number to retrieve                                                                                 |
| `PageSize`  | `integer`       | No       | `20`    | `> 0` (`ListOrdersValidator`)         | Maximum number of order summaries per page                                                                      |
| `Status`    | `string`        | No       | —       | Enum: `New`, `Cancelled`, `Completed` | Filters orders by lifecycle status                                                                              |
| `BuyerId`   | `string` (UUID) | No       | —       | Valid UUID (`Guid`)                   | Filters orders by buyer ID for `admin` callers; overridden with the caller's own buyer ID for non-admin callers |

### Response headers

`ListOrdersEndpoint` applies `WithPaginationHeaders()` (`PaginationHeaderFilter`), which appends two headers on `200 OK` responses:

| Header             | Format                                    | Description                                                                                                          |
| :----------------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------- |
| `Pagination-Count` | Integer string (for example, `57`)        | Total number of orders matching the active status and buyer filters across all pages                                 |
| `Link`             | Comma-separated `<uri>;rel=<rel>` entries | Navigation URIs with `first`, `self`, `last`, and conditional `previous` / `next` relations preserving query filters |

### Response schema (`OrderDto[]`)

A `200 OK` response body serializes `PagedResult<OrderDto>` as a JSON array of `OrderDto` summary objects. To retrieve line items for an order, call [[query|GetOrder]].

| Field       | Type     | Required | Constraints                           | Description                             |
| :---------- | :------- | :------- | :------------------------------------ | :-------------------------------------- |
| `[].id`     | `string` | Yes      | UUID                                  | Unique identifier of the order          |
| `[].date`   | `string` | Yes      | ISO 8601 `date-time`                  | UTC timestamp when the order was placed |
| `[].total`  | `number` | Yes      | Decimal currency amount               | Total recorded amount for the order     |
| `[].status` | `string` | Yes      | Enum: `New`, `Cancelled`, `Completed` | Current lifecycle status of the order   |

## Error responses

| Code / status           | Condition                                                                                                                                                    | Recovery behavior                                                   |
| :---------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------ |
| `400 Bad Request`       | `PageIndex <= 0`, `PageSize <= 0`, unrecognized `Status` enum value, or malformed `BuyerId` UUID (`application/problem+json` `HttpValidationProblemDetails`) | Correct invalid query parameters; do not retry unchanged            |
| `401 Unauthorized`      | Missing, expired, or invalid Entra ID bearer token                                                                                                           | Re-authenticate and retry                                           |
| `403 Forbidden`         | Authenticated principal lacks Ordering API roles or scopes                                                                                                   | Request a token with `customer` or `admin` role and Ordering scopes |
| `429 Too Many Requests` | Caller exceeded `PerUserRateLimit` or global rate limit (`application/problem+json` + `Retry-After` header)                                                  | Wait for the `Retry-After` duration before retrying                 |
