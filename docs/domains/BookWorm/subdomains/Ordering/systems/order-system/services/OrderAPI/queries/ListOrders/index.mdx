`ListOrders` queries [[service|order-api]] (`GET /ordering/api/v1/orders`) to return a paginated list of order summaries with optional status and buyer filters. Non-administrator callers are automatically scoped to their own authenticated Microsoft Entra ID buyer ID, while administrators (`admin` role) can filter across buyers.

## Overview

| Property                           | Value                                                                                                                             |
| :--------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------- |
| **Bounded Context**                | Ordering                                                                                                                          |
| **Owner Service**                  | [[service\|order-api]]                                                                                                            |
| **Protocol / Format**              | HTTP `GET`, `application/json` response                                                                                           |
| **Gateway Endpoint**               | `GET /ordering/api/v1/orders` (service path `/api/v1/orders`)                                                                     |
| **Authentication & Authorization** | Microsoft Entra ID JWT — `customer` or `admin` role plus scopes `ordering_read`, `ordering_write`                                 |
| **Idempotency / Concurrency**      | Read-only and naturally idempotent                                                                                                |
| **Rate Limit / Caching**           | Global concurrency (`100`), per-IP fixed-window (`30 req/min`), and per-user token bucket (`30` limit, `20` per `10s`, queue `5`) |
| **Contract Version**               | `1.0.0` (`ApiVersions.V1`)                                                                                                        |

## Request & Response Contract

### Query Parameters

| Name        | Type              | Required | Constraints                           | Description                                                                                                     |
| :---------- | :---------------- | :------- | :------------------------------------ | :-------------------------------------------------------------------------------------------------------------- |
| `PageIndex` | `integer`         | No       | Default `1`; must be `> 0`            | 1-based page number to retrieve                                                                                 |
| `PageSize`  | `integer`         | No       | Default `20`; must be `> 0`           | Maximum number of order summaries per page                                                                      |
| `Status`    | `string`          | No       | Enum: `New`, `Cancelled`, `Completed` | Filters orders by lifecycle status                                                                              |
| `BuyerId`   | `string` (`uuid`) | No       | Valid UUID                            | Filters orders by buyer ID for `admin` callers; overridden with the caller's own buyer ID for non-admin callers |

### Response Headers (`200 OK`)

| Name               | Type     | Required | Constraints                               | Description                                                                                                          |
| :----------------- | :------- | :------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------- |
| `Pagination-Count` | `string` | Yes      | Integer string (e.g., `57`)               | Total number of orders matching the active status and buyer filters across all pages                                 |
| `Link`             | `string` | Yes      | Comma-separated `<uri>;rel=<rel>` entries | Navigation URIs with `first`, `self`, `last`, and conditional `previous` / `next` relations preserving query filters |

### Success Response (`200 OK`)

Returns a JSON array of order summary objects. To retrieve line items for an order, call [[query|GetOrder]].

| Name        | Type                   | Required | Constraints                           | Description                             |
| :---------- | :--------------------- | :------- | :------------------------------------ | :-------------------------------------- |
| `[].id`     | `string` (`uuid`)      | Yes      | Valid UUID                            | Unique identifier of the order          |
| `[].date`   | `string` (`date-time`) | Yes      | ISO 8601 UTC timestamp                | UTC timestamp when the order was placed |
| `[].total`  | `number`               | Yes      | Decimal currency amount               | Total recorded amount for the order     |
| `[].status` | `string`               | Yes      | Enum: `New`, `Cancelled`, `Completed` | Current lifecycle status of the order   |

## Behavior & Side Effects

- **Role-scoped filtering:** Standard customers only see their own orders (any `BuyerId` parameter is overridden); administrators can filter across all buyers.
- **No state mutation:** Pure read query with no database writes or integration events.

## Error Responses

| Status / Code           | Condition                                                                                        | Client Recovery Action                                              |
| :---------------------- | :----------------------------------------------------------------------------------------------- | :------------------------------------------------------------------ |
| `400 Bad Request`       | `PageIndex <= 0`, `PageSize <= 0`, unrecognized `Status` enum value, or malformed `BuyerId` UUID | Correct invalid query parameters; do not retry unchanged            |
| `401 Unauthorized`      | Missing, expired, or invalid Entra ID bearer token                                               | Re-authenticate and retry                                           |
| `403 Forbidden`         | Caller lacks Ordering API roles or scopes                                                        | Request a token with `customer` or `admin` role and Ordering scopes |
| `429 Too Many Requests` | Rate limit quota exceeded (`Retry-After` header included)                                        | Wait for the `Retry-After` duration before retrying                 |
