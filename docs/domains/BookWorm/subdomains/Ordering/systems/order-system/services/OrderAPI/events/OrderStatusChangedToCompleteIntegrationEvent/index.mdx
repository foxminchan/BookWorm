`OrderStatusChangedToCompleteIntegrationEvent` (v1.0.0) reports that Ordering API transitioned an `Order` aggregate from `New` to `Completed`. Finance consumes this event to complete its Durable Task orchestration instance and dispatch `CompleteOrderCommand` to Notification; it confirms an authoritative order status change and is neither a completion request nor an email delivery receipt.

## Overview

| Property              | Value                                                                                                              |
| :-------------------- | :----------------------------------------------------------------------------------------------------------------- |
| **Owner**             | Ordering bounded context (`Ordering API`)                                                                          |
| **Producer**          | [[service\|order-api]]                                                                                             |
| **Consumer**          | [[service\|order-orchestration]] (`OrderOrchestrator`)                                                             |
| **Source**            | `src/Services/Ordering/BookWorm.Ordering/IntegrationEvents/Events/OrderStatusChangedToCompleteIntegrationEvent.cs` |
| **Protocol / format** | Kafka + CloudEvents JSON (Wolverine)                                                                               |
| **Kafka topic**       | `bookworm.{env}.ordering.order-status-change-to-complete` (where `{env}` is the kebab-case environment name)       |
| **Message identity**  | `BookWorm.Contracts.OrderStatusChangedToCompleteIntegrationEvent`                                                  |
| **Partition key**     | `OrderId` (preserves per-order saga ordering on Kafka)                                                             |
| **Outbox**            | Wolverine PostgreSQL outbox (`orderingdb`, `wolverine` schema) with EF Core transactional middleware               |

## Parameters and fields

The schema below defines the camelCase JSON `data` payload carried inside the CloudEvents envelope (`additionalProperties: false` in JSON Schema). All seven properties are present in the serialized contract, including nullable `fullName` and `email`.

| Name           | Type                 | Required | Default                 | Constraints                                              | Description                                                                    |
| :------------- | :------------------- | :------- | :---------------------- | :------------------------------------------------------- | :----------------------------------------------------------------------------- |
| `id`           | `string` (UUID)      | Yes      | `Guid.CreateVersion7()` | UUID v7 inherited from `IntegrationEvent`                | Unique identifier for this integration event instance.                         |
| `creationDate` | `string` (date-time) | Yes      | `DateTime.UtcNow`       | ISO 8601 UTC timestamp inherited from `IntegrationEvent` | UTC timestamp when Ordering API created the event.                             |
| `orderId`      | `string` (UUID)      | Yes      | —                       | Valid UUID; also used as Kafka partition key             | Identifier of the completed `Order`.                                           |
| `basketId`     | `string` (UUID)      | Yes      | —                       | Valid UUID (currently populated from `Order.BuyerId`)    | Buyer-linked basket reference supplied by Ordering `EventMapper`.              |
| `fullName`     | `string \| null`     | Yes      | `null`                  | Nullable string                                          | Customer full name when available on the buyer record.                         |
| `email`        | `string \| null`     | Yes      | `null`                  | Nullable email format                                    | Customer email address when available; Finance skips email dispatch if absent. |
| `totalMoney`   | `number` (`decimal`) | Yes      | —                       | Non-negative monetary amount                             | Total purchase amount associated with the completed order.                     |

:::note
The current Ordering `EventMapper` populates `basketId` with the order's `BuyerId`. Downstream consumers must not assume `basketId` was independently resolved from Basket API.
:::

### CloudEvents envelope headers

| `requestid`   | Propagated from the triggering HTTP request                       | Correlates order completion across Ordering API, Finance, and Notification. |

## Error handling and delivery guarantees

| Condition                               | Behavior                                                                                                            | Recovery behavior                                                                     |
| :-------------------------------------- | :------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------ |
| `email` or `fullName` is `null`         | Payload remains valid; Finance checks `order.CanSendNotification` before dispatching `CompleteOrderCommand`.        | Consumers must tolerate `null` contact fields without failing deserialization.        |
| Transient broker or orchestration error | Wolverine outbox guarantees at-least-once publication from `orderingdb`; Kafka trigger retries delivery to Finance. | Inspect Durable Task Scheduler state and `bookworm.{env}.ordering.dead-letter-queue`. |
| Contract mismatch                       | Caught in CI by Pact consumer/provider verification.                                                                | Verify against `tests/pacts/Finance-Ordering.json`.                                   |
