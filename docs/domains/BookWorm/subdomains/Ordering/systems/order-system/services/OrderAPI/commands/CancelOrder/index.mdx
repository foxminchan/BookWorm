The `CancelOrder` command (`PATCH /api/v1/orders/{orderId}/cancel`) transitions an existing `Order` from `New` to `Cancelled` in **Ordering API** (v1.0.0) and triggers downstream cancellation orchestration through Kafka. External callers reach this endpoint through the YARP **API Gateway** at `/ordering/api/v1/orders/{orderId}/cancel`.

## Behavior and side effects

- **Access scoping:** Callers with the Entra ID `admin` role query orders using `OrderFilterSpec(orderId, Status.New)`. Callers without `admin` (customers) query using `OrderFilterSpec(orderId, buyerId)`, where `buyerId` is parsed as a GUID from `ClaimTypes.NameIdentifier`.
- **State transition:** `Order.MarkAsCanceled()` invokes `OrderLifecycleDecider` to transition `Status.New` to `Status.Cancelled` and raises `OrderCancelledEvent`. Orders already in `Status.Cancelled` or `Status.Completed` cannot transition again: admins receive `404 Not Found` (filtered out by `OrderFilterSpec`), whereas customers hitting their own non-`New` order trigger `OrderingDomainException`.
- **Event store and Kafka outbox:** Inside the `[Transactional]` unit of work on PostgreSQL (`orderingdb`), `OrderEventHandler` appends `OrderCancelledEvent` to the Marten `OrderSummary` stream. Marten's Async Daemon (`MartenEventPublisher`) maps it via `EventMapper` to `OrderStatusChangedToCancelIntegrationEvent` and publishes it through the Wolverine PostgreSQL outbox (`wolverine` schema) to Kafka topic `bookworm.{env}.ordering.order-status-change-to-cancel` (partitioned by `OrderId`).
- **Idempotency key lifecycle:** `IdempotencyEndpointFilter` claims `PATCH:{path}:{x-request-id}` in Redis with `When.NotExists` for 3600 seconds. Duplicate requests within that window return `409 Conflict`. If the handler returns HTTP `5xx` or throws an exception, the filter deletes the Redis key so the client can safely retry.

## Error responses

| Code / status               | Condition                                                                                                                                         | Recovery behavior                                                                         |
| :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------- |
| `400 Bad Request`           | Missing or whitespace `x-request-id` header (`ValidationException`), or non-GUID `NameIdentifier` claim (`ArgumentException`)                     | Provide a non-empty `x-request-id` header and valid token claims; do not retry unchanged. |
| `401 Unauthorized`          | Missing, expired, or invalid Entra ID bearer token                                                                                                | Acquire a fresh Entra ID access token and retry.                                          |
| `403 Forbidden`             | Authenticated caller lacks `customer`/`admin` role or `ordering_read`/`ordering_write` scopes                                                     | Request the required Entra ID role and scopes before retrying.                            |
| `404 Not Found`             | Order does not exist, is soft-deleted, belongs to another buyer, or (for `admin`) is not in `New` status                                          | Verify the `orderId` and current order status; do not retry unchanged.                    |
| `409 Conflict`              | `x-request-id` was already processed for this path within the 3600-second Redis TTL (`ProblemDetails`)                                            | Treat as a duplicate submission and query the order status before taking further action.  |
| `412 Precondition Failed`   | Concurrent PostgreSQL (`DbUpdateConcurrencyException`) or Marten (`ConcurrencyException`) update conflict                                         | Refresh the order state and retry with a new `x-request-id` if the order is still `New`.  |
| `429 Too Many Requests`     | Caller exceeded `PerUserRateLimit` or global rate limits                                                                                          | Wait for the `Retry-After` header interval before retrying.                               |
| `500 Internal Server Error` | Customer attempted to cancel an owned order already in `Cancelled` or `Completed` status (`OrderingDomainException`), or unhandled server failure | Inspect the order's current status; do not retry non-`New` transitions.                   |
