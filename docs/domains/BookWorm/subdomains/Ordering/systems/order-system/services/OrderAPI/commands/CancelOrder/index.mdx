`CancelOrder` transitions an existing order from `New` to `Cancelled` in [[service|order-api]] (`PATCH /ordering/api/v1/orders/{orderId}/cancel`) and triggers downstream cancellation orchestration through Kafka.

## Behavior & Side Effects

- **Access scoping:** Administrators can target any `New` order; customers can only target orders matching their authenticated buyer ID.
- **State transition:** Transitions `New` to `Cancelled`. Orders already in `Cancelled` or `Completed` status cannot transition again (admins receive `404 Not Found`; customers targeting their own non-`New` order receive `500 Internal Server Error`).
- **Event publishing:** Appends the cancellation event to the event store and publishes [[event|OrderStatusChangedToCancelIntegrationEvent]] via transactional outbox to [[channel|bookworm.&#123;env&#125;.ordering.order-status-change-to-cancel]] (partitioned by `OrderId`).
- **Idempotency key lifecycle:** Claims the `x-request-id` key in Redis for 3600 seconds (`409 Conflict` on replay) and deletes the key if the operation fails with `5xx` so retries can proceed.

## Error Responses

| Status / Code               | Condition                                                                                                             | Client Recovery Action                                                                   |
| :-------------------------- | :-------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------- |
| `400 Bad Request`           | Missing or whitespace `x-request-id` header, or invalid user identifier claim                                         | Provide a non-empty `x-request-id` header and valid token claims; do not retry unchanged |
| `401 Unauthorized`          | Missing, expired, or invalid Entra ID bearer token                                                                    | Acquire a fresh Entra ID access token and retry                                          |
| `403 Forbidden`             | Caller lacks `customer`/`admin` role or `ordering_read`/`ordering_write` scopes                                       | Request the required Entra ID role and scopes before retrying                            |
| `404 Not Found`             | Order does not exist, is soft-deleted, belongs to another buyer, or (for `admin`) is not in `New` status              | Verify the `orderId` and current order status; do not retry unchanged                    |
| `409 Conflict`              | Duplicate `x-request-id` for this path within the 3600-second TTL                                                     | Treat as a duplicate submission and query order status before taking further action      |
| `412 Precondition Failed`   | Concurrent update conflict on the order or event stream                                                               | Refresh order state and retry with a new `x-request-id` if still `New`                   |
| `429 Too Many Requests`     | Rate limit quota exceeded (`Retry-After` header included)                                                             | Wait for the `Retry-After` interval before retrying                                      |
| `500 Internal Server Error` | Customer attempted to cancel an owned order already in `Cancelled` or `Completed` status, or unhandled server failure | Inspect the order's current status; do not retry non-`New` transitions                   |
