## 1. Publish Order Completion Event to Kafka

When an order transitions to `Completed`, **Ordering API** dispatches `OrderStatusChangedToCompleteIntegrationEvent` via `IEventDispatcher` so **Finance** can complete the orchestration saga and emit `CompleteOrderCommand`.

### Payload details

- `id`: UUIDv7 generated by `IntegrationEvent` (`Guid.CreateVersion7()`).
- `creationDate`: UTC ISO 8601 timestamp (`DateTime.UtcNow`).
- `orderId`: UUID of the completed order (Kafka partition key).
- `basketId`: UUID serialized as `basketId` (supplied from `Order.BuyerId` by `OrderEventMapper`).
- `fullName`: Customer name (`string | null`).
- `email`: Customer email (`string | null`).
- `totalMoney`: Order total (`decimal`).

### Example payload

```json
{
	"id": "01960a1b-9002-7c00-8a9b-0c1d2e3f4g02",
	"creationDate": "2026-11-25T16:25:00Z",
	"orderId": "01960a1b-3c4d-7e00-8a9b-0c1d2e3f4a99",
	"basketId": "01960a1b-2c3d-7e4f-8a9b-0c1d2e3f4a01",
	"fullName": "Minh Nguyen",
	"email": "minh.nguyen@bookworm.dev",
	"totalMoney": 59.98
}
```

### Using this example

**Ordering API** publishes `OrderStatusChangedToCompleteIntegrationEvent` to `bookworm.{env}.ordering.order-complete` via its transactional outbox; **Finance** raises the external event to `OrderOrchestrator`, which issues `CompleteOrderCommand`.

    Guid OrderId,
    Guid BasketId,
    string? FullName,
    string? Email,
    decimal TotalMoney
