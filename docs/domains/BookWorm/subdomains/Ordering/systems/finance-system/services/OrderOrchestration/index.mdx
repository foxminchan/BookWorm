## Service Responsibility & Boundary

Order Orchestration is an internal durable workflow worker within the [[domain|ordering]] domain that coordinates post-checkout basket cleanup retries and order lifecycle email commands over Kafka. It tracks one orchestration instance per Order ID in Azure Durable Task Scheduler, delegating authoritative Order state to [[service|order-api]], basket deletion to [[service|basket-api]], and email delivery to [[service|notification-api]]. It does not process payments or expose HTTP or gRPC endpoints.

## Service Profile

| Property                                  | Value                                                                                                  |
| :---------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| **Bounded Context / Domain**              | [[domain\|ordering]]                                                                                   |
| **Owner Team**                            | [[team\|commerce-fulfillment-team]]                                                                    |
| **Runtime Style**                         | Durable Orchestrator & Async Kafka Worker                                                              |
| **Public / Gateway Exposure**             | Internal Only (no HTTP or gRPC API)                                                                    |
| **Authentication & Authorization Policy** | Internal worker; Azure Managed Identity RBAC for Durable Task Scheduler                                |
| **Owned Data Store(s)**                   | Azure Durable Task Scheduler (orchestration state and timers, keyed by Order ID)                       |
| **Key Resilience / Idempotency Pattern**  | Order-ID correlation deduplicating checkout events and bounded 30-minute retry timers (max 3 attempts) |

## Contracts & Data Ownership

Order Orchestration owns only per-order coordination saga state (`Placed`, `BasketDeletionFailed`, `Completed`, `Cancelled`).

:::note
Despite the Finance system name, this service does **not** authorize or settle payments. [[service|order-api]] remains the sole authority for Order aggregates and business status; timeout exhaustion in Order Orchestration marks only the coordination workflow cancelled without cancelling the Order itself.
:::

:::warning
Both [[service|basket-api]] and [[service|notification-api]] consume [[command|PlaceOrderCommand]] on the same topic. When a durable timeout reissues [[command|PlaceOrderCommand]], both consumers receive the retry, which can generate an additional placement email.
:::
