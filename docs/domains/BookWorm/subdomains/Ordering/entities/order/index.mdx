`Order` is the Ordering aggregate root for an accepted purchase placed by a buyer. Ordering API owns it and persists it in PostgreSQL (`orderingdb`) through EF Core, with a Marten event store in the same database for order summaries.

## Lifecycle rules

`Order` delegates transitions to `OrderLifecycleDecider`. Only orders in `New` can move to a terminal state.

| Current status | `MarkAsCompleted()`                                | `MarkAsCanceled()`                                 |
| :------------- | :------------------------------------------------- | :------------------------------------------------- |
| `New`          | Moves to `Completed`; raises `OrderCompletedEvent` | Moves to `Cancelled`; raises `OrderCancelledEvent` |
| `Completed`    | Throws `OrderingDomainException`                   | Throws `OrderingDomainException`                   |
| `Cancelled`    | Throws `OrderingDomainException`                   | Throws `OrderingDomainException`                   |

- **Placement:** The constructor sets `status` to `New` and raises `OrderPlacedEvent`.
- **Soft delete:** `Delete()` sets `isDeleted = true` without changing `status`. EF Core hides deleted orders and their items.
- **Saga separation:** Finance orchestration progress, basket deletion outcomes, and email delivery are tracked outside `Order`.

Repeated `Complete` actions on a completed order and repeated `Cancel` actions on a canceled order are idempotent in `OrderLifecycleDecider`; they return the existing state with no new transition. Completing a canceled order or canceling a completed order throws `OrderingDomainException`.

## Relationships

| Related entity         | Cardinality                    | Mapping                                     |
| :--------------------- | :----------------------------- | :------------------------------------------ |
| [[entity\|buyer]]      | Many orders to one buyer       | `buyer_id`                                  |
| [[entity\|order-item]] | One order to many items        | `order_items.order_id`, `ON DELETE CASCADE` |
| [[entity\|book]]       | Referenced through order items | Cross-service reference; no foreign key     |

The `Buyer` relationship is nullable at the database-delete policy level: `BuyerConfiguration` sets `ON DELETE SET NULL`, while `OrderConfiguration` still excludes orphaned order items through the aggregate relationship. Buyer deletion does not cascade-delete accepted orders.
