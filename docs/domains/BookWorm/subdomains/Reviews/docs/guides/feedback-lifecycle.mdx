## Purpose

Reviews owns the individual [[entity|feedback]] record for a Catalog
[[entity|book]]. The feedback record contains the Book ID, reviewer names, an integer rating from 0
through 5, and an optional comment.

Catalog remains the source of truth for the Book and owns only the derived
average-rating and review-count projection. Reviews must not write Catalog
data or share the [[container|rating-database]] with another bounded context.

## Create feedback

1. Authenticate the caller, then use [[command|CreateFeedback]] to submit the
   Book ID, reviewer first name, reviewer last name, optional comment, and
   rating.
2. Validate that the Book ID and reviewer names are non-empty, the comment
   satisfies the service length limit, and the rating is an integer from 0
   through 5.
3. Persist the feedback aggregate in [[container|rating-database]].
4. Return the new feedback identifier.
5. After the transaction commits, publish
   [[event|FeedbackCreatedIntegrationEvent]] on
   [[channel|bookworm.&#123;env&#125;.rating.feedback-create]].

The event is a change to committed feedback, not a notification that Catalog
has already updated its projection.

## Read feedback and summaries

- List feedback through [[query|ListFeedbacks]] with a Book ID, pagination,
  ordering, and direction.
- Generate a summary through [[query|SummarizeFeedback]] when an
  insight is needed. The [[agent|rating-agent]] reads current Catalog context
  and raw feedback, then returns a classification, metrics, justification, and
  confidence.
- Treat summaries as read-time derived insight. They do not replace feedback,
  change a rating, or update Catalog.

## Delete feedback

1. Use [[command|DeleteFeedback]] with administrator authorization for the feedback ID.
2. A missing feedback ID is a not-found outcome; do not treat it as a
   successful deletion.
3. After the aggregate is removed, publish
   [[event|FeedbackDeletedIntegrationEvent]] on
   [[channel|bookworm.&#123;env&#125;.rating.feedback-delete]].
4. Catalog applies the deletion to its rating projection asynchronously.

## Consistency expectations

Catalog's `average_rating` and `total_reviews` can lag behind Reviews while
Kafka delivery or processing is pending. Consumers must be idempotent because
the integration channels provide at-least-once delivery.

If Catalog rejects a created-feedback event because the Book does not exist,
follow the **Recover a failed Catalog rating projection** procedure in the
Runbooks section. That compensation removes the invalid feedback reference; it
is not a customer initiated deletion.
