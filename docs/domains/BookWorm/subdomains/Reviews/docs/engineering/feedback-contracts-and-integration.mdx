This reference defines the HTTP v1 API, validation constraints, **Azure Cosmos DB** (`ratingdb` / `feedbacks`) storage model, Kafka event contracts, and read-only AI summarization rules for **Rating API** (`rating`) in the **Reviews** subdomain.

## Overview

| Property                | Value                                                                                                                                                                                                                      |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**               | Reviews subdomain (**Rating API**, `rating`)                                                                                                                                                                               |
| **Source**              | `src/Services/Rating/BookWorm.Rating/`                                                                                                                                                                                     |
| **Primary store**       | **Azure Cosmos DB** (`cosmos`): database `ratingdb`, container `feedbacks`, partition key `/bookId`, EF Core Cosmos provider with ETag concurrency, Wolverine Cosmos DB persistence (**no PostgreSQL**)                    |
| **Cache & idempotency** | **Redis** (`redis`): FusionCache (`ListFeedbacks` 10-minute TTL tagged by `BookId`) and 24-hour `IIntegrationEventIdempotencyGuard`                                                                                        |
| **Protocols**           | HTTP v1 (`/api/v1/feedbacks` via API Gateway `/rating/api/v1/feedbacks`), A2A gRPC (`MapGrpcA2A`, `read` policy), MCP client (`mcptools`), Kafka CloudEvents JSON                                                          |
| **Authentication**      | Microsoft Entra ID JWT + Entra Agent Identity (`ratingAgentId`); `admin` policy (`admin` role + `rating_read`/`rating_write`) on `DELETE`; authenticated caller on `/summarize`; `read` policy (`rating_read`) on A2A gRPC |

## Integration boundary overview

Rating API persists individual `Feedback` documents in Azure Cosmos DB, publishes post-commit Kafka events to Catalog API (PostgreSQL `catalogdb`), and exposes read-only AI summarization via `rating-agent`.

## HTTP API contract

All routes are versioned under `ApiVersions.V1` (`/api/v1/feedbacks`, routed externally via `/rating/api/v1/feedbacks`) and apply `PerUserRateLimit`:

| Method   | Path                               | Authorization                                                | Success response                                           | Behavior                                                                                                                                             |
| :------- | :--------------------------------- | :----------------------------------------------------------- | :--------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/api/v1/feedbacks`                | Rate-limited (`PerUserRateLimit`)                            | `200 OK` (`FeedbackId` UUIDv7)                             | Validates payload, saves `Feedback` to Cosmos DB `ratingdb`/`feedbacks`, and publishes `FeedbackCreatedIntegrationEvent` after commit                |
| `GET`    | `/api/v1/feedbacks`                | Rate-limited (`PerUserRateLimit`)                            | `200 OK` (`PagedResult<FeedbackDto>` + pagination headers) | Returns cached (10-minute FusionCache) paged feedback for `bookId` with optional `pageIndex`, `pageSize`, `orderBy`, `isDescending`                  |
| `DELETE` | `/api/v1/feedbacks/{id}`           | `admin` policy (`admin` role + `rating_read`/`rating_write`) | `204 No Content`                                           | Loads feedback by `id` (returns `404 Not Found` if missing), removes it from Cosmos DB, and publishes `FeedbackDeletedIntegrationEvent` after commit |
| `GET`    | `/api/v1/feedbacks/{id}/summarize` | Authenticated (`RequireAuthorization()`)                     | `200 OK` (`SummarizeResult`)                               | Runs read-only `rating-agent` over current Catalog context and raw feedback for book `id`                                                            |

## Parameters and validation rules

### `CreateFeedbackCommand` fields

| Field       | Type     | Required | Constraints                                           | Notes                                                                                                  |
| :---------- | :------- | :------- | :---------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| `bookId`    | `Guid`   | Yes      | Non-empty UUID                                        | Cosmos DB partition key (`/bookId`)                                                                    |
| `firstName` | `string` | Yes      | Non-empty, max `50` chars (`DataSchemaLength.Medium`) | Tagged `[PIIData]` for log redaction                                                                   |
| `lastName`  | `string` | Yes      | Non-empty, max `50` chars (`DataSchemaLength.Medium`) | Tagged `[PIIData]` for log redaction                                                                   |
| `comment`   | `string` | No       | Max `1000` chars (`DataSchemaLength.Max`)             | Optional review text                                                                                   |
| `rating`    | `int`    | Yes      | Inclusive integer `0`-`5`                             | Enforced in both `CreateFeedbackValidator` and `Feedback` domain constructor (`RatingDomainException`) |

### `ListFeedbacksQuery` parameters

| Parameter      | Type     | Required | Default  | Constraints        |
| :------------- | :------- | :------- | :------- | :----------------- |
| `bookId`       | `Guid`   | Yes      | —        | Target book UUID   |
| `pageIndex`    | `int`    | No       | `1`      | Greater than `0`   |
| `pageSize`     | `int`    | No       | `10`     | Greater than `0`   |
| `orderBy`      | `string` | No       | `Rating` | Sort property name |
| `isDescending` | `bool`   | No       | `false`  | Sort direction     |

## Kafka integration contracts

All Reviews and Catalog rating topics use CloudEvents JSON over Kafka, partitioned by `BookId` or `FeedbackId`, with at-least-once delivery and 24-hour Redis `IIntegrationEventIdempotencyGuard`:

| Event                                     | Kafka topic                                        | Producer → Consumer      | Payload fields                   | Semantics                                                                                                                      |
| :---------------------------------------- | :------------------------------------------------- | :----------------------- | :------------------------------- | :----------------------------------------------------------------------------------------------------------------------------- |
| `FeedbackCreatedIntegrationEvent`         | `bookworm.{env}.rating.feedback-create`            | Rating API → Catalog API | `BookId`, `Rating`, `FeedbackId` | Published after Cosmos DB commit; Catalog calls `book.AddRating(Rating)` in `catalogdb`                                        |
| `FeedbackDeletedIntegrationEvent`         | `bookworm.{env}.rating.feedback-delete`            | Rating API → Catalog API | `BookId`, `Rating`, `FeedbackId` | Published after Cosmos DB delete (`Feedback.Remove()`); Catalog calls `book.RemoveRating(Rating)`                              |
| `BookUpdatedRatingFailedIntegrationEvent` | `bookworm.{env}.catalog.book-update-rating-failed` | Catalog API → Rating API | `FeedbackId`                     | Published when Catalog cannot find `BookId`; Rating calls `feedback.Revert()` and deletes the record (no-op if already absent) |

## Error responses

| Status                  | Condition                                                                                                                              | Recovery behavior                                               |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------- |
| `400 Bad Request`       | Validation failure (empty `bookId`/`firstName`/`lastName`, `rating` outside `0`-`5`, `comment` > `1000` chars, or non-positive paging) | Fix request payload; do not retry unchanged                     |
| `401 Unauthorized`      | Missing or invalid Microsoft Entra ID token on `/summarize` or `DELETE`                                                                | Re-authenticate and retry                                       |
| `403 Forbidden`         | Authenticated caller lacks `admin` policy on `DELETE /api/v1/feedbacks/{id}`                                                           | Use an administrator account                                    |
| `404 Not Found`         | `DELETE` targets a nonexistent `FeedbackId` or `/summarize` targets an unknown book                                                    | Verify identifier; missing feedback is never converted to `204` |
| `429 Too Many Requests` | Caller exceeded `PerUserRateLimit`                                                                                                     | Wait for `Retry-After` duration before retrying                 |

## AI summarization boundary

- **Read-only agent:** `rating-agent` (defined in `Agents/rating-agent.yaml`, governed by `Policies/rating-agent.yaml` and Presidio PII middleware) reads Catalog context via MCP `get_book` and raw feedback via `GetCustomerReviews`.
- **No mutations:** Summarization never writes to Cosmos DB `ratingdb`/`feedbacks` or Catalog `catalogdb`.
- **Derived output:** Classification, metrics, justification, and confidence in `SummarizeResult` are read-time derived insights, never authoritative rating scores.

## Pre-merge change checklist

1. Update FluentValidation rules, OpenAPI v1 metadata, and `ProblemDetails` responses for any HTTP change.
2. Preserve Cosmos DB container `feedbacks` mapping, `/bookId` partition key, and ETag concurrency in `FeedbackConfiguration.cs`.
3. Verify `FeedbackCreatedIntegrationEvent` and `FeedbackDeletedIntegrationEvent` emit only after commit, and `Feedback.Revert()` does not emit `FeedbackDeletedIntegrationEvent`.
4. Verify duplicate Kafka delivery and missing-book compensation (`BookUpdatedRatingFailedIntegrationEvent`).
5. Run `mise run format`, `mise run build`, and `mise run test` (confirming Pact suites `Rating-Catalog` and `Catalog-Rating` pass).
