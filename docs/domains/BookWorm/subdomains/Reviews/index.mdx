Reviews is BookWorm's Supporting bounded context for individual customer book feedback (`Feedback` records containing a `BookId` reference, `0`–`5` integer rating, reviewer names, and optional comment). `Rating API` stores authoritative feedback in **Azure Cosmos DB** (`ratingdb` / `feedbacks` container partitioned by `/bookId`), publishes rating changes to Catalog over Kafka with compensating cleanup for missing books, and hosts the remote `Rating Agent` over HTTP and A2A gRPC.

## Scope and constraints

- **In scope:** Creating, listing, and deleting individual customer feedback records, enforcing uniqueness per `(BookId, reviewer name)`, publishing rating change events to Catalog, compensating invalid book references, and generating read-only AI feedback summaries.
- **Out of scope:** Owning canonical book metadata (`Catalog`), managing baskets (`Shopping`), or processing orders (`Ordering`).
- **Key constraints:** Rating API uses **Azure Cosmos DB** with `WolverineFx.CosmosDb` persistence and **no PostgreSQL database**. AI-generated feedback summaries never alter stored `Feedback` records or Catalog's numeric rating summary.

## Runtime view

- **Feedback creation and projection:** Rating API persists the `Feedback` document in Cosmos DB and publishes `FeedbackCreatedIntegrationEvent` (`bookworm.{env}.rating.feedback-create`, partitioned by `BookId`/`FeedbackId`). Catalog consumes the event and updates its derived `averageRating` and `totalReviews`.
- **Feedback deletion:** Authorized removal publishes `FeedbackDeletedIntegrationEvent` (`bookworm.{env}.rating.feedback-delete`) so Catalog recalculates its derived summary.
- **Missing-book compensation:** If Catalog cannot locate the referenced `BookId`, Catalog publishes `BookUpdatedRatingFailedIntegrationEvent` (`bookworm.{env}.catalog.book-update-rating-failed`). Rating API deletes the orphaned `Feedback` record idempotently (already-deleted records are a safe no-op).
- **AI summarization:** `Rating Agent` screens feedback text through Presidio PII middleware, queries Microsoft Foundry under `Policies/rating-agent.yaml` guardrails, and caches the resulting summary in Redis via FusionCache.

## Deployment and cross-cutting concerns

- **Hosting and ingress:** `rating` runs behind the YARP API Gateway (`/rating/{**remainder}`) with internal Container App ingress; Chat API reaches `Rating Agent` internally via A2A gRPC.
- **Security and privacy:** Microsoft Entra ID enforces `admin` and `read` policies; Entra Agent Identity (`ratingAgentId`) handles OBO token exchange; `rating-identity` authenticates passwordlessly to Cosmos DB (custom Cosmos Data Role), Redis, and Microsoft Foundry. Presidio redacts PII before LLM calls.
- **Observability and resilience:** OpenTelemetry correlates HTTP, A2A gRPC, Cosmos DB, and Kafka spans by `BookId` and `FeedbackId`; exhausted Kafka listeners route to `bookworm.{env}.rating.dead-letter-queue`.

## Quality scenarios and known risks

| Quality attribute / risk | Scenario or exposure                                                               | Current mitigation or gap                                                                                        |
| :----------------------- | :--------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------- |
| **Eventual consistency** | Catalog's rating summary lags newly submitted feedback                             | Intentional decoupling so storefront discovery never depends synchronously on Reviews                            |
| **Data hygiene**         | Feedback submitted for a deleted or nonexistent book UUID                          | Explicit Kafka compensation (`BookUpdatedRatingFailedIntegrationEvent`) deletes orphaned feedback idempotently   |
| **Reviewer uniqueness**  | Duplicate reviews limited by `(BookId, reviewer name)` rather than user subject ID | Relies on reviewer-name uniqueness; changing to verified buyer-ID scoping would require a domain contract update |
