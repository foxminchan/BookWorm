## Purpose & Ownership Boundary

Rating Database (`ratingdb`) is the authoritative Azure Cosmos DB system of record owned exclusively by [[service|rating-api]] in the Reviews bounded context. Cosmos DB was chosen for low-latency, single-partition document reads keyed by `/bookId` when listing book reviews or running AI summarization, alongside native Wolverine Cosmos DB message persistence.

## Consistency, Isolation & Security Guardrails

- **ETag optimistic concurrency & conflicts:** Concurrent modifications raise ETag concurrency failures, and duplicate/conflict responses (`409 Conflict`) are surfaced cleanly at the API boundary. Note that the provisioned `feedbacks` container declares `/bookId` as its partition key without a Cosmos unique-key policy.
- **Governed read-only agent access:** [[agent|rating-agent]] reads reviews through its governed review-lookup tool (`default_action: deny`, rate-limited at `30/minute`). Generated AI summaries and classifications are never written back to `ratingdb`.
- **Eventual consistency with Catalog:** [[service|catalog-api]] never queries Cosmos DB directly; it consumes [[event|FeedbackCreatedIntegrationEvent]] and [[event|FeedbackDeletedIntegrationEvent]] to update derived `average_rating` and `total_reviews` projections in [[container|catalog-database]].
- **PII & validation:** Reviewer `firstName` and `lastName` are annotated for PII redaction in command logs, and rating bounds (`0`â€“`5`) are enforced at the [[service|rating-api]] boundary.

:::warning
**Database-per-Service Isolation:** Only [[service|rating-api]] may write to `ratingdb`, and [[agent|rating-agent]] is restricted to governed read-only queries. Never run PostgreSQL DDL scripts against Rating in live environments (the attached `schema.sql` is a legacy/reference relational DDL only; the active store is Azure Cosmos DB).
:::
