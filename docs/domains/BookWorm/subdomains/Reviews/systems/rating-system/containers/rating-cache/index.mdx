Rating cache is the non-authoritative FusionCache L1 + Redis L2 caching layer used by [[service|rating-api]] to cache per-book AI feedback summaries produced by the `SummarizeFeedback` query. It avoids repeated multi-step LLM summarization runs for identical books while keeping [[container|rating-database]] (Azure Cosmos DB) as the sole source of truth for customer feedback.

## Overview

| Property               | Value                                                                                                                                                                                                                                              |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**              | Reviews bounded context — [[service\|rating-api]] (`rating`)                                                                                                                                                                                       |
| **Aspire resource ID** | `redis` (shared Azure Managed Redis resource)                                                                                                                                                                                                      |
| **Source**             | `src/Services/Rating/BookWorm.Rating/Features/Summarize/SummarizeFeedbackQuery.cs`, `src/Services/Rating/BookWorm.Rating/Domain/EventHandlers/FeedbackCacheInvalidationHandler.cs`, `src/Services/Rating/BookWorm.Rating/Extensions/Extensions.cs` |
| **Engine**             | FusionCache (`2.10.0`) + Redis (local container + RedisInsight in development; Azure Managed Redis in cloud)                                                                                                                                       |
| **Authoritative**      | No (`authoritative: false`, `readWrite`)                                                                                                                                                                                                           |
| **Classification**     | `internal`                                                                                                                                                                                                                                         |
| **Retention**          | Transient (`6 hours` for reviewed books; `1 minute` when `ReviewCount == 0`)                                                                                                                                                                       |

## Architecture and cache-miss flow

Rating API registers an Azure-authenticated Redis client (`DisableAutoActivation = false`), FusionCache (L1 memory + Redis L2 + Redis backplane + distributed lock + 2-hour fail-safe via `BookWorm.Chassis`), and a 24-hour integration event idempotency guard (`AddIntegrationEventIdempotency()`).

## Cache keys, payload, and TTL policy

`SummarizeFeedbackHandler` configures explicit per-entry `Duration` (L1) and `DistributedCacheDuration` (L2) values rather than relying on the global `Caching:Expiration` default.

| Cached state                                   | Logical key                                       | L1 & L2 TTL                  | Source on miss                                                 | Invalidation strategy                                                                                                                                           |
| :--------------------------------------------- | :------------------------------------------------ | :--------------------------- | :------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Book with feedback (`ReviewCount > 0`)**     | `rating:summary:v1:{BookId}`                      | `6 hours`                    | `ISummarizer.SummarizeAsync` (Cosmos DB + Map-Reduce workflow) | Actively evicted on `FeedbackDeletedEvent` and `FeedbackRevertedEvent`; expires by 6-hour TTL on additional `FeedbackCreatedEvent` writes                       |
| **Book with no feedback (`ReviewCount == 0`)** | `rating:summary:v1:{BookId}`                      | `1 minute`                   | Cosmos DB query (no LLM call made)                             | Actively evicted immediately on `FeedbackCreatedEvent` (when cached `ReviewCount == 0`), `FeedbackDeletedEvent`, and `FeedbackRevertedEvent`, plus 1-minute TTL |
| **Book feedback list entries**                 | Tagged with `RatingCacheKeys.FeedbackTag(BookId)` | `Caching:Expiration` default | Cosmos DB query (`ListFeedbacks`)                              | Actively evicted by tag (`RemoveByTagAsync`) on `FeedbackCreatedEvent`, `FeedbackDeletedEvent`, and `FeedbackRevertedEvent`                                     |

### Cached `SummarizeResult` payload

Values are serialized as JSON using `System.Text.Json` and contain six fields:

- `summary` — Synthesized natural-language summary of customer feedback.
- `classification` — Deterministic tier (`NoData`, `Bad`, `Good`, or `TopRated`) computed by `RatingClassifier.Classify`.
- `averageRating` — Computed arithmetic average rating across stored feedback records.
- `reviewCount` — Total count of feedback records evaluated.
- `evidence` — Supporting review themes identified by the quality-assessment step.
- `confidence` — Assessment confidence level.

## Operational notes

- **Up to 6-hour staleness window on new reviews for already-reviewed books:** `FeedbackCacheInvalidationHandler` actively evicts `rating:summary:v1:{BookId}` on deletions, reversions, and when a previously unreviewed book (`ReviewCount == 0`) receives its first review. Adding another review to a book that already has a cached summary (`ReviewCount > 0`) refreshes on the 6-hour TTL.
- **Targeted cache invalidation:** To force regeneration for a single book without impacting other services on the shared Redis cluster, delete only the key matching `rating:summary:v1:{BookId}` rather than flushing the entire Redis instance.
- **Shared-instance flush warning:** Flushing `redis` globally also clears active baskets in [[container|basket-database]], locks/idempotency markers in [[container|order-cache]], and 24-hour Kafka event idempotency keys across five services.
