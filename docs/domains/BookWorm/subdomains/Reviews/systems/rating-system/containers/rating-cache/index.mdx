## Purpose & Ownership Boundary

Rating Cache is the non-authoritative FusionCache L1 + Redis L2 caching tier owned exclusively by [[service|rating-api]] in the Reviews bounded context. Caching avoids repeated multi-step LLM summarization runs for identical books while keeping [[container|rating-database]] (Azure Cosmos DB) as the sole source of truth for customer feedback.

## Logical Data Layout & Key Patterns

| Key Pattern                                       | Stored Data                                                                                                  | TTL / Eviction                              | Invalidation / Update Trigger                                                                     |
| :------------------------------------------------ | :----------------------------------------------------------------------------------------------------------- | :------------------------------------------ | :------------------------------------------------------------------------------------------------ |
| `rating:summary:v1:{BookId}` (`reviewCount > 0`)  | JSON summary payload (`summary`, `classification`, `averageRating`, `reviewCount`, `evidence`, `confidence`) | `6 hours` (L1 & L2)                         | Actively evicted on feedback deletions/reversions; refreshes by 6-hour TTL on additional reviews. |
| `rating:summary:v1:{BookId}` (`reviewCount == 0`) | Empty-state summary payload (avoids LLM calls)                                                               | `1 minute` (L1 & L2)                        | Actively evicted immediately when the first feedback is created, deleted, or reverted.            |
| Feedback list keys (tagged by `BookId`)           | Paginated [[entity\|feedback]] list payloads                                                                 | `30 minutes` (`Caching:Expiration` default) | Actively evicted by tag on feedback creation, deletion, or reversion.                             |
| Integration idempotency keys                      | 24-hour Kafka message deduplication markers                                                                  | `24 hours`                                  | Automatic TTL expiration after consumer processing.                                               |

## Consistency, Isolation & Security Guardrails

- **Asymmetric summary staleness window:** Deletions, reversions, and the first review on an unreviewed book evict `rating:summary:v1:{BookId}` immediately; adding another review to an already-reviewed book refreshes on the `6-hour` TTL to bound LLM summarization cost.
- **Stampede & fail-safe protection:** Distributed Redis locking ensures only one replica invokes [[agent|rating-agent]] on a cache miss, and a 2-hour fail-safe window protects availability during transient downstream issues.
- **Targeted invalidation:** To force regeneration for a single book, delete only `rating:summary:v1:{BookId}`.

:::warning
**Shared Redis Key-Prefix & Flush Isolation:** Rating Cache shares the `redis` cluster with [[container|basket-database]], [[container|catalog-cache]], [[container|order-cache]], and Notification idempotency markers. Never flush the shared Redis instance globallyâ€”doing so clears active customer baskets, distributed checkout locks, and 24-hour Kafka idempotency markers across five services.
:::
