`FeedbackDeletedIntegrationEvent` (v1.0.0) signals that Rating API deleted an existing customer `Feedback` document from Azure Cosmos DB (`ratingdb` / `feedbacks`). Catalog API consumes this event to subtract the removed score from the target book's denormalized rating summary in PostgreSQL (`catalogdb`).

## Overview

| Property                 | Value                                                                                                                                                    |
| :----------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**                | Reviews bounded context (`Rating API`)                                                                                                                   |
| **Producer**             | [[service\|rating-api]]                                                                                                                                  |
| **Consumer**             | [[service\|catalog-api]] (`FeedbackDeletedIntegrationEventHandler`)                                                                                      |
| **Source**               | `src/Services/Rating/BookWorm.Rating/IntegrationEvents/Events/FeedbackDeletedIntegrationEvent.cs`                                                        |
| **Protocol / format**    | Kafka + CloudEvents JSON (Wolverine)                                                                                                                     |
| **Kafka topic**          | `bookworm.{env}.rating.feedback-delete` (where `{env}` is the kebab-case environment name)                                                               |
| **Message identity**     | `BookWorm.Contracts.FeedbackDeletedIntegrationEvent`                                                                                                     |
| **Partition key**        | `BookId` (configured via `opts.MessagePartitioning.ByPropertyNamed("BookId", "FeedbackId")`)                                                             |
| **Outbox / idempotency** | Published via Wolverine Cosmos DB persistence (`WolverineFx.CosmosDb`, `ratingdb`); consumed in Catalog API with 24-hour Redis idempotency keyed by `id` |

## Parameters and fields

The table below reflects the runtime C# contract (`FeedbackDeletedIntegrationEvent : IntegrationEvent`) serialized as camelCase JSON inside the CloudEvents envelope.

| Name           | Type                 | Required | Default                 | Constraints                                              | Description                                                                |
| :------------- | :------------------- | :------- | :---------------------- | :------------------------------------------------------- | :------------------------------------------------------------------------- |
| `id`           | `string` (UUID)      | Yes      | `Guid.CreateVersion7()` | UUID v7 inherited from `IntegrationEvent`                | Unique event identifier; used by Catalog API as the Redis idempotency key. |
| `creationDate` | `string` (date-time) | Yes      | `DateTime.UtcNow`       | ISO 8601 UTC timestamp inherited from `IntegrationEvent` | UTC timestamp when Rating API created the event.                           |
| `bookId`       | `string` (UUID)      | Yes      | —                       | Valid UUID; also used as Kafka partition key             | Identifier of the book whose rating summary must be decremented.           |
| `rating`       | `integer`            | Yes      | —                       | `0`–`5` (`int`)                                          | Rating score removed from the book's denormalized rating summary.          |
| `feedbackId`   | `string` (UUID)      | Yes      | —                       | Valid UUID                                               | Identifier of the deleted `Feedback` document.                             |

:::warning
**Schema drift notice:** The legacy EventCatalog file `schema.json` sets `"additionalProperties": false` and omits `id` and `creationDate` inherited from `IntegrationEvent`. Catalog API actively reads `id` for Redis idempotency; consumers must accept all five fields.
:::

## Error handling and delivery guarantees

| Condition                                                     | Behavior                                                                                                                        | Recovery behavior                                                       |
| :------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------- |
| Target book not found in `catalogdb`                          | `FeedbackDeletedIntegrationEventHandler` returns without modifying state or emitting a compensating event.                      | No action required; no local rating summary exists to adjust.           |
| Duplicate delivery within 24 hours                            | `IIntegrationEventIdempotencyGuard` skips duplicate processing using `idempotency:FeedbackDeletedIntegrationEventHandler:{id}`. | Prevents double-subtracting a rating on retries.                        |
| Transient PostgreSQL or concurrency error                     | Wolverine retries with cooldown (`50ms`, `250ms`, `1s`) and full jitter.                                                        | Exhausted messages route to `bookworm.{env}.catalog.dead-letter-queue`. |
| Deserialization failure (`JsonException` / `FormatException`) | Routed directly to `bookworm.{env}.catalog.dead-letter-queue`.                                                                  | Validate payloads against `tests/pacts/Catalog-Rating.json`.            |
