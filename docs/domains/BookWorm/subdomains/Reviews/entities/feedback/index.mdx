`Feedback` is the Reviews aggregate root for one customer's rating and optional comment about a book. Rating API owns it and persists it in Azure Cosmos DB, not PostgreSQL.

## Overview

| Property                  | Value                                                                                                         |
| :------------------------ | :------------------------------------------------------------------------------------------------------------ |
| **Owner**                 | Reviews bounded context / **Rating API** (`rating`)                                                           |
| **Source**                | `src/Services/Rating/BookWorm.Rating/Domain/FeedbackAggregator/Feedback.cs`                                   |
| **EF Core configuration** | `src/Services/Rating/BookWorm.Rating/Infrastructure/EntityConfigurations/FeedbackConfiguration.cs`            |
| **Backing store**         | Azure Cosmos DB database `ratingdb`, container `feedbacks`, partition key `/bookId` (EF Core Cosmos provider) |
| **Base type**             | `AuditableEntity<FeedbackId>`, `IAggregateRoot`                                                               |
| **Identifier**            | `FeedbackId` (Vogen value object wrapping `Guid`); generated as UUID v7 in the constructor                    |
| **Concurrency**           | Cosmos DB `_etag` (`UseETagConcurrency()`); `RowVersion` is ignored                                           |

## Invariants and behavior

- **Rating range:** The constructor throws `RatingDomainException("Rating must be between 0 and 5.")` outside `0`-`5`.
- **No discriminator:** `HasNoDiscriminator()` stores documents without an EF Core type discriminator.
- **Conflict handling:** `RatingDbContext.SaveEntitiesAsync` maps a Cosmos DB `409 Conflict` to `"A feedback from this author already exists for this book."` and a concurrency failure to `"The feedback was modified or deleted by another request."`.
- **Domain events:** The constructor raises `FeedbackCreatedEvent(bookId, rating, id)`. `Remove()` raises `FeedbackDeletedEvent(bookId, rating, id)`. `Revert()` raises `FeedbackRevertedEvent(bookId)` after a downstream failure.
- **Rating summary:** Rating API publishes `FeedbackCreatedIntegrationEvent` and `FeedbackDeletedIntegrationEvent`. Catalog API updates `Book.averageRating` and `Book.totalReviews` from them.

No Cosmos DB unique-key policy for `(bookId, firstName, lastName)` is declared in `AppHost.cs` or `FeedbackConfiguration`. Duplicate-review prevention is not guaranteed by database constraints.

Neither `FeedbackConfiguration` nor the generated `cosmos.bicep` declares a unique-key policy. The generated container only sets `/bookId` as its partition key; uniqueness by reviewer name is not guaranteed by the repository deployment artifacts. Separately managed Azure configuration was not inspected.
