## Purpose & Scope

This platform trigger topic carries periodic five-minute signals published by [[service|scheduler-service]] to instruct [[service|catalog-ingestion]] to synchronize pending book-search embeddings into the vector store. The payload contains only an event identifier and timestamp, with no book or customer data.

:::note
**Intentional Naming Exception:** This topic is unprefixed (`scheduler.process-vector-batch`) across all environments and omits the `{env}` parameter so static serverless Kafka triggers can bind to a constant topic name.
:::

## Ordering, Retries & Failure Handling

- **Single-writer exclusivity:** [[service|catalog-ingestion]] acquires an exclusive database advisory lock; overlapping triggers exit immediately without duplicate indexing.
- **Transient retries:** If embedding generation or vector store writes fail, unacknowledged rows remain in the pending catalog queue rather than being discarded.
- **No DLQ required:** Because the five-minute schedule re-triggers batch processing automatically, failed batches self-heal on the next cycle once dependencies recover.
- **Consumer idempotency:** Queue revision checks prevent stale embeddings from overwriting newer book edits made while a batch is in flight.
