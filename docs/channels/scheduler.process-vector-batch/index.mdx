Scheduler publishes this periodic signal to ask Catalog Ingestion to synchronize pending book-search vectors. The signal is issued every five minutes and contains no individual book or customer data.

**Producer:** Scheduler service. **Consumer:** Catalog Ingestion worker.

This topic is intentionally named `scheduler.process-vector-batch` in every environment; it has no `{env}` parameter.

## Topic and message

The message is a small CloudEvents JSON trigger with an event ID and creation time. There is no Kafka key. Catalog Ingestion processes pending updates in batches; if another worker is already processing, a trigger may finish without doing work. Failed work remains pending for a later scheduled run.

## Operations and recovery

Check Scheduler and Catalog Ingestion logs, plus the availability of the embedding, vector-search, and database services. A failed batch leaves pending updates for a subsequent run, so restoring dependencies is normally sufficient; do not manually acknowledge or delete pending updates. This worker trigger has no dedicated dead-letter topic. The five-minute schedule retries outstanding work.
