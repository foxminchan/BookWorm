`bookworm.{env}.ordering.order-status-change-to-cancel` (v1.0.0) is the Kafka topic owned by Ordering API that reports an `Order` transitioning from `New` to `Cancelled`. Finance consumes `OrderStatusChangedToCancelIntegrationEvent` through an Azure Functions Kafka trigger to signal the running `OrderOrchestrator` saga instance. This channel reports business cancellation state and is distinct from order soft deletion and Finance's downstream `CancelOrderCommand`.

## Delivery, partitioning, and consumer behavior

- **Transactional outbox:** Ordering API publishes `OrderStatusChangedToCancelIntegrationEvent` through Wolverine's PostgreSQL outbox (`orderingdb`, `wolverine` schema) bound to EF Core transactions (`UsePostgresOutbox`), guaranteeing at-least-once dispatch after committing the `Order` status change.
- **Partitioning:** Ordering API partitions by `OrderId` so events for the same order stay on a single partition within this topic.
- **Finance Durable Functions consumption:** `OrderCancelledTrigger` listens on `%KafkaTopics:OrderStatusChangedToCancel%` with `ConsumerGroup = "finance"`, unwraps the CloudEvents `data` object via `CloudEventsMessageParser.Deserialize`, and invokes `client.RaiseEventAsync(orderId, "OrderStatusChangedToCancelIntegrationEvent", @event)` against Durable Task Scheduler (`finance-taskhub`).
- **Saga transition:** `OrderCancelledStep` transitions the `OrderOrchestrator` aggregate to terminal `OrderStatus.Cancelled` and, when `Order.CanSendNotification` is true (both `FullName` and `Email` are non-blank), dispatches `CancelOrderCommand` on [[channel|bookworm.&#123;env&#125;.finance.cancel-order]].

## Error responses and dead-letter behavior

| Condition                                                                                         | Handling behavior                                                                                                                                                                                                        | Recovery behavior                                                                                                                                                 |
| :------------------------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Invalid JSON or malformed CloudEvents envelope                                                    | `CloudEventsMessageParser.Deserialize` throws `JsonException` or `InvalidOperationException` inside `OrderCancelledTrigger`.                                                                                             | Inspect `finance` Azure Functions logs and Kafka consumer group `finance` offsets; Finance does not configure a Wolverine native DLQ for incoming Kafka triggers. |
| Durable Task Scheduler (`finance-taskhub`) unreachable                                            | `client.RaiseEventAsync` fails inside `OrderCancelledTrigger`.                                                                                                                                                           | Verify Durable Task Scheduler health and Azure Functions host logs before replaying or resetting offsets.                                                         |
| Order already in terminal saga state (`Completed`, `Cancelled`, `BasketDeletionFailed`, `Failed`) | `OrderLifecycleDecider` rejects non-terminal transitions with `FinanceDomainException` if an orchestration is still executing; events raised to an already completed orchestration instance are ignored by Durable Task. | Inspect `OrderOrchestrator` instance status (`orderId`) in Durable Task Scheduler.                                                                                |

The Finance and Catalog Ingestion `host.json` files contain no Kafka retry or commit overrides. With `Microsoft.Azure.Functions.Worker.Extensions.Kafka` 4.3.3 defaults, `CommitOnFailure` is `true`: a failed invocation's offset is stored for auto-commit and the message is not retried. If disabled, the extension retries the message in place up to five times, then force-commits and skips it. See the versioned [`KafkaOptions`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Config/KafkaOptions.cs), [`SingleItemFunctionExecutor`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Trigger/SingleItemFunctionExecutor.cs), and [`AsyncCommitStrategy`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Trigger/AsyncCommitStrategy.cs) sources.
