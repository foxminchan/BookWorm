Basket publishes this topic after checkout cleanup succeeds. Finance uses the confirmation to continue the order workflow; it does not mean the order itself is complete.

**Producer:** Basket service. **Consumer:** Finance order coordination.

A repeated checkout request may also produce this confirmation when the basket was already handled. Finance ignores duplicate confirmations once it has recorded the outcome.

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.basket.delete-complete`. Replace `{env}` with `development`, `staging`, or `production`. Messages are CloudEvents JSON and are keyed by `orderId` so outcomes for an order stay together. The example shows the order ID, deleted basket ID, and order total.

## Operations and recovery

If Finance does not progress, check the Kafka record and Finance service logs using the order ID. Confirm that the order workflow is active before replaying. Replaying a successful cleanup confirmation is safe after the outcome has been recorded; do not treat it as an order-completion signal.
