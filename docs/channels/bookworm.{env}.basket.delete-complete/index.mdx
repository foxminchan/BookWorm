`bookworm.{env}.basket.delete-complete` (v1.0.0) is the Kafka topic owned by Basket API that reports successful checkout basket cleanup to Finance. Basket API publishes `BasketDeletedCompleteIntegrationEvent` as the result of handling `PlaceOrderCommand`. The event reports basket state only; it does not indicate order completion.

## Delivery, partitioning, and consumer behavior

- **When Basket API publishes:** `PlaceOrderCommandHandler` returns this event in two cases. First, when `IBasketRepository.DeleteBasketAsync` returns `true`. Second, when the 24-hour Redis idempotency key for the `OrderId` already exists, so a repeat command is answered without another delete.
- **Partitioning:** Keyed by `OrderId`.
- **Finance consumption:** `BasketDeletedCompleteTrigger` deserializes the CloudEvents `data` object and raises external event `BasketDeletedCompleteIntegrationEvent` on `OrderOrchestrator` instance `orderId`. `BasketDeletedCompleteStep` marks the basket deleted, registers a `DeleteBasketFailedCommand` compensation, and publishes [[channel|bookworm.&#123;env&#125;.finance.delete-basket-complete]].
- **Duplicates:** The orchestrator waits for this event only while `Order.BasketDeleted` is `false`. Extra raised events are not processed again.

## Error responses and dead-letter behavior

| Condition                          | Handling behavior                                                                | Recovery behavior                                                      |
| :--------------------------------- | :------------------------------------------------------------------------------- | :--------------------------------------------------------------------- |
| Malformed CloudEvents payload      | `CloudEventsMessageParser.Deserialize` throws in `BasketDeletedCompleteTrigger`. | Inspect `finance` Functions logs and consumer group `finance` offsets. |
| Durable Task Scheduler unreachable | `RaiseEventAsync` throws.                                                        | Restore `finance-taskhub` connectivity.                                |
| Orchestration already terminal     | Durable Task ignores events for finished instances.                              | Inspect instance status by `orderId`.                                  |

The Finance and Catalog Ingestion `host.json` files contain no Kafka retry or commit overrides. With `Microsoft.Azure.Functions.Worker.Extensions.Kafka` 4.3.3 defaults, `CommitOnFailure` is `true`: a failed invocation's offset is stored for auto-commit and the message is not retried. If disabled, the extension retries the message in place up to five times, then force-commits and skips it. See the versioned [`KafkaOptions`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Config/KafkaOptions.cs), [`SingleItemFunctionExecutor`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Trigger/SingleItemFunctionExecutor.cs), and [`AsyncCommitStrategy`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Trigger/AsyncCommitStrategy.cs) sources.
