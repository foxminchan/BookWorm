## Purpose & Scope

This topic transports successful basket-cleanup confirmations published by [[service|basket-api]] within the Shopping bounded context after a submitted basket is removed. [[service|order-orchestration]] consumes these events to advance the post-checkout saga; confirmation here indicates basket cleanup only, not final order completion.

## Ordering, Retries & Failure Handling

- **Partition-key ordering:** Records are partitioned by `orderId` so cleanup confirmations for a given order are processed sequentially.
- **Transient retries:** [[service|order-orchestration]] applies bounded retry/backoff on transient storage or orchestration host faults.
- **Poison & failure posture:** Because Finance consumes this topic directly via orchestration workers, there is no dedicated service DLQ; persistent consumer failures surface in worker diagnostics and orchestration state.
- **Consumer idempotency:** Repeated checkout cleanup requests may emit duplicate confirmations; [[service|order-orchestration]] ignores duplicates once the saga has recorded the outcome.
