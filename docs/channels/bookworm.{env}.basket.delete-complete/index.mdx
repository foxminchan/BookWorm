## Overview

This channel carries [[event|BasketDeletedCompleteIntegrationEvent]] messages from
[[service|basket-api]] after [[domain|shopping]] deletes a customer's
[[entity|basket]] during checkout. Consumers can continue the
[[domain|ordering]] workflow without treating basket state as order state. The
topic is generated by the shared Kafka topic router from the Basket service
owner and the `delete-complete` event topic.

<ChannelInformation />

## Message contract

The event is serialized as a CloudEvents message with an `application/json`
data payload:

| Field          | Type      | Required | Description                                 |
| -------------- | --------- | -------- | ------------------------------------------- |
| `id`           | UUID      | Yes      | Integration-event identifier.               |
| `creationDate` | date-time | Yes      | UTC event creation timestamp.               |
| `orderId`      | UUID      | Yes      | Order associated with the checkout cleanup. |
| `basketId`     | UUID      | Yes      | Basket deleted by the cleanup operation.    |
| `totalMoney`   | decimal   | Yes      | Purchase total associated with the order.   |

## Delivery and handling

- Delivery is **at least once**; consumers should be idempotent by event
  `id`, or by the `orderId` and `basketId` pair.
- A message on this channel means the basket deletion operation completed
  successfully. It does not indicate payment settlement or order completion.
- Consumers should retain the event identifiers and timestamp for tracing
  checkout coordination.
