`bookworm.{env}.ordering.user-checked-out` (v1.0.0) is the Kafka topic owned by Ordering API that carries `UserCheckedOutIntegrationEvent` after a customer places an order. Finance consumes this stream through an Azure Functions Kafka trigger to start an `OrderOrchestrator` Durable Task saga instance for post-checkout basket cleanup and order emails. Publication confirms order persistence in Ordering API only, not basket cleanup or order completion.

## Delivery, partitioning, and consumer behavior

- **Transactional outbox:** Ordering API publishes `UserCheckedOutIntegrationEvent` via Wolverine's PostgreSQL outbox (`orderingdb`, `wolverine` schema) bound to EF Core transactions (`UsePostgresOutbox`), guaranteeing at-least-once dispatch after committing the new `Order`.
- **Partitioning:** Ordering API partitions by `OrderId` so messages for the same order stay on a single partition within this topic.
- **Idempotent saga startup:** `UserCheckedOutTrigger` subscribes to `%KafkaTopics:UserCheckedOut%` with `ConsumerGroup = "finance"` and unwraps the CloudEvents `data` object using `CloudEventsMessageParser.Deserialize`. Before starting a workflow, it queries `client.GetInstanceAsync(orderId)` in Durable Task Scheduler (`finance-taskhub`); if an instance already exists, it logs a warning and returns without creating a duplicate orchestration.
- **Orchestration configuration:** For new orders, `UserCheckedOutTrigger` starts `OrderOrchestrator` with `InstanceId = orderId` and `OrderStateMachineSettings` (`MaxAttempts: 3` timeout retries and `MaxRetryTimeout: 00:30:00` per wait window in `BookWorm.Finance/appsettings.json`). `OrderOrchestrator` immediately publishes `PlaceOrderCommand` to [[channel|bookworm.&#123;env&#125;.finance.place-order]].

## Error responses and dead-letter behavior

| Condition                                              | Handling behavior                                                                                                               | Recovery behavior                                                                                                                                           |
| :----------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Duplicate checkout delivery for the same `orderId`     | `UserCheckedOutTrigger` detects an existing Durable Task instance via `GetInstanceAsync(orderId)`, logs a warning, and returns. | Expected idempotent deduplication; no duplicate saga starts.                                                                                                |
| Invalid JSON or malformed CloudEvents envelope         | `CloudEventsMessageParser.Deserialize` throws `JsonException` or `InvalidOperationException` in `UserCheckedOutTrigger`.        | Inspect `finance` Azure Functions logs and consumer group `finance` offsets; Finance does not configure a Wolverine native DLQ for incoming Kafka triggers. |
| Durable Task Scheduler (`finance-taskhub`) unreachable | `GetInstanceAsync` or `ScheduleNewOrchestrationInstanceAsync` throws inside `UserCheckedOutTrigger`.                            | Restore Durable Task Scheduler connectivity and inspect Azure Functions logs and consumer offsets.                                                          |

The Finance and Catalog Ingestion `host.json` files contain no Kafka retry or commit overrides. With `Microsoft.Azure.Functions.Worker.Extensions.Kafka` 4.3.3 defaults, `CommitOnFailure` is `true`: a failed invocation's offset is stored for auto-commit and the message is not retried. If disabled, the extension retries the message in place up to five times, then force-commits and skips it. See the versioned [`KafkaOptions`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Config/KafkaOptions.cs), [`SingleItemFunctionExecutor`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Trigger/SingleItemFunctionExecutor.cs), and [`AsyncCommitStrategy`](https://github.com/Azure/azure-functions-kafka-extension/blob/4.3.3/src/Microsoft.Azure.WebJobs.Extensions.Kafka/Trigger/AsyncCommitStrategy.cs) sources.
