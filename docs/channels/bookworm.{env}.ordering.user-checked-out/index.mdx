Ordering publishes this event after it has saved a new order. Finance consumes it to start the post-checkout workflow, which coordinates basket cleanup and order notifications.

**Producer:** Ordering service. **Consumer:** Finance order coordination.

The event confirms order persistence only. It does not confirm basket cleanup, completion, or email delivery. The consumer avoids starting a second workflow for an order it has already seen.

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.ordering.user-checked-out`. Replace `{env}` with `development`, `staging`, or `production`. Messages are CloudEvents JSON keyed by `orderId`; the example includes basket and order identifiers, customer details, and total. The `basketId` field in current messages represents the buyer identifier; it may not be an independent Basket service record. Finance starts the workflow and publishes [[channel|bookworm.&#123;env&#125;.finance.place-order]].

## Operations and recovery

If no workflow starts, check Finance worker logs, consumer progress, and workflow status by order ID. A duplicate checkout event is normally ignored when a workflow already exists. This direct worker trigger has no dedicated dead-letter topic, so investigate its processing outcome before resetting offsets or replaying. Avoid exposing customer contact details in diagnostics.
