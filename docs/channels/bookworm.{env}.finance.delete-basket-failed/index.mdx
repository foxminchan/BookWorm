Finance publishes this command when Basket reports that checkout cleanup failed, or when the workflow must compensate for a later failure. Ordering consumes it to soft-delete the order record; the order's business status is not changed.

**Producer:** Finance order coordination. **Consumer:** Ordering service.

This topic is distinct from Basket's upstream failure event: [[channel|bookworm.&#123;env&#125;.basket.delete-failed]].

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.finance.delete-basket-failed`. Replace `{env}` with `development`, `staging`, or `production`. Messages are CloudEvents JSON keyed by `orderId` and carry basket and order details. Failed Ordering messages go to [[channel|bookworm.&#123;env&#125;.ordering.dead-letter-queue]].

## Operations and recovery

Verify the order state and failure context before replaying because this command soft-deletes the order record. If the order is already absent, handling is a no-op. For a dead-lettered message, restore database or service health and confirm the payload matches the intended order before replay.
