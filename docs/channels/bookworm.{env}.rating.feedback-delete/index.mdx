`bookworm.{env}.rating.feedback-delete` (v1.0.0) is the Kafka topic owned by Rating API that notifies Catalog API when a `Feedback` record is deleted. Catalog API consumes `FeedbackDeletedIntegrationEvent` to remove the deleted rating from the book's denormalized average rating and review count.

## Delivery, partitioning, and consumer behavior

- **Producer persistence:** Rating API deletes the `Feedback` record in Azure Cosmos DB (`ratingdb` / `feedbacks`, partition key `/bookId`, no PostgreSQL) and publishes through Wolverine with `WolverineFx.CosmosDb` persistence (`UseCosmosDbPersistence("ratingdb")`).
- **Partitioning:** Keyed by `BookId` so feedback deletions for the same book stay on a single partition within this topic.
- **Consumer processing and idempotency:** Catalog API consumes with Wolverine's PostgreSQL durable inbox (`catalogdb`, `wolverine` schema). `FeedbackDeletedIntegrationEventHandler` acquires a 24-hour Redis/FusionCache key (`idempotency:FeedbackDeletedIntegrationEventHandler:{id:N}`), fetches the `Book` from `catalogdb`, calls `book.RemoveRating(@event.Rating)`, and commits via EF Core.
- **Missing-book no-op:** If `book` is `null`, Catalog API returns without updating any row and does not emit `BookUpdatedRatingFailedIntegrationEvent`.

## Error responses and dead-letter behavior

| Condition                                                                                                                                              | Handling behavior                                                                                       | Recovery behavior                                                                                                       |
| :----------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------- |
| Target `Book` does not exist in `catalogdb`                                                                                                            | Handler returns cleanly as a no-op; no compensation event or DLQ entry is emitted.                      | Expected when the book was already removed.                                                                             |
| Transient database or infrastructure failure (`TimeoutException`, `HttpRequestException`, `DbUpdateConcurrencyException`, transient `NpgsqlException`) | Redis idempotency key is released; Wolverine retries at `50ms`, `250ms`, and `1s` with full jitter.     | After retries exhaust, Wolverine moves the envelope to [[channel\|bookworm.&#123;env&#125;.catalog.dead-letter-queue]]. |
| `JsonException` or `FormatException`                                                                                                                   | Immediately moved to [[channel\|bookworm.&#123;env&#125;.catalog.dead-letter-queue]] with zero retries. | Fix contract mismatch between Rating API and Catalog API before replaying.                                              |
