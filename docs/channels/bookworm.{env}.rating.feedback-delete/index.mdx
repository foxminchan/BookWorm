## Purpose & Scope

This topic transports feedback-deleted events published by [[service|rating-api]] within the Reviews bounded context when a customer removes feedback. [[service|catalog-api]] consumes these events to subtract the removed rating from the book's displayed summary. If the book no longer exists in Catalog, the event is treated as a safe no-op without compensation.

## Ordering, Retries & Failure Handling

- **Partition-key ordering:** Keying by `bookId` preserves per-book ordering alongside feedback creation events.
- **Transient retries:** [[service|catalog-api]] applies bounded retries with backoff for transient database or concurrency errors.
- **Immediate DLQ routing:** Malformed payloads, deserialization errors, or exhausted retries route to [[channel|bookworm.&#123;env&#125;.catalog.dead-letter-queue]].
- **Consumer idempotency:** Deletions for missing books or already-removed feedback entries are handled as safe no-ops.
