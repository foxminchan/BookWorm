This topic holds Finance basket-cleanup outcome commands that Ordering could not process. It receives both the cleanup-success and cleanup-failure commands.

**Writer:** Ordering service. **Reader:** Operators investigating or recovering failed messages. Records preserve the original message and order key.

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.ordering.dead-letter-queue`. Replace `{env}` with `development`, `staging`, or `production`. Source topics are [[channel|bookworm.&#123;env&#125;.finance.delete-basket-complete]] and [[channel|bookworm.&#123;env&#125;.finance.delete-basket-failed]]. Kafka retention is configured by the broker.

## Operations and recovery

Check Ordering service and database health and inspect the order before replaying. The success command only records an operational outcome; the failure command soft-deletes the order record. Replaying a success is safe; replay a failure only after verifying that its side effect is intended. An already-missing order is treated as a no-op.
