`bookworm.{env}.ordering.dead-letter-queue` (v1.0.0) is the native Kafka dead-letter topic for Ordering API. Wolverine routes incoming Finance basket-cleanup commands here when Ordering API exhausts its retry policy or cannot deserialize the payload. Ordering API pairs this Kafka DLQ with PostgreSQL durable inbox/outbox storage in `orderingdb`.

| Parameter | Type     | Required | Default       | Allowed values                         | Description                              |
| :-------- | :------- | :------- | :------------ | :------------------------------------- | :--------------------------------------- |
| `{env}`   | `string` | Yes      | `development` | `development`, `staging`, `production` | Kebab-case Aspire host environment name. |

A dead-lettered record preserves the original CloudEvents value (`DeleteBasketCompleteCommand` or `DeleteBasketFailedCommand`) and Kafka key (`orderId`).

Wolverine 6.65.1 adds `exception-type`, `exception-message`, `exception-stack` (truncated to 8,192 characters), `failed-at` (Unix milliseconds), and `original-destination` to native dead-letter records; Kafka records also include `original-partition` and `original-offset`. The delivery-attempt count is in the `attempts` header. See the [version-pinned diagnostic header reference](https://github.com/JasperFx/wolverine/blob/V6.65.1/docs/tutorials/dead-letter-queues.md#diagnostic-headers-on-dead-letter-messages).

## Routing rules

| Exception                                                                                               | Retries before DLQ                                              | Source                          |
| :------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------- | :------------------------------ |
| `TimeoutException`, `HttpRequestException`, `DbUpdateConcurrencyException`, transient `NpgsqlException` | `3` retries at `50ms`, `250ms`, `1s` with full jitter, then DLQ | `ConfigureDefaultErrorHandling` |
| `JsonException`, `FormatException`                                                                      | None (immediate DLQ)                                            | `ConfigureDefaultErrorHandling` |

:::note
`DeadLetterQueueExpiration = 7 days` applies to Wolverine's PostgreSQL durable storage in `orderingdb` (`wolverine` schema). Kafka topic retention for `bookworm.{env}.ordering.dead-letter-queue` is governed by broker configuration.
:::

## Replay safety

| Check                                   | Why it matters                                                                                                                                                                                                                                                                                                    |
| :-------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`orderingdb` health and correlation** | Inspect Ordering API logs and `orderingdb` connectivity using `orderId` and `traceparent` to separate transient database outages from contract mismatches.                                                                                                                                                        |
| **Soft-delete side effect**             | Neither command changes an order's business `Status` (`New`, `Completed`, `Cancelled`). Verify order state before replaying `DeleteBasketFailedCommand`, because it soft-deletes the `Order` record (`order.Delete()`).                                                                                           |
| **Idempotency behavior**                | `DeleteBasketCompleteCommandHandler` only logs and is inherently safe to replay. `DeleteBasketFailedCommandHandler` uses `IIntegrationEventIdempotencyGuard` (`idempotency:DeleteBasketFailedCommandHandler:{id:N}`, 24-hour TTL), releases the key on failure, and treats an already-missing `Order` as a no-op. |
