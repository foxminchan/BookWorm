`bookworm.{env}.finance.place-order` (v1.0.0) is the Kafka topic owned by Finance that fans out `PlaceOrderCommand` to two independent consumers. Basket API deletes the submitted basket and reports the outcome; Notification sends a new-order email. A message on this topic does not prove that an order was persisted, and it is not a Notification-owned topic.

## Delivery, partitioning, and consumer behavior

- **Publication triggers:** `OrderOrchestrator` publishes once at saga start. `PlaceOrderTimeoutStep` republishes after each `MaxRetryTimeout` window (`00:30:00`) with no outcome, until `MaxAttempts` (`3`) is reached; then the saga cancels. Each publish goes through `PublishPlaceOrderActivity` (retry policy: `3` attempts, `5s`, `2.0x`). Finance publishes regardless of `CanSendNotification`.
- **New `id` per reissue:** `ToPlaceOrderCommand()` builds a new record, so every timeout reissue carries a new `id`. Durable Task activity retries reuse the same serialized input and `id`.
- **Basket API:** `PlaceOrderCommandHandler` acquires a 24-hour Redis key keyed by `OrderId`. On first receipt it deletes the basket from Redis and returns `BasketDeletedCompleteIntegrationEvent` or `BasketDeletedFailedIntegrationEvent`. On a repeat for the same `OrderId` it skips deletion and returns `BasketDeletedCompleteIntegrationEvent`. If deletion throws, it releases the key and rethrows.
- **Notification:** `PlaceOrderCommandHandler` acquires a 24-hour Redis key keyed by message `id`, skips blank `email`, renders `Orders/OrderEmail` with subject `"BookWorm: Your Order Has Been Received Successfully"`, and sends via MailKit. A timeout reissue (new `id`) can send another email.
- **Saga independence:** Successful basket cleanup does not complete the order or finish the saga.

## Error responses and dead-letter behavior

| Condition                                        | Handling behavior                                         | Recovery behavior                                                                                           |
| :----------------------------------------------- | :-------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------- |
| Basket not found or Redis delete returns `false` | Basket API returns `BasketDeletedFailedIntegrationEvent`. | Finance publishes `DeleteBasketFailedCommand`; Ordering API soft-deletes the order.                         |
| Redis exception in Basket API                    | Key released, exception rethrown.                         | Wolverine retries transient types at `50ms`, `250ms`, `1s` with full jitter, then routes to the Basket DLQ. |
| SMTP or MJML failure in Notification             | `NotificationException` after the Polly pipeline.         | Routed to the Notification DLQ.                                                                             |
| `JsonException` or `FormatException`             | No retries.                                               | Moved to the consuming service's DLQ.                                                                       |
