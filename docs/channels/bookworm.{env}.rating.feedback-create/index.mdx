`bookworm.{env}.rating.feedback-create` (v1.0.0) is the Kafka topic owned by Rating API that notifies Catalog API when a customer submits a new `Feedback` record. Catalog API consumes `FeedbackCreatedIntegrationEvent` to update the target book's denormalized rating summary (`average_rating` and `total_reviews`) without accessing Rating API's Cosmos DB directly.

## Delivery, partitioning, and consumer behavior

- **Producer persistence:** Rating API persists `Feedback` records in Azure Cosmos DB (`ratingdb` / `feedbacks`, partition key `/bookId`, no PostgreSQL) and pairs Wolverine with `WolverineFx.CosmosDb` persistence (`UseCosmosDbPersistence("ratingdb")`).
- **Partitioning:** Keyed by `BookId` so concurrent feedback creations for the same book land on a single Kafka partition.
- **Consumer processing and idempotency:** Catalog API consumes with Wolverine's PostgreSQL durable inbox (`catalogdb`, `wolverine` schema). `FeedbackCreatedIntegrationEventHandler` acquires a 24-hour Redis/FusionCache key (`idempotency:FeedbackCreatedIntegrationEventHandler:{id:N}`), fetches the `Book` from `catalogdb`, calls `book.AddRating(@event.Rating)`, and commits via EF Core.
- **Missing-book compensation:** If `book` is `null`, Catalog API does not throw or dead-letter the event; it returns `BookUpdatedRatingFailedIntegrationEvent(@event.FeedbackId)` as a cascaded message on [[channel|bookworm.&#123;env&#125;.catalog.book-update-rating-failed]] so Rating API reverts and deletes the orphaned Feedback.

## Error responses and dead-letter behavior

| Condition                                                                                                                                              | Handling behavior                                                                                       | Recovery behavior                                                                                                       |
| :----------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------- |
| Target `Book` does not exist in `catalogdb`                                                                                                            | Handler commits and emits `BookUpdatedRatingFailedIntegrationEvent` via `catalogdb` outbox.             | Rating API consumes the failure event and deletes the orphaned Feedback; no DLQ routing occurs.                         |
| Transient database or infrastructure failure (`TimeoutException`, `HttpRequestException`, `DbUpdateConcurrencyException`, transient `NpgsqlException`) | Redis idempotency key is released; Wolverine retries at `50ms`, `250ms`, and `1s` with full jitter.     | After retries exhaust, Wolverine moves the envelope to [[channel\|bookworm.&#123;env&#125;.catalog.dead-letter-queue]]. |
| `JsonException` or `FormatException`                                                                                                                   | Immediately moved to [[channel\|bookworm.&#123;env&#125;.catalog.dead-letter-queue]] with zero retries. | Fix contract mismatch between Rating API and Catalog API before replaying.                                              |
