## Overview

This channel carries [[event|BasketDeletedFailedIntegrationEvent]] messages from
[[service|basket-api]] when [[domain|shopping]] cannot delete a customer's
[[entity|basket]] after checkout. Consumers use the failure outcome to recover
the [[domain|ordering]] workflow without interpreting it as successful
cleanup. The topic is generated by the shared Kafka topic router from the
Basket service owner and the `delete-failed` event topic.

<ChannelInformation />

## Message contract

The event is serialized as a CloudEvents message with an `application/json`
data payload:

| Field          | Type          | Required | Description                                    |
| -------------- | ------------- | -------- | ---------------------------------------------- |
| `id`           | UUID          | Yes      | Integration-event identifier.                  |
| `creationDate` | date-time     | Yes      | UTC event creation timestamp.                  |
| `orderId`      | UUID          | Yes      | Order associated with the checkout cleanup.    |
| `basketId`     | UUID          | Yes      | Basket that could not be deleted.              |
| `email`        | email or null | No       | Customer address for recovery or notification. |
| `totalMoney`   | decimal       | Yes      | Purchase total associated with the order.      |

## Delivery and handling

- Delivery is **at least once**; consumers should make recovery and
  notification processing idempotent.
- A message on this channel means basket cleanup failed. It must not be
  interpreted as successful deletion.
- Consumers should use `orderId` and `basketId` to correlate the failure with
  the checkout attempt and use `email` only when present.
