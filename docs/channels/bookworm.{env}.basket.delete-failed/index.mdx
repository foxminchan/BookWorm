Basket publishes this topic when it cannot remove the basket during checkout. Finance records the failure and asks Ordering to soft-delete the order. No customer email is sent for this outcome.

**Producer:** Basket service. **Consumer:** Finance order coordination.

An exception while accessing basket storage is not this business outcome; it is a processing failure and may appear in the Basket dead-letter topic.

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.basket.delete-failed`. Replace `{env}` with `development`, `staging`, or `production`. Messages are CloudEvents JSON and are keyed by `orderId`. The example includes the order and basket IDs, customer email when available, and order total.

## Operations and recovery

Check the order and basket state before replay. A missing basket can be a valid failure outcome, while a storage outage should be resolved before retrying. Finance handles duplicate failure outcomes without applying the same workflow transition twice. Replaying this event can lead to the order being soft-deleted; verify the order state first.
