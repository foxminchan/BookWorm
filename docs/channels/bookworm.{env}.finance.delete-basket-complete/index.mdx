`bookworm.{env}.finance.delete-basket-complete` (v1.0.0) is the Kafka topic owned by Finance that notifies Ordering API after checkout basket cleanup succeeds. Ordering API consumes `DeleteBasketCompleteCommand` to record an audit log entry without changing the order's business status (`New`, `Cancelled`, or `Completed`). This channel is distinct from Basket API's upstream `bookworm.{env}.basket.delete-complete` integration event.

## Delivery, partitioning, and consumer behavior

- **Finance orchestration step:** When `OrderOrchestrator` receives `BasketDeletedCompleteIntegrationEvent`, `BasketDeletedCompleteStep` marks the basket deleted, registers `PublishDeleteBasketFailedActivity` as a LIFO compensation, and dispatches `DeleteBasketCompleteCommand` through `PublishDeleteBasketCompleteActivity` (Durable Task activity retry policy: `3` attempts, `5s` initial delay, `2.0x` backoff).
- **Partitioning:** Finance keys Kafka records by `OrderId` so commands for the same order stay on a single partition within this topic.
- **Ordering API consumption:** Ordering API listens with Wolverine's PostgreSQL durable inbox (`orderingdb`, `wolverine` schema, 1-hour `KeepAfterMessageHandling`, 7-day `DeadLetterQueueExpiration`). `DeleteBasketCompleteCommandHandler` writes an `Information` log message (`LogBasketDeletionCompleted`) with `orderId` protected by `[SensitiveData]` redaction and performs no database write or status transition.
- **Idempotency:** Because the handler only logs the completion event and mutates no state, repeated at-least-once deliveries are inherently safe.

## Error responses and dead-letter behavior

| Condition                                                                                                                                  | Handling behavior                                                                                                                                                                                                                                       | Recovery behavior                                                                                                         |
| :----------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------ |
| Transient infrastructure failure (`TimeoutException`, `HttpRequestException`, `DbUpdateConcurrencyException`, transient `NpgsqlException`) | `WolverineHostExtensions.ConfigureDefaultErrorHandling` retries with `50ms`, `250ms`, and `1s` cooldown intervals plus full jitter.                                                                                                                     | After retries exhaust, Wolverine routes the envelope to [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]]. |
| `JsonException` or `FormatException`                                                                                                       | Immediately moved to [[channel\|bookworm.&#123;env&#125;.ordering.dead-letter-queue]] with zero retries.                                                                                                                                                | Inspect payload contract compatibility between Finance and Ordering API before replaying.                                 |
| Finance activity failure while publishing                                                                                                  | Durable Task retries `PublishDeleteBasketCompleteActivity` up to `3` times (`5s`, `2.0x` backoff); if still failing, `OrderOrchestrator` executes registered LIFO compensations (`PublishDeleteBasketFailedActivity` and `PublishCancelOrderActivity`). | Inspect Durable Task Scheduler (`finance-taskhub`) history and Kafka broker health.                                       |
