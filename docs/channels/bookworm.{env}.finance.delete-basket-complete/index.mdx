Finance publishes this command after Basket confirms successful checkout cleanup. Ordering consumes it to record the outcome for operational tracking; it does not change the order's business status.

**Producer:** Finance order coordination. **Consumer:** Ordering service.

This topic is distinct from Basket's upstream success event: [[channel|bookworm.&#123;env&#125;.basket.delete-complete]].

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.finance.delete-basket-complete`. Replace `{env}` with `development`, `staging`, or `production`. Messages are CloudEvents JSON keyed by `orderId`; the example carries the order ID and total. Failed Ordering messages go to [[channel|bookworm.&#123;env&#125;.ordering.dead-letter-queue]].

## Operations and recovery

Ordering makes no business-state change when handling this message, so replay is safe after verifying the order ID and consumer health. If the record is dead-lettered, check Ordering service logs and database connectivity, then replay after restoring service. Do not interpret the log confirmation as an order status transition.
