`bookworm.{env}.catalog.dead-letter-queue` (v1.0.0) is the native Kafka dead-letter topic for Catalog API. Wolverine moves an incoming Feedback event here when Catalog API exhausts its retry policy or cannot deserialize the payload. A missing book is not a DLQ case; Catalog API publishes a compensation event instead.

## Parameters and fields

| Parameter | Type     | Required | Default       | Allowed values                         | Description                              |
| :-------- | :------- | :------- | :------------ | :------------------------------------- | :--------------------------------------- |
| `{env}`   | `string` | Yes      | `development` | `development`, `staging`, `production` | Kebab-case Aspire host environment name. |

A dead-lettered record keeps the original CloudEvents value and Kafka key (`bookId`, from Rating API partitioning).

Wolverine 6.65.1 adds `exception-type`, `exception-message`, `exception-stack` (truncated to 8,192 characters), `failed-at` (Unix milliseconds), and `original-destination` to native dead-letter records; Kafka records also include `original-partition` and `original-offset`. The delivery-attempt count is in the `attempts` header. See the [version-pinned diagnostic header reference](https://github.com/JasperFx/wolverine/blob/V6.65.1/docs/tutorials/dead-letter-queues.md#diagnostic-headers-on-dead-letter-messages).

## Routing rules

| Exception or condition                                                                                  | Result                                                                                                                                 | Source                                   |
| :------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------- |
| `TimeoutException`, `HttpRequestException`, `DbUpdateConcurrencyException`, transient `NpgsqlException` | `3` retries at `50ms`, `250ms`, `1s` with full jitter, then DLQ                                                                        | `ConfigureDefaultErrorHandling`          |
| `JsonException`, `FormatException`                                                                      | DLQ with no retries                                                                                                                    | `ConfigureDefaultErrorHandling`          |
| Book missing on `FeedbackCreatedIntegrationEvent`                                                       | No DLQ; publishes `BookUpdatedRatingFailedIntegrationEvent` to [[channel\|bookworm.&#123;env&#125;.catalog.book-update-rating-failed]] | `FeedbackCreatedIntegrationEventHandler` |
| Book missing on `FeedbackDeletedIntegrationEvent`                                                       | No DLQ; no-op                                                                                                                          | `FeedbackDeletedIntegrationEventHandler` |

:::note
`DeadLetterQueueExpiration = 7 days` applies to Wolverine durable storage in `catalogdb`. Kafka topic retention is configured on the broker.
:::

## Replay safety

| Check                                              | Why it matters                                                                                                                                                                                        |
| :------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `catalogdb` and broker health                      | Separates transient outages from contract errors.                                                                                                                                                     |
| Idempotency key `idempotency:{HandlerName}:{id:N}` | Both handlers run inside `IIntegrationEventIdempotencyGuard`, which releases the key on failure. A replay of a failed event re-runs; a replay of an already applied event within 24 hours is skipped. |
| Authoritative Feedback state in Rating API         | Replay from Rating API data instead of patching `average_rating` or `total_reviews` in `catalogdb`.                                                                                                   |
