## Purpose & Scope

This topic transports order-cancellation notification commands published by [[service|order-orchestration]] after an order transitions to cancelled. [[service|notification-api]] consumes these commands to submit a cancellation email when valid customer contact details are present. No delivery confirmation is sent back to Finance.

## Ordering, Retries & Failure Handling

- **Partition-key ordering:** Keying by `orderId` preserves ordering for lifecycle notification commands targeting the same order.
- **Transient retries:** [[service|notification-api]] applies bounded SMTP client retries and Kafka listener cooldowns on transient mail-provider failures.
- **Immediate DLQ routing:** Malformed payloads, rendering errors, or exhausted retries route to [[channel|bookworm.&#123;env&#125;.notification.dead-letter-queue]].
- **Consumer idempotency:** [[service|notification-api]] deduplicates by message ID for 24 hours; blank email addresses are skipped safely, and operators must check [[service|sendgrid-api]] activity before replaying.
