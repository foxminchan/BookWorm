Finance publishes this command after an order is canceled. Notification consumes it to submit a cancellation email when the order has customer contact details.

**Producer:** Finance order coordination. **Consumer:** Notification service.

The topic reports a request to send an email; it is not confirmation that the message reached the recipient. Finance does not receive an email-delivery result.

## Channel information

<ChannelInformation />

## Topic and message

The topic is `bookworm.{env}.finance.cancel-order`. Replace `{env}` with `development`, `staging`, or `production`. Messages are CloudEvents JSON keyed by `orderId`; the example includes customer details and order total. Notification skips delivery when no usable email address is present. Failed Notification messages go to [[channel|bookworm.&#123;env&#125;.notification.dead-letter-queue]].

## Operations and recovery

Before replaying a failed email, check the mail provider's activity because a timeout may happen after the provider accepted the message. Replaying the same message may be suppressed for a limited period, but a newly issued message can send a duplicate email. Avoid copying customer names or email addresses into incident notes. This topic is shared with other consumers only through the Notification dead-letter route; replaying it does not change order state.
