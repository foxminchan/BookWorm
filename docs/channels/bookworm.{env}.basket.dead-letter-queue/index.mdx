`bookworm.{env}.basket.dead-letter-queue` (v1.0.0) stores Basket API messages that could not be processed. Basket API uses this topic when it has exhausted its retries or when a message does not use the expected format.

The topic currently receives failed order-placement messages from [[channel|bookworm.&#123;env&#125;.finance.place-order]].

Each record contains the original order-placement request and details about why processing failed.

The record includes an order ID and may include an error message, failure time, source topic, and number of processing attempts. These details help operators determine whether the failure is temporary or requires a message or application fix.

## When a message arrives here

- Basket API may move a message here after temporary connection or database failures have been retried.
- Basket API may move a message here immediately when it cannot read or understand the message format.
- Unexpected Basket API failures are also preserved here rather than discarded.

The dead-letter topic is not a replacement for a normal Basket API response. It is a last-stop record for investigation and recovery.

:::note
Records remain in this topic according to the Kafka broker's retention policy.
:::

## Before replaying a message

1. Check whether the order still exists and whether checkout has finished.
2. Confirm that Redis is healthy and that the basket has not already been deleted.
3. Verify whether this is a temporary service outage or a permanent message-format problem.
4. Replay only to Basket API. The original source topic is also consumed by Notification, so replaying the original topic could send another email.

Replaying a message after the basket was successfully deleted should not delete it again.
